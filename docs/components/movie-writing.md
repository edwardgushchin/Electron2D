# Movie writing

Last updated: 2026-10-16

Owns non-real-time rendered recording through [MovieWriter](../classes/MovieWriter.md), [MovieRecording](../classes/MovieRecording.md) and internal [PNGMovieWriter](../classes/PNGMovieWriter.md)/[AVIMovieWriter](../classes/AVIMovieWriter.md)/[OGVMovieWriter](../classes/OGVMovieWriter.md). [ADR 0109](../decisions/movie-writing.md#adr-0109) owns the typed protocol and host adaptations.

## Runtime flow

Engine.Run(window, path, fps) and its RunAsync counterpart reserve the ordinary owned window lifecycle. After native rendering opens, selection probes custom writers newest-first, then the built-in .png, .avi or .ogv handler. Cold output/bus-effect preparation is closed and recreated for the movie rate; independently attached players or standalone samples reject before conversion. Metadata configures an offline FAudio master and the existing audio bus graph before SceneTree construction/Autoplay. Begin receives the initial rendered pixel dimensions. Each successful process step submits a real canvas frame, reads completed viewport pixels, obtains that frame's PCM, and calls the selected writer. Native input, Ready, physics/process, pause, deferred work and scene teardown remain the ordinary runtime paths.

Fixed mode uses a rational integer physics-tick remainder and bypasses realtime jitter compensation/catch-up dropping. One second at 7 FPS contains exactly 60 ticks at the default physics rate, avoiding a floating-accumulator boundary loss. Process/render delta is exactly 1/FPS times TimeScale; fixed physics callbacks execute every due step, including more than MaxPhysicsStepsPerFrame at low FPS. Audio duration uses an independent output clock. For 48000 Hz at 59 FPS, successive stereo blocks have 1626 or 1628 samples and the total after N frames is floor(N*48000/59) stereo frames. Native mixer quanta may prefetch less than one quantum beyond that consumed boundary; unused PCM is retained, not remixed or lost.

The private audio bridge initializes a master with no platform output stream and invokes the existing FAudio engine procedure. Voices, native SRC, source callbacks, ordered effects and meters use the same graph as live output. The native procedure still contains callback failures; the owner checks source/effect failures before publishing a movie frame. Device switching rejects. Last-player detachment retains the offline graph until Engine cleanup. Recording does not make external microphone input deterministic.

Automatic pre-delete veto retains a borrowed custom writer registration; later AddWriter calls reclaim only committed disposal entries. Runtime-active and callback owner guards still reject before notification.

## Lifetime and failures

The creating thread registers/disposes custom writers; runtime hooks execute serially on the runtime owner. Registered instances remain borrowed and cannot be disposed while any runtime is reserved. Hook reentry into registration, nested runs and active disposal rejects. Invalid public path/FPS arguments preserve an unconsumed root; after reservation the runtime owns and cleans the root even if selection, metadata, native preparation, Begin, Ready, frame or End fails.

End is attempted after an attempted Begin, including a partially failed Begin. Metadata/selection failures do not invoke End. End runs before scene/native teardown; later cleanup always continues. Callback exceptions remain failures, and distinct cleanup errors aggregate. The requested movie path stays visible through teardown and clears when the reservation releases. Captured Images and PCM spans are borrowed only for OnWriteFrame; retention requires an explicit caller copy.

## HDR input

Every writer receives screen-encoded RGB8. Linear half-float viewport pixels retain source precision through centered crop/resize, then apply RGB output transfer before byte quantization. Alpha remains untransferred and is discarded. Alternating HDR/SDR selections preserve the same writer lifetime, dimensions and rational PCM clock. [HDR canvas targets](hdr-canvas.md) records native dark-gradient/PNG checks and output limits.

## Built-in output

A .png path writes basename00000000.png onward and basename.wav. Frame images are opaque RGB8. Size changes use a centered aspect-cover crop and bilinear resize to the initial dimensions. WAV stores little-endian 32-bit signed PCM and finalizes RIFF/data lengths on End, including after a failed frame. RIFF overflow rejects before appending. The destination directory must exist. Prior files matching the exact basename plus eight decimal digits and .png are removed at Begin; other files are preserved. Produced filenames are overwritten; codec/file failure can leave a valid partial recording. Two typed project settings select the built-in audio rate (48000 Hz default, 1000..200000) and speaker mode (Stereo default).

A .avi path writes one classic AVI file containing MJPEG video and interleaved little-endian PCM. MovieWriterVideoQuality accepts finite 0..1, defaults to 0.75 and maps values below 0.01 to JPEG's minimum one-percent quality. Compression is lossy even at 1. MovieWriterAudioBitDepth accepts 16 (default) or 32; 16-bit output takes each signed Int32 sample's high 16 bits. Rate/channel settings apply to both built-ins. Settings are sampled before scene activation and stay fixed throughout the file. AVI dimensions must be positive and at most 32767 per axis. Real RGB8 readback, centered cover resizing and rational cumulative audio clocks are shared with PNG.

The [AVI RIFF reference](https://learn.microsoft.com/en-us/windows/win32/directshow/avi-riff-file-reference) defines the container layout. AVI stores two stream headers with exact rate/scale, frame/sample lengths, aligned 00dc/01wb chunks and an idx1 keyframe index. Index sizes exclude padding and offsets are relative to the movi FOURCC. The 32-bit RIFF length bounds a recording to about 4 GiB; each frame reserves space for its index entries before writing. Exceeding that bound fails before appending. On a failed partial frame, End truncates to the last complete video/audio pair, writes the index and patches lengths. A new output replaces the requested AVI file; parent directories must exist. IO errors during finalization are propagated and can still leave an incomplete file.

A .ogv path writes Theora video and Vorbis audio through a private native bridge with statically linked, pinned Xiph codecs. It uses the same real pixels, rational audio clock and failure-safe host. Initial dimensions must be positive/even; visible dimensions remain exact when internal planes require macroblock padding. Alpha is discarded and RGB8 is converted to limited-range YCbCr 4:2:0. Shared video quality maps 0..1 to Theora 0..63. MovieWriterOGVAudioQuality defaults to 0.5 (-0.1..1), MovieWriterOGVEncodingSpeed to 4 (1..4, higher is faster, capped at the codec maximum), and MovieWriterOGVKeyframeInterval to 64 (1..1024 frames). They are sampled before scene activation. Audio bit depth affects AVI only; Vorbis consumes full-range mixed PCM converted to float.

The [Vorbis channel specification](https://xiph.org/vorbis/doc/Vorbis_I_spec.html#x1-800004.3.9) defines its encoded speaker order. OGV reorders 5.1/7.1 accordingly. Four mixer channels in 3.1 become six Vorbis channels with silent rear left/right, preserving center/LFE instead of describing them as quadraphonic rears. AudioServer still reports the requested 3.1 mix; stereo stays two channels.

The interleaver orders pages by granule time, flushes a separate initial Vorbis priming page and retains the latest Theora packet for EOS. Empty per-frame PCM blocks do not terminate audio. End flushes exact final frame/sample granules and handles zero-frame output; a scene failure finalizes submitted frames. IO errors are contained across the unmanaged callback and propagated; a failed physical write can leave an incomplete Ogg page. Native allocations, pending pages and the GC handle are released before the file closes, including partial Begin failure. Produced destinations are replaced; parent directories must exist. This is file encoding, independent of the absent video playback/resource family.

Source fingerprints, the four encoder exports (nine total after the video decoder extension), loader dispatch, desktop/cross producers, native packages and license audits include Electron2DOGV. Static profiles merge the full codec closure into one archive; a standalone link also executes from a build directory containing spaces.

Independent FFmpeg checks verify decoded pixels/samples, timeline order, keyframe limits and distinct native speaker tones, including silent 3.1 rear channels. Evidence is retained in ignored bin/ogv-movie-validation/2026-10-15.

## Project movie startup

Engine.RunMovie(Window) and RunMovieAsync(Window) sample MovieWriterFile (empty by default) and MovieWriterFPS (60, positive) with active feature overrides, then execute the same recording lifecycle and built-in encoders. A blank profile path fails before reserving or consuming a window. Existing explicit recording Run/RunAsync path and FPS arguments retain precedence, including their 60 FPS optional default. Ordinary runs remain realtime even when a movie file is configured.

MovieWriterDisableVSync defaults to false. Every movie entry point samples it before startup and propagates the value through reserved/deferred hosts. True retains the Disabled presentation request after native display creation and before renderer creation; unsupported policies use the existing fallback. False preserves the backend's ordinary default. This does not persist a presentation request into the next display lifetime, change project settings or prevent later explicit scene presentation changes. MovieProfileTests covers all codec profiles, settings persistence/overrides/snapshots, explicit precedence, ordinary/async ownership and failure cleanup. Local evidence belongs under ignored bin/movie-profile-validation/2026-10-15; foreign native execution, physical presentation and owner acceptance remain separate gates.

The project-profile slice passes source GPU/Compatibility and public-package NativeAOT portable/GPU/Compatibility checks, including fresh-process project load/capture; a self-contained JIT GPU consumer also passes. The managed candidate is 0.1.0-movie.20261015.6 over the unchanged native candidate 0.1.0-movie.20261015.4. The current Wayland GPU host falls back to Enabled for a Disabled request; Compatibility applies Disabled. Tests compare startup with the supported result of the same public presentation request. The initial test's unconditional Disabled expectation was corrected to preserve that native fallback contract. Independent decoding verifies exact frame/sample counts for all emitted profile codecs. Android propagation is implemented but profile execution on Android and other foreign hosts is unverified.

AVI framing verification uses a portable fixed-byte odd/even chunk vector to establish zero padding, unpadded lengths and the next chunk boundary independently of renderer/JPEG output. Native recording continues to verify actual payload padding whenever present, full index extents and quality-dependent file size. A main verification run produced only even JPEG lengths (1206/3018 bytes), exposing the former test's unsupported assumption that a renderer fixture must generate at least one odd-length payload. The [native JPEG quality contract](https://wiki.libsdl.org/SDL3_image/IMG_SaveJPG_IO) permits three quality bands, so different requested qualities can also share quantization tables. This is a test correction; the RIFF writer's encoding behavior is unchanged.
