# Typed runtime undo history

Last updated: 2026-10-15

Owns [UndoRedo](../classes/UndoRedo.md) and [UndoRedo.MergeMode](../classes/UndoRedo.MergeMode.md). Public runtime consumers can author reversible Node/Resource edits through existing typed PropertyDescriptor and Action boundaries. Editor context/UI coordination remains a later consumer. No backend, dependency, reflection or universal-value store is added.

The creating thread owns history. Nested creation builds one pending outer action without mutating completed merge entries. Commit publishes the completed cursor, invokes scheduled do work, changes version/notifies and trims. Prepared Undo/Redo replay retained operation lists. Failure aggregation attempts later operations/observers and keeps the documented cursor/version transition; it cannot automatically roll back arbitrary caller side effects.

Merge policies use a strict 800ms monotonic creation window, name and backwards policy. All executes only the new suffix on merge commit; Ends keeps initial undo/latest do and forced operations on both sides. Retained event snapshots avoid invocation-array allocations in successful replay. Authoring, merging, registration, retirement and diagnostics are cold transitions.

Object reference operations transfer conditional ownership of non-Resource ElectronObjects. Discarding redo disposes do claims; trimming applied history disposes undo claims. Aliased claims preserve retained objects until final matching-side retirement. Resource parameters are rejected, with assets remaining borrowed through ordinary callback/property values. Cleanup publishes structural retirement, attempts all selected objects and aggregates failures. Bulk prefix/branch/history removal moves retained action storage linearly rather than repeatedly shifting a growing list.

UndoRedoTests exercises ordering/nesting, record-only edits, both undo orders, merge/counter boundaries, forced do/undo, version/limit metadata, typed property validators, direct disposed targets, conditional alias/retirement/errors, owner/reentry/disposal guards, 4096-action trimming and actual scene/resource authoring/file persistence. Prepared 128-cycle Undo/Redo/event playback passes zero managed-byte checks separately from cold transitions. Native scene paint/add/remove/branch ownership and real pixels pass UndoRedoRenderingTests on current Linux GPU/compatibility hosts; each backend passes 64 warmed full rendered playback frames at zero managed bytes, measured ProcessFrameStarted through FramePostDraw. Input setup, readback, captures and native allocations are outside that interval.

The independent public-only NuGet/NativeAOT consumer has reflection-disabled JSON and zero IL warnings. Separate author/render processes save an undo/redo-authored compressed big-endian scene, load it and exercise fresh rendered edits/undo/redo on both backends from /tmp with LD_LIBRARY_PATH unset. Native allocations, foreign platforms, complete editor integration and human owner acceptance remain separately reported gates. [ADR 0105](../decisions/undo-history.md#adr-0105) owns the runtime boundary; ADRs 0001/0002/0003/0005/0014/0027/0090 continue to apply.
