# Scene animation

Last updated: 2026-10-27

[ADR 0093](../decisions/scene-animation.md#adr-0093) owns reusable typed animation. The executable chain is [Animation](../classes/Animation.md) → [AnimationLibrary](../classes/AnimationLibrary.md) → [AnimationMixer](../classes/AnimationMixer.md) / [AnimationPlayer](../classes/AnimationPlayer.md) → an ordinary typed node property setter → the existing renderer.

## Author and execute

```csharp
var position = new PropertyDescriptor<Entity, Vector2>(nameof(Entity.Position),
    n => n.Position, (n, value) => n.Position = value);
var clip = new Animation { Length = 1 };
var track = clip.AddTrack(position);
clip.TrackSetPath(track, "Sprite:Position");
clip.TrackInsertKey(track, 0, new Vector2(16, 16));
clip.TrackInsertKey(track, 1, new Vector2(48, 16));
var library = new AnimationLibrary();
library.AddAnimation("move", clip);
var player = new AnimationPlayer();
player.AddAnimationLibrary("", library);
root.AddChild(player); // Sprite is another child of root.
player.Play("move");
player.Advance(0); // Optional immediate application.
```

Each value/Bézier track has an exact compile-time value type and writable descriptor. Method tracks share an exact receiver type and keep each callback payload typed. Relative paths resolve a node of the descriptor's owner type; the optional colon suffix must equal its property name. Missing/wrong-type targets contribute no writes. `Node2D`'s scene role is `Entity`; neutral targets remain `Node`. Built-in interpolation reuses the typed Tween math profile. Noninterpolatable values default to nearest holding, while callers may provide their own typed linear interpolation function. No reflection property setter or arbitrary value container is involved.

Keys are sorted by finite double time. Equal times replace, changing a key time also replaces an occupied destination, and generic access rejects the wrong value type. Continuous tracks evaluate on every update. Discrete tracks write every crossed key in direction order, including repeated loop seams, and avoid repeated setters when no key was crossed. A new binding or explicit seek initializes its sampled value. If an enormous discrete delta cannot make representable progress, evaluation fails and pauses rather than entering an endless loop.

Linear looping connects last/first keys when loop-wrap is enabled; disabling wrap holds edge values. Nearest, linear, time-aware cubic and scalar float/double angle modes execute. Cubic uses the track's typed linear interpolator, so custom interpolators must also support extrapolation. Integer rounding, nonlinear math values, out-of-duration keys and ping-pong edge controls still require the wider interpolation audit recorded as Partial in coverage; the scalar/vector sample checks do not prove every possible generic profile. Capture mode admits snapshot fades through the mixer.

Markers have unique names and times within approximate equality. Adding at an existing time replaces its marker and resets its color to white. Queries return time order; previous includes an exact marker time and next is strictly later. Marker edits notify Changed so resource consumers see committed edits. Clear removes tracks and resets length/loop, while retaining markers and the step hint.

A mixer rejects duplicate library namespaces and duplicate registration of the same library instance. Libraries borrow resources, forward their change names, sort queries ordinally and detach subscriptions deterministically. Replacing a name commits its new entry before removed/added events; reentrant removal is respected. Shallow copies retain resource aliases; deep copies duplicate nested resources through the existing graph session. Clip key containers copy independently; nested resource keys follow deep-copy policy. Arbitrary custom reference values remain caller-owned.

## Playback and lifetime

Idle/physics modes use Node's internal callbacks and inherited process/pause eligibility. Manual mode uses only Advance; detached manual execution is supported. RootNode defaults to the parent. Qualified names use `library/clip`, with an empty library namespace admitting plain names. Play applies on the next update, Pause retains assignment/position and clears queued names and capture caches, and Stop clears the queue and resets position/custom speed; keepState preserves target values. Seek clamps to the section and does not emit completion. Stopped AssignedAnimation rewinds without starting; active assignment switches using the current signed speed. Setting CurrentAnimation to empty or the stop sentinel queues stopping through the attached SceneTree; detached manual playback stops synchronously. Zero speed keeps playback enabled. Finite playback holds its endpoint and emits completion once, then consumes a queued or configured-next name. Linear/ping-pong loops retain overshoot and do not finish.

Resource edits, tree changes, selected clips, root changes and ClearCaches rebuild binding containers on next evaluation. Warmed playback performs no path parsing or value boxing. Each evaluation snapshots bindings and stops after a reentrant control/resource change. Setter failures pause unchanged playback and propagate. Disposed or queued targets and removed/disposed clip sources are handled without transferring resource ownership to the player.

Audio tracks execute as described below; all current cue and property/Bézier track files execute through the typed persistence profiles below. Three-dimensional transform/blend-shape tracks and their root-motion extraction are excluded by the 2D product decision. Exact AnimationMixer/Player nodes now reconstruct authored scene state as described below. AnimationTree reconstructs authored graph and typed parameter state through its exact scene factory. RESET save preparation now executes through PackForSave; editor UI transactions remain separate.

## Weighted transitions and capture

AnimationPlayer now accepts positive custom blend durations. SetBlendTime configures a named transition; PlaybackDefaultBlendTime provides fallback, with exact, source-wildcard and destination-wildcard lookup order. Wildcard names still need registered animations for SetBlendTime validation. Zero duration switches immediately. GetBlendTime queries the explicit pair only. Outgoing clips keep their time, speed, loop/section state and independent remaining contribution; they continue sampling as the new clip advances. Finite completion clears outgoing clips and holds the current endpoint.

The pinned implementation computes the main contribution from outgoing weights before their decay and samples outgoing contributions after decay. For constant values 10→30 with duration 1 and successive quarter-second advances, outputs are 10, 16.6667, 23.3333 and approximately 30; an additional zero advance yields exactly 30. Interrupted transitions retain multiple sources and follow the same ordering. This is a source behavior audit, not a frame-rate-invariance or monotonicity claim.

Each property has a typed accumulator shared by compatible descriptors for the same target ID/name. Conflicting value types fail at preparation. Non-deterministic mode normalizes total participating weight separately for each property; absent tracks leave other properties untouched. Deterministic mode accumulates deltas against zero or an enabled first RESET key, so missing contributions use that base. Discrete Dominant preserves crossed key writes over continuous values; Recessive lets continuous output replace them; ForceContinuous samples nearest values on every update. Discrete ranges still preserve loop/section crossing order. Duplicate tracks share one weight per source instance while all their authored contributions are accumulated.

Bool and integer components round after all contributions; Int64 promotion uses decimal to preserve near-limit values. Scalar/vector/color/rectangle accumulators use reusable numeric scratch. Transform deltas compose through affine group operations. Angle interpolation unwraps around the RESET angle. Strings blend Unicode scalar codes and length, replacing invalid resulting scalar values with the standard replacement rune. Supported typed arrays blend elements, zero-pad missing elements and preserve base tails when unnormalized total weight is below one. String/array outputs are independent values and may allocate; mutable custom reference values remain caller-owned. Custom typed linear interpolation supplies accumulation for other interpolatable value types. No untyped engine value accessor is introduced.

Capture reads enabled Capture-track targets into a separate owned Animation snapshot. Getter/preparation failure does not replace a valid existing snapshot. PlayWithCapture starts a clip with explicit curve/easing; PlaybackAutoCapture does the same for ordinary Play by default. Negative duration derives the maximum first-key interval, or last-key interval when starting from the end. Custom clip speed does not change the capture clock; absolute SpeedScale does. Pause/Stop and ClearCaches cancel snapshots. Source/target rebind cancels a stale snapshot. Borrowed clips, libraries and targets are never disposed by the capture cache. Nested Advance is rejected; setters and typed postprocess hooks may change the controller, with later stale commits abandoned.

## Bézier and method tracks

`AddBezierTrack` accepts only writable float/double property descriptors. `AnimationBezierKey` stores scalar value and relative time/value handles; specialized insert/get/set methods and generic key/container operations share the same storage and revision notifications. Finite handle time signs clamp inward (incoming ≤ 0, outgoing ≥ 0). Sampling inverts cubic time with ten bisections plus adjacent-sample interpolation, has no loop seam interpolation, and ignores generic easing/interpolation metadata. No keys inside clip length yields zero; one such key yields its value; with multiple in-range keys, supplied sample time still searches the full key list. The finite balance-ratio parameter retains the runtime contract; editor handle balancing is absent. Bézier values participate in weighted RESET/rest accumulation and typed postprocessing alongside ordinary properties; they do not create capture snapshots.

```csharp
var x = new PropertyDescriptor<Entity, float>("X",
    n => n.Position.X, (n, value) => n.Position = new(value, n.Position.Y));
var clip = new Animation { Length = 1 };
var curve = clip.AddBezierTrack(x);
clip.TrackSetPath(curve, "Sprite:X");
clip.BezierTrackInsertKey(curve, 0, 16, outHandle: new(1f / 3, 0));
clip.BezierTrackInsertKey(curve, 1, 80, inHandle: new(-1f / 3, 0));
var call = clip.AddMethodTrack<Entity>();
clip.TrackSetPath(call, "Sprite");
clip.TrackInsertKey(call, .5, new AnimationMethodKey<Entity, bool>("visibility",
    static (target, visible) => target.Visible = visible, false));
// Add this clip to an AnimationLibrary and attach a player as shown above.
```

Each method key has its own exact argument type, typed delegate and diagnostic name; multiple signatures coexist in one receiver track. `MethodTrackGetParams<T>` rejects another signature; generic key reads accept the receiver-key base or the actual concrete key type. No object argument array or reflection method lookup occurs. Multi-argument callbacks use tuples/immutable records. Copies keep delegates/custom nested references borrowed, clone directly held arrays, and deep-copy directly held Resource payloads using the existing graph session.

Methods execute through players and AnimationTree, including node-only path filters, silent Sync branches and ordinary blend weights. Internal/startup seek calls the exact key, external seek the nearest preceding key inside the clip; update-only seek/Stop suppress side effects. Crossed keys run in direction order through reverse/sections/repeated linear and ping-pong loops. Idle zero delta does not repeat keys. Playback consumes its startup seek even with method tracks disabled; enabling a track later invokes only subsequently crossed keys. Immediate mode runs in evaluation and reentry/source edits abandon stale traversal. Deferred is the default: keys are retained until the SceneTree safe point, independently of later source edits/cache clearing; disposed/deleting or moved targets are skipped. Callback failures follow SceneTree aggregate delivery and return pooled records in finally; immediate failures pause unchanged player playback.

Per-binding pending records initially number max(16, key count). Call `PrepareMethodCallbacks` before a larger burst, such as many manual advances/loops without a deferred flush. The pool never grows during dispatch; exceeding it throws while retaining already accepted calls. Shared SceneTree queue capacity warms separately, and user callback allocations are not counted as engine guarantees. ## Nested animation tracks

`Animation.AddAnimationTrack` creates a node-only track targeting an existing AnimationPlayer. Specialized name insert/get/set methods and generic string key/container APIs share sorted times, equal-time replacement, revision notifications, interpolation metadata and independent copies. Missing/wrong-role/deleting targets do not execute. There is no new production type, reflection method lookup or section payload in a key.

```csharp
var clip = new Animation { Length = 2 };
var track = clip.AddAnimationTrack();
clip.TrackSetPath(track, "ActorPlayer");
clip.AnimationTrackInsertKey(track, 0, "walk");
clip.AnimationTrackInsertKey(track, 1, "[stop]");
// Register clip in a parent player's library. ActorPlayer is another relative target.
```

Ordinary updates execute the final crossed key in traversal order; a large step deliberately does not start every intermediate clip. Reverse, bounded sections and repeated linear/ping-pong crossings retain this last-key policy. [stop] or a missing name stops playback still controlled by that binding; seek skips those names. Idle zero delta does not repeat commands. Weight/path filters and silent Sync clocks use the existing AnimationTree contract.

Internal startup and external seek choose the preceding key within clip bounds and compute elapsed child time from its key. Select the child clip before seeking, use its own length/loop policy, and clamp finite external endpoints. Internal startup beyond a finite child's lifetime does not start it. Stopped external targets are assigned/sampled synchronously and remain stopped; running/internal targets play/seek and apply on their ordinary next update. Update-only selection/seek preserves the target's stopped/playing policy and suppresses method callbacks. The child continues its own automatic or Manual phase: parent advancement does not add an implicit child Advance and does not reorder SceneTree callbacks. These timing/correctness adaptations avoid old-selection clamping and incorrect loop periods.

Cleanup stops still-controlled children with keepState, preserving values and borrowing nodes/libraries/clips. Control revision protects independent later Play/Seek/Pause/Stop from stale cleanup, including control takeover inside observers. Ownership is set before startup notification so parent Stop or a failed startup observer leaves no orphan child. Pause/Stop, selected-parent-clip changes, ClearCaches, root/tree changes, source rebuild and disposal apply this policy. Resource edits rebuild lazily on the next evaluation; dropping the final event track also clears prior ownership. Self/currently-evaluating targets reject before control, preventing recursive synchronous seek. Exceptions can retain earlier committed values and clocks; no whole-scene rollback is claimed.

Direct property/discrete evaluation retains its own prepared bindings, distinct from weighted accumulators. Control changes reset discrete initial cursors without reconstructing bindings; structural source/root/tree changes rebuild cold. ## Audio tracks

```csharp
var clip = new Animation { Length = 2 };
var cue = clip.AddAudioTrack();
clip.TrackSetPath(cue, "Speaker");
clip.AudioTrackInsertKey(cue, .25, sound, startOffset: .05, endOffset: .1);
// sound is an existing borrowed AudioStream; register/attach the parent as above.
```

Ordinary movement starts the last crossed key, including repeated/reverse loops; seek/startup selects the preceding key within the clip and advances its start offset by elapsed key time. Every still-playing repeated cue remains tracked in bounded records. UseBlend scales gain by clip contributions, with per-receiver normalization outside deterministic mode; false uses unit cue gain. Initial gain is applied before starting the native transport, avoiding a full-volume transient on silent branches.

Authored sources/receivers remain borrowed; temporary parent/child/native state belongs to the controller transport.

Pause/Stop, selected-parent-clip changes, ClearCaches/structural invalidation and disposal stop cue output. ## Key optimization

`Animation.Optimize(allowedVelocityError: .01, allowedAngularError: .01, precision: 3)` reduces existing built-in float, double and Vector2 value curves in their typed key containers. The operation uses time-aware adjacent velocities, a relative speed ratio, normalized vector direction and absolute tolerance `10^-precision`. Both error inputs must be finite within 0–1; precision is 0–15. Nonconstant endpoints remain. A near-constant curve may retain only its first key. Angle curves unwrap adjacent values and retain a key when the combined turn reaches half a revolution.

Linear, linear-angle and nearest interpolation participate; nearest only removes near-constant keys. Equal-speed vector corners still require the direction test. Discrete keys retain their crossed writes, including repeated equal values. Cubic curves, custom interpolators, eased segments and unsupported value families remain unchanged because their behavior cannot be established by these velocity tests. Nonfinite values and unrepresentable velocities do not authorize deletion. Tolerances are local adjacent-segment tests, not a global maximum positional-error bound. The operation is cold authoring work; repeated list removal can be quadratic for dense redundant clips.

All tracks commit before one `Changed` notification; a no-op stays quiet. Observer failure does not restore removed keys. Reentrant no-op calls terminate, resource copies retain separate keys, and attached library/mixer caches rebuild through their existing change observers. ## Typed clip persistence

`Animation` and `AnimationLibrary` have exact factories in the existing `.e2dres` graph format. Before saving and in every loading process, call `ResourceFileTypes.RegisterAnimationProperty` with a stable portable ID, the exact descriptor used for authoring, and the same custom value interpolator when present. This is allocating application setup. The registration restores one exact Node receiver/value family without member reflection or serialized delegates. Float/double bindings also restore scalar Bézier tracks. Descriptor/interpolator pairs and IDs cannot be registered twice; read-only descriptors reject. A changed application schema needs its own stable ID/version.

Stored state includes timing/loop/step, ordered tracks, relative paths, enabled/imported/loop-wrap/interpolation/update metadata, strictly increasing finite key times, finite transitions, typed key values, Bézier handles, named marker times/colors and named library references. Resource keys and library aliases use the existing graph table and ownership/publication rules. The marker blob has version 1 with a fixed little-endian interior; the outer archive supports its existing byte order, compression, dependencies and cache modes. Files have at most 4096 tracks, 65536 marker records and the existing 65536-field graph budget, with reserved metadata capacity. Storage and loading remain cold allocating work.

Value-property and Bézier tracks execute after loading. Method, audio and nested-player tracks use the cue schemas below; method receivers/callbacks require their own compiled registration. Owned AnimationPlayer/Mixer/Tree nodes and graph resources still require their own exact stored factories/definitions; this resource slice does not enable their PackedScene reconstruction. Unregistered descriptors or unsupported keys cannot silently lose fields or overwrite an existing asset. Runtime-only unregistered clips still author, copy and play normally.

The public workflow is: register bindings, author a clip and library, `ResourceSaver.Save`, load `AnimationLibrary` in a fresh process, attach it through `AnimationPlayer.AddAnimationLibrary`, and advance or run the ordinary scene host. Native and fresh-process verification results are recorded with the slice checks; editor persistence and other platform acceptance remain separate.

Partial public authoring example; the relative Sprite target is supplied by the consuming scene. Register this same binding once during setup in each process.

```csharp
var position = new PropertyDescriptor<Entity, Vector2>(
    nameof(Entity.Position), n => n.Position, (n, v) => n.Position = v);
ResourceFileTypes.RegisterAnimationProperty("game.entity.position.v1", position);
using var clip = new Animation();
int track = clip.AddTrack(position);
clip.TrackSetPath(track, "Sprite:Position");
clip.TrackInsertKey(track, 0, new Vector2(16, 16));
clip.TrackInsertKey(track, 1, new Vector2(48, 16));
using var library = new AnimationLibrary();
library.AddAnimation("move", clip);
ResourceSaver.Save(library, "user://motion.e2dres", SaverFlags.BundleResources);
```

The loading process registers the same binding, loads `ResourceLoader.Load<AnimationLibrary>("user://motion.e2dres")`, and passes the resulting library to an existing player's `AddAnimationLibrary`. The file owns decoded resource dependencies; the player borrows the library for its normal lifetime.
