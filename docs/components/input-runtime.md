# Input runtime component

Last updated: 2026-09-24

## Scope

This component converts caller-supplied typed events into raw device state, named action state, per-process/per-physics transitions, and synchronous scene callbacks. Its pointer-control facade delegates to the active display; it owns no native device or pump.

`InputMap` initializes ordinary, rebindable `ui_focus_next`/`ui_focus_prev` and `ui_left`/`ui_up`/`ui_right`/`ui_down` actions from typed `ProjectSettings` defaults. The first two use Tab and Shift+Tab; each directional action uses its arrow key, D-pad button and signed left-stick axis on any controller. Explicit `LoadFromProjectSettings` validates registered version-one `input/<action>` definitions and replaces the map after project settings load. An unhandled root viewport action can move Control focus after the focused Control receives GUI input. A left-stick transition moves focus once while held and can move again after returning to neutral. Automatic traversal requires `FocusMode.All`; an explicit path may select `Click`. Nested viewport ownership, scroll clipping and exact spatial ranking remain open.

The public `InputMap.LoadFromProjectSettings()` reads the process registry; the isolated registry overload uses the same candidate preparation. Active typed feature overrides, all five bindable event families and built-in UI defaults are included. A malformed later binding, unidentified key, unsupported version or 33rd serialized record fails before the live map changes; a successful swap invalidates old pressed contributions before `ProjectSettingsLoaded`.

## Owned types

`Input`, `InputMap`, `InputActionSettings`, `InputBindingSettings`, `InputBindingKind`, `InputEvent`, `InputEventAction`, `InputEventFromWindow`, `InputEventWithModifiers`, `InputEventKey`, `InputEventMouse`, `InputEventMouseButton`, `InputEventMouseMotion`, `InputEventJoypadButton`, `InputEventJoypadMotion`, `InputEventScreenTouch`, `InputEventScreenDrag`, `InputEventGesture`, `InputEventMagnifyGesture`, `InputEventPanGesture`, `Key`, `KeyModifierMask`, `KeyLocation`, `MouseButton`, `MouseButtonMask`, `JoyAxis`, and `JoyButton`.

## Runtime flow

1. A host constructs a live `InputEvent` and calls `Input.ParseInputEvent`.
2. An active MainLoop validates owner-thread and idle-running eligibility before mutation.
3. InputMap validates all relevant live bindings and collects matches under its configuration lock.
4. Input commits raw state and per-binding action contributions under its state lock.
5. Optional pointer emulation creates one device-`-1` event: the first active touch contact generates mouse input, while a left-button mouse press/drag/release can generate scene-only touch input. The generated event is dispatched before its source and is never emulated again. Generated mouse input also commits raw and mapped state; a generated touch does not.
6. If an Engine loop is active, the source event is synchronously forwarded to it, even if a generated-event callback failed. Callback failures from both events are combined.
7. For a Viewport root, SceneTree removes the final transform from window input before callbacks; temporary positional copies are disposed after synchronous dispatch, even on failure. Node-root input retains its original identity. SceneTree captures nodes, walks the snapshot in reverse depth-first order through Node input, then routes root viewport GUI pointer/focused keyboard input, then unhandled `ui_*` focus actions, then unhandled-key and unhandled Node stages. It revalidates membership before ordinary Node callbacks.
8. Each process/physics frame clears only its own just-transition lane in `finally`.

## Dependencies and interactions

The component reads typed versioned action records from `ProjectSettings` only during explicit map loading; it validates before replacement and raises the loaded event after pressed-state invalidation. The component uses `Resource` for event duplication/change reporting, `PropertyDescriptor` for inherited stored event fields, `ElectronObject` for singleton lifecycle/property discovery, `Vector2`/`Transform`/`Mathf` for value operations, Engine/MainLoop for host integration, and Node/SceneTree for dispatch. Pointer mode, shape, custom image and warp methods delegate to the active `DisplayServer`, which owns SDL state and native errors. Input itself has no direct SDL dependency.

## Invariants

- No partially applied action mapping: loop eligibility and matching finish before raw/action mutation.
- No parse re-entry; state remains committed if later user callbacks fail.
- An emulated press owns a matching release even if its setting is disabled while held. Mouse-button masks remain per device so an emulated release cannot clear a physical hold.
- SDL-originated touch-to-mouse and mouse-to-touch duplicates are filtered before `Input`, so each native source produces one configured emulation path.
- Multiple bindings contribute independently; action strength is the maximum live contribution.
- Editing or copying a registered binding synchronously invalidates cached contributions for every action using that reference before fallible public change observers run.
- Disposing a registered binding outside matching removes it from every affected action and clears its contributions before public disposal observers run.
- Exact matching filters extra modifiers and analog direction; releases remove their mapped source.
- Synthetic action descriptions skip synthetic bindings during lookup and fall back to the action name, so cyclic description lookup cannot recurse.
- Node ordering and handled semantics are deterministic; callback exceptions are aggregated.
- Event resources remain caller-owned. Input neither disposes nor stores submitted event objects after transition identity expires.
- Every event value has a validated stored typed property descriptor, and constructor-specific device defaults are the corresponding revert values.
- Touch and drag contact indexes retain the full signed `int` value supplied by a caller; the native display adapter assigns its own non-negative contact indexes.
- Native pointer controls require an active display on its owner thread. `Input` retains only the viewport default cursor policy; `DisplayServer` owns the current native shape and mouse mode. Closing the display removes native pointer capability without disposing the singleton.
- Warmed non-emulated matching and traversal reuse bounded collections. Emulated events and positional viewport-conversion copies are short-lived owned resources and allocate.

## Current implementation status and exclusions

Keyboard, mouse buttons/motion, touch/drag, magnify/pan gestures, controller buttons/axes, direct action events, action maps, raw key/mouse/controller and action queries, vector composition, transition latches, release-all, and Node propagation are implemented.

The separate [Display server](display-server.md) supplies native keyboard, mouse, wheel, and touch input and basic cursor/window control through this component's typed event surface. `Input.MouseMode`, current cursor shape, shape selection, custom image and warp use that native display path. Mouse-motion accumulation, explicit flush, mouse/touch emulation, and SDL-origin duplicate filtering are implemented. `SetDefaultCursorShape` retains the root-viewport default and immediately reapplies a hovered Control override; it does not synthesize the pinned mouse-motion event. Wayland rejects pointer warping; supported backend movement is unverified. Root viewport Control mouse routing, hover, keyboard focus and managed Tab/arrow/D-pad/left-stick navigation run between input and unhandled stages. The viewport exposes the focus owner and release, while focus change, enter and exit notifications run on the scene owner thread; [ControlInputTests](../../tests/Electron2D.Tests/ControlInputTests.cs), [ControlFocusNavigationTests](../../tests/Electron2D.Tests/ControlFocusNavigationTests.cs) and [ControlHoverTests](../../tests/Electron2D.Tests/ControlHoverTests.cs) check these managed paths. Controller discovery/effects, sensors, MIDI, shortcuts, and complete GUI/nested viewport routing retain their separate prerequisites under [ADR 0038](../decisions/input.md#deferred-coverage-and-exact-implementation-triggers).

`InputEventFromWindow.WindowID` is a signed 64-bit stored event value. The current SDL host filters foreign native window events and writes public main-window ID zero to delivered keyboard, mouse and touch events. Caller-created events may retain any ID; owning additional windows and routing their input requires the separate multiwindow host slice.

Gesture resources retain source `Position`, `Factor` and `Delta` values, including zero, negative or non-finite values where applicable. `InputEventGesture` uses the inherited `Device` property with revert default zero. A positional `XformedBy` call still rejects non-finite coordinates before making a copy. The current SDL adapter delivers finger touch/drag and wheel-button input but does not synthesize magnify or pan gesture events; gesture delivery from native input needs the first touch/trackpad recognition slice.

Mouse events use inherited `Device` default 32 and retain caller-supplied button-mask bits and coordinate components. Native SDL mouse events supply known buttons and client positions; caller-created payloads are copied without narrowing. `XformedBy` validates local coordinates before copying. Root viewport input keeps its own coordinate space, while Control GUI delivery converts `GlobalPosition` on each temporary copy into the receiving CanvasLayer's coordinates and rejects derived overflow before callback delivery. Nested viewport routing remains an explicit dependency.

Mouse button and motion resources retain source `ButtonIndex`, `Factor`, pressure, tilt, local and screen movement values without validation. Cancellation controls effective pressed/released queries. Mouse-motion accumulation adopts the latest positions and velocities and sums both relative vectors, including arithmetic overflow. The SDL host validates finite derived coordinates, velocity and wheel amounts before publishing events; malformed queued input is reported while later events continue. On tested Wayland input, fractional wheel factors and physical client-pixel motion survive, and captured mode keeps relative movement while reporting zero velocities. Stylus identity/pressure/tilt, nested viewport transforms, fractional Wayland density and physical devices remain unverified or absent at their own integration boundaries.

Mouse-button `AsText` localizes the nine known button/wheel names, `Button #n` fallback and double-click suffix after the platform modifier prefix. Mouse-motion `AsText` localizes its two-slot position/velocity sentence, formats integral and non-finite components as `.0` and `nan`/`inf`, and uses source wording when a translation has the wrong placeholder count. `VerifyInputText` checks ordinary, unknown and translated values; controller, touch and gesture descriptions remain on their own text rows.

Screen touch and drag resources likewise retain caller-supplied positions, pressure, tilt and motion vectors. A canceled contact is neither pressed nor released; drag accumulation is indexed and preserves floating overflow. The SDL touch adapter validates finite client-pixel position, relative motion, velocity and pressure before contact/index/timestamp mutation. Duplicate downs reject, invalid motion or cancellation leaves the active contact usable, and valid cancellation frees its index for the next contact. A focused Wayland synthetic queue check verifies this ordering. Native double-tap recognition, pen eraser/tilt delivery and nested viewport scaling remain open.

Base InputEvent predicates use independent press/cancel flags. `IsActionReleased` queries InputMap even for a canceled event, so a matching canceled press reports a released action status and an unknown action still fails validation. Base `Accumulate` returns false for non-motion events; mouse motion and screen drag use their pinned indexed/compatible merge rules. Non-positional `XformedBy` returns the same borrowed event; positional overrides return validated caller-owned copies. InputMap registration and deadzones are case-sensitive and validated before mutation; action and binding collections are immutable snapshots of live binding references. Removing an existing binding or erasing all bindings invalidates pressed contributions; removing an absent binding is a no-op. Exact InputMap binding lookup now uses the same family-specific action matching as event queries, including modifier release rules, controller direction/deadzone and first-binding order. Public synthetic `IsMatch` can recognize a physical source through another action, but map registration, lookup and removal keep those event families distinct. Known key names, origin markers, unset text and the action-map separator/fallback now use their audited display and translation rules; remaining concrete event text and native platform verification retain separate coverage rows.

`InputEventAction` stores an ordinal action name, any signed index (negative values select the slot after mapped bindings), a pressed flag and finite clamped strength. Parsing rejects a resolved index beyond 31 before mutation. It tracks contributions by action, device and selected index: a zero-strength press stays pressed, and releasing one explicit index preserves the others. Changing a registered synthetic binding invalidates cached contributions before public change handlers. `AsText` skips synthetic bindings, uses the first concrete binding, and falls back to the action name; concrete localized wording retains its own coverage limit.

A temporary allocation probe on Linux/.NET 8 warmed one active Control under one CanvasLayer for 32 dispatches, then measured 134,144 managed bytes over 128 `Viewport.PushInput` mouse deliveries. The diagnostic print was removed after measurement; the normal GUI ownership test remains. This path already creates disposable positional copies and does not meet ADR 0014's zero-allocation hot-path gate. No native or callback-external allocation claim follows from this measurement. Input dispatch needs a contract-preserving ownership design and an active/idle allocation check before the full mouse type can be marked complete.

For native SDL key events, the display adapter records the event's logical key, maps its scancode to a physical key, and derives the unmodified layout label from that scancode separately. The label may be a non-Latin printable key and need not equal the logical key; non-Latin printable scalars are normalized to invariant uppercase key identities. Left/right control, shift, alt, and GUI scancodes produce the matching `KeyLocation` on press and release; other scancodes use `Unspecified`. The adapter currently leaves `InputEventKey.Unicode` at zero; committed text uses a separate event. SDL key events have no produced text scalar, while text-input events may contain multiple scalars or an IME commit without a key-event identifier. A native per-key Unicode source with verified IME/composition semantics is required in the first native keyboard/text adapter slice. Caller-created `InputEventKey` values may supply a Unicode scalar directly.

## Verification

`tests/Electron2D.Tests/Program.cs` covers validation, complete stored event-property discovery/defaults, duplicate bindings, the 32-source ceiling, modifier exactness, pre-mutation owner/execution rejection, state-before-callback ordering, reverse stage order, handled input, independent process/physics transitions, callback failure aggregation, parse re-entry, failure-safe binding invalidation, raw-strength vector composition, direct actions, mouse/controller state, atomic event accumulation, event transforms including unchanged pan delta, release-all, permanent singleton registration, and zero warmed non-emulated managed allocation. Emulation checks cover defaults, first-touch ownership across devices, pairing across setting changes, mapped synthetic mouse state, mouse-to-touch scene delivery, recursive suppression, and callback failure continuation. The optional SDL dummy-driver suite checks native pointer modifier translation. `InputActionSettingsTests` verifies typed project-file round-trip, map replacement and rollback, event families, and warmed matching allocation in managed code.

The SDL dummy-driver suite also checks that a key's scancode label is independent of its logical keycode, that release clears label state, that non-Latin label code points retain their key identity in the mapper, and that all eight side-specific modifier scancodes plus an ordinary key carry the expected location on press and release. A physical keyboard layout has not been exercised.

The modifier-bearing event base uses the inherited `Device` descriptor with keyboard default 16; mouse and gesture descendants override the default through their concrete type. Autoremap chooses Meta on macOS or Control elsewhere, clears those bits when disabled, and prevents direct writes while enabled. `SetModifiersFromEvent` copies that policy atomically and notifies property-list observers when the policy changes. Native SDL key events omit their own modifier bit while keeping other held bits; injected dummy and Wayland events verify both sides of Shift, Control, Alt and GUI on press and release. Physical keyboard behavior remains unverified.

The optional `ELECTRON2D_TEST_INPUT_POINTER=1` Wayland run opens one display, verifies five native mouse modes, all 17 cursor shapes, a copied custom cursor image, direct DisplayServer shape readback, unsupported warp and cleanup after closing the display. The focused `ELECTRON2D_TEST_INPUT_MODIFIERS=1` run passes on Wayland. A full Wayland display-suite run on 2026-09-24 stopped at the DisplayServer feature-capability assertion before modifier checks; an earlier run also encountered `Surface already associated with window` in its window-mode path. These remain separate display-suite issues.

The targeted `ELECTRON2D_TEST_CONTROL_HOVER=1` Wayland run verifies native Control cursor precedence, immediate refresh on default/filter/property changes and display cleanup. This synthetic input check does not establish physical pointer behavior or other-platform semantics.

Viewport localization preserves raw Input state and the original by-event transition identity; a positional copy has a distinct InstanceID. All six positional XformedBy implementations validate derived finite coordinates before Duplicate, preventing unowned partial event copies on overflow. [CanvasCoordinateTests](../../tests/Electron2D.Tests/CanvasCoordinateTests.cs) verify this boundary, disposal on callback failure and local-coordinate borrowing; native injection is covered by CanvasCoordinateRenderingTests.
