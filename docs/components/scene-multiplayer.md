# Typed scene multiplayer

Last updated: 2026-10-04

## Public surface and ownership

[MultiplayerAPI](../classes/MultiplayerAPI.md) owns the high-level interface and typed default factory; managed providers inherit it directly, replacing the separate extension facade. [SceneMultiplayer](../classes/SceneMultiplayer.md) is the default with owned offline local authority until a network transport is supplied. Caller-supplied MultiplayerPeer remains borrowed and is never closed/disposed by interface replacement or disposal. All operations and disposal require the constructing thread. SceneTree owns only defaults it creates; custom/default supplied APIs remain caller-owned and must detach before disposal.

Each tree initializes its default before node entry/ready. SetMultiplayer assigns a live interface to the default or an existing absolute branch path; each interface has one tree/branch assignment. The nearest matching ancestor branch selects Node.Multiplayer. A null default replacement creates a fresh default; a null custom removes its override. Replacement validates/attaches before committing, commits maps before old cleanup, and detaches previous configuration. Cleanup failure leaves committed ownership visible. Tree activation rollback/finalization attempts API detach/disposal without disposing supplied transports. Node exit runs before interface teardown.

MultiplayerPoll starts true. Idle/process frames poll a prepared snapshot of assigned interfaces after ProcessFrameStarted and before node callbacks, including while paused. Physics frames do not poll automatically. Callback replacement removes old snapshot participants through their attachment identity; later newly assigned interfaces wait until the next frame. Poll failures aggregate while other interfaces/nodes/frame phases run. Set MultiplayerPoll=false for explicit owner-thread Poll control.

## Typed RPC authoring and arguments

[RPCMethod](../classes/RPCMethod.md) and [RPCMethod of TNode/T](../classes/RPCMethod.Generic.md) are immutable direct Node callbacks with nonzero stable numeric IDs, explicit encoded-size/encoder/decoder delegates, and concrete generic argument models. Tuples/records can represent multiple arguments. No reflection, string method invocation, universal object value or engine dynamic serializer exists. Every participant must agree on IDs and its application wire codecs. Custom providers can call public GetEncodedSize/Encode/Decode/Invoke/InvokeEncoded; they own admission and sender scope.

Node.RPCConfig registers the token and copied [RPCOptions](../classes/RPCOptions.md); null removes it. Duplicate IDs assigned to different tokens and incompatible receiver types reject. GetNodeRPCConfig returns copied [RPCRegistration](../classes/RPCRegistration.md) snapshots with borrowed immutable tokens. Methods are disabled when absent; explicit RPCMode.Disabled rejects delivery. AnyPeer admits any connected sender; Authority compares against the receiving node's current authority. GetMultiplayerAuthority starts one; SetMultiplayerAuthority validates positive IDs and optionally changes current descendants only. Authority and RPC policy changes are local and do not replicate themselves. Configure derived Node factory/constructors for PackedScene reconstruction; active transport or runtime method edits are not serialized scene data.

Node.RPC broadcasts; RPCID supplies broadcast/positive/exclusion target. MultiplayerAPI.RPC accepts the concrete Node/token/arguments. RPCOptions controls call-local, requested transfer mode/channel and remote policy. A zero-initialized default policy is Disabled; `new RPCOptions()` selects Authority, remote-only, Reliable/channel zero. Call-local targets include broadcast, self or a negative exclusion that does not exclude self. Local-only calls reject without CallLocal. Remote send precedes local delivery; configured local delivery is still attempted after transport send failure, and failures are reported together. The synchronous local callback sees local ID as sender; remote callbacks see original source even through relay. Scopes restore in finally, including nested local calls and failures; outside dispatch the sender is zero. Successful application codecs should be deterministic, validate full input/trailing bytes and write exactly their declared size.

RootPath is an absolute node path, or empty. Scene assignment configures it automatically. RPC paths are relative to this root and limited to 4096 UTF8 bytes; receive validates strict UTF8, subtree containment and matching branch API. Method ID and receiver policy are checked before codec/callback invocation. Paths resolve/cache on first use, not on each warmed packet. Rename/hierarchy/root/assignment changes invalidate caches at the internal boundary before external tree observers can throw. Changed paths must match on participants before further calls.

## Peer admission and authentication

Admitted identities are separate from direct transport identities and pending authentication. GetPeers snapshots admitted peers; GetAuthenticatingPeers snapshots pending direct sessions. AuthCallback=null admits new direct connections immediately. A nonnull callback is captured when its session begins, then PeerAuthenticating fires; it receives borrowed nonempty bytes through SendAuth. Existing sessions keep their captured callback when the property changes. Only authentication commands are accepted while pending; application/RPC bytes are ignored.

SendAuth requires nonempty bytes and a session with neither side complete. CompleteAuth sends local completion and commits it only after a successful send. PeerConnected fires only after both confirmations; clients also receive ConnectedToServer when server ID one is admitted. Empty authentication messages denote completion and never invoke AuthCallback. AuthTimeout is a live monotonic duration, initially three seconds; finite nonnegative, zero disables expiration. Timeout/disconnect removes pending state before PeerAuthenticationFailed; local explicit DisconnectPeer suppresses its local event and removes state before transport cleanup. Established client transport loss emits ServerDisconnected; establishment failure emits ConnectionFailed.

Connection/authentication events attempt all subscribers and aggregate failures. Recursive Poll and disposal during dispatch reject. Callback Clear/transport replacement/detach changes generation, stopping the old iteration. Clear drops network/path state without closing its peer and is a low-level reset; existing native membership is not magically rediscovered. Outgoing encoding cannot reset/reassign its transport/root/interface before construction finishes.

## Custom messages and server relay

SendBytes requires nonempty payload and admits broadcast/positive/negative-exclusion targets with a requested mode/channel. PeerPacket receives a borrowed span and original sender ID; copy when retaining bytes. The transport determines actual reliability/channel; WS/WSS remains Reliable/channel zero.

ServerRelay defaults true on capable transports. Servers notify clients when other admitted peers join/leave. A client can address another admitted client through server ID one. Relay preserves original source, transfer metadata and broadcast/exclusion behavior, skips sender/excluded peers, and processes server-targeted/broadcast data locally when appropriate. Clients accept relay notifications/data only from the server; servers reject forged peer notifications and nested system wrappers. IDs must be positive and distinct from self; int.MinValue cannot represent exclusion. Turning relay off changes topology and should be coordinated across participants.

The private scene protocol uses command byte 3 for raw data and 7 for system messages; system auth=0, add=1, remove=2, relay=3. Add/remove/relay carry a little-endian signed identity in bytes two through five. RPC command zero carries little-endian uint32 method ID, uint16 UTF8 relative-path width, path bytes and application codec payload. This internal protocol is separate from raw MultiplayerPeer packets; foreign high-level interoperability is not promised by a shared low-level WebSocket transport.

## Preparation, failures and replication

MaxPacketBytes is the complete encoded-message budget, initially 65536, constrained to 64 bytes through 64 MiB. Set before assigning a network peer; assignment prepares send/receive/relay storage. Both prepared and transport capacities apply, including relay/header overhead. Capacity/identity errors reject rather than silently truncate. Oversized inbound packets are drained using the transport's bounded allocating snapshot error path, then reported; malformed/unauthorized/forged messages cannot block later valid packets. Snapshot/error/setup/path-discovery/membership transitions allocate explicitly. Fanout captures prepared recipients so managed transport admission during send cannot invalidate enumeration; transport failure attempts remaining recipients and local delivery before reporting errors. Repeated stable RPC, raw span messages, ready relay and idle Poll reuse storage; application codecs/callbacks remain responsible for their own allocations.

Typed root, node/spawner and node/synchronizer ObjectConfigurationAdd/Remove overloads now execute with [scene spawning/replication](scene-replication.md). MaxSyncPacketSize/MaxDeltaPacketSize provide real complete-group batching. General dynamic object decoding remains excluded by ADR 0001; explicit property/argument codecs preserve concrete models. In-memory PackedScene templates spawn automatically; file scene-format/loading/editor authoring remains separately triggered.

## Verification

[SceneMultiplayerTests](../../tests/Electron2D.Tests/SceneMultiplayerTests.cs) executes a public tree containing server and two client branches in WS and WSS. It checks broadcast/local/positive client-client routing, original sender, authority rejection/change, raw bytes, path rename, owner/budget/disposal and automatic polling toggle. Additional native tests cover bilateral authentication/challenge, deadline, callback continuation, oversized/truncated/forged packet drain, recursion and callback reset. A managed MultiplayerAPI subclass exercises typed default factory, configuration, codec execution, polling and borrowed detachment. Each 64-cycle warmed native WS/WSS RPC/process-frame interval and idle interval reports zero managed bytes.

These network tests are display independent and establish programmatic authoring/headless execution, not rendered/editor/agent or human acceptance. Typed spawning/property synchronization is now verified separately by SceneReplicationTests. Foreign hosts, routed throughput, external native allocation and real application schema/security acceptance remain separate. See [ADR 0094](../decisions/networking.md#adr-0094) and [platform verification](../platform-verification.md).
