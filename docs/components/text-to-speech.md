# Native text-to-speech

Last updated: 2026-11-07

The static DisplayServer TTS family and immutable TTSVoice descriptors execute Windows system speech and Linux/FreeBSD Speech Dispatcher through display-owned native producers. [ADR 0118](../decisions/text-to-speech.md#adr-0118) owns the typed projection, queue, provider and platform contract. These are bounded desktop adapters under ADR 0021; FreeBSD execution and the full delivered-package matrix remain unqualified.

## Configuration and public behavior

Set ProjectSettings.AudioGeneralTextToSpeech before opening a display. The registry defaults `audio/general/text_to_speech` to false, marks it basic and restart-required, and persists it through ordinary typed settings. An existing display retains its sampled policy. Feature.TextToSpeech probes a real native producer; disabled/absent queries return no voices and false speaking/paused state. Unsupported execution controls fail explicitly. Native speech does not require a visible window or a graphical renderer, so desktop dummy video still uses its real speech provider.

TTSGetVoices returns an independent array of immutable TTSVoice values: ID is the exact provider identifier, Name is installed display metadata and Language uses native ISO language/variant codes such as Windows en_US or Speech Dispatcher en-US_none. A default descriptor has empty fields. TTSGetVoicesForLanguage uses ordinal case-sensitive prefix matching and retains provider order; an empty prefix selects all voices. Voice IDs can remain valid across display sessions, independently of opaque application utterance IDs.

TTSSpeak accepts original text/native-supported speech markup, an installed voice ID, volume (default 50), pitch (1), rate (1), signed long utteranceID (0) and interrupt (false). Text and voice must be nonnull and contain no NUL; pitch/rate must be finite. Clamp volume to 0..100, pitch to 0..2 and rate to 0.1..10. Prepare and validate before changing earlier queued work. Empty text schedules Canceled without native output. Interrupt first cancels active/pending requests. Duplicate and negative IDs are ordinary independent requests, not deduplication keys.

TTSPause/TTSResume are idempotent, including idle pause. A nonempty new request resumes pause; empty text does not. Native pause takes effect at a provider boundary after buffered output, not at the exact managed call instant. Native notices queued earlier can arrive afterward. TTSStop purges active/pending work, emits one Canceled notice for each request and resets pause after successful native resume. Requests execute FIFO with per-request voice/volume/pitch/rate, independently of the engine audio bus graph. System speech is not automatically included in engine movie/audio-bus capture.

Two TTSSetUtteranceCallback overloads preserve callback arities. Started/Ended/Canceled take Action with a long ID; Boundary takes Action with int position and long ID. Enum/arity mismatch rejects before replacing state; a typed null clears it. The native provider is polled by ProcessEvents, and accepted notices retain the exact callback snapshot. Delivery stays on the display owner; callbacks can enqueue/control speech. Pump/disposal reentry still rejects. Errors aggregate while required later notices/requests remain eligible. ForceProcessAndDropEvents retains speech notices because they are not input.

Boundary positions are Unicode-scalar indices in the original submitted source. The Windows mapper removes the generated pitch wrapper, handles surrogate pairs and predefined/hex/decimal entities, and retains literal comment/CDATA source lengths. Numeric references are canonicalized before native synthesis because SAPI handles their spellings and offsets inconsistently. Provider markup support and word granularity remain native observations. Windows converts pitch to SAPI markup and rate logarithmically into its supported -10..10 range; high requested rates saturate at native capacity rather than silently leaving a previous native rate after an invalid setter. This does not promise an exact tenfold acoustic rate or identical voices across hosts.

Linux/FreeBSD connect to the real system Speech Dispatcher over SSIP. The runtime uses BCL sockets, not a shipped libspeechd dependency. SPEECHD_ADDRESS selects unix_socket:PATH or inet_socket:HOST:PORT; otherwise use the ordinary XDG runtime/cache socket. An absent local service may autospawn through the installed speech-dispatcher executable. Autospawn waits up to ten seconds for the installed starter; its configured communication method/socket/port must match the requested endpoint. A remote endpoint never starts a local daemon. Host service/module installation and audio routing remain host prerequisites.

Speech Dispatcher enumerates its catalog once per producer and returns independent arrays. Reopen the display to refresh host catalog changes; native start failures remain explicit if a retained voice becomes unavailable. Repeated speech does not query the entire external catalog. The selected TextServer supplies Unicode word ranges. Preparation decodes entities for segmentation, retains the original source and inserts private word-end marks only into text spans. Authored marks, comments, CDATA and attribute quotes cannot forge those boundaries. Explicit inline SSML sentence breaks follow sentence punctuation: eSpeak NG 1.52 otherwise drops intermediate dispatcher pause checkpoints before subsequent marks, leaving only the last checkpoint. Separators retain source coordinates while native pacing remains provider-dependent. Control commands drain the actual pause/terminal notification before subsequent controls or replacement starts, because a command reply alone precedes the service transition. Stopping a paused native message first resumes its retained stream and then waits for cancellation; this retires the native paused snapshot instead of waiting for a cancellation that a paused service does not emit. Idle pause stays in the owner queue without scheduling an asynchronous service pause. Per-client pause context is zero; native resume can repeat a preceding boundary. Linux volume/pitch map to -100..100 and logarithmic rate saturates at the provider's 0.5..2.5 capacity.

SSIP control replies have a ten-second budget, 64 KiB line limit and 64 MiB frame limit. Partial notifications also expire after ten seconds across owner pumps. The producer prepares a 64 KiB read buffer and capacity for 4096 notices encountered during cold control reads; overflow fails explicitly. Malformed framing/UTF-8/metadata, unsolicited control replies and EOF retire the connection. The owner reports failure and cancels every active/pending request once, including a paused queue; availability and pause queries become false. A dead connection is closed idempotently. Lost control cannot prove that an external service stopped already accepted audio; reopening starts a fresh producer and never replays retired requests.

## Native ownership and retirement

WindowsSpeech is private backend code using exact blittable COM vtables and System32 imports. No new managed/native dependency or public COM/audio handle is shipped. The producer balances only COM initialization it acquired, borrows a pre-existing apartment, releases enumerator/token/data-key objects and task-memory strings, and keeps native stream identity separate from application IDs. WindowsSpeech and SpeechDispatcherSpeech share the private INativeSpeech/NativeSpeechText event and preparation boundary. COM event payloads are released inside the Windows producer before normalized events leave it. No managed callback runs through a native speech callback. Native preparation/start errors cancel the failed request and remain reported through the owner pump; later queued work can proceed.

Display close attempts native purge, releases the synthesizer/COM reference even after failure, and clears requests, notices and delegates. Speech is asynchronous rather than modal and does not prevent ordinary display retirement. No callbacks transfer to a later display.

## Verification and remaining work

[Shared public checks](../../tests/Electron2D.Tests/TTSChecks.cs) run through the root profile and [standalone consumer](../../tests/TTS.Consumer/README.md). The independent [SDK voice inspector](../../tools/text-to-speech/voices.cpp) compares actual token metadata. The [process loopback inspector](../../tools/text-to-speech/loopback.cpp) captures only the tested process tree, with real signal, zero-volume, buffered pause/resume, output duration and voiced-frequency controls. It records raw PCM16 stereo at 44.1 kHz and native capture metadata. Silence permits at most one conversion LSB; initial pause settling is measured separately from native buffered output.

Tests cover disabled/restarted settings, snapshot independence, language filtering, owner/null/NUL/finite/voice/arity failures, signed/duplicate IDs, queue order, accepted delegate replacement, callback failure/reentry, stop/interrupt, Unicode/entity/markup source coordinates and active retirement/reopening. Compilation and callbacks alone do not qualify speech audio: source, fresh-package and strict NativeAOT profiles require the independent native captures.

On Windows build 26300, the source root runner, a fresh Core package, strict full-trim NativeAOT and NativeAOT with dummy video each passed 83 public checks with seven independent process-audio captures. Three installed voices agreed with SDK enumeration. Captured controls measured signal peak 22574, zero-volume peak one conversion LSB, normal/fast active durations of 93711/36078 frames and low/high voiced frequencies of approximately 136/244 Hz. Buffered pause reached the conversion-noise floor before output resumed. Disabled profiles also passed, and status-indicator regression retained 75 checks with 20 independent Shell inspections. These are local Windows receipts, not foreign-host or physical-listening acceptance.

Linux qualification uses a real private Speech Dispatcher/eSpeak NG service and an explicitly routed Pulse sink. The [Linux public consumer](../../tests/TTS.SpeechDispatcher.Consumer/README.md), independent libspeechd voice inspector and Pulse helper separate real output from the synthetic protocol-failure controls. A private service sink belongs to a separate producer process; it is not engine-process loopback. Preserve source/Core-package/NativeAOT identities and every provider/configuration dependency.

On WSL Arch Linux x64, the source consumer with dummy video, root CLR runner with a real X11 display, fresh Core-package consumer and strict full-trim NativeAOT each passed 84 public checks with seven independent private-sink captures. All profiles retained the same candidate managed assembly and the explicitly identified production Linux native loader profile. 14,805 voices matched independent libspeechd enumeration. Source, Core-package and NativeAOT synthetic SSIP profiles passed 39 protocol/failure checks, including delayed control transitions, per-producer catalog snapshots, fragmented notices, server/client/syntax refusals and expired partial frames. NativeAOT uses runtime/compiler 10.0.14. Native output measured peak 32768, zero-volume peak 0, normal/fast durations 94383/41037 frames and low/high voiced frequency approximately 74/172 Hz in the NativeAOT receipt. Pause reached exact silence and resume restored signal. Warmed active dispatch measured zero owner/all-thread managed bytes; idle owner dispatch also measured zero.

The cached Linux catalog follows the retained producer lifetime; malformed UTF16 rejects during preparation before interrupting queued work. The real-provider checks exposed asynchronous cancel/pause/resume ordering that a command reply alone cannot qualify. Stop resumes a retained paused native stream before waiting for its terminal cancellation.

The real-service autospawn source profile also passed 84 checks and seven private-sink captures from an initially absent socket. The test used a private executable wrapper/configuration, matching Unix socket and the actual installed service binary.

Wayland speech integration, FreeBSD, Apple, Android/mobile/TV/Web adapters and actual delivered-platform-package host receipts remain open. The X11 receipt verifies display/speech integration, not rendered pixels. Windows host PCM is not physical listening, acoustic voice-quality acceptance, exact cross-provider rate equivalence, complete native allocation accounting or full product-platform qualification. The declaration count does not close these gaps.
