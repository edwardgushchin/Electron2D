# Code authoring

Last updated: 2026-10-07

[CodeEdit](../classes/CodeEdit.md) connects the existing TextEdit document, highlighter, canvas, theme, InputMap, Timer and typed scene storage into a source-authoring widget. [CodeCompletionOption](../classes/CodeCompletionOption.md) replaces an untyped option dictionary with immutable typed fields and exact generic borrowed values. The complete owning API and inheritance are recorded in [CodeEdit coverage](../coverage/classes/CodeEdit.md); class pages describe the document, delimiter/fold, marker, completion, symbol and stored contracts.

At selection, CodeEdit (146 own reference rows), RichTextLabel (174, including one deprecated member) and GraphEdit/GraphNode/GraphElement (175 combined rows across three controls) were compared. CodeEdit uses one already executable TextEdit specialization, directly unlocks application/editor code-authoring and reuses the completed text, fonts, history, canvas and file backends. Rich text needs markup/effects; graph authoring needs three connected model/layout/port controls. CodeEdit was the strongest reachable capability. Runtime authoring and native rendered output are verified; compilation alone is not agent/editor acceptance under ADR 0090.

CodeEditTests exercises indentation/tab stops, paired committed input/newlines/backspace, grouped undo, scalar/escaped/whole-line delimiter boundaries, indentation/comment/string/region folding and header shifts, line marker movement/history and observer-failure continuation, copied configuration, generic option payloads, fuzzy/quoted/multicaret completion, custom virtual filtering and bounded reentrant queue/cancellation delivery, automatic requests, remapped navigation, named regions, routed symbol validation/hover/lookup with actual scene Timer ownership and stored cursor preservation and read-only input versus explicit document actions. PackedScene, ResourceSaver and a separate fresh process execute CodeEdit factory registration and dictionary codecs, followed by actual restored indentation.

The native hosts run real SDL keyboard confirmation, fold/unfold geometry and custom StyleBox mutation rejection through the shared inherited TextEdit guard, actual shaped/colorized text, marker, guideline, completion and highlighted hint pixels on current Linux Wayland GPU and compatibility. Each backend measures 64 prepared ordinary caret/selection/render frames and 64 prepared completion-selection/scroll/render frames after 64 warm-up frames, with zero managed bytes on the owner thread. Native glyph/driver/library allocations, physical keyboard/IME/screen-reader use, foreign OS/RIDs and user acceptance are unverified. Cold first shaping, edits/history, delimiter parsing and provider filtering are excluded from those prepared measurements.

The visually inspected native captures have matching SHA-256 `4e0ba97c37552980a44ac265d197ab0420c32698d0d4b8c7b59369861f99d930`. The native captures are `/tmp/e2d-code-gpu-final.png` and `/tmp/e2d-code-compat-final.png`; they are local verification artifacts, outside the repository and unpublished. Native virtual-keyboard/symbol-picker and semantic accessibility retain the inherited DisplayServer session and AccessibilityServer dependencies. Concrete editor project/script authoring requires ADR 0090 operations; an application-supplied completion provider is not a language compiler or editor acceptance.

Cold history retains the existing O(document size) snapshot ceiling. Candidate matching retains a cold O(prefix length * display length squared) dynamic search; a prefix-minimum table is the upgrade if very long provider lists require it. Prepared drawing reuses layout and geometry buffers. No second renderer, language server or vendor modification was introduced.

After CodeEdit, the next selection compares RichTextLabel/RichTextEffect/CharFXTransform (190 own rows, one pinned deprecated member, three connected types), GraphEdit/GraphNode/GraphElement (175 own rows, three connected controls) and Script/CSharpScript (21 own rows, one pinned deprecated member, one accepted production Script identity). Rich text offers immediate styled dialogue, links, tables and animated glyphs on current Font/TextLayout/canvas/resource backends, and unlocks custom effects and their glyph state. Graph authoring unlocks ports/connections and editor/game graph consumers but needs three new layout/interaction roles. Script still needs the accepted source/assembly association, Resource loading and live owner/metadata integration under ADR 0091. Rich text is the next capability priority.

The full-suite verification initially failed with tiered compilation enabled: AudioDelay's silent interval measured 5416 managed bytes; a longer individual warmup passed audio but a physics parameter interval then failed. Isolated delay passed and the original full suite passed with tiered compilation disabled. The final Release test project explicitly selects that stable optimized JIT profile; production settings are unchanged, and all zero-byte assertions/counts remain intact. Temporary numeric audio instrumentation and per-test warmup changes were reverted. These observations isolate the runtime-profile sensitivity, but do not identify its allocating call stack or prove the tiered profile allocation-free.
