# Copied native depth and stencil state

Last updated: 2026-10-28

`RDPipelineDepthStencilState` copies depth testing/writes, stored-depth bounds and independent front/back eight-bit stencil state into each graphics pipeline. Configuration remains caller-owned; mutation or disposal after creation does not change native pipelines, ordered view/pass programs or sampled component-map variants. [Local device](local-compute.md#depthstencil-graphics-and-sampling) owns attachment formats, clears, sampling and resource lifetime.

`EnableDepthRange` defaults to false; `DepthRangeMin` and `DepthRangeMax` both default to zero. Each bound accepts finite zero through one. Pipeline creation requires an enabled range to be ordered and to have a depth attachment. Disabled ranges ignore ordering. Bounds compare the existing depth/stencil attachment value at each covered sample against the inclusive range; they do not compare incoming vertex/fragment depth. The test works independently of depth comparison/writes. Earlier successful depth writes affect later bounds tests. See the native [depth bounds operation](https://docs.vulkan.org/spec/latest/chapters/fragops.html#fragops-dbt) and [static pipeline requirements](https://docs.vulkan.org/refpages/latest/refpages/source/VkGraphicsPipelineCreateInfo.html).

Depth bounds require independently enabled Vulkan depthBounds. The factory queries the pinned native device and tries at most 32 optional raster combinations before reducing the current precision/storage profile. A missing or refused bounds feature leaves per-face stencil, wide lines, sample shading, alpha-to-one and ordinary storage usable. A requested unavailable range raises NotSupportedException; there is no inert switch.

Stencil compare/write masks retain the low eight bits of signed int values. References for visible faces must fit zero through 255. Front/back compare, fail, depth-fail and pass operations retain their separate selectors and original defaults. Both visible faces may now have different effective masks and references. Culling keeps the existing surviving-face projection and ignores invalid reference values on an unused face. Equal effective state continues through ordinary SDL pipeline creation.

The call-local native adapter copies VkPipelineDepthStencilStateCreateInfo and supplies independent front/back masks/references. It removes only the shared dynamic stencil-reference selector when independent values are required, so SDL's common reference commands cannot replace the static copied faces. Ordinary pipeline switching still restores its dynamic reference. The same adapter composes bounds/stencil with line width, primitive discard, sample masks, sample shading and alpha-to-one. Existing locked layout caches, shader ownership, failure rollback and pending native retirement remain authoritative. Shared renderer callbacks are never changed.

## Executable checks

Build `tests/DeviceGraphicsStorage.Consumer` with the matching render bridge. The `depth`, `depth-source` and `depth-canvas` profiles exercise binary/source GLSL/HLSL output and the retained canvas. `depth-refuse` runs with either the physical query fixture `mask-depth.c` or the device-creation fixture `test_depth_mask.c`; `depth-unavailable` and `depth-failure` use the existing raster adapter fixture. Repeat these profiles in strict trimmed NativeAOT.

Checks cover inclusive normalized/zero-sized ranges, stored-versus-incoming depth, prior depth writes, disabled/inverted/nonfinite ranges, missing attachments and actual independent simultaneous faces. Stencil compare/write masks and references survive description mutation, pass/fail/depth-fail operations, switching to ordinary pipelines and pending pipeline/framebuffer retirement. Two views/two passes retain both native roles with four samples and automatic resolves. Sampled component variants combine bounds/stencil, four-pixel lines, one-sample coverage, sample shading and alpha-to-one; independently passing bounds make primitive-discard rejection observable. Prepared draw/readback, variant and view/pass cycles check thirty-two iterations after sixteen warmups for zero owner-thread managed bytes. The ordinary depth suite retains all eight stencil operations, comparison operators, culling, depth bias, sampling and aspect/lifetime errors.

Linux/Wayland Vulkan on the exercised GPU is the qualification boundary. Native/driver heap cost, throughput, validation layers, other platforms/backends and owner visual acceptance remain unverified. Raw depth/stencil aspect transfers, depth resolve and additional dynamic-state API keep their separate dependencies.
