# Canvas rendering

Last updated: 2026-10-10


Process-wide service operations and events use static access to retained objects under [ADR 0095](../decisions/singleton-services.md#adr-0095). ## Low-level primitive commands

RenderingServer now records line/polyline/multiline, filled rectangle/circle/ellipse, polygon/one-to-four-vertex primitive, texture rectangle/region and indexed triangle arrays directly on owned or borrowed items. These operations reuse retained geometry and destination sampling; texture commands resolve the backing RID without invoking high-level virtual texture draw hooks. Input spans are copied, so subsequent caller edits do not change commands. No public resource or node is manufactured as a placeholder. Recording is owner-thread-only and rejects replay/native-submission mutation; source redraw replaces low-level edits as before.

Polylines accept empty/white, uniform or per-vertex colors. Multilines additionally accept one color per segment or separate endpoint colors, including interpolated wide/antialiased geometry. Rectangles/filled ellipses use existing winding/degenerate/feather behavior. Primitive partial attributes keep their existing white/first-color/zero-UV defaults. Textures remain borrowed and their live update/proxy/lifetime behavior is unchanged. Missing texture on rectangle commands selects internal white.

`CanvasItemAddTriangleArray` copies indexed or sequential triangles with white/uniform/per-vertex colors and optional full UVs. A negative count uses complete triples from all indices; nonnegative count selects exactly count times three indices and rejects overflow/out-of-range. Without indices, nonpositive count uses complete vertex triples; unused trailing vertices/indices do not draw. Bounds include all copied input points. Bone and weight channels independently accept zero or four values per vertex: missing indices/weights default to zero. Stored bone indices stay in 0..65535 and weights clamp/truncate to UNORM16, including its first quantum. The existing owned/scene palette conjugation, unnormalized weight sums, finite checks, stale/singular fallback and replay-reader lease apply to this producer too. Classic scene Polygon skin retains its separate normalized-influence policy.

`CanvasItemAddSetTransform` changes subsequent drawing placement; `CanvasItemAddAnimationSlice` switches a repeating half-open visibility interval. Hidden intervals also skip state commands until a later interval permits them. Transform, interval and clip state reset for every replay. `CanvasItemAddClipIgnore` bypasses only rectangular clipping for subsequent commands; false restores it and alpha masks still apply. Compositor owner entries remain present when custom bounds are outside the viewport, so masked/grouped command ranges always close. An empty inherited clip no longer suppresses a later visible ignore command, while earlier drawing transforms remain active.

`CanvasItemSetDrawIndex` changes stable render-sibling order within equal Y/Z groups, independently of Node order. Native items start at zero; authored children use their existing scene index and roots use per-canvas scene traversal order. Source structural changes republish affected native index overrides. `CanvasItemSetUseParentMaterial` selects borrowed material from the actual native parent; its getter remains authored and the source flag setter republishes it. Actual additive material output is verified on both backends. `CanvasItemSetVisibilityLayer` changes the native 32-bit mask tested by every destination viewport and its ancestors; authored getter/input/process state remain separate. The source VisibilityLayer setter republishes only that native field.

[RenderingPrimitiveTests](../../tests/Electron2D.Tests/RenderingPrimitiveTests.cs) exercises copied prefixes, invalid-input rollback/recovery, independent/default skin channels, first UNORM16 quantum, freed palettes, clip resurrection, multiline endpoint colors and 128 warmed indexed/gradient clear/record/replay intervals with zero managed bytes. Its public native host verifies all seventeen producers/state methods, skin, transform/interval, signed order, masks, source republishing and cleanup on Linux Wayland GPU/compatibility with fallback disabled. Existing 31-case ordering tests pass on both backends. These captures establish actual rendered behavior rather than authoring/compilation alone; whole-loop/native allocations, physical/foreign targets and owner acceptance are unverified.

The line/polyline/multiline and primitive rows retain Partial for the exact shared raster prerequisite: hardware subpixel point/line/end coverage is not established for the existing one-pixel triangle footprints. Their new low-level recording path is executable. MSDF/LCD commands need their signed-distance/subpixel shader and sampler contract; particle commands need real GPU emitter storage; direct material RID binding now executes through the shared [shader/material identity layer](shader-materials.md#shader-and-material-identities). None is presented as an inert flag or implemented by compiling a signature.

## Caller-owned canvases and items

`RenderingServer.CanvasCreate` / `CanvasItemCreate` create stable, caller-owned logical RIDs in the active rendering session. Empty items draw nothing until parented to a canvas and given Mesh/MultiMesh/nine-patch commands. `FreeRID` and renderer shutdown release their storage. Canvas/item children retain independent identities: freeing or detaching a parent makes its subtree invisible until reparented, and does not free borrowed mesh, texture, palette or instance resources.

`CanvasLayer.GetCanvas` and `CanvasItem.GetCanvas` return stable borrowed scene identities independently of native startup. The item query follows authored scene membership and returns empty while detached. Each existing viewport owns a default canvas; layers own separate canvases. These identities cannot be freed by RenderingServer. A physics `World` does not yet own a rendering canvas: shared-world default-canvas binding/replacement remains the exact prerequisite for its canvas member.

Canvas parents use an independent renderer graph. Parent can be a live canvas, item or empty RID. Cycles and a depth exceeding 1024 parent edges reject before changing the parent. Server transform, visibility, modulation, self modulation, Z/relative Z, behind-parent, Y sort and sampler fields affect replay without changing scene-node properties, notifications, processing, input, serialization or `GetParentItem`. Matching source setters republish their field according to their ordinary equal-assignment rules; scene parenting republishes native parenting. Native parents can reference source scene items, which still obey their scene lifetime.

`ViewportAttachCanvas` attaches one canvas to any number of active same-tree viewports. Each attachment has independent transform and layer/sublayer stacking; `ViewportRemoveCanvas` suppresses only that destination. Changing transform/stacking does not implicitly attach. Scene getters keep authored transforms; matching CanvasLayer transform/layer setters republish their primary view. Default scene canvas camera/snapping/following behavior continues through the existing viewport preparation. Replay uses destination viewport sampling and framebuffer size.

`CanvasSetModulate` multiplies the complete canvas after inherited and self tint. `CanvasSetItemMirroring` repeats a direct root and its subtree once along each nonzero axis, in canvas coordinates; zero disables repetition. Mesh/MultiMesh/nine-patch commands resolve existing typed RIDs and borrow their resources. `CanvasItemClear` replaces the retained command list. A pending source redraw replaces low-level command edits with its own recording; low-level calls inside Draw append to that recording. Nine-patch reuses the accepted stretch/tile/tile-fit tessellation, source regions/reflections and center suppression, with an empty texture RID selecting internal opaque white. Palette attachment, materials, textures, ordering and native triangle submission reuse the established mesh pipeline.

`DebugCanvasItemGetRect` computes current local retained geometry bounds, including drawing transforms. `CanvasItemSetCustomRect` overrides bounds for clipping and viewport culling, without rewriting command geometry. `CanvasItemSetClip` clips the item and its descendants to those local bounds. Z values stay within -4096 through 4096; inherited Z clamps. Typed TextureFilter/TextureRepeat values share the existing numeric sampler contract, including rejected Max sentinels and the backend limits below. Nonfinite inputs, absent/wrong-domain RIDs, foreign scene owners, off-owner access and mutation during submission reject explicitly.

[RenderingCanvasTests](../../tests/Electron2D.Tests/RenderingCanvasTests.cs) exercises source projections/republishing, packing, borrowed identities, native Mesh/MultiMesh pixels, two simultaneous viewports, per-view transforms, order/tint/clip/custom culling/mirroring, cycle/depth validation, parent/canvas orphan survival, redraw replacement and explicit/shutdown cleanup. Native captures exercise Linux GPU and compatibility with fallback disabled. 128 warmed clear/record/replay cycles allocate zero managed bytes. Native prepared mutation plus FramePreDraw-to-FramePostDraw intervals are reported separately from scene processing, without asserting whole-frame zero allocation; native allocator counts, whole-loop allocation freedom, other platforms, large-scene throughput and owner acceptance remain unverified. Other primitive server commands, visibility-layer/material/light/occluder consumers and shared World canvas ownership remain separately tracked.

## Scope and owned types

The component owns [RenderingServer](../classes/RenderingServer.md) and its internal GPU and compatibility backends. [CanvasItem](../classes/CanvasItem.md) records rectangle, line, polyline, dash, arc, circle, ellipse, polygon, short primitive and texture commands, including six typed text drawing entrypoints over Font; [Label](../classes/Label.md) supplies themed shaped text and effects; [Polygon](../classes/Polygon.md) supplies a filled spatial contour node; [Line](../classes/Line.md) supplies an editable spatial polyline node; [Parallax](../classes/Parallax.md) repeats a camera-relative canvas subtree; [ParallaxBackground](../classes/ParallaxBackground.md) and [ParallaxLayer](../classes/ParallaxLayer.md) supply the independent legacy canvas/layer pair; [Sprite](../classes/Sprite.md) supplies the ready-to-use texture/frame/region node; [AnimatedSprite](../classes/AnimatedSprite.md) supplies timed playback and consumes [SpriteFrames](../classes/SpriteFrames.md) and [SpriteFrames.LoopMode](../classes/SpriteFrames.LoopMode.md) from Resources; [AnimatedTexture](../classes/AnimatedTexture.md) selects timed borrowed frame textures without a node; [Texture](../classes/Texture.md) and [shader materials](shader-materials.md) provide borrowed resources. Engine.Run owns the root Window and the renderer lifetime. This is an executable part of the rendering vertical slice, with broader API coverage still incomplete.

## Runtime flow

1. Open the backend selected by typed ProjectSettings. GPU initialization can fall back only when enabled; shader-dependent draws fail on compatibility.
2. Advance AnimatedTexture resources on unscaled monotonic time, deliver their Changed events, then deliver FramePreDraw, advance the scaled render clock and capture visible nodes. For pending recording, clear commands, then deliver NotificationDraw, synchronous Draw handlers and OnDraw in order. All three may draw. QueueRedraw inside this recording coalesces; internal resource changes remain pending for the next frame. Failure clears partial commands, retains the dirty flag and closes the recording scope before host cleanup.
3. Recapture after drawing callbacks. Resolve canvas roots in scene order, behind-parent subtrees and nested local Y groups; group by canvas layer and sibling index, then sort by effective Z within each canvas, preserving the resolved item order at equal Z. Replay ordered animation/transform state afresh per item, then transform visible retained local geometry into framebuffer pixels. Inherited Modulate and local SelfModulate multiply command colors.
4. Batch adjacent commands only when shader state, blend mode, texture, filter, repeat and anisotropy limit match. Resolve current immutable pixel snapshots and preflight native resources before clearing/drawing. Pixel updates and blend mode changes do not require OnDraw.
5. Upload and submit to the RGBA8 target, copy it to the native window and deliver FramePostDraw. Submission is not display completion. Callback failures trigger Engine.Run cleanup.

Control may contribute a visual-only offset transform to step 3's rendering traversal. Ordinary and Y-sorted child geometry inherits that visual matrix, while logical global transforms and GUI hit testing omit it. With visual-only disabled, the same offset matrix participates in both logical and rendering transforms. The focused scene-hierarchy pixel test verifies a changed Control offset on dummy compatibility and Linux Wayland compatibility/GPU without rewriting the child Sprite's drawing commands.

## Drawing contract

### Fixed canvas blending

[CanvasItemMaterial](../classes/CanvasItemMaterial.md) selects one of five [blend equations](../classes/BlendMode.md) for an item's retained geometry, including texture draws. GPU pipelines use both program payload and mode in their cache key; the five built-in mode entries remain cached across absent frames until backend disposal, while unused custom programs retain eviction; compatibility hardware selects equivalent SDL factors for each geometry or texture batch. The source is not premultiplied automatically for PremultAlpha. SDL software reports success for a premultiplied setting while producing Mix pixels for untextured geometry, so this backend rejects every non-Mix mode before drawing. Native pixel checks cover both kinds of geometry, all five modes on Wayland hardware, live changes without OnDraw, and the software rejection. Light and particle properties remain dependent on their own 2D renderer domains.

Filled rectangles, centered outlines and flat-cap lines use local geometry with compensated local antialias feathers. Negative-width outlines/lines have one-framebuffer-pixel cores. Zero-width ordinary strokes produce no geometry; wide rectangle outlines can expand zero-area input into a visible fill. Nonfinite geometry, transforms or resulting colors fail explicitly. See the stroke and rectangle contracts below for degenerate and thin-width behavior.

Texture drawing stretches, repeats or selects a source region. Negative destination sizes flip without relocating the origin; negative source sizes toggle the corresponding flip. Transpose exchanges UV axes and destination dimensions. Canvas and viewport sampling policies select filtering and addressing as described below. Source clipping clamps half-texel borders while preserving interior interpolation. Texture.GetWidth/GetHeight/GetSize supply logical dimensions; generated curve textures expose their own writable Width. Texture size overrides affect coordinates at command recording; later pixel replacement changes the sampled image without rewriting geometry.

GPU consumes vertex position/color/UV and the imported fragment interface. Built-in TEXTURE is supplied per command, using white for untextured geometry. Compatibility rejects arbitrary shaders, uploads the base mip level and checks unsupported high-precision formats and repeat capabilities. The software driver receives textured triangles separately because SDL 3.4.16's rectangle shortcut loses transposed and constant UVs; native vendored code remains unchanged.

Sprite borrows its texture, records through the texture's virtual region draw method and rebuilds on frame, region, layout or texture changes. Its resource notification callback only marks an atomic redraw request; it cannot run scene code on a worker. CanvasItem consumes that request atomically before OnDraw, retaining notifications that arrive during recording for the next frame. ItemRectChanged is a separate synchronous geometry event: Sprite delivers it after texture identity/centering/offset/active-region/frame/grid changes, with the exact order in its [class contract](../classes/Sprite.md#itemrectchanged). Resource content notifications and Entity transforms do not emit it. Hidden and detached items still deliver; callback failures retain committed geometry and redraw.

[Line](../classes/Line.md) builds editable thick polylines as internal retained triangle arrays, preserving the inherited CanvasItem transform, material, texture sampling and visibility path. The triangle recorder reuses polygon storage and resolves AtlasTexture UVs before committing a command. Line borrows Gradient, Curve and Texture resources and redraws on their changes; PackedScene stores copied point arrays. Finite-segment joint intersection bounds near-reversal geometry, while open-line cap lengths enter interior gradient/curve distance and round-cap UVs cover the arc. The native line pixel test passes round endpoints, a bevel bend, stretched texture sampling and a changed color on Linux Wayland compatibility/GPU (including HLSL/GLSL) and dummy/software. Round caps/joints still lack a complete antialias fringe, and exact source tessellation and UV behavior remain Partial in [coverage](../coverage/classes/Line2D.md).

[Polygon](../classes/Polygon.md) builds filled spatial contours through the same retained polygon recorder. It copies local vertices, index contours, UVs and vertex colors; borrows its texture; and stores typed scene state. Inverted fill bridges the contour to its padded bounds, ignoring explicit index contours while enabled. Native Linux Wayland compatibility/GPU, GPU HLSL/GLSL and dummy/software pixel checks cover separate index contours, texture sampling, inverted fill and redraw after color or border changes. Self-intersections, holes between explicit index contours and skeletal deformation are outside the current executable path; [coverage](../coverage/classes/Polygon2D.md) records the member-specific limits.

## Pixel snapping

Viewport.SnapTransformsToPixel and SnapVerticesToPixel are independent stored flags, false by default. The explicit root Window samples their active ProjectSettings overrides at construction; caller property assignments take precedence. Settings must be loaded before constructing that window. Existing viewports do not track later project changes.

Transform snapping rounds local and accumulated parent origins with floor(value + 0.5) before each normal hierarchy composition. Local basis/rotation/scale remain unchanged. Flattened Y groups compose snapped local origins within the group's coordinate system before sorting; they do not insert extra parent-origin rounding within the flattened chain. Neutral parents and TopLevel retain independent canvas roots. Public node transforms, input coordinates and processing remain fractional.

Vertex snapping rounds final primitive corners after node/draw/framebuffer transforms. The shared geometry path supplies both backends and fragment materials. Texture clipping cells are split on the original diagonal and interpolated within the two snapped triangles; artificial subdivision vertices are not rounded again. This preserves continuous interpolation even when rounding makes a quad non-parallelogram. Texture UVs use the 0.00001 precision adjustment before region clipping. Collapsed triangles draw nothing. Untextured strokes and antialiasing fringes round after tessellation.

Attached Sprite.GetRect, IsPixelOpaque and OnDraw use the rounded local offset under transform snapping. Queries read the current flag, while retained commands keep the offset from their last recording. A viewport flag change does not QueueRedraw or emit ItemRectChanged; request sprite redraw to refresh that recorded offset. Detached sprites have no active viewport offset policy. Vertex snapping does not affect those local queries.

The pinned SDL [software triangle input](https://github.com/libsdl-org/SDL/blob/release-3.4.16/src/render/software/SDL_render_sw.c) truncates fractional vertex coordinates before rasterization. Transform snapping can still leave fractional vertices after scale/rotation, so its edge pixels can differ from hardware. Native checks record that difference and verify the common integer boundary when vertex snapping is also enabled. This is a fallback precision limit under ADR 0028, not identical rasterization.

The audit follows the pinned [canvas culling source](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/servers/rendering/renderer_canvas_cull.cpp), [canvas vertex shader](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/servers/rendering/renderer_rd/shaders/canvas.glsl), [Sprite source](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/scene/2d/sprite_2d.cpp) and Viewport properties. The root project-setting initialization maps to explicit Window construction under the existing typed host lifecycle.

[CanvasPixelSnapTests](../../tests/Electron2D.Tests/CanvasPixelSnapTests.cs) verifies defaults, positive/negative ties, queries versus retained commands, descriptor packing, active project overrides, owner/disposal guards, clipping geometry and warmed allocations. [CanvasPixelSnapRenderingTests](../../tests/Electron2D.Tests/CanvasPixelSnapRenderingTests.cs) exercises both flags independently/together, local versus accumulated translation, neutral/TopLevel boundaries, snapped Y ties, nested scaled Y groups, clipped textures and HLSL/GLSL. Rendering allocation checks also run with both policies enabled. GUI control snapping and embedded containers and multi-view viewport rendering remain separate incomplete capabilities; combined snapping and physics interpolation has not received a native precision audit. Native checks passed on Linux Wayland GPU/compatibility (including HLSL/GLSL) and dummy/software. Both snapping modes retain zero managed allocations in warmed frame submission. Other platforms, visual owner acceptance and a fresh self-contained publish were not checked in this slice.

## Texture sampling

CanvasItem.TextureFilter and TextureRepeat default to ParentNode. A direct canvas parent supplies the inherited policy; a neutral Node or TopLevel breaks that chain. At submission the containing Viewport supplies unresolved defaults (linear/clamp initially). `DrawTextureRect(..., tile: true)` always selects ordinary repeat for that command, even under a mirrored policy. Separate batches retain the resolved filter, repeat and anisotropy limit, so objects sharing a Texture may use different policies in one frame.

Actual canvas-property changes update inheriting canvas descendants, queue redraw under the normal attached/coalescing rules and then raise PropertyListChanged on the changed item. Overrides stop propagation; neutral nodes stop canvas propagation. Viewport defaults are resolved during submission for independent canvas roots. Entry/reparent/TopLevel refresh inherited state; detached policy writes become effective upon entry. Hidden items retain redraw requests. State remains committed if a property-list callback throws. Thread, capture and disposal guards apply before mutation.

Viewport.CanvasItemDefaultTextureFilter defaults to Linear and CanvasItemDefaultTextureRepeat to Disabled. Their ParentNode choice inherits a direct canvas/viewport parent or falls back to those defaults. The current public runtime supports root Window and independent single-layer SubViewport canvases; embedded container and native multiwindow activation remain separate gaps. Viewport.AnisotropicFilteringLevel starts from the active ProjectSettings anisotropy override, normally four samples. The limit affects only anisotropic canvas modes and can change between frames. Disabled preserves ordinary mipmap filtering.

GPU uses all stored image mip levels for mipmap modes and restricts Nearest/Linear to level zero. Images without mipmaps use their sole level. Canvas mip interpolation is linear by default; ProjectSettings.UseNearestMipmapFilter changes it to nearest at GPU-renderer startup. Canvas sampler settings also apply to the reserved TEXTURE binding in HLSL and GLSL materials. Other named material texture parameters use fixed linear filtering, clamp-to-edge coordinates and base-level LOD, including for explicit shader LOD sampling. CanvasItem/Viewport policies do not configure those named samplers; see [shader defaults](shader-materials.md#named-sampler-defaults).

| Sampling capability | GPU | Hardware compatibility | Software compatibility |
| --- | --- | --- | --- |
| Nearest base-level sampling | Yes | Yes | Yes |
| Linear base-level sampling | Yes | Yes | Explicitly rejected |
| Stored mipmaps / anisotropy | Yes | Explicitly rejected | Explicitly rejected |
| Clamp / ordinary repeat | Yes | Yes, subject to wrapping support | Yes, subject to wrapping support |
| Mirrored repeat | Yes | Explicitly rejected | Explicitly rejected |

SDL_Renderer's [address modes](https://wiki.libsdl.org/SDL3/SDL_TextureAddressMode) do not include mirrored repeat. Its pinned [software triangle path](https://github.com/libsdl-org/SDL/blob/release-3.4.16/src/render/software/SDL_triangle.c) does not implement linear filtering; accepting the scale-mode setter alone is not proof of filtered output. The engine rejects that unsupported request before clearing/drawing. Software consumers must explicitly choose nearest for texture drawing. Non-power-of-two repeat still requires the driver's wrapping capability. No backend silently downgrades an unsupported sampling choice.

Sampler caches belong to the GPU backend, are bounded by the enum/anisotropy combinations and are disposed with it. Texture updates and replacements preserve each command's sampling choice. The warmed resolution, batch construction and submission paths allocate no managed memory.


## Canvas lifecycle

Actual SceneTree entry attaches each canvas parent-first and notifies visible entry; exit detaches child-first without visibility/Hidden signals. TopLevel changes rebind the item with an exit/entry pair and schedule redraw. Local Visible changes always notify the item; effective changes propagate through locally visible direct canvas children, including TopLevel, with Hidden following visibility delivery when becoming hidden. Neutral nodes break inheritance and Window visibility reaches every canvas root. Showing and reattachment request fresh recording. C# notification overrides call base for inherited event dispatch; manual tree notifications do not alter membership.

## Canvas ordering

TopLevel items and items below neutral Node parents are independent canvas roots. A root's canvas subtree precedes the next root at equal effective Z. ShowBehindParent draws a child subtree before its parent. YSortEnabled orders the item itself at Y = 0 and direct canvas children by local Y; nested enabled children join that group, while disabled children keep their subtree together at their own Y. Approximate Y ties keep scene order using the shared Mathf contract. Invisible items are omitted, neutral/TopLevel boundaries end the group, and Z takes precedence everywhere. Changes use the next submission without rerecording retained commands and do not reorder processing/input.

The `ZIndex`, `ZAsRelative` and `MoveToFront` audit checks local range/defaults, direct-parent accumulation, neutral/TopLevel isolation, last-sibling moves, repeated no-op, warning refresh, stored state, callback failure and attached owner-thread reads. Invalid Z throws with unchanged state under ADR 0008. The full Wayland renderer run passed 31 ordering pixel cases on compatibility and GPU; other platforms and visual owner acceptance remain unverified.

The appearance audit checks white modulation defaults, finite color validation, borrowed material lifetime, equal-assignment PropertyListChanged, callback-failure commitment, PackedScene storage and attached owner-thread reads. `Modulate` accumulates through direct canvas parents; `SelfModulate` affects only the item's own vertices. `UseParentMaterial` selects the direct parent's effective material without discarding an assigned own material, stopping at neutral and TopLevel boundaries. Focused live pixels pass for inherited Add, own Sub and root Mix blending on Linux/Wayland compatibility/GPU; three modulation frames also pass on dummy/software. Modulation and material-policy changes reuse retained commands; TopLevel rebinding may separately request redraw. Editor UI, other platforms and visual owner acceptance remain unverified.

## Control descendant clipping

`Control.ClipContents` clips each direct canvas descendant's retained batches to the transformed Control rectangle. Nested rectangles intersect; a top-level item, neutral Node or CanvasLayer starts another canvas branch. The GPU path uses a scissor rectangle and compatibility uses the render target's clip rectangle. The Control's own drawing remains unclipped while its clip has visible area; an empty clip culls the entire item. The scene input picker applies the unrounded parent rectangles. Repeated Parallax controls use the combined repeated bounds. [ControlClipRenderingTests](../../tests/Electron2D.Tests/ControlClipRenderingTests.cs) checks nested, rotated, repeated, empty, restored and top-level pixels on dummy/software and Linux Wayland compatibility/GPU. Native output on other platforms and owner visual acceptance remain unverified.

The same rendering checks include a clipped child over 20 warmed frames with zero managed allocations between FramePreDraw and FramePostDraw on each tested backend. Native driver allocations and the host event pump are outside that measurement.

## Ownership and limits

Nodes borrow materials and textures; native texture caches belong to the backend. Updates reuse compatible allocations; replacement recreates them. Unused unleased texture cache entries are released. Attached button controls retain their known state textures through balanced internal residency counts, preventing alternating states from recreating backend allocations; replacement, exit and disposal release those counts. Font glyph snapshots request backend residency across unused frames while their font data is active. Font retirement waits for active native reads and drops that residency request; already recorded immutable glyph pixels remain valid, and an unused frame can release their backend payload. Entries do not keep the owner font alive. Shutdown releases all backend state. A disposed or unreadable texture fails when its retained drawing is consumed. A custom Texture may override drawing with ordinary CanvasItem geometry instead of providing an image.

Current framebuffer and blending precision is RGBA8. GPU samples byte and supported floating-point images, including stored mips. Compatibility support depends on the native driver; the tested drivers reject float textures explicitly. The component has no lights, general alpha-mask clipping, layered mesh targets, a complete GUI widget catalog, independent window renderers or device-loss recovery. Other targets remain unverified under [ADR 0021](../decisions/product.md#adr-0021).

## Animation intervals and rectangles

CanvasItem.DrawAnimationSlice records finite double seconds and replaces the active interval. Every frame evaluates the signed remainder of render time minus offset by the period, with an inclusive begin and exclusive end. Zero period hides; signed periods and bounds outside the period retain their mathematical meaning. Intervals are not nested and boundaries do not implicitly wrap. DrawEndAnimation restores unrestricted drawing without resetting the most recent executed transform. Both commands reset with the item's recording lifecycle and state never leaks into another item.

DrawSetTransform/DrawSetTransformMatrix are now ordered state commands. A transform in a hidden interval is skipped, so subsequent visible geometry uses the last transform that actually executed in the current frame. All geometry families skip texture/material consumption when hidden. Validation still occurs during recording; captured resources must be live when a visible command consumes them. An uncaught callback error clears the complete geometry/state recording. Redraw and replay retain zero warmed allocation.

The completed draw-transform audit checks default scale/rotation, translated and rotated value construction, raw skewed matrices, replacement rather than accumulation, node-before-draw multiplication, invalid command rollback, hidden-interval state, and reset on each replay. Engine.Run forwards its captured scaled process step through Window/SceneTree. Project base/feature changes apply on the next submitted frame. No catch-up for skipped render frames is added. DrawRect now uses reusable CanvasStroke storage. Ordinary outlines are the existing closed polyline path. ## Group composition and screen snapshots

[CanvasGroup](../classes/CanvasGroup.md) composites submitted same-Z descendants as one object. Descendants at another effective Z, TopLevel branches and independent canvas boundaries retain their own submission. Group ordering places its own geometry after its grouped children. SelfModulate therefore changes final group opacity once, preserving equal opacity in overlap regions. Inherited Modulate still participates in child appearance and owner appearance. An assigned material replaces the built-in group shader; an assigned CanvasItemMaterial or null-shader ShaderMaterial supplies ordinary owner shading rather than implicitly retaining the group shader.

Without recorded owner commands, the renderer fits child screen geometry (or notifier bounds), expands it by FitMargin and maps that rectangle through the owner inverse/forward transform before drawing. Explicit owner commands supply the shape and bypass automatic fitting. ClearMargin expands the transparent clearing region around child/owner bounds. Margins are finite, nonnegative screen pixels. A singular owner transform cannot produce the inverse needed by automatic fitting and rejects before native submission; recorded owner geometry retains ordinary singular-transform behavior. Empty groups with no submitted child content do not draw an invented rectangle. The reference warning boundary for nested groups is preserved; this profile explicitly rejects nested same-Z composition and writable-backbuffer sampling by group children. ClipChildren alpha masks now share this storage and enforce the same nested/writable-buffer boundaries; see [alpha masks](#canvas-alpha-masks).

[BackBufferCopy](../classes/BackBufferCopy.md) contributes an operation at its normal canvas Z/order position. Rect mode transforms its signed local Rect to screen bounds and clips it to viewport/ancestor rectangles. The zero-valued Rect is the full-copy sentinel; nonzero empty/outside rectangles supply no defined sampled region. Viewport mode copies the viewport. Disabled, hidden and mask-pruned nodes leave the snapshot unchanged; a copy inside an active group is ignored. Samples outside the copied region are unspecified.

The first ordinary GPU material using reserved SCREEN_TEXTURE makes a complete snapshot if no explicit copy has already supplied it. Later screen-reading draws reuse that snapshot until another explicit copy. A group material consumes its completed transparent backbuffer rather than recursively copying the main image over its children. An optional float2 SCREEN_PIXEL_SIZE uniform receives inverse native target dimensions. Both reserved bindings are excluded from material/default parameters, stored descriptors and value migration. HLSL and GLSL use the same reflected SPIR-V resource path; the shader component contains the exact interface.

CanvasBatch now carries Draw, Copy, GroupBegin and GroupEnd operations. Geometry only coalesces across ordinary Draw batches with equal state, preserving copy/group boundaries. Each viewport target lazily owns one shared native backbuffer; native passes end before copying, generating mipmaps or changing attachments. The default group draw samples premultiplied storage with an equivalent premultiplied blend/tint operation. GPU UseMipmaps allocates native levels when needed and generates them after group drawing, before its material. Compatibility performs baseline copies and group composition with native targets, rejects custom shaders and mipmaps before drawing, and software additionally rejects its unsupported premultiplied group blend. No frame CPU readback/upload bridge or vendor patch is used. Explicit diagnostic/readback paths allocate and synchronize separately. Resize, target detachment and shutdown dispose backbuffer storage with the existing target owner.

## Canvas alpha masks

[CanvasItem.ClipChildren](../classes/CanvasItem.md#alpha-masks) supplies executable Disabled/Only/AndDraw alpha masks using [ClipChildrenMode](../classes/ClipChildrenMode.md). Only's default final shader takes RGB from that screen image and alpha from ordinary owner geometry/texture/tint, ignoring screen alpha. AndDraw first draws the owner into captured storage, then children, and always uses the built-in final mask. Only with a material replaces default masking. Without recorded commands, children draw normally; without a same-Z captured child range, the owner draws normally. Recorded nongeometry commands can capture children but supply no final geometry.

Effective Z, direct canvas ancestry and the existing canvas boundaries determine capture. TopLevel and neutral branches escape. Masks remain atomic in ancestor Y-sort and sort their children internally. Copies within a capture are ignored.
