## Resources and runtime flow

- [Font](../classes/Font.md) owns ordered borrowed fallbacks and reusable single-line/paragraph layout caches. [FontFile](../classes/FontFile.md) owns validated immutable encoded bytes, native metrics and cached glyph images. Its dynamic file path also participates in [ResourceLoader](../classes/ResourceLoader.md) Ignore/Reuse/Replace semantics. Failed decoding retains the existing live font.
- The internal `FontThread` serializes mutable native operations through one reusable synchronous call slot on threaded hosts. The nonthreaded browser profile invokes on its retained execution owner without creating a worker or blocking its event loop. `NativeFontPrecision` owns a FreeType face and HarfBuzz face/font/buffer; HarfBuzz reads SFNT tables through FreeType so WOFF2 bytes need no custom decompressor. Native font structs and handles remain internal. This font owner does not own the renderer or its graphics context.
- `TextLayout` resolves fallback coverage by grapheme, shapes script/direction runs, preserves Unicode scalar clusters and paragraph context, reorders BiDi runs, wraps lines, trims/ellipsizes according to the consumer and applies permitted justification opportunities. Private ICU word and locale-aware line iterators supply dictionary segmentation and line tailoring. `TextBIDI` and `TextScript` adapt the pinned Unicode algorithms; `TextJustification` handles joining opportunities, while `TextMissingGlyph` supplies the applicable hexadecimal fallback boxes.
- `FontData` retains unhinted 26.6 advances until the specified rounding stage. Raster hinting is independent. Half/quarter phases are applied inside the glyph raster, with the corresponding biased baseline snapping, rather than shifting a phase-zero texture. Automatic oversampling uses the font override or one; explicit positive draw factors take precedence. Effective factors are clamped and quantized to 1/64. Glyph and outline pixels become ordinary RGBA ImageTextures shared by cached layouts. Their renderer cache entries remain resident across unused frames until font data retires and drops the residency request; unleased user textures retain the existing per-frame eviction policy. Attached button state textures use separate balanced residency counts. Renderer entries hold no reference back to the owning font, so font finalization can retire glyph storage.
- The six `CanvasItem.DrawChar`/`DrawString`/`DrawMultilineString` and outline entrypoints forward to Font inside the existing drawing scope. Baseline positions, modulation, transform, inherited sampling, clipping and material behavior use the same canvas path as other textured primitives. Canvas character strings must encode exactly one Unicode scalar.
- Theme font storage, defaults and overrides borrow resources and use the existing owner hierarchy. ThemeDB embeds Open Sans SemiBold with its license; native initialization is deferred until a text query. [LabelSettings](../classes/LabelSettings.md) supplies borrowed font selection and ordered outline/shadow effects to the Label consumer.

## Ownership, errors and warm reuse

Resource byte getters and public container snapshots are caller-owned copies. Font setters commit coherent state before public notifications; callback failure does not roll back committed bytes or configuration. Source retirement waits for active font reads before closing native font objects. Already recorded immutable glyph-image snapshots remain usable; retirement drops their backend residency request, so an unused frame releases the GPU payload. Their CPU pixels live only as long as retained commands or other internal snapshots reference them. Fallback graphs reject cycles and excessive depth. Font metadata and cache mutation are synchronized; drawing additionally requires the canvas owner thread and recording scope. Prepared shaping buffers, cached layouts and glyph replay reuse storage. Cache misses, new fonts, glyph rasters and public snapshot-returning APIs can allocate.

No native/backend types appear in the public font API. Public TextServer RID operations, bitmap/cache authoring, font discovery, MSDF and project theme-file import remain distinct capabilities. Per-glyph raster dimensions are bounded by 16,384 pixels. Native boundaries and public font resources accept the packaged desktop, mobile and browser architectures. Windows uses its own WOFF2-capable FreeType, including x86 absent from the upstream binary package. [The native backlog](../platform-verification.md#required-native-dependency-builds) distinguishes multilingual text execution, canvas rendering and production host acceptance; packaging alone proves no foreign execution.

## Font instances and rich font tags

[FontVariation](../classes/FontVariation.md) owns an independent FreeType face, HarfBuzz font and glyph cache while borrowing the underlying Font source and effective fallbacks. Native fvar metadata exposes typed [FontVariationAxis](../classes/FontVariationAxis.md) bounds; design coordinates configure both FreeType and HarfBuzz. Outline strength and matrix run before rasterization/stroke, baseline changes shaped offsets, and palette selection/custom entries use the public FreeType CPAL API. Font.FindVariation returns a caller-owned typed resource. Source/native configuration changes retire the old face after active readers; spacing only invalidates layout. These operations extend the accepted native foundation under ADR 0046.

RichTextLabel creates owned FontVariation span resources borrowing any Font. Its font tags implement glyph_spacing/gl, space_spacing/sp, top_spacing/top, bottom_spacing/bt, embolden/emb, face_index/fi, slant/sln, opentype_variation/otv and opentype_features/otf. Feature tags also use independent instances rather than duplicating source font bytes. Removing document blocks retires their owned instances; theme/source resources remain borrowed. Font/dropcap paths accept typed Font resources.

Before this slice, three candidates were compared: FontVariation has 15 own reference rows, directly unlocks rich font-tag instances and fits the present FreeType/HarfBuzz/canvas backend; Script/CSharpScript has 21 rows but still needs the ADR 0091 source/assembly association and live owner contract; VisualShader has 112 raw class records and 719 own rows before applicable/excluded classification and needs an executable typed canvas shader graph and code generation. FontVariation was the best immediately executable capability. Graph authoring was already complete.

The engine-owned tiny variable, two-palette and two-face collection fixtures are reproducible with tools/coverage/generate_variation_font.py. FontVariationTests verifies exact design bounds/advances, known clamping and unknown tags, independent instances, synthetic raster pixels, selected/custom palette colors, collection identity, source replacement, active-reader retirement, cycles, aliases, font markup and stored-resource loading in a new process. These tests do not establish physical or foreign-platform acceptance. Native prepared-frame results are recorded after exercising the current renderers.

Bindings use the public [FreeType variation](https://freetype.org/freetype2/docs/reference/ft2-multiple_masters.html) and [palette](https://freetype.org/freetype2/docs/reference/ft2-color_management.html) APIs and [HarfBuzz font variations](https://harfbuzz.github.io/harfbuzz-hb-font.html). Public native records remain internal; no renderer, native handle or public RID is added.

The final shared layout applies span-specific signed top/bottom spacing, suppresses terminal glyph spacing, and uses glyph spacing when space spacing is zero. Synthetic advance enters the same rounding/residual stage as native advances. Source/default-theme subscriptions do not keep an unowned variation resource alive. Native GPU and compatibility render the prepared variants and rich font tag for 64 measured intervals with zero managed bytes; visually inspected captures `/tmp/e2d-variation-gpu-final.png` and `/tmp/e2d-variation-compat-final.png` match SHA-256 `9e72add269d6fbe75de7c562d7bb08b314879e567b7567c20d9d83c47e0d570e`. Native allocations, other platforms and owner acceptance remain unverified.

Span features merge with each selected face’s file defaults, including fallback faces; FontVariation native caches retain file defaults separately from span settings. Maximum base/fallback depth is rejected during mutation, and the maximum accepted base chain executes in FontVariationTests. The regenerated compiled ThemeDB ancestry catalog includes the new resource type.
