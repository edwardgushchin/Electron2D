# Text shaping and canvas fonts

Last updated: 2026-09-27

The text component owns dynamic font resources, Unicode paragraph layout and glyph textures. It consumes the existing Resource graph, theme lookup, ImageTexture and retained canvas rather than adding a second graphics stack. [ADR 0046](../decisions/rendering.md#adr-0046) records the precise native bridge and its executable reasons; [ADR 0012](../decisions/product.md#adr-0012) defines packaging and source ownership.

## Resources and runtime flow

- [Font](../classes/Font.md) owns ordered borrowed fallbacks and reusable single-line/paragraph layout caches. [FontFile](../classes/FontFile.md) owns validated immutable encoded bytes, native metrics and cached glyph images. Its dynamic file path also participates in [ResourceLoader](../classes/ResourceLoader.md) Ignore/Reuse/Replace semantics. Failed decoding retains the existing live font.
- The internal `FontThread` serializes mutable native operations through one reusable synchronous call slot. `NativeFontPrecision` owns a FreeType face and HarfBuzz face/font/buffer; HarfBuzz reads SFNT tables through FreeType so WOFF2 bytes need no custom decompressor. Native font structs and handles remain internal. The native worker does not own the renderer or its graphics context.
- `TextLayout` resolves fallback coverage by grapheme, shapes script/direction runs, preserves Unicode scalar clusters and paragraph context, reorders BiDi runs, wraps lines, trims/ellipsizes according to the consumer and applies permitted justification opportunities. Private ICU word and locale-aware line iterators supply dictionary segmentation and line tailoring. `TextBIDI` and `TextScript` adapt the pinned Unicode algorithms; `TextJustification` handles joining opportunities, while `TextMissingGlyph` supplies the applicable hexadecimal fallback boxes.
- `FontData` retains unhinted 26.6 advances until the specified rounding stage. Raster hinting is independent. Half/quarter phases are applied inside the glyph raster, with the corresponding biased baseline snapping, rather than shifting a phase-zero texture. Automatic oversampling uses the font override or one; explicit positive draw factors take precedence. Effective factors are clamped and quantized to 1/64. Glyph and outline pixels become ordinary RGBA ImageTextures shared by cached layouts. Their renderer cache entries remain resident across unused frames until font data retires and drops the residency request; unleased user textures retain the existing per-frame eviction policy. Attached button state textures use separate balanced residency counts. Renderer entries hold no reference back to the owning font, so font finalization can retire glyph storage.
- The six `CanvasItem.DrawChar`/`DrawString`/`DrawMultilineString` and outline entrypoints forward to Font inside the existing drawing scope. Baseline positions, modulation, transform, inherited sampling, clipping and material behavior use the same canvas path as other textured primitives. Canvas character strings must encode exactly one Unicode scalar.
- Theme font storage, defaults and overrides borrow resources and use the existing owner hierarchy. ThemeDB embeds Open Sans SemiBold with its license; native initialization is deferred until a text query. [LabelSettings](../classes/LabelSettings.md) supplies borrowed font selection and ordered outline/shadow effects to the Label consumer.

## Ownership, errors and warm reuse

Resource byte getters and public container snapshots are caller-owned copies. Font setters commit coherent state before public notifications; callback failure does not roll back committed bytes or configuration. Source retirement waits for active font reads before closing native font objects. Already recorded immutable glyph-image snapshots remain usable; retirement drops their backend residency request, so an unused frame releases the GPU payload. Their CPU pixels live only as long as retained commands or other internal snapshots reference them. Fallback graphs reject cycles and excessive depth. Font metadata and cache mutation are synchronized; drawing additionally requires the canvas owner thread and recording scope. Prepared shaping buffers, cached layouts and glyph replay reuse storage. Cache misses, new fonts, glyph rasters and public snapshot-returning APIs can allocate.

No native/backend types appear in the public font API. Public TextServer RID operations, variable axes and palette editing, bitmap/cache authoring, font discovery, MSDF generation and project theme-file import remain distinct coverage capabilities. Per-glyph raster dimensions are bounded by the existing 16,384-pixel canvas texture range. Mobile and browser text remain unsupported until their native assets and executable integration are supplied; desktop packaging alone does not verify another operating system.

## Verification boundaries

[UnicodeTextTests](../../tests/Electron2D.Tests/UnicodeTextTests.cs) checks the pinned Unicode 17 grapheme, word, line-break and BiDi corpus plus warmed allocation behavior. The full external corpus also passed 766 grapheme, 1,944 word-break, 19,338 line-break, 91,707 BiDi-character and 770,241 BiDi-class/direction cases. [NativeFontPrecisionTests](../../tests/Electron2D.Tests/NativeFontPrecisionTests.cs) compares fractional metrics, shaping and raster hashes/bearings against independent C FreeType queries, including WOFF2, combining marks, ligatures, Arabic context, phases and outlines.

[FontTests](../../tests/Electron2D.Tests/FontTests.cs), [FontFileTests](../../tests/Electron2D.Tests/FontFileTests.cs), [FontResourceLoaderTests](../../tests/Electron2D.Tests/FontResourceLoaderTests.cs), [LabelSettingsTests](../../tests/Electron2D.Tests/LabelSettingsTests.cs) and [ThemeFontTests](../../tests/Electron2D.Tests/ThemeFontTests.cs) exercise public resources, atomic replacement, alias copying, missed callbacks, typed theme lookup, drawing guards and warmed operations. [FontRenderingTests](../../tests/Electron2D.Tests/FontRenderingTests.cs) is the native pixel and frame-allocation gate for both current backends. Font pixels and 64 warmed active frames at zero managed bytes pass on Linux Wayland GPU and compatibility. The complete integrated managed suite passes, including ICU dictionary/locale boundaries and concurrent font retirement. Label pixels, effects, visibility, clipping and missed-callback refresh also pass on both backends, including 64 warmed active frames at zero managed bytes. FontLifetimeTests covers reentrant and parallel source replacement, reads during pre-delete notification and bounded mutation retries; native checks preserve recorded glyph pixels after font disposal and release retired backend handles on an unused frame. Native allocator counts, broad-scene performance, other-platform execution and owner acceptance are separate from these managed checks.

A fresh self-contained Linux x64 HostExample publish passes native and license audits: 66 ELF payloads, 46 byte-identical required notices and exactly nine private text-boundary C exports. The private library has its own SONAME and no dynamic ICU dependency. Offline import checks verify the pinned Unicode closure, case tables and ICU source/data hashes. Cross-RID Windows packaging omits the Linux-only boundary library and build target; this does not establish Windows text execution.
