# Editor canvas guides

Last updated: 2026-10-27

[Marker](../classes/Marker.md) supplies a spatial anchor cross, [ReferenceRect](../classes/ReferenceRect.md) outlines a UI rectangle, and [VisibleOnScreenNotifier.ShowRect](../classes/VisibleOnScreenNotifier.md#showrect) displays a detection area. They use ordinary retained CanvasItem drawing in the runtime assembly, the transient [Engine.IsEditorHint](../classes/Engine.md) authoring role, and the public scene/session pipeline. No editor assembly dependency enters the runtime.

Marker draws four one-framebuffer-pixel half-axes from local zero to its signed `GizmoExtents` (ten initially). Positive X is `(0.96, 0.20, 0.32)`, positive Y is `(0.53, 0.84, 0.01)`; negative halves use half RGB brightness. Zero draws nothing; a negative extent reverses the color placement. It remains an ordinary Entity anchor during gameplay. ReferenceRect draws a centered outline around `(0, 0, Size.X, Size.Y)`, initially red and one local unit wide. Finite negative widths clamp to zero, which draws nothing. `EditorOnly = false` also draws the border during gameplay. Minimum size and pointer policy remain inherited Control behavior.

Notifier's stored `ShowRect` defaults to true and draws `(1, 0.5, 1, 0.2)` over its local `Rect` only in the editor role. The flag is inherited by VisibleOnScreenEnabler and has no effect on screen detection or process enabling. Signed rectangle sizes normalize through ordinary drawing. Transform, modulation, visibility, clipping, ordering and renderer precision apply normally to all three guides. The built-in geometry is recorded during NotificationDraw, before user Draw handlers and OnDraw.

Property changes invalidate retained commands; explicit extent and notifier-rectangle assignments also request redraw for equal values. Canvas preparation detects editor-role changes on the scene owner thread and clears or rebuilds the affected commands on the next submitted frame, including guides hidden during a role change. The global hint setter remains advisory and safe from any thread; it invokes no scene callbacks. Tree reentry uses ordinary canvas invalidation. The guides require the hint, without the EditedSceneRoot membership restriction owned specifically by skeletal modification gizmos.

Typed properties, exact scene factories and ResourceFileTypes preserve identity and inherited spatial/layout settings through duplication, PackedScene and fresh-process file loading. Attached reads and authored writes enforce the owner thread; writes during capture, nonfinite geometry/color, and disposed access fail before changing state. Finite signed/HDR colors are retained.

The trusted ProjectSession preview admits the exact built-in Marker, ReferenceRect and VisibleOnScreenNotifier types, preserves their stored settings and disables their processing. Existing rejection of project subclasses, unknown skeletal callbacks and active gameplay node roles remains authoritative. VisibleOnScreenEnabler is not admitted as a passive preview node. The actual ProjectWorkspace subviewport displays guide scenes and follows shared unsaved Entity-transform revisions without saving the authored scene file. This does not add generic Control-property editing to the session protocol.
