# WebSocket messages

Last updated: 2026-10-04

## Scope and owners

[WebSocketPeer](../classes/WebSocketPeer.md) is a [PacketPeer](../classes/PacketPeer.md) for complete text/binary messages over WS/WSS, including server upgrades over borrowed StreamPeer transports. WebSocketState and WebSocketWriteMode are independent top-level enum domains. Internal WebSocketPacketQueue owns prepared payload/frame rings and value metadata. [ADR 0094](../decisions/networking.md#adr-0094) owns threading, transport lifetime, protocol and capacity rules. No new package or vendored code is added.

## Connection flow and ownership

ConnectToURL accepts WS/WSS URLs, defaults a missing scheme to WS, preserves the supplied URL for diagnostics, omits fragments on the wire and rejects embedded credentials. It uses the existing HTTPClient for asynchronous DNS/address fallback, owned TCP/TLS and client HTTP upgrade. WSS validates names/trust through TLSOptions. Poll requires HTTP/1.1 101, upgrade tokens, the exact nonce accept hash, no unrequested extension and the configured subprotocol. HTTPClient exposes its parsed version only internally to this consumer. Server AcceptStream borrows a live stream, including pending/established TLS and custom ordered transports; it never disposes the caller's stream. The native TCP option is enabled automatically once connected. Endpoint queries return empty/zero for custom or closed transports; SetNoDelay explicitly fails when no TCP transport exists.

Server handshake reads at most 4096 bytes without consuming a following frame. It requires GET with exactly three request-line parts, HTTP/1.1, an authority Host, Connection/Upgrade tokens, version 13, a base64 16-byte nonce, no request transfer coding/nonempty body and a negotiated configured protocol. Header-token/control validation rejects injection and reserved required fields cannot be overridden by HandshakeHeaders. Custom headers/protocol arrays copy on get/set; protocols trim whitespace and reject invalid/duplicate tokens. Protocols snapshot at connection preparation; client extra headers are sampled at request dispatch and server extra headers at response construction. When configured protocols are present, a matching protocol is required. Server negotiation follows client offered order. A client extension response is rejected; server extension offers are ignored without negotiation, so RSV bits remain invalid. Handshake parsing/snapshots, DNS/TLS setup and error diagnostics allocate outside prepared message operations.

Ready state transitions Closed → Connecting → Open → Closing → Closed. Polling advances all work on the constructing thread; no worker accesses a caller's stream. Client close/dispose releases owned HTTP/TCP/TLS resources. Server close/dispose forgets only the borrowed stream. Pending decrypted TLS bytes drain even after native TCP FIN; transport EOF alone cannot discard the final close frame. Close metadata and requested URL/selected protocol remain until reset for a new connection. GetCloseCode/GetCloseReason require Closed. Reconnecting from Closing discards the old operation using the same lifetime rules. Disposal rejects a wrong owner before publishing disposed state.

## Messages and control frames

PutPacket sends binary; Send chooses WebSocketWriteMode; SendText encodes directly through prepared storage. Client frames use fresh cryptographic random masks, server frames are unmasked, and receiving the wrong mask direction fails. Poll handles fragmented messages, continuation order, canonical 7/16/64-bit network-order lengths, zero messages, UTF-8 across fragments and ping/pong/close interleaving. Reserved opcodes/RSV, invalid continuations, fragmented/oversized controls, noncanonical/high-bit lengths and invalid text/close payloads result in protocol close. Text must be strict UTF-8; invalid C# UTF-16 in SendText/Close fails encoding. No extension or compression is negotiated.

Inbound reads expose complete application messages only after Poll, and only in Open state. Inherited GetPacket snapshots allocate, while GetPacket(Span<byte>) reuses caller storage. Too-small reads preserve packet order and WasStringPacket; the marker changes only when a packet is consumed. GetPacketError/LastReadException follow PacketPeer. GetCurrentOutboundBufferedAmount counts queued application payload, retaining a partially sent message's full length until its frame drains; framing and controls are excluded. Send copies input before returning and attempts nonblocking progress; queue overflow throws before enqueuing that message.

Ping automatically receives an exact pong payload. HeartbeatInterval uses monotonic seconds, zero disables it, and changing it resets the clock/waiting state. An unanswered ping at the next interval aborts with an unclean close. Close validates a protocol/application code and at most 123 UTF-8 reason bytes; a negative code immediately aborts. Poll until Closed for a clean handshake. Received empty close exposes 1005; received valid close/reason is retained. Local protocol errors report 1002, invalid text 1007, oversize message 1009 after their close frame drains. Transport/forced closure reports minus one. Data already queued is discarded at closure, matching the Open-only packet contract. A peer that never responds to an ordinary close has no implicit close timeout; callers can force Close(-1).

## Prepared capacities

InboundBufferSize/OutboundBufferSize default to 65535; MaxQueuedPackets defaults to 4096. All three configure only Closed state so resizing cannot discard live data or allocate in packet processing. Byte capacities are bounded to 64 MiB; packet counts to 65536. Zero inbound bytes accepts only empty application messages; zero queued packets admits no application messages. OutboundBufferSize=0 uses an explicit 64 MiB prepared ceiling in place of unbounded per-send growth under ADR 0014.

Connection preparation allocates an incoming message accumulator plus its separate queued-payload ring, an outgoing encoding/frame scratch buffer, and an outgoing frame ring with `14 * (MaxQueuedPackets + 4) + 500` bytes of framing/control reserve beyond the payload budget. Value record arrays are separately bounded by packet count; four outgoing records reserve control traffic. Exhausted inbound capacity retains one completed accumulator and stops reading until consumption frees space. Exhausted outgoing control records stop receive progress until flush frees them. These are explicit backpressure boundaries, not silently growing queues. Successful steady-state frame processing, text/span sends and span packet reads make no managed or engine-owned native allocations after preparation; cryptographic RNG, OS and TLS allocator internals remain external measurement boundaries.

## Verification and remaining integrations

[WebSocketTests](../../tests/Electron2D.Tests/WebSocketTests.cs) checks the RFC accept vector, fragmented wire input/UTF-8 with interleaved ping, exact pong, empty and canonical 7/16/64-bit messages, input/output/control pressure, invalid flags/masks/continuations/text/close/lengths, close/EOF/heartbeat, configuration copies, malformed upgrades and owner/disposal guards. Native Linux WS and WSS run in both roles against independent .NET WebSocket/ClientWebSocket peers; client connections also run through public Node/SceneTree polling. Each WS/WSS client measures 64 warmed mask/text/poll/span echo cycles at zero managed bytes; a fragmented custom server measures 64 active and 64 idle cycles at zero managed bytes.

The self-contained Linux packaging check is recorded in [platform verification](../platform-verification.md). Routed networks, browser WebSocket host integration, foreign native TLS/backend packaging, external native allocation totals and human acceptance remain separate. WebSocketMultiplayerPeer still requires the typed MultiplayerPeer contract; scene replication and unified editor/project/agent tools are separate. Handshake/frame rules use [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455).
