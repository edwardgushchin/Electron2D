# MIDI input

Last updated: 2026-11-13

The [ADR 0038](../decisions/input.md#adr-0038) input contract uses the system ALSA Sequencer on desktop Linux and WinMM on Windows. Both work independently of SDL, a window, renderer or audio output. The public values are [InputEventMIDI](../classes/InputEventMIDI.md) and [MIDIMessage](../classes/MIDIMessage.md); static [OS](../classes/OS.md) operations address a retained internal session owner.

ALSA session/client/port names now use [scoped UTF8 input storage](../coverage/performance-producers.md#legacy-platform-input-conversion-2026-10-29). The existing Linux virtual-source regression passes 37 checks; physical controllers and foreign adapters retain their separate gates.

## Session and delivery

`OS.OpenMIDIInputs()` snapshots the input sources and acquires them as a single session. Linux opens a nonblocking ALSA client and subscribes to each source and to sequencer lifetime announcements. Windows opens and starts a WinMM handle for each source. Acquisition failure closes all partial ownership. Repeated open preserves an active session. `OS.GetConnectedMIDIInputs()` returns a defensive source-name array whose indices are the session's event `Device` values. Before open or after close it returns an empty array; a successfully opened session may have no source. Missing adapter/library, denied access and native acquisition errors throw distinct exceptions. A failed session remains observable until close or a fresh open.

Newly connected sources require close/open. Loss of a subscribed source invalidates the whole session and throws `IOException`. ALSA reports port, client and subscription removal. WinMM checks source handles or the enabled state of exposed PnP interfaces before a delivery batch, and observes driver close callbacks. Legacy drivers without a PnP interface rely on driver close or handle invalidation. The application should clear its held-note state and reopen explicitly. Stable session indices and retired callbacks prevent reassignment of stale input.

Engine frame entry polls before physics/process callbacks. `Input.FlushBufferedEvents()` also polls on the active MainLoop owner thread. No active loop leaves native data pending. Each pump handles at most 4096 records. ALSA keeps pending data in its sequencer pool. WinMM callbacks store packed short messages in a preallocated queue with 4096 slots. WinMM backlog notifications carry valid data and use the same queue. A reported ALSA overflow or a full WinMM queue on the next enqueue invalidates the session to expose possible loss of note releases. Reentrant pumping is rejected. Close/open from an input callback is supported: the pump stops reading the previous session. Native reading and public parsing use the same session lock. WinMM callbacks use a separate short queue lock and copy only the source index and packed value. Close retires the callback tokens before releasing device handles.

Every translated event passes through ordinary `Input.ParseInputEvent` and SceneTree input/unhandled stages. The event is borrowed during synchronous callbacks and disposed afterwards; retain a duplicate when needed. MIDI does not create action-compatible bindings or raw keyboard/controller button state. User callback exceptions retain ordinary Input/SceneTree aggregation. Engine.Stop and Engine.Run cleanup close MIDI after finalization even when callbacks throw; failed Engine.Start also retires input acquired during initialization. Close is repeat-safe.

## Messages and resource values

Both adapters project MIDI 1 note on/off, polyphonic pressure, controller, program, channel pressure and pitch-bend events. Channels are 0–15, data bytes 0–127 and pitch bend is unsigned 0–16383, centered on 8192. A zero-velocity note-on retains its message status. ALSA supplies complete protocol events; the independent source fixture exercises fragmented byte writes, running status and realtime bytes interleaved with incomplete messages. WinMM expands running status and reports packed complete short messages.

System quarter-frame, song position/select, tuning, clock, transport, sensing and reset retain their message identity and channel zero. Quarter-frame/song data has no extra public payload projection in the pinned event contract. Variable SysEx payloads and UMP records are not projected into this MIDI 1 event. MIDI output, synthesis and file playback are outside this slice. Invalid channel-message data closes the session with an explicit error.

All eight concrete properties have zero defaults and stored typed descriptors, emit resource changes and preserve manually authored integer values. Text is localized through the normal event template formatter. Duplicate and portable resource save/load preserve the exact type, enum and inherited Device. The event retains base press/release and action semantics.

## Verification and remaining platform work

`tests/Electron2D.Tests/MIDIInputTests.cs` is shared with the public-only `tests/MIDIInput.Consumer` executable. `Fixtures/MIDI/source.c` creates independent ALSA virtual sources through system headers, including an ABI assertion, malformed messages and a flood producer. Checks cover two sources, boundaries, system statuses, owner-thread delivery, close/reopen during a callback, disconnect, overflow, acquisition rollback and cleanup after input/finalization/startup failures. The public consumer passes 37 CLR checks on Linux with the same native producer, including delivery before both frame lanes and rejected reentrant pumping. Strict NativeAOT and local managed-package qualification exercise the same source-to-scene workflow; executable receipts remain separate from full release/native-package qualification. Separate CLR and NativeAOT children pass two assertions each for a missing ALSA configuration and an injected native permission denial. These are virtual-source and controlled-failure checks, not physical hardware acceptance.

On Windows x64, the public consumer passed the system WinMM empty-device profile in CLR and strict NativeAOT on a host with zero input endpoints. The NativeAOT managed event/resource profile also passed. A separate test process loads the native WinMM ABI fixture compiled against the Windows SDK. The fixture supplies two sources, packed short messages and controlled failure callbacks. Its 33 assertions cover scene delivery, backlog, rollback, simulated PnP removal, invalid data, queue overflow, retired tokens and callback failures. The system driver path with a real loopback or controller, native heap attribution and delivered package acceptance remain open.

CoreMIDI on macOS/iOS, Android MidiManager on phone/TV, permission-aware browser Web MIDI and a viable tvOS acquisition path remain dependencies for the three Partial OS methods. ADR 0021 tracks platform and physical-device acceptance separately from event/resource/message declarations.

ALSA releases the client, ports, subscriptions and internal pool on native close. WinMM discards the managed queue and releases each device handle. The system libraries' heaps remain outside Electron2D's allocation ledger. See [native memory inventory](../coverage/native-memory-inventory.md).
