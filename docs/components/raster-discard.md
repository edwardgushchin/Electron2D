# Vertex processing with primitive discard

Last updated: 2026-10-28

`RDPipelineRasterizationState.DiscardPrimitives` defaults to false and is copied by `RenderingDevice.RenderPipelineCreate`. When true, vertex invocations and their storage side effects execute; primitives stop before rasterization and no fragment shader executes. Color and depth/stencil attachments retain their contents. Shader color outputs need not match the unused framebuffer outputs. Device ownership, exact framebuffer/sample compatibility, copied vertex state, specialization, push data and resource validation still apply.

Source and SPIR-V graphics programs may contain a vertex stage alone, including a stage without Position output. Such a program requires primitive discard when creating a pipeline. A fragment-only program and mixed compute/graphics stages remain invalid. Paired programs can also discard primitives; their declared resource layouts retain their ordinary descriptor validation. Existing draw-to-draw and pass-to-compute/copy/readback dependencies order vertex storage writes. Direct/indexed/indirect commands, ordered layer views and framebuffer passes share the same executing path. Sampled component-map variants preserve the copied discard flag.

The native implementation is the pinned Vulkan pipeline adapter. It passes a call-local renderer view into the retained SDL pipeline creator, with the original immutable device fields and shared locked layout caches. At most four descriptor layouts can be created in this call, so it reserves four globally unique layout IDs once per descriptor-count profile before creating them. A device-owned profile cache serializes creation and retains the next unused ID for failures/retries; repeated pipeline creation does not grow the IDs used to index native descriptor pools. A thread-local native callback sets rasterizerDiscardEnable and includes only the vertex stage. It never replaces the original renderer's function pointers or stores the temporary renderer view in an owned object. The native pipeline retains its ordinary SDL shader/layout ownership and retirement. Failed pipeline creation restores the shader references retained by the pinned creator. See the [Vulkan rasterization contract](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineRasterizationStateCreateInfo.html).

SDL retains two shader objects in its pipeline object. Vertex-only programs therefore use a private empty fragment object for that ownership slot; the object is absent from the native pipeline stage list and is never executed. Public source metadata and binary payload retain the original absent fragment. Compute and paired programs keep emitting version-one E2DSBIN containers. Vertex-only programs emit version two with the explicit missing-fragment flag; the reader validates versions, flags and module presence before publication and preserves version-one reading. Failure leaves shader placeholders reusable.

## Executable checks

Build `tests/DeviceGraphicsStorage.Consumer` with the matching private render bridge and run `discard`, `discard-source`, `discard-canvas`, `discard-vertex-only` and `discard-no-vertex`; repeat in strict trimmed NativeAOT. The last two modes use the existing graphics-storage feature mask to disable fragment or vertex stores independently. Vertex-only execution must survive missing fragment stores and reject missing vertex stores before shader/binary publication.

The consumer checks GLSL/HLSL no-Position vertex programs, version-two/placeholder round-trip, copied state after resource mutation, specialization/push values, GPU-produced indirect batches and zero counts, storage ordering and subsequent compute/ordinary graphics/canvas consumers. Color attachments remain unchanged across two views and two passes; exact multisampling and retirement are exercised. A sampled component-map variant has an observable fragment counter and color output, so lost discard state cannot pass by vertex output alone. Prepared cycles require zero owner-thread managed bytes.

`mask-raster.c` with LD_PRELOAD removes the native pipeline procedure for `discard-unavailable`; ELECTRON2D_TEST_RASTER_FAILURE=1 injects native pipeline failure for `discard-failure`. Ordinary graphics must still work. `Electron2DRenderCheck` verifies ABI rejection, unique layout IDs, unchanged original function pointers, 64 concurrent creations/retirements and shader reference counts. The same creation-failure injection checks three reference rollbacks. Native C fixtures use Vulkan 1.0 modules; generated layout extraction pins the SDL function declaration header as well as the implementation and common GPU header.

Linux/Vulkan on the exercised device is the native qualification boundary. Other backends require their pipeline adapters. Native/driver heap allocation behavior, throughput and foreign-platform acceptance remain separate from the managed allocation checks. [Static line width](wide-lines.md) now shares this adapter while retaining discard; dynamic width and patch/tessellation control keep their own dependencies.
