# Native ENet transport and multiplayer

Last updated: 2026-10-05

Private text/audio/ENet binaries now come from the versioned `Electron2D.Native.Linux` dependency in ordinary builds. Full native compilation is explicit through `Electron2DBuildNativeFromSource=true`; [native delivery](../native-packaging.md) records CI production, source receipts, consumer verification and the pending first publication. This changes delivery only, not the public API or platform guards.

## Scope and backend

[ENetConnection](../classes/ENetConnection.md) owns a native host and its UDP/DTLS socket transport. [ENetPacketPeer](../classes/ENetPacketPeer.md) exposes borrowed host-owned peers, packet queues and native statistics. [ENetMultiplayerPeer](../classes/ENetMultiplayerPeer.md) integrates server/client/mesh topology with the existing MultiplayerPeer, SceneMultiplayer, RPC and replication consumers. [ADR 0094](../decisions/networking.md#adr-0094) governs this owner-thread API. All public types ship in Electron2D.dll; native handles and platform callbacks stay private.

The Linux64 profile builds unchanged ENet 1.3.18 core sources at `5a9c537fd464b3c6d3c55e1d3bd47588faf71b42` and FastLZ 0.5.0 behind thirteen engine C exports. An engine-owned socket port supplies real .NET IPv4/IPv6 sockets. ENet's private address word is a routing token into prepared IP/scope/port endpoints; protocol packets do not serialize it. A separate stock Unix ENet executable verifies ordinary wire interoperability without this adapter. Vendored hashes and original licenses are preserved. Engine builds require CMake, Ninja, a C compiler and zlib/Zstandard development libraries; deployed hosts require `libz.so.1` and `libzstd.so.1`. The native payload stays under `runtimes/RID/native`, has its own SONAME and links no managed backend assembly. Linux ARM64 has build/toolchain selection but no execution claim; foreign profiles omit the Linux library and fail ENet setup explicitly.

## Host and peer contract

CreateHost immediately binds an automatic UDP port; CreateHostBound selects a literal/wildcard IP and optional ephemeral port. Limits preserve 1–4095 peers and 0–255 channels, with zero selecting 255. Bandwidth limits use exact unsigned byte rates and zero means unlimited. ConnectToHost permits one outgoing peer on an otherwise idle host and carries a uint32 connection identity. Service advances reliable traffic and returns typed Type/Peer/Data/Channel values; Receive queues a complete native packet on its peer. Flush advances outgoing traffic without waiting. Current peers include connecting/disconnecting identities. Disconnect/reset detaches old wrappers before a native slot can be reused.

Packets support Reliable, Unsequenced and UnreliableFragment flags, independent negotiated channels, fragmentation, ping, throttle and timeout configuration. Channel equality with the negotiated count rejects, correcting an invalid boundary. Timeout's backoff multiplier is independent of minimum/maximum milliseconds; zero selects native defaults. Five compression modes execute None, RangeCoder, FASTLZ, ZLIB and ZSTD; peers must agree. Host statistic reads reset their counter; peer statistic reads preserve it. Packet flags describe the next queued received packet. A fragmented packet sent with None is promoted by ENet to reliable delivery; UnreliableFragment keeps large packets unreliable. Caller-span reads preserve an undersized packet; snapshots copy and allocate.

Each outgoing packet is limited to 16 MiB, with a 64-MiB aggregate queued payload and 65536 native packet slots per host, including empty packets. Native reassembly has a 64-MiB waiting budget per peer. Each managed peer receive queue and multiplayer aggregate inbox allow 4096 packets/64 MiB; exceeding a managed inbox releases the rejected native packet and reports an I/O error. Prepared endpoint census is bounded by max(256, four times peer count); unused tokens are reclaimed and incoming endpoint saturation drops a whole datagram. Preparation/membership/snapshots allocate. Prepared native service/send/span/poll loops reuse managed storage; native packet/command and codec allocator work remains separate.

Destroy invalidates native peer wrappers and attempts all owned cleanup, even if disposal observers fail. Peer disposal forcefully disconnects its logical peer. Unread native receive packets have deterministic cleanup and a finalization fallback. SocketSend sends a raw transport datagram from the host's bound socket for application-owned reachability protocols; it does not provide NAT discovery. RefuseNewConnections preserves active peers and blocks new plain/DTLS admission, including previously prepared but inactive endpoints.

## DTLS and multiplayer integration

DTLSServerSetup upgrades an idle bound host to the existing UDPServer/DTLSServer transport; DTLSClientSetup selects retained default trust or borrowed explicit client policy before connecting. PacketPeerDTLS retains key/certificate/trust state as sessions start. ENet internally configures MTU 1460 and uses the existing prepared record storage for native protocol datagrams; the standalone public PacketPeerDTLS capacity remains 488 bytes. Explicit host polling drives DTLS cookies, handshake and retransmission before reliable ENet negotiation can complete. Server handshake failures discard that endpoint while healthy peers continue. Raw SocketSend requires a ready complete transport send.

Client identity is generated before connecting and transmitted through native connection data; a server rejects reserved/out-of-range/duplicate identities before publishing membership. Server CreateServer applies maxChannels and both bandwidth arguments to their actual native parameters. Channel zero maps reliable traffic to native channel zero and either unreliable mode to native channel one. Positive application channels map to additional channels, with at most 253 configured application channels. Metadata is read from actual received native flags/channel, independent of current outgoing settings. Server routing supports broadcast, a positive target and a negative exclusion; clients send to server. Client/server topology advertises higher-layer relay; mesh does not.

CreateMesh/AddMeshPeer accepts a positive distinct remote identity and a host with exactly one connected peer. The multiplayer endpoint takes responsibility for the host's active protocol lifetime: Close destroys its native state and preserves the borrowed object. Hosts must not be shared between active mesh owners. Host/GetPeer expose borrowed objects whose direct polling, reads, reset or disposal can disrupt the owner. Poll detects detached/disposed borrowed peers. Membership and local connection status commit before callbacks, all event subscribers run, errors aggregate and recursive Poll rejects. Callback Close/recreation invalidates old iteration state. Graceful disconnect publishes a local event on completion; forced local disconnect and Close suppress it.

## Verification and limits

[ENetTests](../../tests/Electron2D.Tests/ENetTests.cs) exercises IPv4/IPv6, all five codecs, 20-KiB fragmented channel packets, uint32 connection/disconnection data, peer/host statistics, tuning, wrong-owner and argument edges, raw datagrams, refusal, reliable retry through a native datagram-dropping proxy, empty-packet send-budget exhaustion/reset, two clients, all delivery modes on channel zero and channel three, routing, forced/graceful events, mesh lifetime, DTLS fragmentation and SceneTree/SceneMultiplayer delivery. The existing SceneReplicationTests native scenario also runs on ENet: custom/automatic/late spawning, pre-Ready state, Always/OnChange sync, visibility, RPC, observer failures and cleanup retain their assertions; 64 prepared active sync/delta and idle scene intervals allocate zero managed bytes. The fixture waits for subsequent property delivery independently of initial spawn readiness across native channels. Sixty-four warmed active and idle multiplayer intervals allocate zero managed bytes. The optional `ELECTRON2D_ENET_ORACLE` executable runs the stock Unix socket backend, including channel payload echo and graceful teardown. The full runner and self-contained deployment exercise the same native contract; class-page excerpts have a separate public consumer compilation/execution check.

Native allocations, Internet/NAT reachability, loss performance, physical networks, foreign/browser hosts, and human/editor/rendered/agent acceptance remain unverified. This is headless native network execution, independent of display. See [platform verification](../platform-verification.md).
