# Multiplayer transports

Last updated: 2026-10-04

## Scope and types

[MultiplayerPeer](../classes/MultiplayerPeer.md) extends PacketPeer with typed identity, routing, next-packet metadata, transfer configuration, admission and owner-thread events. MultiplayerConnectionStatus and TransferMode are separate shared enum domains. [OfflineMultiplayerPeer](../classes/OfflineMultiplayerPeer.md) models a permanently connected local authority with no remote endpoints. [WebSocketMultiplayerPeer](../classes/WebSocketMultiplayerPeer.md) owns a WS/WSS listener/client cohort using the existing [WebSocket](websocket.md) and TLS backends. Internal WebSocketMultiplayerConnection owns each accepted TCP/TLS/WebSocket chain. WebSocketPacketQueue now retains a source ID alongside prepared payload metadata. [ADR 0094](../decisions/networking.md#adr-0094) owns the contract.

## Base and managed extensions

MultiplayerPeer is an abstract C# transport, with virtual TransferChannel, TransferMode and RefuseNewConnections properties and abstract lifecycle/identity/packet hooks. Consumer code extends it directly; the external native extension facade and its pointer/Error/script-array ABI project onto ordinary managed overrides and PacketPeer span hooks. IsServer and IsServerRelaySupported are typed role/capability queries. GenerateUniqueID uses cryptographic randomness to produce values from two through int.MaxValue; hosts still check collisions. Broadcast/server IDs are zero/one, negative targets exclude one peer, and int.MinValue is rejected where an exclusion is interpreted.

Calls/disposal require the constructing thread. PeerConnected/PeerDisconnected are typed Action<int> events. Implementations commit state before dispatch; every captured subscriber runs, and callback errors aggregate afterward. Prepared delegate enumeration avoids invocation-array allocation. Custom implementations are responsible for using CheckPacketPeer and committing their own state before protected EmitPeerConnected/EmitPeerDisconnected. PacketPeer snapshots allocate; span reads preserve undersized packets and last-read status/exception semantics.

OfflineMultiplayerPeer remains Connected, IsServer=true, ID=1, relay=false. Available count, maximum outgoing size, next source and channel are zero; mode is Reliable. Writes discard bytes, explicit reads return empty and succeed, and routing/Poll/Close/disconnect preserve this local authority. This is an executable offline transport contract, not network establishment. Automatic Node/SceneTree default multiplayer assignment still requires the MultiplayerAPI/SceneMultiplayer integration.

## WS/WSS establishment and ownership

CreateServer starts an owned TCP listener and optional borrowed server TLSOptions; its local ID is one and it is immediately Connected. CreateClient starts an owned WebSocketPeer and remains Connecting until the first complete binary message contains exactly a four-byte little-endian signed ID greater than one. The server generates collision-checked positive IDs and sends that message before publishing its connected event. No extra application routing envelope is inserted. HandshakeTimeout uses finite positive monotonic seconds, defaults to three and covers DNS/TCP/TLS/HTTP plus waiting for ID after Open. Live timeout changes apply to existing pending connections. Invalid/text/reserved IDs, malformed upgrade/transport errors and expiration release owned state before any connection event.

The host accepts at most one new socket per Poll. RefuseNewConnections skips admission and drops an already pending peer that becomes Open while refusing; existing ready peers remain usable. New protocols/header arrays sample the configured template at connection preparation; active transports keep their own configuration. TLSOptions is borrowed and must stay live for future accepts; actual TLS sessions retain their native resource payload through the existing security contract. GetPeer exposes a borrowed host-owned WebSocketPeer, including server ID one for a connecting client. Direct packet reads, close or disposal can disrupt the owning protocol. GetPeerAddress/Port return empty/zero for an absent identity.

Ready state and ID commit before events. Event callbacks may send immediately, Close or recreate the host; generation checks stop the old iteration after recreation. Recursive Poll rejects and its event error aggregates after later subscribers. Cleanup detaches status/maps first and releases every owned chain even if a peer's disposal subscriber throws. Recreation during cleanup rejects; nested Close is idempotent. Native client transports are owned by WebSocketPeer; accepted server WebSocket streams borrow TCP/TLS while their connection owner releases the whole chain.

## Routing, packets and capacity

Server SetTargetPeer(0) broadcasts; a positive ID chooses a connected remote, and a negative ID excludes that remote. A client always sends to its server, regardless of its configured target: higher MultiplayerAPI relay owns client-to-client routing. IsServerRelaySupported=true advertises that capability to the higher layer without silently relaying bytes here. TransferMode/TransferChannel settings retain caller choices; WS/WSS actual packets are Reliable on channel zero. GetPacketPeer/Mode/Channel describe the next packet, including after an undersized read; an empty WebSocket host queue returns server ID one. Aggregate receive order follows polled connection order and each connection's FIFO.

PutPacket copies bytes through the owned WebSocket queue. Empty application packets are ignored; incoming empty WebSocket messages are consumed without entering the multiplayer inbox. GetMaxPacketSize retains the source nine-byte reserve and clamps to nonnegative: effective output budget minus nine, using the prepared 64 MiB ceiling for output setting zero. Positive missing targets and excessive payload reject. Broadcast attempts all selected recipients and aggregates failures; successful recipients retain their packets, so fanout is not a transaction.

Input/output capacities default to 65535, packet count to 4096; buffers are at most 64 MiB and counts at most 65536. Capacity changes require Disconnected to preserve prepared aggregate/per-peer storage. Identity setup requires at least four input/output bytes and one packet slot; impossible settings reject before connection. Each WebSocket has its own prepared budgets. The host additionally prepares one aggregate inbox bounded by InboundBufferSize/MaxQueuedPackets and one receive scratch buffer. When aggregate capacity is exhausted, messages remain in the owning WebSocket queue until application consumption frees space. No per-packet array/list growth occurs. Peer membership/handshake preparation is explicit lifecycle work; steady-state Poll/routing/span reads/event dispatch reuse storage. External TLS/OS/RNG native allocation remains unmeasured.

## Disconnection and verification

Close immediately releases the listener, pending and ready connections, maps/inbox and local identity, without PeerDisconnected. Normal DisconnectPeer starts a clean close, keeps polling through Closing, then detaches and emits. Force detaches immediately and suppresses the local event; the remote can still observe a natural disconnect. Client natural disconnect commits Disconnected/ID=0 before its server event. Server pending failures emit no connected/disconnected event; ready failures drop only that peer. Already copied server inbox packets retain their source metadata after a remote leaves; full host Close clears them.

Custom packet/event and native WS/WSS routing/span/Poll active/idle intervals each measure 64 warmed cycles with zero managed bytes.
