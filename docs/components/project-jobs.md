# Shared editor workflow and immutable project jobs

Last updated: 2026-10-27

## Scope and dependency direction

[ADR 0090](../decisions/agent-native.md#adr-0090) stage 2 connects the separate editor executable to [ProjectSession](project-session.md). [SessionProject](../classes/SessionProject.md) creates/opens a version-two `electron2d.project.json` naming one root .NET executable, one typed scene and one strict UTF-8 C# buffer. [SessionJob](../classes/SessionJob.md) builds/runs an immutable input. All project/session/scenario types live in `Electron2D.Editor.Session.dll`, outside the runtime. The editor and ordinary compiled projects consume public runtime APIs; Electron2D.dll references neither tooling nor game assemblies.

Current creation writes the manifest, project/source/scene and `.gitignore`; it does not initialize Git or seed project documentation/journal files. [Git-backed creation and durable context](../decisions/agent-native.md#git-backed-project-memory) are the next project-authoring extension, not behavior supplied by this slice. Opening an existing project likewise performs no Git initialization or history mutation.

The earlier standalone controller, its scenario SDK and version-one formats are removed. There is one shared operation boundary. Existing runtime Engine.Start/AdvanceFrame/Stop, callback-first native hosts, public input and MovieWriter keep their own contracts.

## Human and programmatic views

Launch the editor apphost normally or with `--project DIRECTORY`. The project bar creates in a new directory or opens an existing version-two project. An invalid open preserves the current view; switching/closing flushes pending manual source into recovery and releases the old owner. An exclusive live owner cannot be bypassed by another local application.

The scene tree, position inspector, source editor, history selector and authored preview subscribe to the same session used by trusted local SessionClient handles. Manual source is submitted before observations/mutations/jobs through [SessionCodeBuffer](../classes/SessionCodeBuffer.md), since native TextChanged delivery is deferred. A rejected proposal remains a visible draft beside current shared source; applying it requires explicit reviewed replacement at the fresh token. Save/build/close reject unapplied drafts. CRLF and mixed untouched line endings survive the LF-normalized view. Caret, selected node, tree collapse state and split positions survive unrelated changes. Ctrl-Z/Ctrl-Y and toolbar history use guarded shared operations. Source context menus remain unavailable until their commands can use shared history; the control's separate private undo menu is not exposed.

The authored preview duplicates only exact built-in Node, Entity, Polygon, Line and Sprite roles, without project classes, scripts, event connections or linked instantiation. It applies the exact unsaved pose overlay and displays static authored drawing in a SubViewport. Unsupported active/unknown roles report a capability error. It is not gameplay or a general lifecycle-neutral scene renderer. Run the snapshot for gameplay output. Typed archive reconstruction still executes ordinary trusted constructors/resource setup.

## Immutable input and project profile

StartJob checks both observed document revisions and independently changed scene/code files. One session admits one active job. A private immutable input includes the unsaved scene/source, exact object pose catalog, other project files, both managed SDK binaries and the host-RID native SDK closure. Materialization copies checked file sizes/hashes and repeats the source/SDK inventories; concurrent file changes reject. Compilation pins the resolved .NET SDK version, disables parent Directory.Build imports, shared compiler/MSBuild servers and source-control queries, and writes intermediates/output outside the frozen input. A manifest digest includes snapshot/document identities, revisions and every ordered relative path/size/SHA-256. Inputs are read-only and verified before and after execution, including membership.

The current profile is one framework-dependent net10.0 Microsoft.NET.Sdk Exe, literal references to the selected Electron2D and session binaries, and project-relative inputs. Additional projects, packages, imports, tasks, target frameworks, self-contained/native builds and external item closures reject with a named dependency/profile diagnostic. A qualified SDK must include the real target native libraries; project creation does not manufacture a missing backend. This is a bounded dependency profile, not arbitrary MSBuild dependency discovery.

Limits: 4096 files and 128 MiB project input, 4096 files and 256 MiB SDK input, 64 capture steps, 256 MiB uncompressed requested images, 65536 ordered input edges subject to a conservative eight-MiB encoded request budget, 1–1000000 steps, 1–240 FPS, 2–4096 pixel dimensions, 100–3600000 ms whole-job deadline. Before a job, existing generated results plus estimated input/build/captures must fit one GiB and leave a 512-MiB free-space reserve. Clear completed results before another job if this budget rejects. These are admission estimates; trusted project code retains ordinary filesystem permissions and has no disk quota.

## Build, run, cancel and cleanup

Submission captures session values and starts asynchronous materialization/build; the authoring owner remains available. [SessionJobOptions](../classes/SessionJobOptions.md) selects Build or Run, Headless or explicit GPU/compatibility rendering. [SessionRunHost](../classes/SessionRunHost.md) loads the frozen typed scene and calls a fresh [SessionScenario](../classes/SessionScenario.md). Configure registers factories/actions before scene load. SceneLoaded runs before activation. Ordered input commits before BeforeStep and ordinary processing. AfterStep observes completed process output; rendered mode uses real fixed-cadence MovieWriter images. Reaching the budget without explicit Complete fails. A failed assertion remains failed even if project code catches its exception. Cleanup attempts engine, scene, scenario and context retirement.

Every compiler/game command belongs to its own Linux session/process group. A private executable role in the session assembly watches the author's lifetime pipe. Cancel/deadline kills that owned group and drains bounded logs; abrupt owner death closes the pipe and terminates inherited descendants. Normal command completion also retires remaining same-session descendants before reporting. Unrelated process groups remain outside cleanup. This executes trusted C#/MSBuild with ordinary host permissions, not a hostile-code sandbox; code that deliberately escapes the process session is outside this cooperative profile. Other platforms need a real process-job owner before jobs become available.

Result JSON is separate from stdout/stderr (each retained log is bounded to one MiB and remaining output is drained). Validation ties results to exact request/snapshot/document tokens, project/runtime/SDK binaries, actual renderer/driver, step accounting, exit status, assertions and hashed owned artifacts. Failure is a terminal result, never inferred success from process start. The editor labels stale results and the source snapshot of displayed captures; subsequent edits cannot silently relabel older pixels. A new run does not replace the authored scene.

SessionJob.DisposeAsync cancels/waits for process retirement. ProjectSession disposal requests cancellation; callers still await the returned job. Generated input/build/results remain evidence until terminal RemoveResult or the editor's Clear job results. Removal checks the owned job marker and cannot target source files. No mutable-input build cache or hot reload is implemented.

Public types: [SessionProject](../classes/SessionProject.md), [SessionJob](../classes/SessionJob.md), [SessionJobOptions](../classes/SessionJobOptions.md), [SessionJobKind](../classes/SessionJobKind.md), [SessionJobStatus](../classes/SessionJobStatus.md), [SessionInput](../classes/SessionInput.md), [SessionSnapshotFile](../classes/SessionSnapshotFile.md), [SessionSnapshotInfo](../classes/SessionSnapshotInfo.md), [SessionJobResult](../classes/SessionJobResult.md), [SessionJobArtifact](../classes/SessionJobArtifact.md), [SessionJobDiagnostic](../classes/SessionJobDiagnostic.md), [SessionObservation](../classes/SessionObservation.md), [SessionAssertion](../classes/SessionAssertion.md), [SessionRunHost](../classes/SessionRunHost.md), [SessionScenario](../classes/SessionScenario.md), [SessionRunContext](../classes/SessionRunContext.md), [SessionRunMode](../classes/SessionRunMode.md), [SessionCodeBuffer](../classes/SessionCodeBuffer.md). Internal `CapturedProject` and `SnapshotManifest` carry captured values/provenance; `SnapshotStore` inventories/materializes/verifies inputs; `SceneOverlay` restores exact typed poses. `RunRequest`, `RunReport`, `JobFailure`, `JobJSON` and `JobProtocol` implement the private version-two process contract. `ProcessJob` owns commands/logs/groups; `ProcessWorker` watches owner death and retires descendants. Their state is private tooling state, not runtime declarations.

Internal `EditorApplication` owns switching/window shutdown, `ProjectWorkspace` binds controls/preview/results, `SessionCodeEditor` routes shared history, and `SourceTextProjection` preserves raw source line endings. They use the existing native controls, branding/fonts and public resource lifetimes; there is no second document model, custom game loop or backend probe.

## Verification and remaining gates

[ProjectJobs](../../tests/ProjectJobs/Program.cs) exercises unsaved code+pose snapshots, editable authoring, stale provenance and real headless/native output. Its [failure contracts](../../tests/ProjectJobs/JobContracts.cs) exercise invalid bounds, pending-input ordering/conflicts/reentry, build/callback/assertion/input/budget failures, snapshot mutation, cancellation, deadline and abrupt owner death with descendants. [ProjectWorkspace](../../tests/ProjectWorkspace/Program.cs) drives native input, shared edits/history, inspector, resize, actual build/run/capture/stale display and clearing generated results. [ApplicationTests](../../tests/ProjectWorkspace/ApplicationTests.cs) exercises create/open/switch/failure/recovery in the actual shell. Tests use software Vulkan/OpenGL under Linux/Wayland; physical GPU/input/IME, foreign platforms, native heap/performance and owner visual acceptance are separate.

[Authenticated local operations, the real Codex executor and the native conversation/task panel](project-agent.md) now exercise stage 3 over this owner and job registry. The native acceptance includes an actual model; installed delivery remains a separate gate. General scene editing, language services, importer/exporter/plugin systems, arbitrary project dependency closures, concurrent jobs/agents and hot reload retain their own gates.

[Editor authoring mode](../classes/Engine.md#editor-authoring-mode) distinguishes the editor process from game/scenario execution, preserving authored startup values and explicit preview. The owning contract records scoped timers, automatic-next behavior, native/source verification and remaining acceptance gates.
