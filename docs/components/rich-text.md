# Rich text

Last updated: 2026-10-07

RichTextLabel connects the existing Control, themed FontFile/FreeType/HarfBuzz/ICU text, retained canvas, input, scrolling and typed scene-resource storage. RichTextEffect and CharFXTransform add executable application glyph effects. RichTextEffectEnvironment and RichTextMetadata replace untyped effect dictionaries and link payloads with exact generic borrowed values. InlineAlignment and TextGraphemeFlags retain shared semantic domains. No additional renderer or vendored code change is introduced.

The selection compared RichTextLabel/RichTextEffect/CharFXTransform (190 own reference rows), GraphEdit/GraphNode/GraphElement (175 rows) and Script/CSharpScript (21 rows, including one deprecated member). Rich text unlocks styled dialogue, logs, links, inline media and application/editor consumers through three connected engine types using already executable font/canvas backends. Graph authoring requires three new port/layout/interaction controls. Script requires compiled source/assembly association and a live owner attachment/resource-loader contract. Rich text was the strongest reachable capability.

## Document and ownership

Text retains untranslated source. BBCodeEnabled affects assignment; AppendText parses markup independently and only closes tags opened within its own append call. Clear/manual pushes alter runtime content without changing Text. Pop, PopAll and PopContext restore nested style/frame contexts. Paragraph/list/indent blocks separate paragraph layout and shaping direction. Unknown tags remain literal; quoted brackets, Unicode character and bidi control tags are recognized. Basic font roles, explicit fonts/sizes, OpenType features, colors/outlines, underline/strike, hover hints, links, image dimensions/units/crop/padding, rules, drop caps, tables/cells and builtin/custom effects execute.

GetParsedText retains drop caps, one space per image and structural tab markers. Scalar counts and selected text exclude drop caps and those markers, count newlines/images and concatenate table cells. The keyed AddImage<T> overload places its key first so positional integer width/height calls retain their unkeyed meaning. A color-only UpdateImage accepts no replacement texture. Root line queries treat a table as one inline object; cell lines contribute to table height and interaction. Selection follows scalar boundaries, including supplementary Unicode. Owned VScrollBar and PopupMenu retain identity and reject independent disposal. Runtime stacks, metadata, image keys, selection and worker caches are not scene properties. Stored source/configuration and borrowed registered effect resource arrays load through a fresh process; application subclasses require their registered application factory.

Fonts, textures, effects and environments remain borrowed. The label owns parsed feature font copies and glyph callback state. Active layout/drawing rejects document mutation; custom callbacks cannot dispose their borrowed state. Color, GlyphIndex, Offset, Transform and Visible affect drawing; descriptive Font/range/flags/count/outline writes do not redirect the face. GetGlyphIndex queries the actual callback face. Returning false stops later custom effects while builtin effects continue. Native font reads retain all style fonts in a stable acquisition order during shaping; prepared drawing retains the active face across callbacks.

Threaded prepares immutable document and structured bidi context snapshots on the owner, shapes them on a worker, and publishes completed root paragraphs and final completion on the owner. Mutation/disposal joins the worker before retiring its data. Layout errors are reported. The progress delay controls pending drawing. A deterministic test blocks the second paragraph while owner queries observe the completed first paragraph, then releases the worker and verifies one final completion. Only completed paragraph/frame geometry is published; cells within a pending table are published with that completed table paragraph.

## Verification

Native hosts assert colored glyph/texture pixels, actual glyph replacement, ignored descriptive writes, false custom-chain termination and rejection of active document/state disposal and retirement of removed effect blocks. Native hosts render themed roles, multilingual fallback, custom colored glyphs, table cells, links, inline images and drop caps on current Linux Wayland GPU and compatibility. ## Exact remaining dependencies

Advanced font-tag spacing, embolden, slant/transform, collection face and variable coordinates require FontVariation per-instance shaping/raster cache identity under ADR 0046. OpenType feature overrides and concrete file fonts execute now. Source/assembly-associated Script effect installation requires ADR 0091 resource-loader/live owner integration; typed compiled C# effect resources execute now. Assistive image/table/column names require AccessibilityServer semantic table/cell nodes. Concrete editor project/resource authoring requires ADR 0090 authoring operations. Current native libraries do not establish mobile/browser text prerequisites or foreign-platform acceptance. Deprecated is_ready is excluded under ADR 0004; IsFinished is the modern API.

Paragraph rebuilding and the document snapshot are cold O(document size) operations. Pointer hit lookup currently scans loaded paragraph/scalar bounds; a retained per-line interval index is the upgrade if very large documents make pointer motion material. Table nesting is bounded to 256 layout levels. A complete API inventory is not proof that these separate dependencies are implemented.

After this slice, GraphEdit/GraphNode/GraphElement (175 rows), FontVariation (14 rows plus the newly identified rich/font dependencies) and Script/CSharpScript (21 rows) are the next candidates. Graph authoring offers the broadest directly executable application API and unlocks node/port/connection consumers using the current canvas/text/input/storage backends. FontVariation has a narrower immediate surface and needs per-instance native variation/cache work; Script still needs compiled association and owner loading. Graph authoring is the next preferred connected slice, subject to its owning decision and exact upstream audit.
