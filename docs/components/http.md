# HTTP transfers and stream compression

Last updated: 2026-10-04

## Public surface

[HTTPClient](../classes/HTTPClient.md) exposes polled HTTP/1.1 request/header/body state over owned TCP/TLS or a borrowed StreamPeer. [HTTPRequest](../classes/HTTPRequest.md) adds scene scheduling, dedicated-worker execution, typed completion, progress, redirect policy, timeout, memory/file downloads and content decompression. [StreamPeerGZIP](../classes/StreamPeerGZIP.md) incrementally compresses/decompresses bounded gzip or zlib-wrapped deflate. HTTPMethod, HTTPResponseCode and HTTPStatus are shared HTTP enum domains; HTTPRequestResult is the distinct transfer-completion domain. HTTPTransfer/HTTPProxySettings and the compression PAL helpers remain internal. [ADR 0094](../decisions/networking.md#adr-0094) owns the contract.

## HTTP client flow

ConnectToHost starts asynchronous DNS or an immediate nonblocking numeric connection and polls address candidates. A scheme prefix selects plain/TLS defaults; explicit client TLSOptions retain their resource identity. Poll advances connect, TLS, proxy negotiation, request sends and response headers. Configured HTTP proxies receive absolute request targets; HTTPS proxies receive CONNECT before target TLS/name validation. RequestRaw copies its input; Request uses UTF-8 body bytes. Default fields identify Electron2D, Host and Accept, and add matching Content-Length for a nonempty body. CR/LF/control/token/target/framing validation rejects injected requests and ambiguous lengths.

A supplied Connection is borrowed; replacing/closing the HTTP client releases owned transports and forgets the borrowed stream without disposing it. GetStatus is cached. HasResponse records unread parsed headers even for headerless responses. GetResponseHeaders returns/consumes ordered duplicate field lines; dictionary conversion preserves spelling and uses the last identically spelled duplicate. Metadata and body readiness remain independent. Unknown valid numeric status codes remain representable through HTTPResponseCode; zero denotes no response.

Response parsing handles informational replies, HEAD/bodyless/CONNECT/upgrade replies, fixed length, chunked and close-delimited bodies. Chunk extensions and trailers are consumed; trailers are not returned or applied as framing metadata. Conflicting/negative Content-Length, TE/CL ambiguity, unsupported transfer codings, malformed status/fields/chunk delimiters and premature framed EOF fail explicitly. The prepared response-header budget is 64 KiB by default; the chunk/trailer line budget is 4096 bytes and total trailers share the header budget. Body chunks are decoded stream prefixes bounded by caller storage and ReadChunkSize (256 through 16 MiB), rather than copies of unbounded server chunks. Blocking mode may wait for progress; callers choose that behavior explicitly. Span body operations reuse storage; snapshot arrays and response parsing transitions allocate.

QueryStringFromDict accepts typed ordered scalar entries with valueless nulls or repeated array entries. UTF-8 percent encoding and entry order are preserved. A flat scalar sequence can mix valueless/scalar/repeated keys; callers format other C# values rather than introducing dynamic Variant wire values.

## Scene and worker lifecycle

HTTPRequest requires SceneTree membership. Its internal process lane advances a transfer independently of public ProcessEnabled. UseThreads constructs/operates transports on a dedicated background thread; scene polling reads published progress/completion and invokes RequestCompleted exclusively on the scene owner. Configuration stores in PackedScene through typed descriptors and a static factory; active operations, TLS/proxy runtime references and event subscribers are not stored. Completion releases resources and returns the node to idle before invoking handlers, so reentrant requests and callback exceptions do not duplicate or retain the old operation.

CancelRequest, tree exit and disposal stop processing, signal cancellation and join worker cleanup before returning. They suppress completion for canceled work. Timeout is sampled at start as finite nonnegative scene process seconds; zero disables it. BodySizeLimit, DownloadFile, DownloadChunkSize and UseThreads configure idle nodes. Negative body limits are unlimited. Live gzip and redirect limits apply at response processing; TLS/proxy changes are published to the operation owner for their documented next connection/request boundaries.

Redirect limits default to eight. Relative Location values resolve against the current URI. Unsafe methods on 301/302/303/305 become GET with body/content headers cleared; 307/308 auto-follow only safe methods, matching the accepted source behavior. CONNECT never auto-redirects. Cross-origin redirects strip authorization/proxy-authorization/cookie/Host fields, preventing credential forwarding to a new origin. Response status and transfer success are distinct: a completed HTTP error response can still have HTTPRequestResult.Success.

GetBodySize reports declared wire-body size or minus one; GetDownloadedBytes reports consumed wire bytes before content decoding. Gzip/deflate negotiation preserves explicit caller Accept-Encoding. Content decoding is incremental through bounded StreamPeerGZIP output; wire and decoded limits are checked before memory/file output and strict native stream-end/checksum verification rejects truncated bodies. Aggregate memory downloads are explicit loading work and can grow outside the measured body-span interval. File downloads use an owned sibling temporary file, then atomically replace the destination only on success. Failed/canceled transfers remove only their temporary file and preserve an existing destination. File completion returns an empty byte array.

## Compression backend and budgets

StreamPeerGZIP uses the compression PAL already delivered with the .NET 10 runtime. The internal sequential PAL state, source-generated imports and SafeHandle release match the pinned v10.0.1 native contract. No new package, OS installation, public native handles or vendored source is added. Source state and output buffers are prepared at Start; output rounds to a power of two with a reserved byte, bounded to 64 MiB. Partial writes report input consumed under backpressure; drain output before retrying. Finish is compression-only and preserves finishing state across drain/retry. IsFinished exposes actual native end status, including gzip trailer/checksum verification; concatenated gzip members reset prepared inflate state. Zlib-wrapped deflate follows the reference useDeflate contract, not raw deflate.

Setup, request construction, DNS, TLS handshakes, parsing/header snapshots, aggregate bodies and file operations are cold/loading boundaries. Repeated prepared HTTP body-span/poll and gzip member/read/reset operations allocate no managed bytes in the checked interval. The PAL state is allocated only at preparation; external native codec allocator totals are unmeasured. Direct PAL ABI integration is tied to the selected .NET 10 runtime and requires an executable packaging gate on each claimed target. Current native execution is Linux x64; HTTPS inherits the current Linux OpenSSL 3 backend. Browser HTTP host integration and other-platform/backend/native packaging remain separate.

## Verification

[HTTPTests](../../tests/Electron2D.Tests/HTTPTests.cs) exercises fragmented headers/fixed/chunked/close bodies, informational/headerless/HEAD/CONNECT behavior, chunk extensions/trailers, duplicate/ambiguous/injected fields, query escaping and caller-owned transport lifetime. Native TCP/DNS fallback, forward proxy, CONNECT tunnel and independent SslStream HTTPS server execute on loopback. Scene and worker tests verify owner-thread/idle completion, redirects, incremental gzip, zip-bomb limits, truncated gzip rejection, atomic file preservation/success, timeout/cancel/tree exit, reentry and PackedScene configuration. Independent BCL gzip/zlib decoding verifies compressed wire output; fragmented native decoding verifies checksums/end status. 64 HTTP body-span/poll and 64 gzip member/decode/read/reset cycles each measure zero managed bytes after preparation.

Native codec allocator totals, routed network conditions/throughput, foreign targets/browser, authenticated real-world proxies and owner acceptance remain separate gates. Network checks do not establish rendered output, editor tooling or unified agent/project workflows.
