# Linux native file choosers

Last updated: 2026-10-28

[ADR 0040](../decisions/display.md#adr-0040) owns DisplayServer.FileDialogShow and the existing FileDialog native consumer. Linux Wayland/X11 now select org.freedesktop.portal.FileChooser through the existing system libdbus dependency. Other desktop hosts keep SDL's asynchronous chooser. The extra-control path also exposes the immutable FileDialogOption description; no backend handle escapes.

## Native request and result

A private bus connection owns each request. The non-UI capability probe checks interface version: NativeDialogFile, NativeDialogFileMime and NativeDialogFileExtra need version 1; OpenDirectory needs version 3. Missing service/interface or bus reports no capability. Launch validates arguments and rolls back parent ownership on failure. OpenFile/OpenFiles/OpenDirectory use OpenFile with their actual multiple/directory options; SaveFile carries current_name. Initial folders use UTF-8 NUL-terminated byte arrays. Linux continues to ignore showHidden, and the service may ignore the suggested directory or title.

SDL's exported Wayland handle or X11 ID supplies the parent identifier. An unavailable Wayland export uses the portal's unparented presentation, while the engine still retains the selected logical parent. The backend subscribes before launching, using an unpredictable request token and authentic service owner. Matching also checks the actual returned path, so early responses and older alternate handles are retained without accepting another request's signal. Service-owner or bus disconnection fails outstanding requests. The adapter polls only during the display owner pump; no game callback crosses a native thread boundary.

Filter entries keep `patterns;label;MIME types`. Existing `*.ext`/all-files patterns and comma lists remain valid; MIME rules permit subtype wildcards. Pattern and MIME rules form the portal's union. A filter may contain only MIME rules. FileDialog's All Recognized combines both families, retaining the synthetic/original filter indices. Directory mode ignores filters. The selected current_filter matches its label and ordered native rules to the original filter; an unknown or missing selection returns -1.

Successful local file URIs decode into copied filesystem paths, including Unicode, spaces and escaped `#`. HTTP/remote-host, malformed escapes, query/fragment and embedded-NUL paths reject. One path is required except for OpenFiles. Cancellation delivers false and an empty list. Error/malformed responses or connection loss also deliver false before the event pump reports the failure. All queued callbacks are attempted even when another callback fails. Native completion releases retained parent/request resources; disposal still rejects a pending request or undelivered result. Cold native setup, probing, parsing and callbacks may allocate or block; an idle pump adds no new work.

OpenAny remains explicitly unsupported: the standard portal has no combined file/directory selection. This is the accepted native-backend limit, not an empty implementation. An additional combined chooser requires its separately approved capability under ADR 0040. FileDialog's authored root restriction and options with empty labels/captions continue through its executable custom browser fallback. NativeDialogFileExtra advertises checkbox/choice support, with the exact root and virtual-access limits below.

## Native checkbox and choice controls

`DisplayServer.FileDialogWithOptionsShow` takes an ordered copied list of immutable [FileDialogOption](../classes/FileDialogOption.md) descriptions. The constructor copies captions and clamps the default to zero/one for a checkbox (no captions), or to the available choice indices. Labels/captions must be nonempty and contain no NUL. At most 65536 controls may be requested. The typed callback adds a read-only owned map of [FileDialogOptionValue](../classes/FileDialogOptionValue.md) results to the ordinary success/path/filter result. There is no dynamic dictionary payload or public native option ID.

The portal receives `choices` as `a(ssa(ss)s)`, with stable per-request IDs and numeric choice IDs; checkbox selections are exactly `true`/`false`. Response choices are `a(ss)`. Unknown provider IDs are ignored. Duplicate known IDs, invalid kinds/indices, missing expected choices or malformed payloads fail the complete request before publishing paths or options. Native response ordering does not affect duplicate authored names: the last configured option wins. Cancellation/native failure returns an empty map, empty paths and filter -1; native failures are then reported by the normal aggregate event-pump exception. Immutable results remain readable after the native request retires.

The raw method rejects nonempty `root`: the standard portal cannot restrict navigation. FileDialog retains its existing custom browser for RootSubfolder and virtual resource/user access, or labels/captions the portal cannot represent. Other native hosts keep the extra capability false and reject the raw method until their adapter executes. No confinement or sandbox guarantee is inferred from a feature flag.

FileDialog captures options, defaults, mode and filters when opening. Successful launch publishes captured defaults to GetSelectedOptions; launch failure preserves the prior result. Acceptance replaces these results before FileSelected/FilesSelected/DirSelected. Cancellation retains the captured defaults. Authoring edits while pending affect the next presentation rather than changing the current native request. All new presentations reject while native completion is pending, including after a policy edit would otherwise select the custom browser. The next custom presentation rebuilds its actual controls from current authored defaults.

## Executable evidence

PortalFileChooserTests and check-file-portal.py run real native Wayland clients against a private D-Bus service without activation directories. They check absent service, interface version 2 directory rejection, MIME-only/combined filters and native request serialization, Unicode/escaped names, open/multiple/save/directory, selected/unknown filter, cancel/error, early and alternate handles, unrelated path/sender, invalid URI/NUL/escape/count/type/empty results, callback failure, concurrent results and service death. A separate private-bus shutdown profile verifies one failed callback, released request ownership and a false capability query with ordinary window decorations enabled. The initial control terminated with SIGTERM; a debugger stack identified GIO's exit-on-close signal inside libdecor pumping. The native Wayland display now retains that shared GIO connection with exit-on-close disabled through native teardown, restores the prior policy when the connection survives, and unreferences its retained owner. Tests verify the live policy and restoration for ordinary/scene/installed-portal cycles, and avoid rearming an already closed connection. No production signal handler or decoration bypass is installed. GPU and Compatibility Engine.Run consumers route two MIME-only filters through the actual FileDialog native path and release the scene/display.

The separately installed Wayland FileChooser passes actual visible MIME-filtered file selection and cancellation, driven through its uniquely titled AT-SPI window. The native result validates the selected file and filter index. This is independent of the private protocol fixture. The live harness locates the observed Nautilus chooser action names; it does not claim a general desktop automation interface.

Receipts are retained under ignored bin/portal-file-chooser/2026-10-28. Theme portal and ordinary FileDialog/display regressions also apply because the retained theme probe shares the libdbus declarations. X11/foreign hosts, NativeAOT, native allocation totals and human application acceptance are separate gates; the product's current required native gate is Linux Wayland. No portal daemon, dependency source or installed service is modified; the checks do not edit host configuration.

Protocol references: [FileChooser](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.FileChooser.html), [Request lifecycle](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Request.html), [SDL window properties](https://wiki.libsdl.org/SDL3/SDL_GetWindowProperties).

GIO's native [exit-on-close property](https://docs.gtk.org/gio/property.DBusConnection.exit-on-close.html) documents the process-termination policy. The retained reference and prior value belong to the main display lifetime; child windows borrow that host policy.

The options slice extends the same private-service profiles with exact checkbox/choice serialization, immutable input/result copies, reordered/unknown/duplicate/missing IDs, malformed boolean/index/type/pair/URI results, empty lists and observer failure. Both rendered scene hosts verify request edits, state-before-event, cancellation defaults, repeat presentation, root and empty-caption custom fallback. The installed portal options profile changes an actual checkbox and choice before selecting the file; its readback is independent of the private fixture. Receipts for this slice are under ignored `bin/portal-file-options/2026-10-28`; the same foreign-host, NativeAOT, heap and human-acceptance limits apply.
