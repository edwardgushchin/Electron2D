# File dialogs and operating-system file actions

Last updated: 2026-10-06

FileDialog : ConfirmationDialog provides an executable file/directory browser through the current embedded Window host. It composes DirAccess, ItemList, HSplitContainer/VBoxContainer, LineEdit, OptionButton and MenuButton. OS is a retained permanent static service registered as `OS`; callers cannot dispose or unregister it. No public Instance accessor exists.

## Browser flow and invariants

Resources, UserData and FileSystem select a real directory owner. Access changes reset root/history/filename. CurrentDir navigates relative to the current directory; CurrentPath splits virtual roots without corrupting `res://` or `user://`. RootSubfolder retains the authored string and applies a canonical lexical directory boundary. DirAccess supplies virtual-root and symbolic-link policy; this UI boundary is not a filesystem security sandbox. Failed navigation restores the prior directory.

The list places directories first, applies case-insensitive glob file-type patterns and filename substring filtering, and supports natural name/type or modified-time ordering in both directions. Hidden-file listing uses DirAccess.IncludeHidden. Thumbnail/list arrangements use the exact FileDialog theme icon/color/size keys and shared path-to-borrowed-texture providers. Favorites and recents are copied shared scoped lists, with normalized trailing separators and toggle/reorder/activation and a 20-entry recent history per access scope, preserving other scopes; stale matching directories are pruned. Shared configuration reads/writes belong to the first authoring thread; tree-attached operations also require the scene owner.

The filename-filter toggle controls its input; turning it off clears filtering. Changed programmatic filter values show the input and emit the committed string. Required listing refresh continues after a failed observer. This corrects the pinned comparison source's erroneous filter-control event payload to the documented string. Icon callbacks may change filters during refresh; bounded retries settle against the final state or fail explicitly. Filtering, enumeration, option reconstruction and native OS actions are cold blocking operations; they are not zero-allocation real-time operations.

OpenFile/OpenFiles return existing scoped files; OpenDirectory returns the selected directory or the current directory; OpenAny accepts either kind. SaveFile validates the parent and selected extension, and optionally opens the owned overwrite confirmation. Acceptance emits a destination and never writes/replaces its contents. Cancellation of overwrite retains the browser and original file. Folder creation accepts one leaf name, creates it through DirAccess, then navigates into it. Context and independently rebindable shortcuts support refresh, parent navigation, hidden files, filter/path focus and trash. Context copy uses DisplayServer's clipboard; show-in-file-manager uses OS.

Custom options recreate real CheckBox or OptionButton controls. Values/defaults/names are copied and indexed fields are stored after OptionCount. Defaults clamp to checkbox 0/1 or choice bounds. GetSelectedOptions returns an owned read-only dictionary snapshot of FileDialogOptionValue; duplicate keys use the last configured option. Returned controls/textures are borrowed, owned children and directory handles are disposed with the dialog. Current selection/path, callbacks, shared lists, transient dialogs and filter-input toggle are runtime-only. PackedScene/file factories reconstruct the complete control graph.

## Native and platform boundary

UseNativeDialog intercepts inherited Show/Visible/Popup/centered variants and PopupFileDialog. A supported basic filesystem request without custom options uses DisplayServer's asynchronous SDL chooser. Pending ownership prevents disposal; copied native results are delivered during owner pumping and update the current path before selection/cancel events. Request mode/filters are captured at presentation. Basic OpenAny, unsupported patterns and MIME-only filters fail explicitly. The custom resource/user/options/root-boundary browser remains usable when native-file-extra is absent. Native RootSubfolder/options enforcement requires that extra backend; inherited independent native child windows and semantic/scaling facilities retain their owner prerequisites. Automatic sandbox-native preference requires an OS sandbox probe and is not claimed here.

OS.MoveToTrash dynamically calls the desktop Linux GIO recoverable trash operation. GIO owns mount policies, collision names, metadata and symbolic-link handling. An unsupported request reports an exception; there is no permanent-deletion fallback. Multi-selection trash refreshes the listing even after a later operation fails. System internal mounts such as the current `/tmp` can refuse trash. Windows/macOS/mobile/browser recoverable trash requires its platform backend. OS.ShellOpen delegates default URI/path opening to SDL. ShellShowInFileManager uses the Linux folder-URI fallback; Windows/macOS native item selection remains unavailable. Automated checks do not open external applications.

## Verification

FileDialogTests exercises all five selection modes, filters/hidden files, root rollback and virtual-root identity, copied options and current result types, overwrite cancellation/confirmation, invalid save parents, folder creation, built-in shortcut gates, failed/reentrant filter/icon observers, favorites and fresh-process saved scenes. An isolated child on the home filesystem sets XDG_DATA_HOME to its owned temporary directory, verifies recoverable content/metadata and preservation of a symlink target, then removes only that fixture.

DisplayServerDialogTests verifies all native presentation guards, custom-option fallback, pending disposal and copied callback/cancellation lifecycle. It injects completion data and does not establish physical native chooser acceptance. FileDialogRenderingTests drives real SDL keyboard/pointer events and verifies browser pixels on current Linux Wayland GPU and compatibility. PNGs are visually inspected. Nested context anchors use their actual embedder once; teardown with an active nested tooltip no longer submits deletion to a closed tree queue. Each backend renders 64 retained frames after 32 warmup frames with zero measured owner-thread managed allocation at a fixed target size. Cold listing, pointer copies, OS/native memory, other platforms and owner acceptance remain separate limits.
