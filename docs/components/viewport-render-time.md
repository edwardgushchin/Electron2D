# Viewport render time

RenderingServer.ViewportSetMeasureRenderTime enables independent CPU/GPU measurements for a live scene or caller-owned viewport RID. ViewportGetMeasuredRenderTimeCPU and ViewportGetMeasuredRenderTimeGPU return double milliseconds from the same completed draw. GetFrameSetupTimeCPU returns the last successful frame's common CPU rendering preparation, even with viewport measurements disabled. All four operations require the active renderer owner. Invalid/retired identities reject; enable/disable also preserves the existing capture/submission mutation guard.

## Measurement boundary

CPU scope covers viewport canvas construction, dependency preparation and native drawing/submission. Recursively executed child viewport work and query-completion collection pause the parent's CPU clock. Ordinary process callbacks, frame caps and presentation/VSync waits are outside the scope. Shared authored drawing callbacks execute once during common frame preparation and belong to that setup scope. GPU scope brackets the authoritative backend canvas command stream, including its uploads, clears, internal drawing passes and final canvas-target copy. It excludes later screen presentation and compatibility replay on secondary native surfaces.

Common CPU setup includes shared drawing callbacks, global canvas/visibility/particle preparation, native-frame setup, pending particle work, secondary compatibility replay and completed-frame bookkeeping. It excludes individual viewport submissions and the presentation block. These CPU scopes describe elapsed owner-thread rendering work; CPU/GPU clocks are independent and parallel GPU work is not additive CPU time. No hardware clock calibration or application-wide profiler is implied.

Disabled or not-yet-completed measurements return zero. The previous completed pair remains readable while a new draw is in flight or the viewport is skipped. Publication requires both the native query result and the matching CPU interval; getters poll completion without waiting. Reuse at the next draw waits for that viewport's prior query before resetting it. Enabling is idempotent and allocates cold storage. Disabling clears results and retires pending native storage; re-enabling starts at zero. Resize preserves measurement policy, while viewport retirement/detachment and renderer shutdown release its queries before native contexts/devices. Independent native-window hide/remap follows that existing viewport retirement boundary; enable again for a new session attachment.

## Backend adapters

The pinned Vulkan bridge shares GPUTimestampQueries with RenderingDevice markers. Each measured viewport owns two queries and a retained native fence; no managed fence wrapper is allocated per frame. The elapsed export subtracts raw ticks before exact period scaling, preserving narrow counter wrapping. Absolute device markers retain their existing independent clock contract.

Compatibility uses timestamp queries in the existing Linux GL context, selects/restores that context around query operations and checks native availability/errors. GLES uses the EXT entry points and rejects disjoint results. Software and other backends without an integrated native elapsed-query adapter reject enabling with NotSupportedException; disabled getters and common CPU setup remain usable. A CPU stopwatch never substitutes for a native GPU result. GL contexts on foreign platforms and actual GLES execution remain unqualified.

## Verification

Build the matching tools/render-native bridge and Release linux-x64 runtime/tests. Run the compiled root test DLL with ELECTRON2D_TEST_VIEWPORT_TIMING=gpu and compatibility on Wayland, using SDL_GPU_DRIVER=vulkan for the GPU profile. Both profiles check actual root/SubViewport/caller-RID/native-child images, positive paired results, process-delay exclusion and single-counted shared child drawing preparation, independent enable/disable/re-enable, resize, native remapping, invalid/retired RID and owner/capture guards. After warmup, each checks 64 active plus 64 idle full frames at 0/0 owner-thread managed bytes. ELECTRON2D_TEST_VIEWPORT_TIMING=software with both SDL video driver variables set to dummy and SDL_RENDER_DRIVER=software checks explicit unsupported enabling, zero disabled results and common setup on a real software draw.

Run Electron2DRenderTimestampCheck for native ABI/bounds/unavailable queries, real completed GPU queries, raw-counter wrap arithmetic and exact elapsed conversion. Run the existing ELECTRON2D_TEST_GPU_TIMESTAMPS=local and renderer profiles after shared-query changes. Evidence is retained under bin/viewport-render-time/2026-10-29. These Linux checks do not establish foreign-backend, NativeAOT, native-heap, independent physical timing or human acceptance.
