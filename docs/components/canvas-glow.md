# Canvas glow

Attach a [WorldEnvironment](../classes/WorldEnvironment.md) with a [CanvasEnvironment](../classes/CanvasEnvironment.md) to the scene. Enable glow on the environment. GPU viewports use either ordinary RGBA8 or [HDR canvas storage](hdr-canvas.md). Values above the threshold produce a halo. Bloom also admits values below the threshold. The first selector in scene order with a live resource supplies the environment to each viewport sharing that world. Other worlds select independently.

The resource stores the enabled state, HDR extraction threshold and transition, luminance cap, bloom, blur strength, seven level weights, intensity, mix, blend mode and optional RGB map. The stored weights retain their authored values when normalization is enabled. Normalization divides by the sum of positive weights and leaves an all-zero set silent. The map is stretched across the target. Atlas textures assigned as maps keep the filter footprint within the selected region. Its alpha does not modulate glow. Borrowed resources and maps stay caller-owned. A packed scene preserves its environment links and resource-local copy policy.

After the canvas pass resolves, the GPU copies its pixels to retained scratch storage in the target format. An RGBA8 viewport decodes sRGB to linear half-float before the first filtered read. An HDR viewport already supplies linear pixels. It extracts bright pixels and progressively downsamples through the highest enabled level. A full-size pass combines the selected levels and optional map with the original pixels, keeping the original alpha. The result publishes through the viewport texture, image readback and window presentation. Canvas screen-texture commands run during the scene pass and see its raw content. Never-clear frames preserve unprocessed history so their halo cannot accumulate on subsequent redraws. Scratch targets retire when glow is disabled or the viewport target changes. No framebuffer data travels through managed memory.

[RenderingServer](../classes/RenderingServer.md#canvas-glow) can update the settings on an owned or borrowed environment RID with one validated call. The upsampling switch applies to the current renderer session. Bilinear upsampling is the default. The viewport environment mode can explicitly enable or bypass the effect. By default it inherits the parent viewport's mode, with an enabled root.

## Verification and remaining profiles

Run the Release test executable with `ELECTRON2D_TEST_GLOW=managed`, `gpu` or `compatibility`. The managed profile saves and reloads a typed scene with a shared scene-local environment. The Windows Vulkan profile checks linear pixels, exterior halos, world selection and reordering, blend modes, normalization, threshold and bloom, map masking, server validation, bicubic reconstruction, Never-clear history, MSAA resolve, resizing and a warmed full-frame managed allocation bracket. The Windows Direct3D 11 compatibility profile checks ordinary byte output with glow authored.

The [SDR profile](canvas-tonemapping.md#sdr-canvas-environments) verifies byte output and linear filtering. Compatibility retains ordinary output and needs its own native downsample, upsample and screen blend. The GPU kernel and HDR presentation need independent numeric comparisons and verification across the target matrix. Native allocation counts, throughput and release-package qualification remain open. The [tone mapping pass](canvas-tonemapping.md) integrates exposure and the five operators with glow. [Color adjustment](canvas-color-adjustment.md) can follow the glow composite. [Canvas mode](canvas-environment-background.md#canvas-layers) applies the effect before drawing higher layers on GPU viewports.
