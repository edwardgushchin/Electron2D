# System font matching and automatic fallback

Last updated: 2026-11-07

## Scope and ownership

[SystemFont](../classes/SystemFont.md) connects installed family/style/collection/variable matching to ordinary Font text consumers. [OS](../classes/OS.md) statically exposes GetSystemFonts, GetSystemFontPath and GetSystemFontPathForText through its permanent retained object. Internal [NativeSystemFonts](../classes/NativeSystemFonts.md) owns optional Linux Fontconfig or Windows DirectWrite catalog state and a bounded cold request cache; [SystemFontMatch](../classes/SystemFontMatch.md) carries source path/native face/family. The runtime does not install fonts, change font preferences or invoke a shell font command.

## Runtime flow

Linux enumeration filters scalable TrueType/CFF/Type 1 fonts and returns copied ordered family aliases. Style matching uses configured family preferences, OpenType weight conversion, width and slant. Text matching adds scalar coverage and locale, returning ordered file/face records contributing actual requested coverage. Fontconfig native pattern/charset/object/font-set handles are released on every path; the catalog retains its owned configuration. Missing optional library/catalog or unsupported providers produce absent query results.

Windows retains a DirectWrite factory, installed collection and native fallback object. Enumeration returns copied ordinal-sorted localized aliases. Existing family queries use native weight/italic matching and the nearest native width class (50/62.5/75/87.5/100/112.5/125/150/200 percent). Empty/unknown families use native fallback. Text queries use `MapCharacters` with the requested locale, or current UI culture when empty, and preserve native first-use file order. The effective default locale is part of the cache key, so a changed UI culture cannot reuse the previous native source choice. Script remains optional metadata. Progress ranges and native text/name counts are bounded before publication.

Only eligible local outline file identities enter the existing source reader: DirectWrite file keys resolve through the local font loader, and collection indices remain independent of the file path. Unsupported face types, multi-file faces and nonlocal loaders do not become fabricated paths. Every transient family/font/face/file/loader/string interface is released in `finally`. A source-generated COM text/locale provider pins input only during synchronous native matching and balances its wrapper/pins even on failure; this adds no public interface or extra managed assembly. Catalog access shares the existing serialized gate/cache and needs no display or caller apartment change. Missing factory/collection/fallback support reports an unavailable catalog, preserving theme fallback.

SystemFont loads bounded source bytes, scores all collection faces for family/weight/width/italic, retains tied logical faces, and applies supported variable axes when the match is not exact. Its independent native data uses the existing FontThread owner, unhinted shaping, rounding, phase-aware raster, clipping and retained texture lifecycle. Matching FontVariation instances map logical indices and merge system default coordinates with explicit override precedence. Unresolved requests clone native data from the borrowed theme font, watch it weakly and follow theme replacement without disposing the theme.

FontFile.AllowSystemFallback defaults to true and applies across source replacement, variants, duplication and bitmap loading. Shared layout first tries complete grapheme coverage in explicit sources, then a complete system source before scalar-level missing fallback. Automatic faces are owned by their parent FontData; disabling/changing policies clears future lookup and retires old faces after active parent reads finish. Source retirement recursively frees owned faces. HasChar/GetSupportedChars continue describing retained explicit source coverage; shaped/drawn/character-size queries may additionally resolve platform fallback.

Cold source/callback requests allocate. Prepared scalar/cluster lookups, cached measurement and active rendering reuse native source and texture storage. Request metadata is bounded to 4096 catalog keys, 4096 cluster keys and 65536 scalar keys; a parent retains at most 64 native fallback sources. These ceilings do not imply arbitrary-font/whole-world performance acceptance.

## Storage and verification

Ten typed SystemFont preferences and FontFile's fallback permission are stored with the existing resource schemas. Duplication reconstructs owned native state; fresh-process archives rematch their host instead of persisting machine-specific font paths. Tests isolate Fontconfig via child-only FONTCONFIG_FILE and temporary fixture/cache directories, preserving the workstation catalog. Separate variable and collection catalogs avoid ambiguous fixture styles; empty catalogs verify theme fallback and replacement.

SystemFontTests checks real native matches, variable glyph advance changes, tied logical faces, explicit coordinates, active retirement, copied arrays, invalid queries, silent equal setters, inherited policy behavior and prepared measurement. Current Linux GPU/compatibility capture verifies canvas/Label/RichTextLabel and a distinct automatic Arabic source, with 64 prepared render intervals per backend at zero managed bytes. The Windows profile below uses the same native text/render owners. Native allocators, other platforms, physical/editor and owner acceptance remain separate; CoreText and target delivery gates remain per coverage row.

## Windows native verification

`WindowsSystemFontChecks` is shared by the public-only `tests/WindowsFonts.Consumer` and the root check host (`ELECTRON2D_TEST_WINDOWS_FONTS`). `tools/windows-fonts-probe.cpp` is a separately built Windows SDK client. It enumerates native aliases, resolves exact style files/collection indices and text/locale fallback, and reads independent glyph design advances. The engine checks include Arial regular/bold/italic and bounded styles, other families, live Bahnschrift weight/width coordinates, Cambria Math at native TTC index one, copied arrays, localized aliases, invalid queries/UTF16, supplementary/combining/ZWJ text, concurrent lookups, logical variations, duplication and fresh-process archives. Automatic fallback renders a missing Arabic source while explicit `HasChar` remains false; disabling fallback restores absence.

Actual Vulkan and Compatibility runs render selected SystemFont, Label/RichTextLabel and automatic Arabic fallback. Owned viewport pixels compare the complete fallback crop against an independently selected explicit file/face; no desktop screenshot or foreign window is read. Prepared rendering measures 64 active and 64 idle owner-thread intervals separately. Native heaps and other-thread allocations are not inferred from these measurements. A Linux regression mode compares the unchanged Fontconfig provider with independent `fc-match`, including copied aliases/results, text coverage, validation and absence of display initialization.

With the SDK/MSVC environment and runtime prerequisites configured, compile the observer with `cl /std:c++20 /EHsc /O2 /MT /utf-8 tools/windows-fonts-probe.cpp dwrite.lib ole32.lib`, then run the public consumer with arguments `catalog`, `gpu` or `compatibility`, the absolute observer path, and a private output directory. GPU receipts explicitly select SDL's Vulkan driver. The proof directory `C:/Users/eduar/.codex/artifacts/Electron2D/windows-fonts-20261107` records actual completed source/fresh-Core/strict-NativeAOT/root/main profiles and fingerprints in `qualification.json`.

The checked native closure uses the current source-built FreeType/HarfBuzz/runtime payloads as explicit overrides of the older development package. Rebuilding a consumer can restore that package's older FreeType file; the closure must be reapplied before execution. The matching-bundle guard correctly rejects it instead of running a mixed allocator/shaper. These receipts do not qualify an untouched release-native package, other Windows architectures, CoreText/mobile/browser providers or full ADR 0021 acceptance.

Primary matching sources: [Fontconfig manual](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html), [DirectWrite MapCharacters](https://learn.microsoft.com/en-us/windows/win32/api/dwrite_2/nf-dwrite_2-idwritefontfallback-mapcharacters) and [local file loader](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nn-dwrite-idwritelocalfontfileloader). [ADR 0046](../decisions/rendering.md#adr-0046) defines text ownership; [ADR 0095](../decisions/singleton-services.md#adr-0095) preserves static OS access over its retained service.

## Native raster preferences

DisableEmbeddedBitmaps, ForceAutohinter and GenerateMIPMaps apply to installed matches, independent theme-source realization, FontVariation and owned automatic fallback. Preference changes retire active old data safely, notify outside locks and remain in typed copy/archive state. Actual flags select mono/color native strikes and automatic hinting; generated glyph images carry complete MIP chains. The text component records backend and native pixel verification limits.
