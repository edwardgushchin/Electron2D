# Local compute

Last updated: 2026-10-27

The public [RenderingDevice](../classes/RenderingDevice.md) compute slice is created by `RenderingServer.CreateLocalRenderingDevice()` under [ADR 0028](../decisions/rendering.md#adr-0028). It supplies a portable compute path for application algorithms without exposing native handles or adding domain-specific fluid API. [RDShaderSPIRV](../classes/RDShaderSPIRV.md) owns copied bytecode and compiler diagnostics; [RDUniform](../classes/RDUniform.md) describes borrowed resource bindings. [ShaderStage](../classes/RenderingDevice.ShaderStage.md) and [UniformType](../classes/RenderingDevice.UniformType.md) retain their applicable numeric identities.

## Lifetime and execution

A local device owns private RID identities and belongs to its creating thread. Buffer/shader/pipeline/set operations reject other-device or freed identities. Pipelines and sets borrow their shader; sets borrow buffers. Freeing a dependency invalidates borrowers. Caller disposal releases the entire device graph. Resource freeing finishes pending work; device disposal cancels unsubmitted commands and waits for submitted work.

Storage buffers are GPU allocations with copied uploads and explicit reads. Uniform buffers retain host bytes, copied into command data at each dispatch, so subsequent updates cannot rewrite an already recorded dispatch. One compute list is active at a time. Each dispatch ends its native pass, establishing a dependency before the next dispatch; explicit ComputeListAddBarrier preserves that guarantee. ComputeListEnd ends recording, Submit obtains a fence, and Sync waits/releases it. BufferGetData also completes pending writes. Its span overload reuses caller storage; its array overload intentionally creates an independent result.

The current compute profile accepts one static-workgroup `main` SPIR-V entry point, up to eight storage buffers, eight writable images, sixteen sampled images/samplers and four uniform buffers. Application descriptor set/binding numbers are remapped internally to native slots. Read-only storage annotations may be relaxed internally while preserving their shader instructions. Payload bounds/instruction structure, descriptor identities and unsupported resource kinds are validated before creation; this is not a full semantic verifier for arbitrary SPIR-V instructions. Copied push blocks and typed specialization execute as described below; fixed descriptor arrays execute below; native texture views retain their adapter. Single-pass color graphics and retained canvas/device texture sharing execute as described below. StorageBufferUsage.DispatchIndirect adds the executing indirect-command role; buffer device-address creation remains absent until the backend can expose that capability. Unsupported capability and native errors propagate; no algorithm is silently replayed on CPU after a failed GPU submission.

## GPU-directed chains and buffer transfers

`BufferCopy` validates both byte ranges and records storage-to-storage copies on the GPU timeline. It supports all combinations of storage and uniform buffers: a uniform source is snapshotted into the upload; a uniform destination is updated immediately, synchronizing a storage source first. Same-buffer ranges must be disjoint. Byte offsets and copy lengths need no four-byte alignment. `BufferClear` zeros only its range and requires a size divisible by four; its offset is a byte offset. Storage clear reuses the buffer's prepared upload transfer storage. Copy and clear require no active compute list, even for zero bytes. Empty operations still validate ownership, kind and ranges.

Create a command buffer with `StorageBufferCreate(bytes, usage: RenderingDevice.StorageBufferUsage.DispatchIndirect)`. `ComputeListDispatchIndirect(list, commands, offset)` reads three unsigned 32-bit group counts in X/Y/Z order from a four-byte-aligned offset. Prior GPU writes complete before those counts are consumed, including within the same list. Zero in any axis performs no work. The producer is responsible for group counts within device limits (the portable limit is 65535 per axis); the device does not read the counts back to validate them. Buffer identity, indirect role, twelve-byte capacity, alignment, list, pipeline and sets are validated before recording.

[RenderingDeviceTests.Transfers](../../tests/Electron2D.Tests/RenderingDeviceTests.Transfers.cs) is the executable public-API consumer: one shader calculates counts from storage data, a GPU copy moves the command, and another shader dispatches from it. It also executes producer/consumer dispatches in one list. The prepared update/clear/dispatch/copy/span-readback chain measures zero owner-thread managed bytes; this does not measure driver or native allocations.

## Queued readback

`BufferGetDataAsync(buffer, callback, offset, size)` records a request-time snapshot and later supplies an independent byte array to `Action<byte[]>`. Size zero means the remaining buffer, consistently with the synchronous API. The overload accepting `Memory<byte>` and `Action` writes caller-owned storage and reuses prepared queue entries and native download transfer buffers. Keep that memory valid, and do not read or write it until completion. Uniform bytes are copied at request time; GPU bytes are copied at the request's position among recorded commands. Later source mutations cannot replace either snapshot.

The local workflow is: end the compute list, enqueue one or more reads, call Submit, do other CPU work, then call Sync. Neither the request nor Submit invokes callbacks inline. The request does not wait for its own result; starting new recording may wait for the previous submission, as other device recording already does. These automatic waits collect bytes but defer user callbacks. Explicit Sync and nonempty synchronous storage reads deliver completed callbacks on the creating thread; storage reads copy their own result before delivery so callback readback cannot overwrite it. FreeRID completes pending work, removes the resource, then delivers callbacks. Host-only and empty batches also require Submit/Sync; unsubmitted requests remain pending.

Callbacks run once in FIFO order. A callback may issue reads, submit/synchronize, or free resources. Nested delivery is deferred to the outer delivery loop, so a new callback joins the tail after already completed callbacks. All completed callbacks are attempted even if one fails; AggregateException preserves their original exceptions after delivery. Device disposal cancels recorded, submitted and completed-but-undelivered requests, waits for submitted GPU work and releases transfer resources. Disposing inside a callback cancels the rest of that batch. An invalidated caller Memory fails completion and leaves its request available for disposal or retry; no successful callback is invented for a failed copy.

Queue/transfer preparation must cover the largest range and peak concurrent request count. The byte-array overload intentionally allocates an owned result. The Memory overload's prepared two-request small/large cycle measures zero owner-thread managed bytes; driver/native allocator measurements remain absent. [RenderingDeviceTests.Readback](../../tests/Electron2D.Tests/RenderingDeviceTests.Readback.cs) is a complete public-API consumer: two compute dispatches separated by snapshot requests, CPU work between submission and completion, retained results, reusable output storage and lifecycle/error/reentrancy checks.

## Device images and samplers

[Sampler texel coordinates](sampler-coordinates.md) add copied UnnormalizedUVW settings with native state/operation/view validation, including independent sampler bindings and GPU drawable consumers.

[Native border sampling](sampler-borders.md) adds six copied floating-point/integer border colors and independent normalized U/V ClampToBorder addressing through the pinned Vulkan sampler adapter. Integer/floating-point binding roles are validated before sampling.

`RDTextureFormat`, `RDTextureView` and `RDSamplerState` are caller-owned ElectronObject descriptions. Creation copies their values; later edits/disposal do not change existing RIDs. Ordinary images have one layer. TextureArray stores independent 2D layers. Each layer contains mip zero followed by progressively halved dimensions, clamped to one texel; block-compressed levels round up to complete format blocks. Supply exactly one tightly packed byte chain per layer, or omit initial data for zero encoded bytes. Updates replace one complete layer and require CanUpdate. Native mip offsets are separately aligned and never appear in public data. Sizes are checked with wide arithmetic before native allocation; oversized transfers fail before 32-bit native size arithmetic can wrap.

`TextureGetData` synchronizes and returns an independent array or fills an exact-sized caller Span. CPURead or CanCopyFrom is required. `TextureGetDataAsync(texture, layer, callback)` and its Memory overload use the same request-time/FIFO/owner-thread/completion/cancellation rules as buffer reads. They copy every mip and retain the allocation layout until completion. Prepared upload, dispatch and span-readback cycles, and prepared queued mip-chain reads, measure zero owner-thread managed bytes. Neither measurement covers driver/native allocation. TextureGetFormat returns an independent description; TextureIsValid rejects expired or foreign identities.

A SamplerWithTexture RDUniform contains sampler RID first, texture RID second. Image contains one writable texture RID and binds base mip/layer zero. Integer formats require matching signed/unsigned shader scalars and nearest filters without anisotropy; float/normalized formats require a float shader scalar. Declared storage formats must match exactly. Sampled arrays require an array shader interface. Separate image and sampler declarations execute through independent Texture/Sampler bindings as described below. GLSL combined and same-binding paired declarations consume SamplerWithTexture. Fixed descriptor arrays repeat those ordered identities per element, as described below. Sampler lifetimes are independent; freeing either borrowed identity invalidates the set.

Nearest/linear texel and mip filtering, repeat/mirrored repeat/clamp addressing, LOD limits and native anisotropy/bias settings connect to the native sampler. A nonzero bias on Metal is rejected because the native backend does not apply it. Normalized border addressing executes through the pinned Vulkan adapter; [mirror-clamp](sampler-mirror-clamp.md) executes when its optional native extension was negotiated and otherwise fails explicitly. Comparison sampling executes with matching depth images and shader operations. Border-color and unnormalized-coordinate configuration retains its complete native/shader prerequisite. No constant-return compatibility switches are exposed.

TextureIsFormatSupportedForUsage queries native support for the executing local profile. Color transfer/sampling/storage formats are mapped, including packed and BC/ASTC blocks; depth-target and comparison-sampling roles execute as described below; signed/unsigned R32 atomic storage and ordered framebuffer-input roles query their executing native profile. Storage requires simultaneous read/write format support. Unsupported formats cannot create false-success resources. The full encoded DataFormat vocabulary is a query domain, not a promise that every backend can allocate every format. Sampled component maps execute as described below. Native format reinterpretation fails explicitly; FormatOverride retains its shared native format/subresource-view prerequisite. Shareable format declarations other than the allocation format require that view adapter. Exact multisample targets and copied resolve roles execute as described below; discardable lifetime hints require per-frame last-use analysis. Storage arrays require a subresource-view adapter. Region copies and selected mip/layer clears execute on the GPU timeline; canvas TextureRD/TextureArrayRD require the renderer-sharing bridge. One-dimensional/volume/cube resources and the depth/RepeatW axes are excluded by the strict image boundary.

[RenderingDeviceTextureTests](../../tests/Electron2D.Tests/RenderingDeviceTextureTests.cs) is the complete public-API consumer. GLSL/HLSL combine sampling, float-image output and storage counters in one dispatch. Other fixtures exercise signed/unsigned images, sampled array layers, nearest/linear filters, repeat/mirror/clamp, mip blending and LOD clamps, odd and compressed mip-chain transfers, queued snapshots across mutation, cancellation, independent getters, resource invalidation and prepared allocation budgets.

## Sampled component views

`RDTextureView.SwizzleR/G/B/A` select R, G, B, A, Identity, Zero or One for each sampled output channel. `TextureCreate` captures them before returning; later description mutation/disposal changes no existing image. Constants are numeric zero/one for floating, signed and unsigned sampling. Format expansion, sRGB decoding and filtering precede mapping. Fetch maps its result; gather selects the requested mapped component. Depth comparison produces its comparison value before mapping the depth result's `(D, 0, 0, 1)` components. Size, level and LOD queries remain independent of the map.

The runtime derives shader/pipeline variants from original modules and currently bound images. Scalar/array combined samplers, independent image/filter pairs, opaque forwarding, compute and paired graphics use the same lowering. Sparse outputs, multiview, specialization and push data retain their existing contracts. Maps consume no application uniform slot, and public SPIR-V remains unchanged. Local pipeline caches retain up to 64 native variants; canvas source caches retain the current/previous frame working set with an inactive budget of 64 modules/32 MiB. Creation and new map combinations are cold work; prepared draws/dispatches reuse their variants.

Raw updates, copies, clears and readback preserve stored components. Storage-image descriptors, framebuffer inputs and framebuffer attachments require identity/channel-preserving maps. Alternate format reinterpretation and shared subresource lifetimes retain their separate native-view dependency. Initial sampled channel maps do not imply shared texture creation.

`TextureRD` and `TextureArrayRD` carry the captured map into command and named/global material images, paired canvas stages, normal/specular channels, lighting masks, alpha clipping, glyph composition, particle process shaders and writable-texture blits. Snapshots retain raw storage. Native shader metadata preserves unused declared sampler slots before storage buffers, including a glyph material that ignores incoming COLOR; omission previously shifted that buffer's native layout.

The selected slice was compared with model/canvas/screen matrix producers and alpha-to-one. Channel views unlock image consumers across existing backends without a new native ownership layer. Matrix producers need original command transform bases across retained/instanced/procedural paths. Alpha-to-one still needs a native state or sample-mask adapter preserving the original alpha-to-coverage result. These exact dependencies remain open.

The public-only consumer runs with `dotnet run --project tests/ShaderSamplers.Consumer/ShaderSamplers.Consumer.csproj -c Release -- swizzles-device` or `swizzles-canvas` (optional `hdr msaa`). Internal lowering/cache checks use `ELECTRON2D_TEST_TEXTURE_SWIZZLES=/absolute/compiled/Device dotnet run --project tests/Electron2D.Tests/Electron2D.Tests.csproj -c Release`. Supply the compiled consumer's `Shaders/Device` directory. Actual recorded checks, software/native profile and allocation limits belong to the slice's verification receipt; compilation alone establishes no rendered or hardware acceptance.

## Image region copies and clears

TextureCopy requires CanCopyFrom on the source and CanCopyTo on the destination. It copies raw encoded bytes without sampling or color conversion. Source/destination mip and layer indices select independent subresources; bounds use their actual mip dimensions. The retained Vector3 data-coordinate contract requires zero Z origins and unit depth. Positive finite coordinates/extents are projected to integral backend texels after validating the complete floating range. Compressed offsets must align to block dimensions; incomplete copied blocks must reach both source and destination edges. Same-subresource rectangles must be disjoint. A retained private scratch image implements those self copies with two ordered native copies, while different mip/layer copies use their independent subresources directly.

On Vulkan, formats with equal block geometry and texel/block byte size may reinterpret the copied bits. Other native backends currently require the same format until their compatible-view adapter is verified. Copies with different encoded footprints fail. No CPU readback or resampling is inserted into the GPU chain.

TextureClear requires CanCopyTo, positive bounded mip/layer ranges and no active compute list. A retained private color target clears each selected mip and copies it to selected layers, leaving every neighboring subresource intact. Public texture usage descriptions remain unchanged: a copy-only destination needs no public attachment role. Renderable float/normalized formats support color conversion and HDR; sRGB targets convert linear clear components. Normalized fixed-width channels retain native quantization precision, including half-unit rounding ties. Integer Vulkan clear lanes use the raw 32-bit component bits, matching the encoded clear-value contract; unsigned formats narrow by discarding upper bits, and signed narrow components must be representable or are rejected before recording. Integer clear conversion on other drivers requires a verified adapter. Encoded block formats cannot be native color targets and require a separate color-clear adapter; they are rejected explicitly.

Scratch storage is prepared once per texture at its full dimensions/mip capacity, shared by self-copy and clear, and released with the RID or device after pending work completes. Recording neither submits nor invokes queued callbacks; request-time snapshots before/after a clear or copy retain FIFO and independent contents. [RenderingDeviceTextureTransferTests](../../tests/Electron2D.Tests/RenderingDeviceTextureTransferTests.cs) executes clear → compute → region copy → Memory snapshot through public APIs. After sixteen warm cycles, thirty-two samples allocate zero owner-thread managed bytes; driver/native allocations are unmeasured. This fixture also verifies mip/layer selection, disjoint self copies, reinterpretation, normalized/HDR/sRGB/integer values, compressed edges, malformed ranges, role/ownership/list/lifetime errors and callback timing.

## Device images in canvas

`RenderingServer.GetRenderingDevice()` returns the same renderer-owned device for the active GPU session, or null outside a session/on the compatibility renderer. The existing compute/image API operates on this device on the scene owner thread. End lists before canvas submission. Rendering flushes recorded work after canvas authoring, before native drawing, and delivers queued snapshots before FramePostDraw. Submit, Sync and public device disposal belong to local devices. The renderer disposes its retained device before releasing the native backend.

`TextureRD` borrows one ordinary sampled image; `TextureArrayRD : TextureLayeredRD` borrows an independent array with at least two layers. Set `TextureRDRID` to a live sampled floating/normalized image RID of the retained device. Signed/unsigned integer images execute with matching native scalar pipelines. Direct canvas sampling requires nearest filtering without anisotropy and nearest mip selection; named integer material slots select a nearest sampler. Integer light/mask composition still requires scalar-aware composition shaders. Local-device identities reject even if their private native device is shared. Empty/freed/expired sources have zero live dimensions and no snapshot. Binding validation is atomic, including list, owner thread, role and lifetime checks; a published binding emits Changed. Drawing uses native storage directly, including ordinary/atlas/proxy textures, shader sampler defaults/overrides and layered proxies.

Explicit GetImage/GetLayerData snapshots require CPURead or CanCopyFrom. They synchronize pending work, copy every mip, and never own or modify the source. Directly representable formats keep encoded bytes; other sampled color formats use a temporary native floating RGBA target, including BGRA and signed normalized formats. PixelFormat/GetFormat reports that resulting Image format. Arrays validate the requested layer before reading. HasAlpha retains the ordinary device-resource false policy; HasMIPMaps/MIPMapCount reflect allocation. Archives reconstruct an unbound resource; duplication retains a borrowed live binding.

TextureRDCreate owns only its canvas wrapper; FreeRID never frees the underlying device image. Same-role replacement keeps the destination canvas RID, redirects source aliases and consumes only the replacement wrapper. Ordinary size overrides and path metadata remain logical. TextureGetRDTexture resolves ordinary/layered aliases and returns the borrowed source, including already-sRGB storage; a distinct sRGB view rejects until native format-view ownership exists. RenderingServer.TextureGetRDTexture exports actual renderer-managed ordinary uploads, independent arrays and completed viewport images to the retained device without CPU copying. Compatible authored updates keep the RID; replacing allocation, disposing the source, rebinding the viewport or retiring its target expires it. A viewport RID resolves the completed ping-pong image when each command is recorded. FreeRID releases only the borrowed wrapper; queued native operations retain the old allocation through completion. Device writes change GPU storage, while authored CPU snapshots remain unchanged; the next authored update overwrites device changes. Sampling, raw update/copy/read and supported storage roles reflect actual native allocation flags. Prepare changed uploads before starting a draw list. Empty storage, unrendered targets and the compatibility renderer return an empty RID. Distinct sRGB views still require native format-view ownership.

The executable native fixture is `ELECTRON2D_TEST_DEVICE_CANVAS=1 dotnet run --project tests/Electron2D.Tests/Electron2D.Tests.csproj -c Release`. Its canvas pixels, queued snapshots, GLSL/HLSL arrays, cold conversion, alias replacement and session/ownership guards exercise the actual GPU path. Compatibility availability is checked with ELECTRON2D_RENDER_BACKEND=compatibility. Foreign platforms and native allocator behavior require their own checks.

## Color graphics and compute integration

[RDVertexAttribute](../classes/RDVertexAttribute.md), [RDAttachmentFormat](../classes/RDAttachmentFormat.md), [RDPipelineRasterizationState](../classes/RDPipelineRasterizationState.md), [RDPipelineColorBlendState](../classes/RDPipelineColorBlendState.md) and its [attachment](../classes/RDPipelineColorBlendStateAttachment.md) are caller-owned ElectronObject descriptions. Device creation validates and copies their values. They retain no native handle. Blend attachment arrays copy their container and borrow elements until pipeline creation. Subsequent mutation/disposal of descriptions cannot change a created layout or pipeline.

RDShaderSPIRV owns either one compute module or both vertex/fragment modules. Both graphics stages must declare one main entry point. Reflected float32/int32/uint32 vertex locations and 32/64-bit interstage varyings are matched before native creation. Scalar width participates in matching; wide vectors with three or four components reserve two locations. Vertex attributes and fragment color outputs require the existing 32-bit native format adapters. Fragment outputs must fit the color attachment layout with matching scalar types. Logical descriptor set/binding numbers may be arbitrary; each stage is remapped separately. A descriptor shared across stages requires compatible resource kinds, image scalar/array roles and sufficient uniform capacity for both blocks. Native limits are sixteen sampled bindings, eight readonly storage images, eight storage buffers and four uniform blocks per stage. Storage images remain readonly; ordinary writable buffers follow the [graphics storage contract](#writable-graphics-storage-buffers). Uniform buffers shorter than reflected blocks reject before recording.

Vertex formats copy at most sixteen unique locations and contiguous buffer bindings, with consistent positive stride and frequency per binding. VertexBufferCreate and IndexBufferCreate zero unspecified bytes and copy the initial prefix. AsStorage allows compute and graphics storage production/consumption of those buffers. BufferUpdate/Copy/Clear and synchronous/queued readback apply to all buffer kinds. Vertex arrays borrow buffers with validated offsets/counts; instance capacities are validated against each direct draw. Index arrays borrow a positive index range. Index values and indirect command contents produced on the GPU remain the producer's responsibility; no synchronous validation readback is inserted. Strip restart requires its explicit buffer role and matching topology.

FramebufferCreate borrows up to eight distinct ordinary color render targets and at most one depth/stencil target, with at least one raster attachment, matching dimensions/sample counts and single-mip images with enough layers for the selected view count. Explicit layouts also borrow marked single-sample resolve destinations. FramebufferFormatCreate copies target formats and usage in input order; a framebuffer may validate against an existing format. Freeing an attachment invalidates the framebuffer. Pipelines borrow their shader and retain copied format, topology, rasterization and blend configuration. Shader free invalidates pipelines and sets; borrowers can still be freed explicitly. Native allocations remain device-owned.

One command list, compute or graphics, can be active. DrawListBegin selects full-target clear, load or discarded load per color target, with stored results. Clear values are required per target when clearing. Floating targets require finite components; integer targets use raw lane bits with the same verified Vulkan conversion as TextureClear. ## Fixed device descriptor arrays

RDUniform now describes fixed one-dimensional arrays of Sampler, Texture, SamplerWithTexture, Image, TextureBuffer, SamplerWithTextureBuffer, ImageBuffer and InputAttachment resources. Append one RID per element, or sampler/resource pairs per element for either combined role. The shader declares the exact count. A descriptor array remains distinct from a layered image. UniformBuffer and StorageBuffer each borrow one RID under the pinned executing contract.

The derived native module expands arrays to scalar slots and carries guarded selector values through calls, array parameters and control flow. Invalid indices read zero or suppress writes instead of wrapping into a neighboring binding. Implicit sampled operations evaluate candidates before selection to preserve derivatives; explicit loads and queries branch to the chosen resource. Separate image/sampler arrays reserve possible consumed element pairs; combined arrays correlate paired elements. These pairs share the sixteen native sampled slots. Images share eight native storage-image slots, and formatted buffers share eight storage-buffer slots with ordinary storage buffers. Capacity is checked before native creation. This may add shader work and is not a bindless throughput guarantee.

Set creation copies and validates every identity, role, format and fixed count. Retiring any element invalidates dependent sets. Recording uses the current set, validates resolved specialization counts and preserves existing comparison/integer filtering and active-attachment checks. An unresolved specialized count accepts bounded descriptions at shader-template creation; the actual pipeline enforces its resolved length. A pipeline override can repair an unusable default. Readonly graphics images keep their GPU snapshot behavior for every element. Input arrays consume consecutive logical input indices and exact framebuffer image/sample roles, including explicit multisample loads.

The packaged HLSL authoring path preserves descriptor-array shape through DXC; scalar modules retain the established import route. The packaged compiler rejects input_attachment_index on an array of SubpassInput. GLSL/SPIR-V input arrays execute; HLSL input-array source needs frontend attribute support. Runtime-sized descriptors require variable descriptor-count integration; nested descriptors require their multidimensional resource contract. Ordinary signed/unsigned R32 image and texel-buffer array atomics execute; float/wider atomic capabilities and layered image storage retain native prerequisites. Dynamic buffer offsets and remaining buffer roles keep UniformSetCreate Partial.

## Integer image atomics

Ordinary R32SINT and R32UINT storage images now execute compute integer atomics through scalar and fixed-array Image descriptors. Derived image-array helpers select the actual native image before creating an image texel pointer and executing the atomic instruction. Invalid descriptor indices return zero or suppress stores, preserving neighboring descriptors. The ordinary-image sample operand stays its original constant zero, as required by SPIR-V validation. Integer coordinates address the bound base mip/layer, using the existing Image role. Each dispatch closes its native compute pass; later dispatches, texture reads and canvas consumers observe the resulting GPU storage in order. Within one dispatch the algorithm owns synchronization: atomics prevent lost updates to the selected location, but do not establish arbitrary cross-workgroup barriers or ordering of unrelated memory. ## Shader binaries and deferred identities

RenderingDevice.ShaderCompileBinaryFromSPIRV packages copied successful compute or paired graphics modules and an optional diagnostic name. It uses the same module/capability/interface/lowering path as ShaderCreateFromSPIRV. Concrete native programs are created for validation and released before return; symbolic specialization templates retain their pipeline-time checks, including repairs of invalid defaults by valid overrides. No shader RID is published by packaging. ShaderCreateFromBytecode copies the stages and creates the ordinary program; specialization, sparse output remapping, descriptors, push bytes and lifetime remain on that shared path.

The engine-owned version-one container stores original SPIR-V, not driver pipeline-cache objects. Loading repeats reflection/lowering and native creation; it needs runtime shader translation libraries, but no HLSL/GLSL source frontend. There is no claim of faster native startup, hardware portability acceptance or external binary compatibility. Preserve original modules for future format changes. This is the common-intermediate adaptation under ADR 0028. The pinned Vulkan comparison container also retains SPIR-V, rather than an exported pipeline object; see [its implementation](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/drivers/vulkan/rendering_shader_container_vulkan.cpp).

Parsing checks the eight-byte magic, version, exact total length, SHA-256 payload digest, one compute or two ordered vertex/fragment stages, strict UTF-8 name up to 4096 encoded bytes, zero reserved flags, complete nonempty aligned modules of at most 16 MiB each and absence of trailing bytes. Length checks precede corresponding copies; ordinary module validation still runs after a valid digest. The digest detects corruption and does not authenticate untrusted content. The format is bounded, uncompressed and little-endian. Packaging and loading are cold owner-thread operations outside an active list; they neither submit prior commands nor deliver queued readbacks.

ShaderCreatePlaceholder reserves a real device-owned RID without a native program. It can be passed around and freed immediately. Pipeline factories, uniform-set creation and interface queries reject it until ShaderCreateFromBytecode successfully populates that same RID. A failed parse, validation or native creation leaves the placeholder untouched for retry. Foreign, freed, wrong-kind and already initialized identities reject; live shaders cannot be replaced through this operation. Borrowers retain the existing shader lifetime contract after initialization.

## Metal storage-buffer lengths

Compute pipelines with runtime storage-array length queries own a private
readonly byte-size table on Metal. Native translation inserts it after original
readonly buffers and shifts writable buffer attributes by one; original size
indices and all caller uniform slots remain intact. The table contains actual
bound resource byte ranges, with a separate cycled upload for each dispatch.
Direct, indirect, specialized and binary/placeholder pipelines share the same
owner and binding path. Ordinary Vulkan/DXIL programs and compute programs without
these queries allocate no size-table resources.

Retained particle steps, custom/built-in process programs and routed subemission
use this same mechanism. Headerless storage and oversized queue headers retain
their physical bounds checks. The adapter does not replace those checks with
authored frame/header capacities or copy numerical state to the CPU. Native
resource counts include the private readonly slot and reject capacity overflow
before creation. [ComputePipeline](../classes/ComputePipeline.md) owns both
transfers and pipeline/device lifetime.

The regression covers eight writable buffers and four caller uniforms, distinct
bindings across two dispatches in one submission, both particle source languages,
queue overflow, a physically headerless buffer and prepared dispatch allocation.
Six native Metal particle cohorts per RID pass on ARM64 and x64 at `025f1514f`,
including this direct-dispatch maximum-resource and rebinding regression; see
[platform receipts](../platform-verification.md#runtime-suite-receipts). Full native
suites, indirect/specialized/binary variants and physical performance retain
separate acceptance gates.

## Native screen drawing

The retained RenderingDevice shares native GPU presentation with RenderingServer. ScreenGetWidth/Height query native client pixels, rather than monitor dimensions or logical window units. ScreenGetFramebufferFormat returns a reusable format for the actual native color encoding, with one color and one sample. DrawListBeginForScreen defaults to opaque black, accepts explicit transparent clears and reuses all applicable existing graphics-list operations. InvalidID (-1) is returned by all four methods on local devices. Borrowed renderer devices retain their usual owner-thread and disposal rules.

Screen lists finish before rendering, submit in device order before native canvas drawing, and replace the selected window's final presentation through a GPU-only copy. They neither change canvas viewport images nor publish a second swapchain frame. Multiple completed screen lists target the latest image for that window; recording after FramePostDraw remains pending for the following frame. ForceDraw(false) executes device and canvas work without consuming that pending presentation. An unavailable or minimized swapchain retains the pending screen image and rendering invalidation until a native image is acquired and submitted. A later frame with no screen list returns to ordinary canvas output. A pending screen can present even when that window's canvas viewport update is disabled.

Per-window attachments use native pixel dimensions and format. Resize rebuilds only incompatible private attachments; format IDs and matching pipelines remain reusable. Native child retirement frees its attachments, expires the window ID and rejects active-list mutation before any window state changes. A reopened child gets a fresh ID. Renderer shutdown cancels incomplete passes and owns all remaining allocations. Main-window hide retains the last known native format and pending screen image; the existing Wayland Vulkan restriction on remapping a previously presented root surface remains explicit. Child hide retires its native identity.

The internal RenderingDeviceScreenTests probe reads the exact final GPU presentation image used for the swapchain and separately reads the unchanged viewport canvas. Compilation alone does not establish screen execution. Software-driver pixel, lifecycle, allocation and platform evidence is recorded with the completed verification below.
