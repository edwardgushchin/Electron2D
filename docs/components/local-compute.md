# Local compute

Last updated: 2026-10-11

The public [RenderingDevice](../classes/RenderingDevice.md) compute slice is created by `RenderingServer.CreateLocalRenderingDevice()` under [ADR 0028](../decisions/rendering.md#adr-0028). It supplies a portable compute path for application algorithms without exposing native handles or adding domain-specific fluid API. [RDShaderSPIRV](../classes/RDShaderSPIRV.md) owns copied bytecode and compiler diagnostics; [RDUniform](../classes/RDUniform.md) describes borrowed resource bindings. [ShaderStage](../classes/RenderingDevice.ShaderStage.md) and [UniformType](../classes/RenderingDevice.UniformType.md) retain their applicable numeric identities.

## Lifetime and execution

A local device owns private RID identities and belongs to its creating thread. Buffer/shader/pipeline/set operations reject other-device or freed identities. Pipelines and sets borrow their shader; sets borrow buffers. Freeing a dependency invalidates borrowers. Caller disposal releases the entire device graph. Resource freeing finishes pending work; device disposal cancels unsubmitted commands and waits for submitted work.

Storage buffers are GPU allocations with copied uploads and explicit reads. Uniform buffers retain host bytes, copied into command data at each dispatch, so subsequent updates cannot rewrite an already recorded dispatch. One compute list is active at a time. Each dispatch ends its native pass, establishing a dependency before the next dispatch; explicit ComputeListAddBarrier preserves that guarantee. ComputeListEnd ends recording, Submit obtains a fence, and Sync waits/releases it. BufferGetData also completes pending writes. Its span overload reuses caller storage; its array overload intentionally creates an independent result.

The current compute profile accepts one static-workgroup `main` SPIR-V entry point, up to eight storage buffers, eight writable images, sixteen sampled images/samplers and four uniform buffers. Application descriptor set/binding numbers are remapped internally to native slots. Read-only storage annotations may be relaxed internally while preserving their shader instructions. Payload bounds/instruction structure, descriptor identities and unsupported resource kinds are validated before creation; this is not a full semantic verifier for arbitrary SPIR-V instructions. Push constants, descriptor arrays, specialization constants and native texture views remain separate gaps. Single-pass color graphics and retained canvas/device texture sharing execute as described below. StorageBufferUsage.DispatchIndirect adds the executing indirect-command role; buffer device-address creation remains absent until the backend can expose that capability. Unsupported capability and native errors propagate; no algorithm is silently replayed on CPU after a failed GPU submission.

## GPU-directed chains and buffer transfers

`BufferCopy` validates both byte ranges and records storage-to-storage copies on the GPU timeline. It supports all combinations of storage and uniform buffers: a uniform source is snapshotted into the upload; a uniform destination is updated immediately, synchronizing a storage source first. Same-buffer ranges must be disjoint. Byte offsets and copy lengths need no four-byte alignment. `BufferClear` zeros only its range and requires a size divisible by four; its offset is a byte offset. Storage clear reuses the buffer's prepared upload transfer storage. Copy and clear require no active compute list, even for zero bytes. Empty operations still validate ownership, kind and ranges.

Create a command buffer with `StorageBufferCreate(bytes, usage: RenderingDevice.StorageBufferUsage.DispatchIndirect)`. `ComputeListDispatchIndirect(list, commands, offset)` reads three unsigned 32-bit group counts in X/Y/Z order from a four-byte-aligned offset. Prior GPU writes complete before those counts are consumed, including within the same list. Zero in any axis performs no work. The producer is responsible for group counts within device limits (the portable limit is 65535 per axis); the device does not read the counts back to validate them. Buffer identity, indirect role, twelve-byte capacity, alignment, list, pipeline and sets are validated before recording.

[RenderingDeviceTests.Transfers](../../tests/Electron2D.Tests/RenderingDeviceTests.Transfers.cs) is the executable public-API consumer: one shader calculates counts from storage data, a GPU copy moves the command, and another shader dispatches from it. It also executes producer/consumer dispatches in one list. The prepared update/clear/dispatch/copy/span-readback chain measures zero owner-thread managed bytes; this does not measure driver or native allocations.

## Queued readback

`BufferGetDataAsync(buffer, callback, offset, size)` records a request-time snapshot and later supplies an independent byte array to `Action<byte[]>`. Size zero means the remaining buffer, consistently with the synchronous API. The overload accepting `Memory<byte>` and `Action` writes caller-owned storage and reuses prepared queue entries and native download transfer buffers. Keep that memory valid, and do not read or write it until completion. Uniform bytes are copied at request time; GPU bytes are copied at the request's position among recorded commands. Later source mutations cannot replace either snapshot.

The local workflow is: end the compute list, enqueue one or more reads, call Submit, do other CPU work, then call Sync. Neither the request nor Submit invokes callbacks inline. The request does not wait for its own result; starting new recording may wait for the previous submission, as other device recording already does. These automatic waits collect bytes but defer user callbacks. Explicit Sync and nonempty synchronous storage reads deliver completed callbacks on the creating thread; storage reads copy their own result before delivery so callback readback cannot overwrite it. FreeRID completes pending work, removes the resource, then delivers callbacks. Host-only and empty batches also require Submit/Sync; unsubmitted requests remain pending.

Callbacks run once in FIFO order. A callback may issue reads, submit/synchronize, or free resources. Nested delivery is deferred to the outer delivery loop, so a new callback joins the tail after already completed callbacks. All completed callbacks are attempted even if one fails; AggregateException preserves their original exceptions after delivery. Device disposal cancels recorded, submitted and completed-but-undelivered requests, waits for submitted GPU work and releases transfer resources. Disposing inside a callback cancels the rest of that batch. An invalidated caller Memory fails completion and leaves its request available for disposal or retry; no successful callback is invented for a failed copy.

Queue/transfer preparation must cover the largest range and peak concurrent request count. The byte-array overload intentionally allocates an owned result. The Memory overload's prepared two-request small/large cycle measures zero owner-thread managed bytes; driver/native allocator measurements remain absent. [RenderingDeviceTests.Readback](../../tests/Electron2D.Tests/RenderingDeviceTests.Readback.cs) is a complete public-API consumer: two compute dispatches separated by snapshot requests, CPU work between submission and completion, retained results, reusable output storage and lifecycle/error/reentrancy checks.

## Device images and samplers

`RDTextureFormat`, `RDTextureView` and `RDSamplerState` are caller-owned ElectronObject descriptions. Creation copies their values; later edits/disposal do not change existing RIDs. Ordinary images have one layer. TextureArray stores independent 2D layers. Each layer contains mip zero followed by progressively halved dimensions, clamped to one texel; block-compressed levels round up to complete format blocks. Supply exactly one tightly packed byte chain per layer, or omit initial data for zero encoded bytes. Updates replace one complete layer and require CanUpdate. Native mip offsets are separately aligned and never appear in public data. Sizes are checked with wide arithmetic before native allocation; oversized transfers fail before 32-bit native size arithmetic can wrap.

`TextureGetData` synchronizes and returns an independent array or fills an exact-sized caller Span. CPURead or CanCopyFrom is required. `TextureGetDataAsync(texture, layer, callback)` and its Memory overload use the same request-time/FIFO/owner-thread/completion/cancellation rules as buffer reads. They copy every mip and retain the allocation layout until completion. Prepared upload, dispatch and span-readback cycles, and prepared queued mip-chain reads, measure zero owner-thread managed bytes. Neither measurement covers driver/native allocation. TextureGetFormat returns an independent description; TextureIsValid rejects expired or foreign identities.

A SamplerWithTexture RDUniform contains sampler RID first, texture RID second. Image contains one writable texture RID and binds base mip/layer zero. Integer formats require matching signed/unsigned shader scalars and nearest filters without anisotropy; float/normalized formats require a float shader scalar. Declared storage formats must match exactly. Sampled arrays require an array shader interface. The HLSL separate image and sampler must use the same original set/binding; orphan or descriptor-array samplers fail before native pipeline creation. GLSL combined and HLSL paired declarations consume the same public descriptor. Sampler lifetimes are independent; freeing either borrowed identity invalidates the set.

Nearest/linear texel and mip filtering, repeat/mirrored repeat/clamp addressing, LOD limits and native anisotropy/bias settings connect to the native sampler. A nonzero bias on Metal is rejected because the native backend does not apply it. Border/mirror-clamp need a shader adapter and fail explicitly. Comparison, border-color and unnormalized-coordinate configuration is omitted until its complete executable adapter exists. No constant-return compatibility switches are exposed.

TextureIsFormatSupportedForUsage queries native support for the executing local profile. Color transfer/sampling/storage formats are mapped, including packed and BC/ASTC blocks; depth-target and comparison-sampling roles execute as described below; atomic/subpass roles return false. Storage requires simultaneous read/write format support. Unsupported formats cannot create false-success resources. The full encoded DataFormat vocabulary is a query domain, not a promise that every backend can allocate every format. Native format reinterpretation and nonidentity view swizzles fail explicitly; their descriptor rows remain Partial. Shareable format declarations other than the allocation format require that view adapter. Exact multisample targets and copied resolve roles execute as described below; discardable lifetime hints require per-frame last-use analysis. Storage arrays require a subresource-view adapter. Region copies and selected mip/layer clears execute on the GPU timeline; canvas TextureRD/TextureArrayRD require the renderer-sharing bridge. One-dimensional/volume/cube resources and the depth/RepeatW axes are excluded by the strict image boundary.

[RenderingDeviceTextureTests](../../tests/Electron2D.Tests/RenderingDeviceTextureTests.cs) is the complete public-API consumer. GLSL/HLSL combine sampling, float-image output and storage counters in one dispatch. Other fixtures exercise signed/unsigned images, sampled array layers, nearest/linear filters, repeat/mirror/clamp, mip blending and LOD clamps, odd and compressed mip-chain transfers, queued snapshots across mutation, cancellation, independent getters, resource invalidation and prepared allocation budgets.

## Image region copies and clears

TextureCopy requires CanCopyFrom on the source and CanCopyTo on the destination. It copies raw encoded bytes without sampling or color conversion. Source/destination mip and layer indices select independent subresources; bounds use their actual mip dimensions. The retained Vector3 data-coordinate contract requires zero Z origins and unit depth. Positive finite coordinates/extents are projected to integral backend texels after validating the complete floating range. Compressed offsets must align to block dimensions; incomplete copied blocks must reach both source and destination edges. Same-subresource rectangles must be disjoint. A retained private scratch image implements those self copies with two ordered native copies, while different mip/layer copies use their independent subresources directly.

On Vulkan, formats with equal block geometry and texel/block byte size may reinterpret the copied bits. Other native backends currently require the same format until their compatible-view adapter is verified. Copies with different encoded footprints fail. No CPU readback or resampling is inserted into the GPU chain.

TextureClear requires CanCopyTo, positive bounded mip/layer ranges and no active compute list. A retained private color target clears each selected mip and copies it to selected layers, leaving every neighboring subresource intact. Public texture usage descriptions remain unchanged: a copy-only destination needs no public attachment role. Renderable float/normalized formats support color conversion and HDR; sRGB targets convert linear clear components. Normalized fixed-width channels retain native quantization precision, including half-unit rounding ties. Integer Vulkan clear lanes use the raw 32-bit component bits, matching the encoded clear-value contract; unsigned formats narrow by discarding upper bits, and signed narrow components must be representable or are rejected before recording. Integer clear conversion on other drivers requires a verified adapter. Encoded block formats cannot be native color targets and require a separate color-clear adapter; they are rejected explicitly.

Scratch storage is prepared once per texture at its full dimensions/mip capacity, shared by self-copy and clear, and released with the RID or device after pending work completes. Recording neither submits nor invokes queued callbacks; request-time snapshots before/after a clear or copy retain FIFO and independent contents. [RenderingDeviceTextureTransferTests](../../tests/Electron2D.Tests/RenderingDeviceTextureTransferTests.cs) executes clear → compute → region copy → Memory snapshot through public APIs. After sixteen warm cycles, thirty-two samples allocate zero owner-thread managed bytes; driver/native allocations are unmeasured. This fixture also verifies mip/layer selection, disjoint self copies, reinterpretation, normalized/HDR/sRGB/integer values, compressed edges, malformed ranges, role/ownership/list/lifetime errors and callback timing.

## Device images in canvas

`RenderingServer.GetRenderingDevice()` returns the same renderer-owned device for the active GPU session, or null outside a session/on the compatibility renderer. The existing compute/image API operates on this device on the scene owner thread. End lists before canvas submission. Rendering flushes recorded work after canvas authoring, before native drawing, and delivers queued snapshots before FramePostDraw. Submit, Sync and public device disposal belong to local devices. The renderer disposes its retained device before releasing the native backend.

`TextureRD` borrows one ordinary sampled image; `TextureArrayRD : TextureLayeredRD` borrows an independent array with at least two layers. Set `TextureRDRID` to a live sampled floating/normalized image RID of the retained device. Signed/unsigned integer images execute with matching native scalar pipelines. Direct canvas sampling requires nearest filtering without anisotropy and nearest mip selection; named integer material slots select a nearest sampler. Integer light/mask composition still requires scalar-aware composition shaders. Local-device identities reject even if their private native device is shared. Empty/freed/expired sources have zero live dimensions and no snapshot. Binding validation is atomic, including list, owner thread, role and lifetime checks; a published binding emits Changed. Drawing uses native storage directly, including ordinary/atlas/proxy textures, shader sampler defaults/overrides and layered proxies.

Explicit GetImage/GetLayerData snapshots require CPURead or CanCopyFrom. They synchronize pending work, copy every mip, and never own or modify the source. Directly representable formats keep encoded bytes; other sampled color formats use a temporary native floating RGBA target, including BGRA and signed normalized formats. PixelFormat/GetFormat reports that resulting Image format. Arrays validate the requested layer before reading. HasAlpha retains the ordinary device-resource false policy; HasMipmaps/MipmapCount reflect allocation. Archives reconstruct an unbound resource; duplication retains a borrowed live binding.

TextureRDCreate owns only its canvas wrapper; FreeRID never frees the underlying device image. Same-role replacement keeps the destination canvas RID, redirects source aliases and consumes only the replacement wrapper. Ordinary size overrides and path metadata remain logical. TextureGetRDTexture resolves ordinary/layered aliases and returns the borrowed source, including already-sRGB storage; a distinct sRGB view rejects until native format-view ownership exists. Renderer-managed image uploads and viewport targets have no exported device RID until cache invalidation, borrowed native allocation lifetime and mutable device roles are integrated.

The executable native fixture is `ELECTRON2D_TEST_DEVICE_CANVAS=1 dotnet run --project tests/Electron2D.Tests/Electron2D.Tests.csproj -c Release`. Its canvas pixels, queued snapshots, GLSL/HLSL arrays, cold conversion, alias replacement and session/ownership guards exercise the actual GPU path. Compatibility availability is checked with ELECTRON2D_RENDER_BACKEND=compatibility. Foreign platforms and native allocator behavior require their own checks.

## Build and example

Application compute shaders can be declared as `Electron2DComputeShader` items and built with [ComputeShaders.targets](../../tools/shaders/ComputeShaders.targets). GLSL/HLSL compile through the existing pinned host toolchain, are validated during the build, and are embedded from `obj/compute` into the consumer assembly. Generated bytecode is not tracked. Shipped executables load compiled resources and need no compiler. The [water playground](water-playground.md) consumes only this public API, PhysicsServer and ordinary rendering/input APIs; its CPU fluid implementation remains application code.

## Integer canvas sampling checkpoint

The follow-up candidate comparison chose native integer images over GPU particles (still requiring compute-buffer to canvas-instance storage plus ParticleProcessMaterial execution) and programmable light receivers (requiring cross-language lighting composition). Integer images unlock compute-produced discrete simulation fields and typed material samplers on the existing retained device/backend.

Shader reflection preserves float32/signed32/unsigned32 sampled scalar types together with ordinary/array roles. Defaults, typed setters, RID material adapters, draw-time copies and reload migration all validate the pair. Resource type alone does not authorize a scalar mismatch. Built-in unlit canvas has signed/unsigned native fragment programs; direct/atlas/proxy storage stays on GPU. Linear/anisotropic direct filtering rejects before submission; integer nearest sampling always selects nearest mip filtering independently of the global float texture setting. Named material integer samplers use nearest filtering. Source rebinding, proxy retargeting, expired storage and reload are revalidated.

Integer GetImage/GetLayerData snapshots decode 8/16/32-bit lane signedness into raw-valued Image.Rgbaf, preserving negative values and every mip. Missing channels are zero and missing alpha is one. Float32 cannot represent every 32-bit integer exactly; TextureGetData retains exact bits. HLSL integer resources use Load with paired vk::combinedImageSampler annotations, which also preserve the native descriptor interface when SamplerState is optimized away; the pinned DXC warns that the SamplerState annotation is ignored but requires the pair. Runtime/import reflection also supports samplerless fetch through the retained SPIRV-Cross dummy-sampler analysis API without exposing a public sampler switch.

IntegerCanvasTests verifies actual Linux/Vulkan direct signed/unsigned/atlas/proxy pixels, GLSL typed samplers and pinned-DXC HLSL Load, mixed ordinary/array descriptor signedness, atomic setter rejection and reload migration, raw snapshots/32-bit bit readback and zero owner-thread managed bytes across 32 active frames after 24 warmup. Built-in lighting, normal/specular channels, point-light masks and alpha clipping support raw signed/unsigned values. [The lighting checkpoint](#integer-lighting-checkpoint) verifies their connected native output. Programmable light receivers now execute automatic SPIR-V composition; see [the material checkpoint](shader-materials.md#automatic-scene-lighting). Other platforms, native allocations and owner acceptance remain unverified.

## Color graphics and compute integration

[RDVertexAttribute](../classes/RDVertexAttribute.md), [RDAttachmentFormat](../classes/RDAttachmentFormat.md), [RDPipelineRasterizationState](../classes/RDPipelineRasterizationState.md), [RDPipelineColorBlendState](../classes/RDPipelineColorBlendState.md) and its [attachment](../classes/RDPipelineColorBlendStateAttachment.md) are caller-owned ElectronObject descriptions. Device creation validates and copies their values. They retain no native handle. Blend attachment arrays copy their container and borrow elements until pipeline creation. Subsequent mutation/disposal of descriptions cannot change a created layout or pipeline.

RDShaderSPIRV owns either one compute module or both vertex/fragment modules. Both graphics stages must declare one main entry point. Reflected float32/int32/uint32 vertex locations and fragment varyings are matched before native creation. Fragment outputs must fit the color attachment layout with matching scalar types. Logical descriptor set/binding numbers may be arbitrary; each stage is remapped separately. A descriptor shared across stages requires compatible resource kinds, image scalar/array roles and sufficient uniform capacity for both blocks. Native limits are sixteen sampled bindings, eight readonly storage images, eight readonly storage buffers and four uniform blocks per stage. Graphics storage declarations must be readonly throughout their block. Uniform buffers shorter than reflected blocks reject before recording.

Vertex formats copy at most sixteen unique locations and contiguous buffer bindings, with consistent positive stride and frequency per binding. VertexBufferCreate and IndexBufferCreate zero unspecified bytes and copy the initial prefix. AsStorage allows compute production and readonly graphics storage consumption of those buffers. BufferUpdate/Copy/Clear and synchronous/queued readback apply to all buffer kinds. Vertex arrays borrow buffers with validated offsets/counts; instance capacities are validated against each direct draw. Index arrays borrow a positive index range. Index values and indirect command contents produced on the GPU remain the producer's responsibility; no synchronous validation readback is inserted. Strip restart requires its explicit buffer role and matching topology.

FramebufferCreate borrows up to eight distinct ordinary color render targets and at most one depth/stencil target, with at least one raster attachment, matching dimensions/sample counts and single-layer/single-mip images. Explicit layouts also borrow marked single-sample resolve destinations. FramebufferFormatCreate copies target formats and usage in input order; a framebuffer may validate against an existing format. Freeing an attachment invalidates the framebuffer. Pipelines borrow their shader and retain copied format, topology, rasterization and blend configuration. Shader free invalidates pipelines and sets; borrowers can still be freed explicitly. Native allocations remain device-owned.

One command list, compute or graphics, can be active. DrawListBegin selects full-target clear, load or discarded load per color target, with stored results. Clear values are required per target when clearing. Floating targets require finite components; integer targets use raw lane bits with the same verified Vulkan conversion as TextureClear. The optional region sets viewport and initial scissor. DrawListEnableScissor intersects a finite nonnegative rectangle with framebuffer bounds; zero clips every pixel. DisableScissor restores the full framebuffer. Pipeline binding validates its attachment formats. Blend constants change only with PipelineDynamicStateFlags.BlendConstants. DrawListDraw executes procedural, vertex-array or indexed geometry with positive instance count. DrawListBindVertexBuffersFormat copies its argument arrays for convenience; prepared VertexArray identities avoid that allocation. Reading an active attachment through sampled or storage descriptors rejects feedback. DrawListEnd closes the native pass, making output available to subsequent compute, transfer, graphics and retained canvas consumers.

DrawListDrawIndirect uses a storage buffer created with DispatchIndirect usage. Nonindexed commands are four uint32 words: vertex count, instance count, first vertex and first instance. Indexed commands add the signed int32 vertex offset before first instance. Offset and stride are aligned to four bytes; zero stride selects sixteen/twenty tightly packed bytes. Strided commands issue ordered draws without reading their contents to the CPU. Producers must keep vertex/index/instance ranges in bounds and use zero first vertex/instance when relying on portable built-in identifiers.

Application builds can import tools/shaders/DeviceShaders.targets and declare Electron2DDeviceShader items whose filenames end in .vert.glsl, .frag.glsl, .vert.hlsl or .frag.hlsl. The pinned frontend and independent SPIR-V validator produce embedded Electron2D.Device modules at build time. Games ship bytecode and backend libraries, not source compilers. This profile accepts low-level device interfaces; canvas ShaderImport retains its separate validated material interface.

RenderingDeviceGraphicsTests exercises GLSL/HLSL indexed instances, stage-shared uniform/storage descriptors, sampled textures, copied state, explicit framebuffer formats, error/lifetime guards, graphics-buffer transfer/queued readback, procedural mixing/scissor, indexed indirect draws and a compute-generated strided indirect chain. It checks local target pixels and a real Window canvas consuming the retained device texture. After sixteen warmups, thirty-two draw/indirect/span-readback cycles per language require zero owner-thread managed bytes. This does not measure native/driver allocations or foreign platforms.

Depth/stencil attachment allocation and state, MSAA allocation/resolve, input attachments/subpasses and multiview remain prerequisite slices. Attachmentless passes need native raster-discard/pass support. Push constants need SPIR-V-to-uniform-slot translation; specialization needs executable module constant rewriting. Logic operations, separate constant-alpha color factors, dual-source blending, wide lines and extra dynamic states need backend adapters or capabilities. Those fields and classes are absent until executable; no ignored switches are exposed.

## Depth/stencil graphics and sampling

[RDPipelineDepthStencilState](../classes/RDPipelineDepthStencilState.md) copies depth comparisons/writes and two-sided eight-bit stencil operations. DepthBiasEnabled, DepthBiasConstantFactor, DepthBiasSlopeFactor and DepthBiasClamp execute in [RDPipelineRasterizationState](../classes/RDPipelineRasterizationState.md). Native capability errors propagate. A fragment writes depth only when the depth test is enabled and passes. Depth-only framebuffers are allowed; shaders then have no color outputs and blend attachment arrays are empty.

TextureIsFormatSupportedForUsage queries D16UNORM, X8D24UNORMPACK32, D32SFLOAT, D24UNORMS8UINT and D32SFLOATS8UINT with DepthStencilAttachment and optional Sampling roles. No unsupported format is substituted. D16/S8 has no selected native representation. TextureCreate accepts empty depth data, initializes every layer/mip to zero depth/stencil through native passes, and supports up to 256 depth layers due to native layer selection. Raw depth/stencil upload, readback and rectangular copies retain the explicit aspect-transfer dependency and their usage queries return false. Canvas sampling may use ordinary depth descriptors; CPU snapshots require a depth-to-color conversion first.

Framebuffer attachment order includes depth while shader output locations, blend descriptions and clear color arrays index only color attachments in their relative order. DrawListBegin independently clears, loads or discards available depth/stencil aspects; default clear depth is one and stencil zero. ClearAll/IgnoreAll apply to all available aspects. Clears affect whole attachments even with a restricted draw region. Store preserves both aspects for later passes. Active depth sampling rejects feedback alongside color/storage feedback. Freeing depth invalidates borrowing framebuffers.

StencilOperation.Keep is numeric zero; pinned front/back operation defaults are Zero (numeric one). Compare/write masks use the low eight bits of signed int values, including -1 as all bits. References of visible faces must fit zero through 255. Front/back compare and fail/depth-fail/pass operations are independent. Native masks/reference are shared, so unculled faces require equal effective masks/reference; differing values fail before creation. Front culling uses back masks/reference and vice versa. Depth bounds remain absent until a native bounds-test adapter exists; no stored no-op switches are exposed.

RDSamplerState.EnableCompare and CompareOp copy into native samplers. GLSL sampler2DShadow/sampler2DArrayShadow and paired HLSL Texture2D/Texture2DArray with SamplerComparisonState preserve logical sets/bindings in graphics and compute; shader reflection records the depth-comparison role across stages. Comparison descriptors require enabled comparison samplers and depth images; mismatches reject at UniformSetCreate. Regular samplers can sample depth normally, including arrays and mip levels.

The public-API RenderingDeviceDepthTests checks GLSL/HLSL native depth occlusion, all compare operators, stencil pass/fail/depth-fail operations for both windings and every stencil operation including saturation/wrap, different front/back operations, mask preservation, copied sampler/pipeline state, positive/negative static depth bias and clamp, format/role/lifetime errors, cross-stage comparison-role mismatches, depth-only passes, arrays/mip initialization, compute comparison sampling of both array layers and feedback. A real Window consumes the depth-tested color through TextureRD and verifies rendered canvas pixels. Prepared recording and caller-owned color readback require zero owner-thread managed bytes after sixteen warmups over thirty-two cycles per language. Linux/Vulkan is the exercised platform; native allocations and other backends are not measured.

## Multisample graphics and resolve

[RDPipelineMultisampleState](../classes/RDPipelineMultisampleState.md) copies SampleCount and EnableAlphaToCoverage. [RDFramebufferPass](../classes/RDFramebufferPass.md) copies color indices in shader output order, an optional depth index and a resolve destination per color slot. AttachmentUnused=-1 disables a depth attachment or individual resolve slot. Configuration arrays copy both writes and reads. Created layouts/pipelines retain copied values and are unaffected by later description mutation/disposal.

RDTextureFormat.Samples selects an exact allocation count. The device queries two/four/eight before native creation and rejects unavailable counts instead of accepting native fallback; sixteen/thirty-two/sixty-four remain the numeric selection vocabulary and reject without their backend adapter. Multisample images require ordinary one-layer/one-mip color or depth targets and empty data. Native clears initialize all samples. Sampling/storage multisample descriptors, raw CPU upload/readback and raw rectangular sample copies retain separate adapters; resolve colors to ordinary images before using these consumers. CanCopyTo enables native color TextureClear; CanCopyFrom enables explicit color resolve. Depth clears use draw passes; depth resolves and copy permissions remain unavailable.

IsResolveBuffer marks an ordinary single-sample color destination. Explicit framebuffer descriptions may borrow up to eight render colors, one matching-sample depth image and eight matching-format single-sample resolve colors. All images have equal dimensions, distinct RIDs and one executing role. Every render target has the same exact sample count. Resolve indices follow color slots, independent of raw image order. FramebufferCreateMultipass/FramebufferFormatCreateMultipass currently accept exactly one pass; input/preserve attachments and additional subpasses require native shader/lifetime adapters. Implicit FramebufferCreate remains render-only unless validated with an explicit copied layout. Shader output/blend/clear arrays address only color render slots.

DrawListEnd automatically resolves selected color slots while preserving source samples. TextureResolveMultisample performs a full matching color resolve after a completed pass, with source CanCopyFrom and destination CanCopyTo usage. It preserves source content and does not submit or read to CPU. Marked resolve images cannot be used as render targets; later sampling, transfers and canvas use the single-sample result. All borrowed render/resolve images participate in feedback and lifetime validation. Freeing any invalidates the framebuffer. Pipeline binding compares raster color/depth formats and sample count, so resolve-only layout differences do not imply a different native pipeline.

IsDiscardable remains dependency-blocked: per-frame last-use analysis must preserve data needed by later passes before eliminating stores. SampleMask/EnableMask are reserved native fields; sample masks, alpha-to-one and sample shading stay absent until their executing adapters exist. No configuration is stored as a no-op.

RenderingDeviceMultisampleTests checks GLSL/HLSL native fractional triangle edges against a binary single-sample control, alpha-to-coverage, copied state, stored multisample depth across color and depth-only passes, stored D24/S8 and D32/S8 stencil where supported, explicit/automatic resolves, multiple reordered resolve slots, other exact counts where supported, clear/readback/canvas integration, role/index/format/sample/lifetime guards and feedback. After blocking collection and sixteen warmups, thirty-two prepared draw/automatic resolve/explicit resolve/readback cycles per language require zero owner-thread managed bytes. Linux/Vulkan is exercised; native/driver allocations and foreign platforms remain unverified.
