# Item list input

Last updated: 2026-10-25

[ItemList](../classes/ItemList.md) consumes the existing focused GUI and native committed-text routes. It owns selection/navigation/search state; [natural layout](item-list-layout.md) supplies current grid geometry and both scroll pages. No backend API is exposed to game consumers.

## Navigation and search

Single-mode navigation selects; Multi and Toggle navigation only move Current. Vertical arrows skip disabled/unselectable items in the same actual grid column. Horizontal arrows stay within one logical row, including RTL. Page movement tries exactly four, three, two and one actual rows, without searching past the chosen distance. Boundary arrows that attempted an unavailable eligible item consume the action. The context-menu action requires AllowRMBSelect and an enabled Current; its ItemClicked position is the public content rectangle origin. Accept activates enabled items regardless of selectability. Programmatic selection is silent.

Shift keyboard ranges retain an anchor until Shift release or model restructuring. Their vertical step uses configured MaxColumns, even when wrapping fits fewer columns; zero means a zero configured range step. Mouse Shift ranges instead extend the current-to-clicked interval while preserving other selections and skipping ineligible entries. Keyboard ranges report requested selection in index order: a true MultiSelected request can refer to a disabled/unselectable item whose selected flag remains false. This source contract differs from ordinary toggling; inspect IsSelected when the actual flag is needed.

Unicode keys and the focused native OnTextInput commit use the same retained UTF-16 prefix. Repeated single scalars cycle; later scalars extend the prefix. The configured incremental-search interval expires it. Typed prefix matching is ordinal case-insensitive and considers source text before eligibility. In Single mode, matching an ineligible item therefore retains Current and reports that retained index. Directional continuation uses eligible items, an ordinal case-sensitive prefix, a twice-long timeout and no wrap. Pointer presses, horizontal/page movement, cancel and activation clear the prefix. AllowSearch disables both text producers. Native input methods still require the existing Window IME activation policy; the list does not invent key events from a committed string.

## Pointer and notification order

Left selection and enabled right selection report selection, ItemClicked, then left double-click ItemActivated. The Command/Control toggle and mouse range branches report their changes and click without activation. Disabled entries suppress every item signal. An enabled unselectable entry can click and activate. A plain press on an already selected Multi entry defers exclusive selection until left release and has no click event; motion cancels it. Resizing/reordering/removing the model or changing selection mode retires that pending index.

Every wheel press first reports ItemClicked or EmptyClicked, then changes a real range. Vertical wheels prefer the vertical bar, horizontal wheels prefer horizontal; absent preferred bars and Shift select the other axis. Nonselecting buttons, including wheels, continue through configured InputMap actions after click notification and scrolling. Selecting left/right branches finish immediately. A wheel is accepted after that action phase only when the value moves. Pan updates vertical then horizontal pages without marking the gesture handled itself.

Ordinary typed events use BeginEventEmission. Signal blocking preserves state changes and already accepted delegate snapshots. Exceptions stop the ordinary multicast emission and leave committed state intact; the surrounding scene reports the failure. Disposal clears owned subscriber fields. An input operation cannot recursively invoke itself. After a callback changes item/selection/layout policy, detaches the list or disposes it, the operation stops before using another old index or publishing a stale click/activation. The deferred release is cleared before notification, including the exception path. Idempotent policy/selection assignments preserve later notifications. A later independent input starts normally. Scene owners retain the inherited thread/capture checks.

## Verification

[ItemListInputTests](../../tests/Electron2D.Tests/ItemListInputTests.cs) is linked into the [public-only consumer](../../tests/ItemList.Consumer/Program.cs), alongside existing model/layout/theme/scene tests. It covers all three selection modes, LTR/RTL, page fallback, eligibility, unset cursors, configured versus fitted columns, Unicode and multi-scalar commits, search continuation, signal blocking/order, both wheel axes, range callbacks that clear/shrink/reorder/select/dispose, exception recovery, detachment during scroll callbacks, idempotent assignments, prefix capacity/expiry, direct reentry and off-owner rejection. Reused public input events and a warmed retained prefix exercise 1024 active and 1024 idle intervals with strict zero owner managed bytes. Cold buffer growth and caller-created input objects can allocate.

`input-gpu` and `input-compatibility` run [public native input/render checks](../../tests/Electron2D.Tests/ItemListInputRenderingTests.cs) through ordinary Engine.Run host input boundaries and stateful Input.ParseInputEvent before each step, including selected pixels and 64 complete active input/render frames. The root selector ELECTRON2D_TEST_ITEMLIST_INPUT=native-gpu or native-compatibility adds [actual native event production](../../tests/Electron2D.Tests/ItemListNativeInputTests.cs): queued key press/release and a multi-scalar native text commit traverse the real window and focused list before rendering. Those producer objects are outside the prepared public-frame allocation interval.

The qualification scope is recorded in ignored bin/item-list-input/2026-10-25/. Managed bytes do not measure native heap totals. Software graphics, programmatically injected native events and actual readback do not establish physical keyboard/IME hardware, hardware GPU throughput, other operating systems or owner visual acceptance.
