# Color authoring

Last updated: 2026-11-13

ColorPicker : VBoxContainer is an executable color editor. ColorPickerButton : Button creates its required picker and PopupPanel lazily. ColorPalette : Resource supplies independent ordered swatch data and the built-in typed `.e2dres` factory. These consumers use existing Color math, Range/SpinBox/LineEdit, containers, themes, menus, file dialogs, popup routing and completed viewport textures.

## Color and numeric editing

Picker defaults are white, RGB, HSVRectangle and every section/edit policy enabled; DeferredMode is false. The button defaults black and ToggleMode true. Programmatic Color writes are silent; user input publishes ColorChanged after updating the color and controls. Colors must be finite; signed/HDR channels and alpha are retained. Normalization/exposure widens intermediate linear arithmetic to double so a finite high HDR channel does not overflow before division. Invalid channel/exposure input preserves the last color and restores fields. An observer failure cannot roll back committed color/presentation; a failed surface-release observer still runs required recent-swatch maintenance before reporting the aggregate error.

RGB uses integer 0–255 channels; HSV/OKHSL use hue 0–359 degrees and integer 0–100 saturation/value/lightness. Linear uses 0–1 RGB with Step=.001 and arrow step .01. Alpha uses 0–255 with Step=1, or 0–1/.001 in Linear. The numeric field shares its actual Range with its slider. RGB/Linear accept larger RGB values; alpha stays bounded. Intensity uses -10–10/.001, permits larger values and snaps arrow increments to whole stops. Intensity applies `2 ** intensity` to linear RGB before converting back to nonlinear sRGB, preserving alpha and the original normalized color rather than re-quantizing another channel. Turning intensity editing off preserves the current color; hidden alpha is preserved on text submission.

Hex text accepts the existing HTML/named-color contracts. The constructor view accepts `Color(r, g, b)` or `Color(r, g, b, a)` with the existing bounded numeric expression evaluator in each channel, including nested numeric functions. Empty/trailing arguments, nonfinite results and malformed formulas are rejected without replacing the color. This is scalar color data, not a general object/string/collection Expression host. HDR switches to constructor display. Submission uses captured typed deferred text; first-seen text is cold. Copy uses the real display clipboard and needs an active DisplayServer.

## Spatial input and presentation

Six spatial editors execute: HSV rectangle/hue bar, HSV ring/inner SV square, VHS circle/value bar, OKHSL circle/lightness bar, OK HS rectangle/lightness bar and OK HL rectangle/saturation bar. None hides the surface and shape selector. Surface pointer gestures clamp coordinates and retain their selected wheel region; DeferredMode updates local presentation during the gesture and publishes at release. Keyboard directions edit a focused surface; the wheel switches between its ring and inner square while keyboard editing is inactive, retaining one-percent SV increments; accept/cancel switch its editing state, and controller directions repeat on the owning scene clock. Exit, hiding and focus loss stop gesture/repeat state.

Color fields use a retained 64-by-64 rectangle mesh or 64 angular by 32 radial subdivisions. This shared CPU tessellation executes on GPU and compatibility; it approximates nonlinear color gradients between samples, and does not claim exact shader-pixel equivalence at arbitrary scales. It introduces no second renderer or public shader identity. Theme cursor/background, focus, hue, slider-center, dimensions/margins, preview/revert, shape/menu/copy/add and folded/expanded assets all have real consumers. Current ColorPicker owns 27 theme keys and ColorPickerButton adds bg; authored SVGs and shared StyleBox resources belong to ThemeDB. Focus remains visible, and numeric channel labels supplement color.

The button's getters return stable borrowed required nodes and reject their independent disposal while its owner is live. Opening remembers the color; acceptance commits the focused field before closing, Escape restores the opening value, and PopupClosed resets toggle state. The old/new preview can revert the opening color. Presentation uses GUIEmbedSubwindows on a containing viewport or a supported native popup.

## Swatches, files and sampling

Preset operations are local and silent. AddPreset moves an existing exact color to the end. Recent colors retain at most nine, oldest first; adding an existing recent is silent, and choosing it moves it to the newest position. Get methods return independent arrays. User add/delete publishes PresetAdded/PresetRemoved; CanAddSwatches gates these interactions and typed swatch reordering, while programmatic methods remain available. Delete and gamepad X use the permanently registered InputUIColorPickerDeletePreset project action. Drag payloads retain owner/button identity so another picker cannot reorder this palette.

Swatches and recent sections can fold independently. Palette Save/Save As/Load/Clear commands use FileDialog and ResourceSaver/ResourceLoader. Decoding validates all swatches before replacing the current palette; failed persistence keeps the previous atomic file. ColorPalette copies both array boundaries, retains order/duplicates/HDR, and assignments are silent like the pinned resource. EmitChanged remains explicit for a live observable palette. Duplication owns an independent array.

### Desktop and application sampling

On native Windows or X11 with desktop capture and a non-embedding root window, Pick follows live desktop pixels across application boundaries. The picker updates its preview color silently until left release commits one ColorChanged event and records the recent preset. Right click, Escape and closing the picker cancel and restore the opening color. The input session retires when the preview closes, detaches or is disposed. Selection clicks stay within that session.

On Windows with capture exclusion, a topmost native window displays a nearest-filtered zoom and swatch. It reads the 17-by-17 neighborhood from the desktop, clipping the crop to the active display near its edges. Capture excludes the preview itself. A compact swatch beside the pointer covers X11 and Windows without capture exclusion. X11 owns the pointer grab on a private connection. Windows filters paired left and right clicks while the application has the foreground. A separate Win32 message thread publishes the chosen screen coordinate to the scene owner and releases its hook on cancellation or teardown. [Windows mouse hook delivery](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)

A non-embedding Linux window can use the session's Screenshot portal for an external color. The portal controls the selector and returns one opaque sRGB color. A successful response commits through the same ColorChanged and recent-swatch path. Hiding or detaching the picker, disabling its sampler or closing the display retires the request. A native menu popup releases its pointer grab by closing when the portal accepts the request. The result still reaches its picker while the owning control remains visible and attached. A cancellation leaves the opening color in place.

With embedded root windows or without a desktop picker that can start, Pick captures the containing application viewport's completed image. It presents that image through a popup with scaled, clamped coordinates and a zoom preview. Left release commits and cancellation discards the sample. Hide and disposal release the owned capture. Missing completed rendering or a native sampling failure uses the embedded error dialog or the native message dialog. Leaving an unedited color field keeps the presented value and emits no edit.

`DisplayServer.ColorPicker(Action<bool, Color>)` starts desktop color selection on Windows or through the Linux Screenshot portal on Wayland and X11. `HasFeature(Feature.NativeColorPicker)` reports the display's provider. Individual requests can still be declined. Each accepted request completes on the display owner thread after the native event drain. The callback receives the success flag and opaque sRGB color. Cancellation and backend failure report false with black. Display shutdown retires outstanding requests without delivering callbacks. macOS needs its native picker and permission integration. [Desktop capture contract](desktop-screen-capture.md)

The Windows display accepts one selection at a time while the application is in the foreground with a visible, unrestricted pointer. A small topmost swatch follows the pointer without taking focus. The native input worker captures the left or right button pair while the application owns the foreground. Left release samples that screen coordinate, including over another application's window. Right release, Escape, loss of foreground and leaving visible pointer mode cancel. The display releases the pointer and swatch before invoking the callback, so the callback can start a new selection. This path works with a standalone DisplayServer and uses its native event pump.
