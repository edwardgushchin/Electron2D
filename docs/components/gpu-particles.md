# GPU particles

Last updated: 2026-10-19

## Executable scope

The static `RenderingServer.Particles*` family owns renderer-session particle RIDs on the GPU backend. `CanvasItemAddParticles` submits their mesh passes through the existing retained canvas. Simulation state, previous transforms, history, age ordering, subemission queues and generated vertices remain in native GPU buffers. CPU state retains configuration, timing and a bounded pending manual queue. Compatibility rejects creation explicitly.

Process and draw materials have separate roles. `ParticlesSetProcessMaterial` borrows a [ParticleProcessMaterial](../classes/ParticleProcessMaterial.md) or a `ShaderMaterial` with `Shader.Mode.Particles`; empty material or an unconfigured shader material uses the default process. The canvas item's material and mesh surface materials shade the generated geometry. Meshes, textures and materials remain caller-owned; disposing one while it is in use rejects the next consumer. Freeing a particle RID invalidates its retained commands and detaches incoming subemitter links. All state retires with its renderer session. Stale, foreign and wrong-kind identities and wrong-thread access reject.

The built-in process material executes the settings below. The high-level GPUParticles node and CPU conversion remain dependencies of their next connected slice; their public placeholders are not exposed.

## Configuration and updates

Create, allocate with `ParticlesSetAmount`, assign mesh passes with `ParticlesSetDrawPasses`/`ParticlesSetDrawPassMesh`, and attach with `CanvasItemAddParticles`. An owned canvas RID keeps commands until cleared; drawing through a scene-owned canvas RID follows that item's ordinary draw recording lifecycle. Configure emission with `ParticlesSetEmitting`, lifetime, amount ratio, explosiveness, randomness, speed scale, one-shot and preprocessing. Capacity starts at zero; changing it clears native state. Defaults are lifetime 1 second, speed/amount ratio 1, fixed frequency 30, interpolation enabled, fractional delta and local coordinates disabled, and custom bounds (-4,-4,8,8).

Visible commands request processing once per renderer frame. `ParticlesRequestProcess` and `ParticlesRequestProcessTime` also work for hidden or unattached identities. The latter replaces pending process/residual intervals; preprocessing and these explicit intervals run in fixed subdivisions independently of speed scale. Residual processing disables emission. Positive fixed frequency uses a remainder and caps automatic wall-clock delta at 0.1 second; nonpositive frequency uses variable steps, except segmented trails use 60 Hz. A restart clears phase and records at the next update. One-shot turns emission off before processing the first step into the next cycle. Stopped activity drains after 1.2 lifetimes; `ParticlesIsInactive` describes that activity interval rather than a GPU particle-count readback.

`ParticlesEmit` copies selected position, basis, velocity, color and four numeric custom channels. Bits 1, 2, 4, 8 and 16 select those fields; other bits are ignored. Manual emission disables automatic emission, clearing its previous state when necessary. The pending queue holds at most capacity records and drops excess. No caller array is retained. Finite durations/scales are nonnegative, lifetime is positive, and ratios clamp to [0,1]. Native record/history/expanded-geometry byte and step counters are checked before dispatch.

## Compute frame and routing

The [portable process ABI](particle-shaders.md) remains the shader contract. The renderer initializes or restarts records, integrates existing velocity/age, sets newborn flags, runs the optional authored compute program, captures history and prepares draw ordering. A custom program owns its active flag and any custom lifetime policy; the default process deactivates records at nominal lifetime. `State.x` bits 1/2 indicate active/newborn; bits 8 through 12 retain the supplied-field emission mask during that newborn step, then clear on the next step. Built-in process initialization can preserve explicitly supplied position/basis/velocity/color/custom channels. The includes name this mask and shift. `State.y` is the birth cycle, `State.z` the seed and `State.w` the per-particle delta as float bits. Fractional delta supplies the newborn's fraction of the current step in this last lane.

`EmissionX/Y` is identity in local coordinates and the authored emission pose in world coordinates. `PreviousEmissionX/Y` retains the previous simulation pose, or the current pose on reset.

`Counts` supplies amount, cycle, seed and outgoing queue capacity. `Time` supplies step seconds, nominal lifetime, randomness and explosiveness. `Cycle` supplies old/new phase, interpolation-to-end and amount ratio. `EmitterVelocity.xy` contains the supplied planar velocity and `.w` collision base size. `Options.x` holds emission/fractional/local/reset/full-cycle/default-process bits (1,2,4,8,16,32); `.w` is the dispatch row width. Compute programs flatten `gl_GlobalInvocationID.x + gl_GlobalInvocationID.y * Options.w` for large dispatches.

`ParticlesSetSubemitter` borrows a target in the same renderer and rejects cycles. The topological schedule processes parents before children, independent of creation order. For retained subemission, set the emitted record's `State.x` to the same five field-selection bits used by `ParticlesEmit`; the atomic header remains separate. The GPU converts parent-local through world into child-local coordinates, bounds destination writes and disables child automatic emission. An absent target has an empty bounded outgoing queue. Source programs without the optional queue descriptor do not route emissions.

SDF process samplers use the distance field of the first submitting viewport in the frame. `SDFRect` carries canvas UV scale/offset; the two SDF transform rows include the particle command's canvas basis. A request without a submitting viewport uses an empty field. Collision base size is a shader input, not a spatial collision-object implementation.

## Canvas, trails and bounds

Draw passes accept current array, immediate and procedural meshes, surface materials, ordinary topology, vertex/custom data and canvas clips/modulation. GPU expansion preserves distinct vertex instance ordinals and the normal draw material path, HDR color transfer, MSAA, per-item shader values and particle sprite-sheet UVs. Built-in group-owner geometry computes final screen UVs and premultiplies the complete mesh/particle/item opacity once on the GPU. Index order keeps original records; lifetime/reverse lifetime sort by age on the GPU. Velocity alignment selects the local X or Y basis and preserves planar scale. Depth order, billboards and their channel-rotation options have no planar role.

`ParticlesSetTrails` enables native history for skinned meshes with multiple copied planar bind poses. Weighted mesh vertices interpolate age-separated transforms, colors and custom channels and combine their bind poses; the current birth cycle prevents connecting different incarnations. Trail length accepts at least 0.01 second and caps at ten seconds. Changing trail configuration or fixed frequency resets numerical state; changing pose count resets allocated state. Fixed-step presentation can interpolate previous/current transforms, colors and custom values; no CPU particle readback occurs during ordinary frames.

Custom bounds control ordinary visibility in the command's emitter-local space; world-state conversion does not shift that authored visibility rectangle. World canvas/bounds conversion and child-local subemission require an invertible emission pose; attempting a singular inverse rejects before submission. `ParticlesGetCurrentAABB` is an explicit native synchronization/readback operation: active current records and selected trail history are converted to emitter-local coordinates and expanded by the longest draw-mesh axis. It returns empty before initialized allocation. Mesh callbacks must leave particle ownership stable. The query intentionally allocates copied readback data and belongs outside hot frames.

## Built-in process material

`ParticleProcessMaterial` authors typed settings without a rendering session. Assign its borrowed RID with `ParticlesSetProcessMaterial`; the GPU backend runs a motion pass and an appearance/subemission pass over the same native records. Each stage stays within the sixteen-sampler portable limit; generic textures retain their actual two-dimensional sampling coordinates. No CPU curve atlas replaces their data. Canvas and writable-texture material roles reject this compute-only material.

Births support the shared seven `ParticlesEmissionShape` choices, distribution offset/scale, projected sphere/volume samples, rectangle extents, texture points/normals/colors and an area-uniform ring. PointCount bounds the selected texel index against the position texture dimensions; absent positions fall back to the origin. Direction, initial velocity, supplied emission fields and emitter velocity initialize physical state. World emission transforms the velocity by the emission basis before adding inherited emitter velocity; local emission uses the identity basis. A zero direction has angle zero.

Scalar min/max pairs stay ordered: setting a minimum raises the maximum, setting a maximum lowers the minimum, and SetParam applies minimum then maximum. Inputs must be finite. LifetimeRandomness, friction and bounce clamp to their documented unit intervals; nonnegative radii, point/subemission counts and positive subemission frequency validate before mutation. Inverted independent ring radii reject preparation. Derived nonfinite records deactivate instead of reaching canvas vertices.

Motion includes gravity, linear/radial/tangential acceleration, orbit, radial/directional controlled velocity, constant or quadratic damping, a velocity-limit texture and numeric curl-noise turbulence. VelocityPivot is in simulation coordinates. Orbit is clockwise turns per second; ordinary angle and angular velocity settings are degrees. The angular-velocity curve follows the retained accumulator convention in radians, while the uncurved path derives degrees from elapsed age. TurbulenceNoiseSpeed remains Vector3 because it moves numeric noise coordinates rather than spatial scene state. ScaleOverVelocity samples final limited speed; its coordinate is speed/(max-min), clamped to the unit interval, with the zero-width interval selecting the end for nonzero speed.

Applicable scalar and texture Parameter roles are explicit. TurbInfluenceOverLife has only a curve; InitialLinearVelocity, TurbVelocityInfluence and TurbInitialDisplacement have only scalar ranges. Invalid role access rejects. Assigning a CurveTexture or CurveXYZTexture initializes only missing Curve objects to unit samples in the owning range and preserves authored curves. Regular lifetime channels use diagonal `(phase, phase)` sampling; turbulence lifetime and scale-over-velocity use `(coordinate, 0)`. A scalar CurveTexture orbit reads red; other orbit textures read blue.

Appearance combines base color, lifetime and initial ramps, hue rotation, alpha and emission curves, angle/alignment, scale and animation phase. Explicit supplied custom data is copied before subsequent curve integration. Custom stores rotation radians, normalized age, animation phase and lifetime factor. The built-in material privately retains physical XY velocity in TransformX.z/TransformY.z and curved angular accumulation in VelocityAge.w; the planar draw path does not consume those spare lanes. Its private State.x bits track contact/end/start/hide lifecycle separately from the portable active/newborn and supplied-field bits. Custom compute programs keep their own policy for these spare lanes.

Rigid collision resolves the first submitting canvas SDF, using collision base size and optional previous particle scale, then friction/bounce. HideOnContact deactivates penetrating particles. A zero gradient has a finite axis fallback; tangency does not create a contact. AtCollision can query the SDF with ordinary collision response disabled. Subemission supports Constant (at most one per substep), AtStart (once per birth), AtEnd (once) and AtCollision, with optional inherited velocity. The outgoing queue is bounded by the linked child capacity, including a child larger than its parent. Saturation drops excess without overwriting storage.

Sampled ViewportTexture inputs participate in ordinary WhenVisible dependency submission for both stages and linked children. Compute runs in the first submitting viewport, so a process sampling that very viewport observes its previous completed target; the next frame sees its new pixels. Borrowed custom texture callbacks must leave process-material identity/configuration and retained particle storage stable. A failed preparation preserves pending manual emission and seek timing for retry.

Stored material settings and registered curve/gradient texture factories preserve shared resource identities through duplication and typed archives. Curve textures persist their authored curves, dimensions and initialization state. Gradient textures with a detached source persist the last immutable pixels independently of changed logical dimensions. Frozen-pixel headers and byte counts validate before mutation. File settings and HDR payloads have fresh-process managed checks; runtime records and pixels are exercised separately. Editor-only emission-shape notification awaits an executable editor consumer. Spatial attractors, cylinder axes/heights/cones, Z flattening/rotation/scale and inert DisableZ switches have no planar role.

## Verification limits

`ParticleServerTests` exercises real Linux Wayland/software-Vulkan pixels for process/draw separation, local/world coordinates, fixed/explicit timing, wrap/one-shot/residual processing, subemitters, trails, bounds, ordering, velocity axes, HDR/MSAA and hidden requests. Owner/thread/identity/domain/finite/capacity and mesh-callback reentry validation is executable. Multiple generated streams retain identity across empty clipping and reversed batch order. Native process failure and a later draw-only failure exercise cancellation/retry of unpublished state, manual queues and weighted geometry uploads. Thirty-two warmed process/sort/render intervals allocate zero managed owner bytes. Physical GPU performance, native allocator accounting, other platforms and owner acceptance remain separate gates.

The built-in material profiles add 26 native channel/distribution cases, 13 contact cases, 10 basis/noise/nonfinite cases, ten timed subemission frames, live process-only viewport pixels, callback failure/retry and 32 warmed frames with zero managed owner bytes. These are software-Vulkan checks, not physical-GPU or owner acceptance.
