# Hierarchical cells

Last updated: 2026-10-07

[Tree](../classes/Tree.md) and [TreeItem](../classes/TreeItem.md) provide executable multi-column retained hierarchy authoring. TreeItem is an owned non-node object with typed cells, metadata, resources, buttons and callbacks. Tree owns its root/attached branches, prepared row/column geometry, borrowed-resource watches/residency, scrollbars and embedded cell editors. Removing a child transfers a live detached branch to the caller; reparenting may transfer ownership between controls. Columns resize the complete attached branch family.

The component consumes scene lifecycle and ordinary Control/Viewport input, Font/TextLayout Unicode/grapheme/BIDI shaping, typed themes and canvas recording. Single/row/multiple selection, cursor state, folding/visibility, tri-state propagation, titles, icons/buttons/custom drawing, tooltips/search, scroll fitting and drop feedback use that shared model. The typed custom drawing canvas is the Tree CanvasItem in its active drawing scope; callers receive actual local cell rectangles without a public native handle. Hierarchy/layout mutation during build/draw is rejected. Observer failures preserve committed state and continue the subsequent notification lanes.

String editors use the existing LineEdit/TextEdit; multiline commits with Ctrl/Meta+Enter. Numeric editors use the existing expression parser and synchronized HSlider; text-defined range options use PopupMenu IDs. Escape cancels pending text/expression changes; slider and choice changes commit through ItemEdited. CustomPopupEdited requests an application-defined editor. Popup editors require GUIEmbedSubwindows on the containing viewport. Independent native child-window hosting remains a Window/DisplayServer dependency, so compilation does not establish that workflow.

PackedScene stores Tree/Control options and full indexed column profiles through registered factories. The item graph, cell resources/metadata/callbacks, transient selection, scroll and popup sessions are runtime authoring state. Fresh-process loading restores configuration and can immediately create/select/shape a new hierarchy. Semantic cell/button descriptions are retained/readable authoring data; native publication waits for the semantic service. Editor-authored item graphs and their automation remain separate integration gates under ADR 0090.

[TreeTests](../../tests/Electron2D.Tests/TreeTests.cs) exercises ownership/detach/cross-tree moves, traversal/fold/visibility, metadata and copied parser options, numeric/choice bounds, tri-state propagation and callback failure, selection/cursor/signal order, pointer/modified keyboard input, geometry/RTL, icon button IDs, drop sections/unfolding and stored/fresh-process scenes. Native queued SDL keys exercise single/multiline/expression/slider/choice commit and Escape cancel. Current Linux desktop GPU and compatibility readbacks exercise actual glyphs, checks/ranges, icons, custom drawing, fold/scroll and RTL hit geometry. Each exercised selection policy is measured over 64 prepared selection/render intervals after 64 warm-up frames; single and multiple selection both measure zero managed bytes on the current GPU and compatibility hosts. Native event Resource copies, native allocations, physical input, other targets and owner visual acceptance are outside that measurement.

Authoring/shaping and changed text/resource/theme layout are cold. Cached depth/visibility/unfolding propagate once per rebuild; depth-first sibling traversal retains a worst-case O(sibling count squared) cold ceiling from linear sibling lookup. Prepared rows, TextLayouts and resident textures are reused; resource generation changes invalidate on the owning scene thread. A runtime-only CellButton ID need not be unique and is independent of the pressed button index. Required internal children reject direct disposal while their Tree lives.

Tree/ItemList share [VerticalScrollHintMode](../classes/VerticalScrollHintMode.md) under ADR 0051 because their values and vertical policy are identical. Tree selection and ItemList selection keep separate enum identities because their row/cell policies and values differ. Coverage records the complete own hierarchy/cell surface, its one deprecated exclusion, typed callback/tuple/canvas adaptations and exact inherited/native/editor dependencies; no broader platform or semantic acceptance follows from this slice.

Column expansion accumulates positive ratios in 64-bit arithmetic. GetColumnWidth saturates at Int32.MaxValue when float layout represents a larger fitted width, rather than returning a negative overflowed pixel count. TreeTests exercises both integer boundaries.

ExpandRight merges consecutive empty noneditable String cells, stopping before other modes and editable targets. Shaping, drawing and local hit rectangles use the same expanded cell; merged cells are omitted until normal geometry is restored by a later rebuild.
