# Graphics adapter identity

The rendering server publishes an immutable snapshot of its selected adapter when the renderer opens. `GetVideoAdapterName`, `GetVideoAdapterVendor`, `GetVideoAdapterAPIVersion` and `GetVideoAdapterType` read that snapshot without creating a device or consulting another GPU. Calls before startup and after shutdown return empty strings and `DeviceType.Other`. The snapshot can be read from worker threads.

SDL GPU supplies the selected device name and any driver name and version it publishes. The pinned Vulkan bridge reads hardware vendor ID, classification, API version and the 16-byte pipeline cache UUID from the selected physical device's properties. The cache UUID is emitted as 32 lowercase hexadecimal digits. The retained and local `RenderingDevice` queries read their device's identity under the normal owner and lifetime rules.

The OpenGL compatibility path captures the renderer, vendor and version strings while the owned window context is current. Software reports no graphics adapter. On Windows and desktop Linux, `OS.GetVideoAdapterDriverInfo()` returns a caller-owned pair when either driver field is known. An unavailable field is empty. With neither field, it returns an empty array.

The Direct3D 12 GPU backend reads its borrowed logical device and physical adapter from the existing native driver-resource bridge. Direct3D 11 Compatibility queries the existing renderer device for its DXGI adapter. Direct3D 12 Compatibility resolves its actual device LUID in DXGI. All three read the adapter description, PCI vendor and classification from DXGI and the feature level from the device. Feature levels use the `12_2` or `11_0` form. DXCore reads the driver description and four-part driver version for the same LUID. Queried interfaces release their temporary COM references.

The Direct3D 12 GPU cache key joins the DXGI LUID bytes, adapter revision and observed driver version. It is shared by main and local leases and can change on device reinitialization or driver update. A missing driver version leaves the key empty. Vulkan retains its native UUID. A preceding native module without the identity or driver-resource export still reports the public SDL properties. With DXCore unavailable, Direct3D retains the DXGI fields and the driver values available from SDL. Metal, browser identity, additional Compatibility drivers and delivered packages retain their platform qualification under [ADR 0021](../decisions/product.md#adr-0021).

The `ELECTRON2D_TEST_ADAPTER_IDENTITY` profile checks the renderer after drawing a frame. The `vulkan` profile takes the expected model, API version, lowercase cache UUID without separators, driver name, hardware vendor and device type from an independent adapter inventory. It also checks local-device ownership and retirement, and the caller-owned driver array. The `direct3d12`, `direct3d12-compatibility` and `direct3d11` profiles take a path to the [Windows SDK fixture](../../tests/Electron2D.Tests/Fixtures/GraphicsAdapter/direct3d.cpp). Build it from an x64 developer shell with `cl /std:c++20 /EHsc /W4 /WX /LD direct3d.cpp /link dxgi.lib dxcore.lib`. Select `SDL_GPU_DRIVER=direct3d12` for GPU and `SDL_RENDER_DRIVER=direct3d12` or `direct3d11` for Compatibility. The fixture queries the running backend's actual COM device, checks the published fields and verifies the Direct3D 12 GPU key on both leases. The `opengl` profile compares strings with the current native context, and `software` verifies unavailable identity. Use `vulkan-no-identity` with a preceding native module and the same Vulkan inventory to check missing-export behavior.

Windows x64 exercised all three Direct3D profiles on an RTX 3090 Ti. The Direct3D 11 profile also checked Microsoft's CPU adapter with the `SDL_RENDER_DIRECT3D11_WARP=1` hint. Independent Vulkan inventory and the SDL software control passed on the same host. Older Windows without DXCore, hybrid GPU switching, Windows ARM64, NativeAOT and delivered packages retain separate verification.
