# Native popup menus

Last updated: 2026-11-06

[NativeMenu](../classes/NativeMenu.md) implements [ADR 0117](../decisions/native-menus.md#adr-0117) as a static facade over one display-owned ElectronObject. Windows desktop uses system User32, GDI and Comctl32; it adds no runtime dependency. Other display drivers report no PopupMenu feature and reject creation before native entry. IsAvailable observes a display session, including an unsupported driver.

## Ownership and execution

CreateMenu returns a globally nonreused RID. HasMenu observes this session's retained model; all other menu calls validate the owner thread and exact live identity. FreeMenu rejects an attached submenu; Clear, RemoveItem and submenu replacement detach children without transferring or destroying their independent lifetime. A child has one parent and cycles reject before mutation. Display retirement detaches/frees every remaining tree before its HWND. Native handles remain private. Caller disposal of the retained service rejects.

Logical indices include hidden records. Insertion appends for -1 and otherwise clamps to the current bounds; getters, setters, movement and removal require nonnegative in-range indices. Moving a record retains its command, callbacks, tag, state and borrowed resources. Labels reject null and embedded NUL. Native text is Unicode. Check/radio, checked, disabled and hidden values affect actual native items. State/MaxStates are explicit application metadata, as are check changes after selection; selection does not toggle or cycle values automatically. Text, submenu, tag and icon lookup returns logical indices, or -1.

Tags use exact generic types, including typed null. Action and Action<T> replace dynamic callback payloads. A generic insertion requires its callback argument explicitly (null is allowed), so a three-argument lambda binds the ordinary activation overload. For integer submenu metadata use the explicit generic AddSubmenuItem<int> overload; its nongeneric integer argument is the insertion index. Typed callback assignment and tag replacement validate exact types before mutation. Callbacks, tags and icon sources are borrowed; retirement does not dispose them.

Popup blocks the owner in the OS menu loop and reserves the native owner and root display against retirement/event pumping. The direct service uses the main native window; the PopupMenu bridge supplies its actual containing native owner. Recursive presentation, conflicting native dialogs and item mutation during tracking reject. Open callbacks may populate menu items during native initialization; icon preparation itself forbids reentrant mutation. IsOpened follows actual initialization/uninitialization. GetSize is zero before native layout and subsequently retains the last observed item rectangle extent. Interface RTL affects the real native layout.

Mouse hover follows native selection notifications. Native callback exceptions stay inside the unmanaged boundary until tracking unwinds. After cleanup, close callbacks run before activation. Required callbacks still run after an earlier callback fails; failures aggregate. Close callbacks may change/free records or start another popup. A selected record dispatches only if it and its owner remain live and enabled. Cancellation emits no activation. Empty native menus do not create a popup window.

Icons are copied to owned premultiplied BGRA DIBs from borrowed readable Texture snapshots, with a 64 MiB image pixel budget. Changed/disposed resources mark records for owner-thread refresh. Only the presented visible tree is prepared; an unrelated unreadable icon cannot prevent another popup from opening. Failed copy/update retains the old native bitmap, releases presentation reservations and permits retry. Item retirement unsubscribes and deletes copied bitmaps. This cold UI path has no allocation-free claim.

## PopupMenu integration

PreferNativeMenu defaults to false and persists in ordinary PackedScene storage. With a supported Windows display, eligible plain/check/radio/icon/separator/submenu trees use NativeMenu instead of opening canvas windows. IsNativeMenu is true during that modal presentation, including PopupHide; native RIDs and delegates never enter the archive. AboutToPopup runs once before the decision, allowing authored edits. Geometry follows the existing embedded viewport/native parent transforms with checked integer translation. Native OS placement may fit the requested desktop anchor to its monitor; system fonts and decoration determine native size independently of canvas theme and Size/ShrinkWidth geometry.

Native selection notifications update the source focused index; keyboard-style focus emits IDFocused, while mouse hover updates focus without that event. The bridge emits native close/PopupHide before the existing IDPressed/IndexPressed activation, and checks the source record is still live after callbacks. Icons remain borrowed. It detaches/frees the whole temporary native graph through its exact retained owner even when callbacks fail; it never binds cleanup to a later display session. Native presentation never sets the canvas Visible property. Hide or Visible=false during native tracking cancels the whole native popup tree, including a request from a child submenu. Unsupported drivers and unsupported roles retain the canvas implementation: search bars, shortcuts/accelerators, persistent selection policies, titled separators, tooltips/indentation, item text direction/language overrides, modified/scaled icons, graph zoom or extra user controls. MenuButton/OptionButton/MenuBar consumers keep their existing PopupMenu identity and can opt in through it. A dropdown native popup does not turn MenuBar into a system global menu bar.

## Verification and limits

[NativeMenuChecks](../../tests/Electron2D.Tests/NativeMenuChecks.cs) is shared by the root runner and the [public consumer](../../tests/NativeMenu.Consumer/README.md). The independent [Win32/MSAA oracle](../../tools/native-menu/oracle.cpp) finds only windows in the tested PID, inspects real HMENU item labels/flags/geometry, captures actual pixels and invokes native accessibility actions. It does not read engine internals or move the physical cursor. Home/Enter without an initial selected item cancelled even an independent C++ control; the successful keyboard profile first selects with Down. Unfocused keyboard attempts are not selection evidence. The inspector uses native accessibility invocation for general selection; the keyboard profile requires the verified own foreground owner before posting the Down/Enter keyboard sequence; it rechecks the exact foreground HWND and PID before each key pair and cancels on loss of ownership. It uses scoped WM_CANCELMODE for cancellation. Native menu MSAA accSelect returns E_NOTIMPL; it is not used to claim focus delivery.

The final fresh-package and strict full-trim NativeAOT runs each pass 92 public checks and 17 independent native popup inspections in both renderer profiles; unsupported-driver controls also pass. Source/root and artifact receipts retain exact identities. Both Compatibility and Vulkan GPU scene bridges execute; this does not qualify the Windows D3D12 canvas path. The authored tests cover identity/thread/index/type failures, hidden reorder, independent submenu ownership, Unicode, checks/radio/disabled flags, 16×16 alpha/changed/disposed icons, real open/close/hover/state/size/RTL, nested selection, callback failures and reentry, stale suppression, owner retirement/reopening, scene preference, canvas fallback and actual secondary-window ownership, MenuButton/OptionButton activation and the compiled native-type catalog. Native UI automation is not physical human acceptance.

Global/system menu identities and registration, distinct key callbacks/accelerators and native tooltip/indentation/minimum-width producers remain explicit coverage dependencies. Linux/Apple/mobile/TV/Web adapters, full ADR 0021 package/platform qualification, accessibility host acceptance and performance/provider-heap accounting remain open. The Windows native cohort is source-built; a successful consumer is not release qualification of every platform package.

[Status indicators](status-indicators.md) now borrow the same NativeMenu root identities. The menu owner tracks shared status bindings, rejects attaching a bound root as a submenu, and detaches bindings at FreeMenu. Native bitmap snapshot conversion is shared with the Shell icon producer.
