# File save and swap

Last updated: 2026-10-21

`OS.SetUseFileAccessSaveAndSwap(bool enabled)` controls subsequent ordinary `FileAccess.Open` calls with exactly `FileAccessModeFlags.Write`. The retained process service stores a thread-safe flag, initially false. Each open captures its behavior. Changing the flag does not alter an already open stream. ReadWrite/WriteRead and process pipes retain direct access. Compressed/encrypted files and configuration persistence retain their independent atomic whole-file commits, including publication on Flush.

An enabled open exclusively creates a random sibling of the resolved destination. The old target remains visible, or a new target remains absent, until Close/disposal flushes and closes the staging stream and replaces the destination. Flush persists staging without publishing it. Empty successful output intentionally replaces the target with an empty file. Caller exceptions or argument validation do not cancel otherwise successful output. Two independent writers use different siblings; the last successful close wins. This is blocking file I/O, suitable for save/asset preparation rather than frame callbacks.

Path retains the caller's original physical or virtual name. AbsolutePath identifies the staging file and remains that observation after close, even though a successful replacement removes that name. Instance file attributes and UnixPermissions address staging. Existing Unix modes are copied; a new target starts with mode 0644. Symbolic links retain their identity: the final resolved target is captured at open, and staging lives beside that target. Directories, devices and FIFOs reject before opening them, using the existing SDL filesystem classifier. Parent directories are never created automatically. The directory-backed virtual path contract is lexical; concurrent external path replacement is not a security sandbox or compare-and-swap operation. Existing hard links continue referring to the old inode.

An underlying write, resize or flush failure cancels publication and removes partial staging during deterministic cleanup. Close aggregates cleanup errors and leaves the instance closed. A failure of the final replacement instead retains the completed staging file at AbsolutePath for caller recovery; Close does not retry a completed owner. Windows replacement preserves destination metadata through the platform replacement operation and retries sharing/access failures up to 1000 attempts with 1 ms between attempts. Foreign execution remains unverified. No filesystem crash, power failure or native allocator guarantee follows from this policy.

CreateTemp retains its original temporary-name ownership: keep=false deletes the committed logical file after close, while keep=true preserves it. PCKPacker commits only a fully finalized directory and cancels a faulted staged session. OGVMovieWriter cancels staging after codec/callback failure; an ordinary scene exception still finalizes already submitted valid frames. AVI and PNG WAV mixed-mode streams retain their existing direct behavior.

## Verification

`ELECTRON2D_TEST_SAVE_SWAP=managed` exercises default/snapshot/toggle behavior, physical/res/user paths, independent writers, exact modes, transformed/configuration persistence, symlinks and Unix permissions, directory/FIFO/missing-parent rejection, injected physical I/O and final replacement failure, temporary ownership, package finalization/faults, native codec failure and an abrupt child-process exit without disposal. It also measures 1024 prepared 4096-byte writes with zero owner/all-thread managed bytes. The crash fixture proves the exercised managed process exit, not storage survival after power loss.

The gpu/compatibility and separate ogv-gpu/ogv-compatibility profiles run the existing rendered movie and OGV consumers with staging enabled: actual pixels/audio, recording lifecycle, completed native files and failures. Software Wayland/X11 execution, runtime/API/wiki checks and default file/package/movie regressions are recorded separately from hardware, foreign host and owner acceptance. Source-built OGV and current native file-codec assets must match the runtime ABI.
