# Menu strips

Last updated: 2026-10-10

[MenuBar](../classes/MenuBar.md) is a Control presenting its direct ordinary [PopupMenu](../classes/PopupMenu.md) children through the existing embedded window, text/theme and scene/file backends. It does not reparent, copy or replace caller menu nodes. Internal children and neutral nodes do not become headers; reorder retains each menu's configuration, and removal detaches subscriptions and closes a visible menu without disposing it. Normal parent disposal owns child lifetime.

## Authoring and input

Enable `GUIEmbedSubwindows` on the containing viewport. Add PopupMenu children and their commands; connect existing IDPressed/IndexPressed events. Count includes disabled and hidden headers. Titles follow popup Title, or Name when empty; SetMenuTitle creates an override, while assigning the current default title resumes automatic naming. Tooltip, disabled and hidden flags follow popup identity. Disabled/hidden headers reject user opening and owner shortcuts; changing either flag closes an active menu. All-disabled/empty navigation terminates. Hidden headers reserve no width or separation. Indices are nonnegative and checked. Language rejects null/NUL, and TextDirection rejects unknown enum values. Attached access and edits require the scene owner.

Defaults preserve Flat=false, SwitchOnHover=true, Language empty, TextDirection.Auto and FocusMode.Accessibility. The latter uses the inherited Control accessibility policy; set FocusMode.All for ordinary keyboard focus while the semantic accessibility backend is absent. Left/right wrap over eligible menus and open the first enabled nonseparator command; accept/down opens the selected or first eligible menu. An open top-level popup forwards horizontal actions to its owning strip after its existing submenu actions. Popup commands keep their original check/state, echo, shortcut and close policies. SetDisableShortcuts gates the strip's owner shortcut stage; it does not rewrite child shortcut records or an already-visible popup's input stage.

Pointer opening has no item focus. While a menu is open, hover switching requires SwitchOnHover and the common viewport hit test choosing the same strip. Overlays, unrelated controls and disabled/hidden headers cannot trigger it. The embedding-window router updates this hover state while a popup owns pointer delivery. Hover uses the routed viewport event position, so headless PushInput works without a native pointer query. Popup anchors include global/canvas transforms and exactly one required embedding-window offset; RTL aligns the trailing edge and the common popup host fits it within the viewport.

Opening rejects callback reentry. Translation/text-preparation callbacks cannot edit or dispose the strip; typed popup header descriptors validate the same owner before committing their stored fields. Failed hide observers still permit required peer presentation, eligibility/layout updates and child removal to complete. Hiding or exiting the owner closes its menus; external popup visibility updates active decoration. AboutToPopup removal skips detached presentation. Ordinary child operations retain the existing Node callback failure aggregation and scene ownership rules.

## Theme and storage

The built-in MenuBar type contains all 21 pinned theme keys: ten ordinary/mirrored normal, disabled, hover, pressed and hover_pressed styles, seven text colors, font/font_size and two constants. Inherited typed theme lookup/overrides resolve each key. Font shaping uses translation, language and writing direction; layout direction independently mirrors geometry. Flat suppresses decorations while preserving text/margins. Focus text color remains visible when normal; disabled, hover and pressed colors take precedence. Cold font/structure setup allocates; prepared text caches and draw commands are reused.

PackedScene and the built-in file factory reconstruct exact MenuBar and independently owned PopupMenu children. Four typed private scene fields on each popup restore optional title override, tooltip, disabled and hidden settings before child attachment. The settings follow their owning popup even when packing prunes an unowned sibling; no header index is stored. Scalar style/language/direction/hover properties and inherited theme overrides are stored. Runtime shortcut-disable choice, delegates, active/hover/focus state and internal caches are not stored.

IsNativeMenu reports false for the current embedded menu backend. `prefer_global_menu` and `start_index` remain precise coverage dependencies under ADR 0041: an accepted NativeMenu service decision, main-menu contiguous insertion/reordering across bars, borrowed popup bindings, callbacks/lifetime cleanup and target verification. No inert preference/insertion property is exposed. Class correspondence also retains inherited Control semantic accessibility/editor facilities and independent native child-window hosting on their owning rows.

## Verification

[MenuBarTests](../../tests/Electron2D.Tests/MenuBarTests.cs) checks defaults, direct/internal membership, title/tooltip identity, reordering/removal, keyboard/pointer/hover, no eligible headers, disabled/hidden/echo shortcuts, owner/thread boundaries, failed hide cleanup, AboutToPopup detach, RTL/canvas/nested anchors, reentrant presentation and shaping/descriptor guards, pruned siblings and fresh-process saved scenes. [Native tests](../../tests/Electron2D.Tests/MenuBarRenderingTests.cs) exercise queued SDL pointer/key events, actual header/menu pixels and warm title/focus/render frames. Linux Wayland GPU and compatibility pass the SDL/pixel sequence and 64 active title/focus/render frames after 32 warmup frames with zero managed bytes between ProcessFrameStarted and FramePostDraw. Both header and open-menu PNGs were inspected; other platforms, native allocation totals, large menu workloads and human visual acceptance remain separate gates.
