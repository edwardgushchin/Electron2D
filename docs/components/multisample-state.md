# Sample coverage, fragment frequency and alpha

Last updated: 2026-10-28

`RDPipelineMultisampleState` is a caller-owned copied graphics description. `SampleCount` retains the exact framebuffer sample count; `EnableAlphaToCoverage` uses fragment alpha to derive coverage. `SampleMasks`, `EnableSampleShading`, `MinSampleShading` and `EnableAlphaToOne` now execute through the pinned Vulkan pipeline adapter. Null state keeps one sample and ordinary shading. Each pipeline, ordered view/pass and sampled component-map variant retains its own values after description mutation or disposal. Primitive discard and line width remain independent copied raster roles.

An empty `SampleMasks` array enables all raster samples. A nonempty public array must have as many entries as raster samples: four entries for Samples4. This preserves the current facade's validation shape. Entries are raw uint 32-bit words; bit b of word w controls sample 32*w+b. The native operation consumes the first ceil(samples/32) words and ignores trailing entries and bits. Current executable counts one/two/four/eight therefore consume the first word. Reads and writes of the public array copy. A wrong nonempty length rejects at pipeline creation. Samples16/32/64 retain their separate native count/resource adapters.

`EnableSampleShading` defaults to false. When enabled, a fragment must process at least max(ceil(MinSampleShading*sampleCount),1) distinct covered samples, subject to native fragment invocation rules. The fraction defaults to zero and accepts finite zero through one. Disabled state ignores the fraction. Shader sample-index/position inputs independently force full sample frequency; sample interpolation preserves its native semantics. Original source/SPIR-V, exported modules and version-one shader binary payloads retain those declarations. Sample-rate capability and sample input decorations are validated before native publication; an unavailable feature rejects source/SPIR-V/binary/placeholder paths, and a rejected placeholder remains reusable.

`EnableAlphaToOne` defaults to false and replaces surviving fragment alpha with one after alpha-to-coverage. It also executes without alpha-to-coverage and feeds subsequent blending. The engine follows the executing native operation rather than treating this property as a switch that only stores state. Sample masks and alpha-to-coverage continue controlling sample coverage. See [native multisample state](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineMultisampleStateCreateInfo.html) and [sample shading](https://docs.vulkan.org/spec/latest/chapters/primsrast.html#primsrast-sampleshading).

The factory independently negotiates sampleRateShading and alphaToOne beside wideLines and depthBounds. Optional raster combinations are tried in a bounded sixteen-profile loop before reducing the current shader precision/storage profile. Missing sample shading does not remove alpha-to-one, mask coverage, wide lines or storage operations, and vice versa. A requested unavailable state or sample-rate shader raises NotSupportedException. Masks require the native adapter but neither optional feature. The existing call-local pipeline creator carries mask/fraction/flags by value; the native call borrows a stack mask only during synchronous pipeline creation. Shared renderer callbacks are never mutated. Existing layout caches, shader references, failure rollback and pending retirement remain authoritative.

## Executable checks

Build `tests/DeviceGraphicsStorage.Consumer` with the matching render bridge. Run `samples`, `samples-source`, `samples-canvas`, the three `samples-refuse-shading/alpha/both` modes with both physical-query and device-creation masks, and `samples-unavailable/failure`. Repeat in strict trimmed NativeAOT. Set ELECTRON2D_SAMPLE_OUTPUT to a private fixture directory; a capable `samples` run emits real binary containers used by the following refusal profiles. Source mode also needs the installed ShaderImport tool.

GLSL/HLSL checks cover exact zero/quarter/half/three-quarter/full resolved coverage, high/trailing mask bits, copied arrays/state, alpha replacement order, minimum/full frequency, shader sample index/position/interpolation, following compute, pending retirement and prepared zero-owner-thread-managed-byte cycles. An attachmentless four-sample fragment producer executes 64 storage writes over 16 pixels, including pending target/pipeline retirement and zero warmed owner bytes. Two views/two passes and automatic resolves retain masks. A sampled component-map line combines four-pixel width, one-sample coverage, sample shading and alpha-to-one. Retained canvas consumes the resolved output. Refusal profiles verify raw SPIR-V/binary publication, reusable placeholders, missing-capability rejection and executing surviving state/storage/wide-line roles. Pipeline failure repeats three times and leaves ordinary graphics usable.

Linux/Vulkan on the exercised GPU is the qualification boundary. Native/driver heap cost, throughput, Vulkan validation layers, other backends/platforms and owner visual acceptance remain unverified. [Local device](local-compute.md#multisample-graphics-and-resolve) owns framebuffer/sample-count/resource restrictions.
