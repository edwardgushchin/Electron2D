# Two-dimensional mesh surfaces

Last updated: 2026-10-02

## Scope

[Mesh](../classes/Mesh.md), [ArrayMesh](../classes/ArrayMesh.md), [MeshSurfaceData](../classes/MeshSurfaceData.md), [MeshInstance](../classes/MeshInstance.md), CanvasItem.DrawMesh and RenderingServer mesh identities form the initial executable surface/drawing slice under [ADR 0092](../decisions/mesh.md#adr-0092). It consumes the existing canvas vertex/material/texture/clip/order/sampling backend path; no new dependency or vendor modification is added.

## Runtime and invariants

Adding a surface copies typed vertex/color/UV/index arrays and validates topology, counts, finite values and indices before commit. Colors use the pinned RGBA8 UNORM clamp/truncate boundary; positions and UV use ordinary float pairs. Indexed and nonindexed points, independent lines, line strip, triangles and triangle strip append actual framebuffer geometry on both native backends. Points/lines stay one pixel wide after transforms. ArrayMesh records borrow live storage, while custom Mesh callback snapshots refresh on Changed; current per-surface materials and node material fallback are resolved for actual submission. Shader materials retain the existing GPU/fallback capability gates.

MeshSurfaceData is the typed replacement of the existing array-of-arrays concept: Vertices, Colors, UVs and Indices. No generic Get/Set/Call is exposed. Region updates retain the pinned exercised channel byte layout and accept partial records with two-pass finite validation before writing. Metadata/name/material/copy/free operations retain explicit ownership and error rules. Render replay and updates use prepared storage; loading, structural edits, duplicate/query copies and property discovery are cold operations. Structural growth is not claimed allocation-free.

RenderingMeshRegistry owns logical RID lookup only: resource entries remain weak/borrowed; renderer-created ArrayMesh entries stay owned until FreeRID or shutdown. Mesh disposal invalidates its resource RID. Renderer teardown attempts owned mesh cleanup separately from owned texture and backend cleanup. MeshInstance does not dispose its borrowed resources. Retained ArrayMesh geometry remains live after a Changed listener failure even if a later node redraw listener was not reached.

## Verification and limitations

MeshTests checks custom callback/revision failure recovery, negative counts, zero-allocation custom idle snapshots, independent 2D triangle faces, warnings, multi-record rollback, deep subresource copies and copied arrays, surface metadata, index/topology validation, packed/partial region updates and rollback, listener failure after commit, duplication, borrowed identity/scene storage/disposal, every primitive policy and 64 warmed active update/record/replay cycles. MeshRenderingTests drives real Engine.Run windows, initial/edit/position/remove pixels, owned server producers/queries/free/shutdown, packed stride reporting/rejection, off-owner and borrowed-RID mutation guards, per-surface material overrides, UV sampling and each of the five native primitive topologies. It saves test PNGs for visual inspection. Each native renderer checks 20 warmup then 64 active and 64 idle render frames. The final instrumented GPU/compatibility runs measure zero managed bytes; five further consecutive GPU profiles also pass. One earlier GPU rerun observed 112 managed bytes in the idle interval before per-frame scene/renderer diagnostics were attached. Its origin has not been localized, so these passing bounded intervals do not establish an unconditional zero-allocation guarantee across native startup/configuration timing. The strict assertion remains enabled, with phase diagnostics printed after teardown on failure. Native/driver allocations, other platforms, custom callback allocations and broad workload performance remain unmeasured.

Exact deferred inputs stay in coverage: typed deformation/morph and LOD consumers, normal/tangent/UV2/custom attributes with real shaders, compression, skeleton/skin, shadow/light meshes, placeholders and outline geometry-processing APIs. GetFaces already extracts 2D triangle faces; 3D TriangleMesh intersection and lightmap-size hints are excluded by ADR 0004. Core static surfaces execute; these are dependencies, not shipped stubs or claims of complete Mesh/ArrayMesh parity. Scene-file persistence remains separate under ADR 0090.
