# Two-dimensional mesh surfaces

Last updated: 2026-10-07

## Executable skeletal polygons

The [skeletal component](skeletal-animation.md) now supplies actual bone/rest/pose palettes and weighted retained Polygon deformation. MeshSurfaceData bone/weight channels, packed skin regions and four/eight-influence Mesh/MultiMesh consumers now execute through scene/owned palettes. Polygon retains its distinct strongest-four normalized influence policy.

## Scope

[Mesh](../classes/Mesh.md), [ArrayMesh](../classes/ArrayMesh.md), [ImmediateMesh](../classes/ImmediateMesh.md), [MeshSurfaceData](../classes/MeshSurfaceData.md), [MeshInstance](../classes/MeshInstance.md), CanvasItem.DrawMesh and RenderingServer mesh identities form the initial executable surface/drawing slice under [ADR 0092](../decisions/mesh.md#adr-0092). It consumes the existing canvas vertex/material/texture/clip/order/sampling backend path; no new dependency or vendor modification is added.

## Runtime and invariants

Adding a surface copies typed vertex/color/UV/index arrays and validates topology, counts, finite values and indices before commit. Colors use the pinned RGBA8 UNORM clamp/truncate boundary; positions and UV use ordinary float pairs. Indexed and nonindexed points, independent lines, line strip, triangles and triangle strip append actual framebuffer geometry on both native backends. Points/lines stay one pixel wide after transforms. ArrayMesh records borrow live storage, while custom Mesh callback snapshots refresh on Changed; current per-surface materials and node material fallback are resolved for actual submission. Shader materials retain the existing GPU/fallback capability gates.

MeshSurfaceData is the typed replacement of the existing array-of-arrays concept: Vertices, Colors, UVs, Indices, Bones and Weights. No generic Get/Set/Call is exposed. Region updates retain the pinned exercised channel byte layout and accept partial records with two-pass finite validation before writing. Metadata/name/material/copy/free operations retain explicit ownership and error rules. Render replay and updates use prepared storage; loading, structural edits, duplicate/query copies and property discovery are cold operations. Structural growth is not claimed allocation-free.

RenderingMeshRegistry owns logical RID lookup only: resource entries remain weak/borrowed; renderer-created ArrayMesh entries stay owned until FreeRID or shutdown. Mesh disposal invalidates its resource RID. Renderer teardown attempts owned mesh cleanup separately from owned texture and backend cleanup. MeshInstance does not dispose its borrowed resources. Retained ArrayMesh geometry remains live after a Changed listener failure even if a later node redraw listener was not reached.

ImmediateMesh adds invisible begin/append/end drafts, finite attribute/vertex validation, first-use attribute backfill, incomplete-primitive retry and clear/cancel. It owns private ArrayMesh storage, so committed data, material edits and clear are visible to already recorded commands without allocating new custom callback snapshots. Draft growth and structural commit/copy remain cold operations; repeated playback and prepared material/pose changes are hot. Duplication copies only completed surfaces and preserves borrowed/deep/local resource ownership. Clear and material edits emit Changed after commit under the shared resource invalidation contract.

The final instrumented GPU/compatibility runs measure zero managed bytes; five further consecutive GPU profiles also pass. The strict assertion remains enabled, with phase diagnostics printed after teardown on failure. Native/driver allocations, other platforms, custom callback allocations and broad workload performance remain unmeasured.

Exact deferred inputs stay in coverage: typed deformation/morph and LOD consumers, normal/tangent/UV2/custom attributes with real shaders, compression, shadow/light meshes, placeholders and outline geometry-processing APIs. GetFaces already extracts 2D triangle faces; 3D TriangleMesh intersection and lightmap-size hints are excluded by ADR 0004. Core static surfaces execute; these are dependencies, not shipped stubs or claims of complete Mesh/ArrayMesh parity. ArrayMesh scene-file geometry/material persistence now executes; other mesh subtypes retain their own file-schema prerequisites.

## Repeated instance resources

[MultiMesh](../classes/MultiMesh.md) and [MultiMeshInstance](../classes/MultiMeshInstance.md) add copied packed transforms, optional color/raw shader data, visible prefix and actual retained repeated draws. Mesh.GetAABB produces Rect2 bounds; automatic instance bounds merge the visible prefix and CustomAABB provides local culling overrides. Both native renderers preserve surface-then-instance order. The GPU backend uploads each unskinned ArrayMesh/ImmediateMesh triangle surface once and captures a retained stream of instance poses, tint and custom data. Compatibility, other topologies, custom Mesh callbacks, skinning, pixel snapping, screen notifiers and canvas groups/masks retain expanded geometry. The instance stream shares the existing canvas upload allocation; writable device buffers and indirect commands remain unavailable. Custom fragment data executes on GPU location two; compatibility rejects shaders.

[CanvasMultiMesh](../classes/CanvasMultiMesh.md) serializes resource replay, culls against framebuffer/scissor rectangles and detects reentrant storage edits before submission. [RenderingMultiMeshRegistry](../classes/RenderingMultiMeshRegistry.md) separates weak borrowed identities from renderer-owned resources and captures prepared physics targets without holding the registry gate during resource callbacks. Attached node replacement retains owner/capture guards, while committed Resource changes safely invalidate canvas state from a worker. Count/configuration changes are cold allocations; warmed per-instance edits, bounds, tick capture and replay reuse storage.

[MultiMeshTests](../../tests/Electron2D.Tests/MultiMeshTests.cs) covers defaults, eight-float packing, legacy arrays, copying, transactional finite validation, flags/count/visible bounds, Fast/High/reset/large-value interpolation, scene-local ownership, callback mutation/reentry/disposal recovery, surface order and worker invalidation. Sixty-four warmed bounds queries and active/idle replay cycles assert zero managed bytes. [MultiMeshRenderingTests](../../tests/Electron2D.Tests/MultiMeshRenderingTests.cs) exercises eight native pose/color/visible/RID/shader/culling/texture pixel phases, actual hardware-stream selection, canvas-group fallback and adjacent ordinary draws, canonical owned child mesh identities, owned/borrowed/thread/indirect guards and actual intermediate physics poses. ## Server palettes and four/eight skin records

Static RenderingServer Skeleton operations create/read/update/free caller-owned palettes, and protect borrowed scene Skeleton palettes from writes/free. Equal allocation preserves data; resizing clears transforms to zero. CanvasItem.GetCanvasItem supplies a stable borrowed scene identity; CanvasItemAttachSkeleton connects an owned/scene palette without changing drawing commands. Attachment does not inherit, own the palette or survive scene copies/files. Missing/freed/empty palettes and singular coordinates replay original geometry. Scene palettes must share viewport/canvas layer with their consumer. General owned canvas creation remains separate.

Bones/Weights are copied flattened arrays with four slots, or eight under Use8BoneWeights. Indices are uint16-representable and must resolve when attached, including zero-weight slots. Weights use float32 clamp/truncate to UNORM16 and retain authored sums. Skin region bytes are indices then weights per vertex (16/32-byte stride), accepting partial records. Replay conjugates bone transforms through item/base matrices with homogeneous translation weighted by the total, then applies command-local transforms, UV/color/material/filter/clip/order. Zero summed weights collapse local position under a valid palette. Both backends process every one of the eight slots.

Mesh/MultiMesh bound queries retain authored positions. Skinned MultiMesh bypasses rest-bound culling conservatively; this prevents losing geometry deformed into view. Owned palette callbacks hold a replay reader count so set/resize/free cannot mutate a captured view; failed callbacks release it. Packed-region byte arithmetic is widened across all three channel buffer families. No hardware skin/compute buffer is exposed.

Exact ArrayMesh factory and versioned geometry/name/skin bytes (4096 surfaces, 65536 name code units, 64 MiB) persist separately from typed Material arrays; graph aliases are preserved. Malformed buffers fail before replacing prior geometry. Warm pose/region/replay is allocating only during first preparation or structural capacity changes. MeshSkinTests checks four/eight import, independent copies, partial packed regions, float32 UNORM quantum, unnormalized deformation, different/reflected/nonuniform/rotated/singular bases, missing indices and recovery, command-local ordering, weak identity/disposal, malformed storage and fresh .e2dscene material aliases with actual deformation. Headless 128 prepared scene-palette mesh intervals measure zero managed bytes. ELECTRON2D_TEST_MESH_SKIN_HOST=1 with ELECTRON2D_MESH_SKIN_RENDERER=gpu or compatibility on current Linux x64 verifies actual owned four/eight/scene palette pixels, the fifth influence, rotated owned bases, callback write/resize/free guards, owned skin-region/stride API and teardown. Each final host measures 64 active + 64 idle full scene/draw intervals at zero managed bytes. Captures were visually inspected; native allocator activity, large scenes, foreign platforms and owner acceptance remain unverified.
