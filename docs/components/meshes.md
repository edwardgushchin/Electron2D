# Two-dimensional mesh surfaces

Last updated: 2026-10-12

## Executable skeletal polygons

The [skeletal component](skeletal-animation.md) now supplies actual bone/rest/pose palettes and weighted retained Polygon deformation. MeshSurfaceData bone/weight channels, packed skin regions and four/eight-influence Mesh/MultiMesh consumers now execute through scene/owned palettes. Polygon retains its distinct strongest-four normalized influence policy.

## Scope

[Mesh](../classes/Mesh.md), [ArrayMesh](../classes/ArrayMesh.md), [ImmediateMesh](../classes/ImmediateMesh.md), [MeshSurfaceData](../classes/MeshSurfaceData.md), [MeshInstance](../classes/MeshInstance.md), CanvasItem.DrawMesh and RenderingServer mesh identities form the initial executable surface/drawing slice under [ADR 0092](../decisions/mesh.md#adr-0092). It consumes the existing canvas vertex/material/texture/clip/order/sampling backend path; the renderer uses the existing backend; structural tangent generation uses the internal MikkTSpaceSharp dependency.

## Runtime and invariants

Adding a surface copies typed vertex/color/primary-UV/secondary-UV/index arrays and validates topology, counts, finite values and indices before commit. Colors use the pinned RGBA8 UNORM clamp/truncate boundary; positions use float pairs; UVs use float pairs unless CompressAttributes is selected. Indexed and nonindexed points, independent lines, line strip, triangles and triangle strip append actual framebuffer geometry on both native backends. Points/lines stay one pixel wide after transforms. ArrayMesh records borrow live storage, while custom Mesh callback snapshots refresh on Changed; current per-surface materials and node material fallback are resolved for actual submission. Shader materials retain the existing GPU/fallback capability gates.

MeshSurfaceData is the typed replacement of the existing array-of-arrays concept: Vertices, Normals, Tangents, Colors, UVs, UV2s, Indices, Bones and Weights. No generic Get/Set/Call is exposed. Region updates retain the pinned exercised channel byte layout and accept partial records with two-pass finite validation before writing. Metadata/name/material/copy/free operations retain explicit ownership and error rules. Render replay and updates use prepared storage; loading, structural edits, duplicate/query copies and property discovery are cold operations. Structural growth is not claimed allocation-free.

RenderingMeshRegistry owns logical RID lookup only: resource entries remain weak/borrowed; renderer-created ArrayMesh entries stay owned until FreeRID or shutdown. Mesh disposal invalidates its resource RID. Renderer teardown attempts owned mesh cleanup separately from owned texture and backend cleanup. MeshInstance does not dispose its borrowed resources. Retained ArrayMesh geometry remains live after a Changed listener failure even if a later node redraw listener was not reached.

ImmediateMesh adds invisible begin/append/end drafts, finite attribute/vertex validation, first-use attribute backfill, incomplete-primitive retry and clear/cancel. It owns private ArrayMesh storage, so committed data, material edits and clear are visible to already recorded commands without allocating new custom callback snapshots. Draft growth and structural commit/copy remain cold operations; repeated playback and prepared material/pose changes are hot. Duplication copies only completed surfaces and preserves borrowed/deep/local resource ownership. Clear and material edits emit Changed after commit under the shared resource invalidation contract.

## Server palettes and four/eight skin records

Static RenderingServer Skeleton operations create/read/update/free caller-owned palettes, and protect borrowed scene Skeleton palettes from writes/free. Equal allocation preserves data; resizing clears transforms to zero. CanvasItem.GetCanvasItem supplies a stable borrowed scene identity; CanvasItemAttachSkeleton connects an owned/scene palette without changing drawing commands. Attachment does not inherit, own the palette or survive scene copies/files. Missing/freed/empty palettes and singular coordinates replay original geometry. Scene palettes must share viewport/canvas layer with their consumer. General owned canvas creation remains separate.

Bones/Weights are copied flattened arrays with four slots, or eight under Use8BoneWeights. Indices are uint16-representable and must resolve when attached, including zero-weight slots. Weights use float32 clamp/truncate to UNORM16 and retain authored sums. Skin region bytes are indices then weights per vertex (16/32-byte stride), accepting partial records. Replay conjugates bone transforms through item/base matrices with homogeneous translation weighted by the total, then applies command-local transforms, UV/color/material/filter/clip/order. Zero summed weights collapse local position under a valid palette. Both backends process every one of the eight slots.

Mesh/MultiMesh bound queries retain authored positions. Skinned MultiMesh bypasses rest-bound culling conservatively; this prevents losing geometry deformed into view. Owned palette callbacks hold a replay reader count so set/resize/free cannot mutate a captured view; failed callbacks release it. Packed-region byte arithmetic is widened across all three channel buffer families. No hardware skin/compute buffer is exposed.

Exact ArrayMesh factory and versioned geometry/name/skin bytes (4096 surfaces, 65536 name code units, 64 MiB) persist separately from typed Material arrays; graph aliases are preserved. Malformed buffers fail before replacing prior geometry. Warm pose/region/replay is allocating only during first preparation or structural capacity changes. ## Secondary UV storage and shader consumer

MeshSurfaceData.UV2s is an independent optional finite float2 per vertex. Surface imports, queries, custom snapshots and duplication copy it. ImmediateMesh.SurfaceSetUV2 follows the same first-use backfill and subsequent-vertex policy as primary UV. TexUV2 is inferred from actual data; explicit channel flags reject absent data. Packed attributes contain present RGBA8 color, primary float2 UV, then secondary float2 UV. Absent channels take no bytes; secondary-only storage has stride eight and both UVs with color have stride twenty. Partial updates validate every affected pair before committing any record.

AMS2 mesh archives add secondary counts/payloads under the existing bounded, transactional schema. The reader also accepts AMS1, giving old surfaces an absent secondary channel. Packed scenes and resource factories preserve ArrayMesh and completed ImmediateMesh data in a fresh process.

Retained ordinary, custom, owned-RID, hardware/expanded MultiMesh, skinned and point/line/strip geometry preserve UV2. GPU vertex location seven carries float2 secondary UV to fragment location four; raw instance custom remains fragment location two and lighting metadata remains internal location three. The common interface accepts secondary input in GLSL/HLSL. Missing secondary data supplies zero. Compatibility draws the same stored meshes using primary sampling and explicitly rejects programmable materials through its existing capability gate. UV2 adds no automatic lightmap or alternate texture binding.

## Compressed attributes

[MeshCompression](../classes/MeshCompression.md) owns canonical four-byte UV/UV2 UNORM16 pairs and six-byte normal/tangent frames plus shared Vector4 UV scale. Float XY remains eight bytes; frame records follow the entire position block. A frame contains an octahedral axis word then an angle/handedness word. Color/custom/skin/index layouts retain their ordinary contracts; compressed attribute records order color (four), UV (four), UV2 (four), then selected custom records. Normal-only input synthesizes a tangent and tangent-only compression rejects. Nonorthogonal/zero input projects to a numerical frame and is not magnitude preserving. Joint packing reencodes normals during tangent regeneration while preserving exact UV data/scale.

The scale is zero for wholly [0,1] coordinates, otherwise twice each component's maximum absolute value across the corresponding channel. Encoding divides by that scale and adds 0.5; decoding subtracts 0.5 and multiplies. Whole-vector approximate-zero scale (all four components below 0.00001) retains the existing packing policy; zero components decode exactly zero. Scale overflow and any invalid later custom/position record reject before any write. Canonical bytes, including partial frame/UV patches, survive duplication, AMS7, fresh scenes and morph source refresh. Older AMS1–6 remain readable; archive preflight includes scale/count/format validation. All five topology consumers use decoded caches; the GPU canvas record remains 148 bytes, so there is no measured GPU upload or total-memory reduction claim.

[MeshCompressionTests](../../tests/Electron2D.Tests/MeshCompressionTests.cs) checks scaled and zero-axis precision, tangent synthesis/rejection, identity/180-degree/handedness endpoints, partial updates, late-record rollback, exact copy/archive bytes, legacy imports, regeneration, extraction, callbacks, fresh scene drawing and warmed edits. Its 70 orthonormal-frame records come from independent pinned C++ routines: reconstructed direction error below 0.001, angle codes within one quantum and axis codes within eight near 180-degree float cancellation. Those are corpus bounds, not a guarantee for arbitrary degenerate TBN. [MeshCompressionNativeTests](../../tests/Electron2D.Tests/MeshCompressionNativeTests.cs) verifies GLSL/HLSL UV/frame/custom pixels and compatibility geometry through ordinary/custom, morph, LOD, eighth-slot skin, per-instance, group and owned service paths. Each checks 24 warmup, 64 active and 64 idle complete frames at zero managed bytes. Evidence: `bin/mesh-compression-validation/2026-10-12/`. Native allocator totals, other platforms and human acceptance remain open under ADR 0021.
