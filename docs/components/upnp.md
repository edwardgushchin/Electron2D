# UPNP gateway discovery and control

Last updated: 2026-10-04

## Surface, ownership and flow

[UPNP](../classes/UPNP.md) owns ordered membership over borrowed [UPNPDevice](../classes/UPNPDevice.md) metadata objects. Shared [UPNPResult](../classes/UPNPResult.md) and separate [IGDStatus](../classes/IGDStatus.md) preserve discovery/control and gateway-assessment domains. [UPNPProtocol](../classes/UPNPProtocol.md) is internal. It reuses native sockets and [HTTPClient](../classes/HTTPClient.md); no additional native library/package, public backend handle or general SOAP action API is introduced.

Calls, queries, configuration and disposal require the constructing thread. A device can be added to multiple same-thread collections; duplicate membership is permitted. Clear/remove/replace/disposal release membership without disposing caller-held devices. Disposed devices are skipped by gateway selection; indexed access rejects a disposed entry. Devices have no retained socket; each network exchange closes its owned HTTP transport. Querying metadata is immediate. Discovery and commands allocate cold state and block explicitly, including when called from a scene callback. Applications needing background execution construct/use/dispose these owners on that caller-selected thread and marshal their own results.

## Discovery

Discover starts with timeout 2000 milliseconds, TTL two and case-sensitive filter InternetGatewayDevice. Negative timeout, TTL outside zero through 255 or null filter returns InvalidParameter before clearing old membership. Valid discovery clears membership. Source port zero is ephemeral, one maps to 1900, other valid ports bind directly. DiscoverMulticastIF accepts empty default, native name/ID or a matching address. IPv4 sends SSDP to 239.255.255.250:1900; IPv6 sends site-local ff05::c and link-local ff02::c with selected scope/hops. Default IPv6 selects an up non-loopback interface with an IPv6 address; unavailable family/interface reports a typed failure. Native multicast routing remains OS-dependent; browser raw discovery throws PlatformNotSupportedException.

Common filters search IGD/WANIP/WANPPP/root targets; other filters search ssdp:all. Actual M-SEARCH includes HOST, MAN, bounded MX and ST. Replies require a successful HTTP-like status, unique nonempty LOCATION/ST and an absolute HTTP location. Repeated location/target pairs deduplicate; distinct identities remain ordered. Replies are at most 16 KiB and the census at most 256 identities; overflow reports MemoryAllocationError rather than growing without bound. No valid response returns NoDevices. A discovered census with no matching filter returns Success with an empty list. Discovery waits the requested response interval, then performs bounded HTTP assessment for matching entries; timeout is not a whole-operation deadline.

Each device retains its advertised description URL and target. Description HTTP status/empty body/malformed XML/missing gateway service/invalid control endpoint are classified separately. Parsing requires the device namespace, prohibits DTD and external resolution, limits XML depth to 64 and decoded bodies to one MiB. URLBase and relative controlURL resolve as standard URIs; credentials, fragments and non-HTTP control URLs reject. WANCommonInterfaceConfig identifies the IGD role; ordered WANIPConnection 1/2 or WANPPPConnection 1 candidates are tested with GetStatusInfo and GetExternalIPAddress. A connected candidate with a nonzero valid assigned IP becomes OK and retains its service/control endpoint and routed local client address. Alternate candidates can succeed after a disconnected one. Each assessment uses that device's own description, correcting cross-device metadata assignment and stale backend return-code classification. Private/reserved assigned addresses remain valid local gateway endpoints; this does not establish external Internet reachability through upstream NAT.

## Commands and errors

GetGateway selects the first live OK entry; its convenience query returns empty on absent gateway or command failure. Add/delete convenience methods return NoGateway before validating device parameters when no gateway exists. Devices start UnknownError and empty strings; metadata is explicitly writable. IsValidGateway projects status without network access; arbitrary caller-authored configuration is validated when executing commands.

AddPortMapping first requires OK, external port one through 65535, internal port zero through 65535, exact UDP/TCP, nonnegative lease seconds and a valid local client IP. Zero internal port copies external port; zero duration requests a permanent lease. Empty label uses Electron2D. SOAP fields include empty remote host, enabled one and correctly escaped UTF8 label; arbitrary XML-invalid characters reject. Positive lease values are sent for the gateway to accept/refuse; lease/conflict policy and actual reachability remain the gateway's authority. No automatic renewal or cleanup is implied. Delete validates external port/protocol and can use explicit valid control metadata even without OK status, preserving the direct-device command contract.

Each GET/SOAP HTTP exchange has a five-second monotonic deadline and one-MiB decoded response budget. HTTP framing, fragmented/chunked bodies and transport teardown use HTTPClient. SOAPAction, envelope/body namespace, exact service/action response and fault codes are validated; ambiguous bodies/fields and wrong action replies reject. Known gateway faults map to stable UPNPResult identities; unknown codes return UnknownError. QueryExternalAddress requires exactly one valid IP field. Typed local/control outcomes replace integer error returns; index/null/thread/disposed misuse uses ordinary C# exceptions. Configuration/collection/disposal does not silently remove real gateway mappings.

## Verification and boundaries

[UPNPTests](../../tests/Electron2D.Tests/UPNPTests.cs) runs an independent native multicast SSDP responder and fragmented TCP SOAP gateway. A stalled independent peer verifies the actual five-second timeout. It checks default/bounds/order/borrowed lifetime/owner rules, reply dedup/filter/no-device behavior, URLBase/local route, connected/disconnected and malformed/empty/non-IGD/invalid-control descriptions, exact escaped mapping fields, deletion, all exercised SOAP fault mappings, wrong-action/DTD/oversize/IP failures, IPv4/IPv6 SOAP and public Node/SceneTree use. Sixty-four repeated metadata query cycles report zero managed bytes; discovery/HTTP/XML/command preparation and native allocations remain outside that interval.

A separate public consumer passed real IPv4 gateway discovery/status/external-address queries without mapping changes. Real gateway add/delete acceptance and externally routed connectivity, IPv6 routed multicast, other platforms, native allocator totals and human/rendered/editor/agent acceptance remain separate. These are native network/programmatic scene checks, independent of display protocol. See [platform verification](../platform-verification.md) and [ADR 0094](../decisions/networking.md#adr-0094).
