# Editor domain

Last updated: 2026-10-26

The editor is a separate desktop executable at [Electron2D.Editor.csproj](../../editor/Electron2D.Editor.csproj). It consumes the public runtime API and owns no runtime backend. The first slice is a persistent branded startup window, titled `Electron2D`, with a 1152×800 client area.

| Component | Types and integration | Current state |
| --- | --- | --- |
| [Shared project session](../components/project-session.md) | [ProjectSession](../classes/ProjectSession.md), [SessionClient](../classes/SessionClient.md), typed snapshots/requests/history in `Electron2D.Editor.Session.dll` | Shared owner/native views, guarded edits/undo, persistence/recovery and authenticated local attach |
| [Project jobs](../components/project-jobs.md) | [SessionProject](../classes/SessionProject.md), [SessionJob](../classes/SessionJob.md), [SessionScenario](../classes/SessionScenario.md) | Unsaved immutable build/run/capture, explicit native backends, stale attribution, cancellation/deadline/cleanup |

The runtime never references this assembly. Desktop targets follow [ADR 0021](../decisions/product.md#adr-0021); the current executable gate is Linux/Wayland. [ADR 0027](../decisions/product.md#adr-0027) owns the source/assembly boundary. [ADR 0090](../decisions/agent-native.md#adr-0090) governs shared authoring operations.

The [shared editor workflow](../components/project-jobs.md) now creates/opens a bounded source project, binds scene tree, position inspector, code/history and passive authored preview to one live session, and builds/runs immutable unsaved snapshots. Actual native captures retain exact input attribution and stale state. Failed opening preserves the current workspace; switching/shutdown preserves recoverable unsaved documents and retires jobs. The separate session library remains usable without UI.

Users can work manually, control an agent in the editor, or connect an external local client to the same operations. An [explicit no-UI owner and MCP bridge](../components/project-agent.md#programmatic-and-no-ui-paths) also permit authoring and jobs without opening the editor window. The host must already be running; only one owner can write. The current no-UI host retains unsaved recovery and grants no default save/discard rights. Continuing in the native editor requires stopping that host and reopening the project. Rendered game verification still requires its native backend/display. See [ADR 0090's user workflows](../decisions/agent-native.md#user-workflows-and-editor-independent-access) for the product contract and the component page for exact qualification limits.

[ADR 0090](../decisions/agent-native.md#adr-0090) stages 1–3 now execute for this bounded Linux binary-SDK/Codex profile. The real native-panel scenario verifies unsaved human/agent edits, stale conflict repair, actual capture, interruption and same-conversation reconnect. Read the [qualified profile and measured limits](../components/project-agent.md); this does not establish general agent productivity or human visual acceptance. General scene/resource operations, language services, arbitrary dependency closures, installed delivery, other platforms, concurrent agents and hot reload retain their own gates.

The next architectural requirement is [Git-backed project memory](../decisions/agent-native.md#git-backed-project-memory): every new game gets a local repository, canonical portable `AGENTS.md`, project documentation, current-state summary and six-section development journal available to a fresh agent regardless of provider or conversation. Qualified client profiles must actually load the shared engineering policy; new commits follow Conventional Commits 1.0.0. The [context/documentation contract](../decisions/agent-native.md#bounded-context-and-documentation-workflow) uses bounded bootstrap and sectioned retrieval instead of preloading the whole documentation tree. This belongs to editor/no-UI tooling, outside the shipped runtime. The current creator only writes `.gitignore`; repository initialization, instruction bootstrap, shared Markdown/journal editing and Git/context operations remain unimplemented.

The accepted [Git workspace](../decisions/agent-native.md#git-workspace-in-the-editor-and-operation-host) makes status/diff/history, partial staging, commits, branches, merge/conflicts, remotes/fetch/pull/push, worktrees and explicit recovery available inside the editor and through shared operations. It must protect dirty documents and other worktrees' shared refs. The [bundled development skill and provider targets](../decisions/agent-native.md#bundled-development-skill-and-provider-support) belong to the editor/tooling delivery. These capabilities are planned; current provider qualification is listed explicitly in the [support matrix](../components/project-agent.md#provider-and-client-support).

## Accepted delivery order

Stages 1–3 establish the bounded shared document owner, native authoring views, immutable job evidence and one actual executor through local operations and the task/conversation panel. Stage 4a adds Git-backed creation, shared Markdown/journal publication, conventional commits, bounded context and delivered skill loading. Stage 4b supplies the full Git workspace. Stage 4c qualifies the additional named executors/clients and expands operations, spatial context and composition with measured task success. Installed/foreign-platform delivery retains its gates. See [ADR 0090](../decisions/agent-native.md#delivery-and-acceptance) and the [coverage roadmap](../coverage/roadmap.md#live-project-and-agent-delivery). The measured real-agent task establishes only the stated bounded workflow; importer/exporter/plugin coverage, broader task productivity and human visual acceptance remain separate.
