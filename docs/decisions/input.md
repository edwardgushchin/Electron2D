# Input decisions

Last updated: 2026-10-25


Public process-wide service operations delegate statically to retained objects under [ADR 0095](singleton-services.md#adr-0095). Owning lifetime, threading and native resource contracts below continue to apply.

This log owns durable decisions for input events, action mapping, process-wide input state, and scene input propagation. Current executable behavior is described by the [Input domain](../domains/input.md), [Input runtime component](../components/input-runtime.md), and class documents.

## ADR 0038: Typed input events, action state, and scene propagation

- Status: Accepted; the native display/event-pump integration, including pointer emulation, is recorded in [ADR 0040](display.md#adr-0040)
- Date: 2026-09-21
- Last updated: 2026-10-25

### Context

Electron2D needs keyboard, mouse, touch, gesture, and controller input before a native SDL host exists. The stable Godot 4.7.2 Input/InputMap/InputEvent hierarchy is the coverage reference, with typed C# replacing Variant/Callable. Native root-window and viewport coordinate routing are implemented. Root viewport Control hit testing, mouse delivery and keyboard focus now run; Shortcut resources and the scene shortcut stage now execute; complete GUI routing and a MIDI product decision remain absent; native controller mapping and platform-info parity are still partial.

An earlier statement that a missing feature was merely "deferred" was not sufficient for context-free continuation. Every gap needs a concrete prerequisite and a rule that tells a later agent whether work is actionable.

### Decision

- `Input` and `InputMap` are non-disposable process-wide `ElectronObject` singletons registered permanently in `Engine`.
- Input events are typed mutable `Resource` subclasses. The implemented hierarchy is `InputEvent`; `InputEventAction`; `InputEventFromWindow`; `InputEventWithModifiers`; key, mouse button/motion, controller button/motion, screen touch/drag, and magnify/pan gesture types. Every event value is an inherited stored typed property descriptor whose revert default matches construction.
- Action names are ordinal strings. `InputMap` owns registration order and borrows live binding references. Configuration calls are lock-serialized; callers must not mutate or dispose a binding concurrently with matching. An all-device controller binding is a wildcard when it is the stored candidate, including exact binding lookup/deduplication.
- `ProjectSetting<InputActionSettings>` values under `input/<action>` are the versioned persistence contract. Version 1 stores a finite deadzone and at most 32 ordered typed `InputBindingSettings` records. The binding kind discriminates key, mouse button, controller button/axis and synthetic action events; only action-identifying fields persist. Unknown JSON members, unsupported versions, wrong setting types and invalid fields fail explicitly. No migration exists before a second version is defined; a future migration must transform an entire candidate before publication. The six active `ui_*` focus actions are built-in typed project settings, so initial map construction and later reload use the same defaults. Other action keys require explicit typed registration.
- `InputMap.LoadFromProjectSettings` prepares and validates a replacement map from `ProjectSettings`, then atomically swaps it under the map lock. Failure before the swap leaves current bindings and pressed state intact. Every affected action contribution is invalidated after the swap; `ProjectSettingsLoaded` is raised synchronously afterward and a throwing subscriber observes committed state. Old binding references remain usable if callers retained them; detaching them prevents later edits from changing the new map. Loading is an explicit project-setup operation and may allocate; warmed per-event matching remains allocation-free. Load the project file through `ProjectSettings` first when persisted values are wanted.
- Controller-axis events store the source motion value and derive raw `IsPressed` from absolute magnitude at least 0.5. Action matching independently applies each action's own deadzone, while `GetVector` composes raw strengths before applying its one circular deadzone. Version-one persisted controller bindings retain finite, usable ID and direction ranges even though caller-created events can store broader source values. Raw button/axis queries accept signed identities and return the last submitted per-device state; a negative physical device ID raises a typed C# argument error.
- Action-map descriptions omit synthetic action indirection. A synthetic event description uses the first concrete binding or falls back to its action name, preventing recursive description lookup and duplicate alternatives.
- `Input.ParseInputEvent` serializes parsing, validates the active loop's owner thread and execution state, rejects re-entry and source-capacity overflow, resolves mappings before mutation, commits raw/action state before callbacks, and synchronously forwards the same caller-owned event to the active `MainLoop`. A SceneTree with a Viewport root then localizes window input; positional callback events are temporary copies disposed after dispatch. Input state and by-event transition identity still refer to the original parsed event.
- Pointer emulation is an Input policy over typed source events. The first active touch contact produces left-button mouse input by default; optional mouse-to-touch translation uses left-button input and touch index zero. Generated events use device ID `-1`, precede the source event, and never recurse. Generated mouse events update raw and mapped state; generated touch events are scene-only. A setting change during an emulated press retains its matching release. Native SDL pointer counterparts are deduplicated before parsing. Source delivery continues after generated-event callback failure, and the failures are combined if both dispatches fail.
- Controller motion samples use the existing numeric `Vector3` under ADR 0033: acceleration/gravity in metres per second squared, gyroscope pitch/yaw/roll and stationary calibration bias in radians per second. These are sensor channels, not scene positions. `JoyMotionCalibration` is an immutable typed projection of the gyroscope-offset record; absent/uncompleted calibration returns null. The native owner enables available channels transactionally, samples once after its event pump, applies manual bias calibration and gravity filtering, and retires data with the device identity. Unsupported devices retain absent results; disabled or focus-suppressed readings are zero. Read snapshots use the Input lock; mutations require the live display owner. The connected slice and its verification limits belong to [controller motion sensors](../components/gamepad-motion.md).
- `Input` exposes typed mouse mode and cursor shape controls through the active `DisplayServer`; the display remains the single owner of native pointer state and SDL errors. Without a display, pointer control fails while managed input remains usable. The default-cursor call retains a default separately from the active shape; root-viewport Control hover can override it and refresh native selection immediately. The pinned synthetic mouse-motion side effect and complete nested viewport routing remain separate gaps. A pointer warp uses client-area coordinates and explicitly rejects backends without the capability, including Wayland.
- The native SDL keyboard adapter keeps layout-aware `Keycode`, physical `PhysicalKeycode`, and localized `KeyLabel` distinct. It derives the label from the scancode under the active layout without SDL's Latin-letter normalization and preserves printable non-ASCII Unicode scalars in the typed key vocabulary. Left/right modifier scancodes identify key location. `InputEventKey.Unicode` stays zero on native SDL key events: they contain no produced text scalar, and separate text-input events may carry multiple scalars or an IME commit without identifying the producing key press. Native committed text and IME composition now enter the root scene as complete typed strings and codepoint selections through focused Control hooks/events and the existing scene-wide IME notification. They are not synthesized into key events. A future slice claiming per-key InputEventKey.Unicode parity must provide a native per-key Unicode source; key-to-text correlation from the SDL event stream alone is not a valid substitute.
- Registered binding changes use an internal invalidation channel before public `Resource.Changed` delivery, so a throwing user handler cannot preserve stale action contributions. Disposing a registered binding removes it from every affected action before public disposal observers. Motion accumulation commits all fields atomically before its single public change notification.
- Positional transforms require finite inputs and validate derived event coordinates before allocating a copy. They transform local position and applicable local motion; pan gesture delta remains the host-reported value while only its position changes.
- `SceneTree` dispatches a captured hierarchy in reverse depth-first order through `OnInput`, then routes root viewport pointer input to a hit Control or keyboard/controller input to the focused Control, then `OnShortcutInput` for key, gamepad-button and direct shortcut events, followed by keyboard-only `OnUnhandledKeyInput` and `OnUnhandledInput`. `SetInputAsHandled` stops the current and later stages. Removed/disposed nodes are skipped; callback failures are aggregated after eligible delivery continues. The process-wide action map starts with Tab/Shift+Tab and directional `ui_*` bindings for arrow keys, D-pad buttons and left-stick axes on any controller; callers may rebind or erase them. Navigation runs after focused GUI callbacks when the event remains unhandled. Exact spatial ranking, scroll clipping and nested viewport routing remain separate gaps.
- Ready notification enables overridden typed input callbacks before OnReady under ADR 0006; callers retain explicit disabling and pause-aware control through `InputEnabled`, `ShortcutInputEnabled`, `UnhandledKeyInputEnabled`, `UnhandledInputEnabled`, and `CanProcess()`. These four switches are local processing metadata: coordinated getters and owner/current-group setters share the other callback switches under ADR 0006, with capture and receiver lifetime validation. Setters do not authorize worker input dispatch, hierarchy edits or physical authoring. All six public callback switches have stored typed descriptors; detached scene reconstruction precedes automatic ready preparation.
- Process and physics just-pressed/just-released windows are independent. Each lane clears its own transition state in `MainLoop` `finally`, including failed callbacks. Warmed non-emulated event matching and scene traversal reuse buffers and allocate no managed memory; generated pointer events and positional viewport-conversion copies allocate short-lived resources.
- `Shortcut` owns a copied ordered array of borrowed nullable input events; exact event matching uses live alternatives, while a direct `InputEventShortcut` matches resource identity. Nested shortcut events are rejected as alternatives before assignment. The direct event starts pressed and remains outside action-binding families. Resource copies preserve aliases and deep-copy selected shortcut/event subresources.
- Root GUI delivery also captures touch contacts by index, routes drag/release to the captured control outside its rectangle, and applies local transforms and processing gates to touch, gestures and mouse events. Paused or disabled buttons cancel transient attempts without activation or a toggle-value change, correcting the stuck-contact case when the release is suppressed during pause. Always-processing controls remain active. This is the bounded pre-release correction allowed by ADR 0034, not a claim that the pinned source already cancels this case.
- `Control.ShortcutContext` is a weak node identity: unset means global, a live context accepts its focused node or descendants, and an expired context remains inactive until explicitly cleared. Packed scenes capture a relative path under ADR 0023. The root GUI mouse capture records all pressed button bits; additional buttons preserve the capture until the final release. Keyboard focus follows the left-button ancestor policy.
- Root-viewport GUI drag/drop projects dynamic source data through `DragPayload<T>` and a drag-specific non-generic base for polymorphic target hooks, without a general `Variant`, public `object` value or untyped dictionary under ADR 0001. Payloads borrow caller values and last only until drop/cancel; detached parentless preview Controls transfer to a temporary highest-layer canvas and are disposed at drag end. Control virtual hooks and nullable typed forwarding delegates cover production, acceptance and delivery. Viewport exposes borrowed drag state, a signed threshold initially sampled from `gui/common/drag_threshold`, description and cancellation; a left-held motion attempts the source/ancestor chain only after travel exceeds the threshold, while an explicit force starts immediately. Target checks walk the hit Control/ancestor chain until a stopping filter, using each candidate's local point. Left release/press can drop; right press or `ui_cancel` cancels. Node drag-begin/end notifications observe respectively active and cleared payload state; drop callback errors still finalize and leave success false. Preview and source removal, scene rollback and teardown clear ownership before hierarchy exit. Native GPU and compatibility paths draw the preview above ordinary canvas layers and update CanDrop/Forbidden cursor feedback. Nested viewport and cross-window drag routing remain separate blocked capabilities.
- Accessible drag/drop uses the existing connected viewport drag transaction and typed payloads. Control.AccessibilityDrag prepares preview ownership before the producer callback; AccessibilityDrop tests the focused target/ancestor chain and finalizes through the ordinary drag completion path. Keyboard requests pass positive-infinite coordinates to virtual/forwarded drag hooks as the reference non-positional sentinel. Public GetDragData/CanDropData/DropData convenience calls retain finite-coordinate guards. LineEdit preflights complete normalized drop capacity and rechecks after focus/IME preparation, so truncation cannot silently delete the unaccepted source suffix. The same protection applies to ordinary pointer drops; it corrects the pre-release partial-insertion/data-loss behavior. Built-in text controls use selection/caret state for that sentinel, without requiring a preceding pointer press; this corrects the pinned keyboard-start dependency on pointer-only drag-attempt state. The permanent ui_accessibility_drag_and_drop setting starts unbound and remains configurable. Unhandled focused GUI input invokes drag/drop after ordinary GUI callbacks, with by-event transition filtering for analog input.
- Control.GrabClickFocus coalesces the last target per viewport into the existing deferred queue. It transfers an existing capture only: held left/right/middle buttons release the previous Control directly with internal device identity, then corresponding presses reach the target in the next captured deferred batch. All capture bits remain until real releases, keyboard focus/global pressed state are unchanged, and synthetic events bypass scene input/unhandled stages and parent bubbling. Targets are weak; stale target/viewport work cancels. Release failures continue other releases and schedule presses before reporting; target disposal/retargeting cancels stale presses. Requests and capture are runtime state, not packed properties. Control.GetScreenPosition uses the accepted screen transform; Control.WarpMouse composes local/canvas/viewport coordinates and native integer validation. Embedded viewports use their containing Window, while absent native hosts and unsupported desktop placement fail explicitly.
- Typed C# exceptions replace numeric error codes. Dynamic `Variant` event payloads, string-based calls, and untyped metadata are permanently excluded by ADR 0001.
- The SDL host now owns joystick/gamepad subsystem lifetime and native handles. Input owns typed identity and capability snapshots, mapping overrides, per-device pressed state, vibration requests and the unfocused policy; controller events follow ordinary InputMap and SceneTree delivery. The built-in typed project setting supplies the Engine.Run startup policy. Virtual devices passed initial/hotplug, mapped/raw input, remapping, rumble/LED, ignored vendor/product IDs, per-device isolation and scene/action delivery on Linux Wayland and dummy. The exact SDL2 mapping grammar, Steam/XInput info fields, deferred connection-signal timing and physical hardware behavior remain Partial in coverage. A warmed virtual-button probe measured 28,672 managed bytes for 128 active native events and zero for 128 idle event pumps on dummy and Wayland; active native event construction remains an ADR 0014 allocation gap. The graph authoring SDL motion producer also measures 145408 managed bytes over 64 prepared native input/frame intervals, while the actual 64 graph handler and render intervals measure zero. Native event construction and GUI transformed-event ownership require their own complete scoped borrowed-event preparation/lifetime layer; the graph control implementation does not close that shared producer gap.

Manual device sensor values use four independent retained Vector3 fields under ADR 0033. Static getters and setters serialize each complete value through the Input lock on any thread, including during Engine execution. Values initially contain zero and copy every floating-point component unchanged, without normalization, calibration, input events or native startup. This supports device-free debugging; values survive Engine stop/restart until explicitly replaced. These operations are separate from per-controller motion state. Manual setters execute completely; getter coverage remains Partial until the owning mobile adapter supplies automatic device acquisition. The native acquisition row below refers to that missing host producer.

DisplayWindowEvents input subscriptions add the per-native-window observation phase owned by ADR 0044. Caller-owned Input.ParseInputEvent and native/emulated events share it after state commit and before scene routing. With active native-window input subscribers, off-owner parsing rejects before state mutation; without that native observation phase the existing input ownership rules remain unchanged. This phase preserves source-window selection, untagged broadcast, recipient snapshots, retirement and independent failure delivery.

### Deferred coverage and exact implementation triggers

The following items are **not actionable now** unless their trigger is present in the repository or the user explicitly authorizes the named prerequisite in the same task. They must be included in the prerequisite's first production-ready vertical slice unless the row says a later decision is also required.

| Deferred item | Exact missing dependency | Implementation trigger | When to implement |
| --- | --- | --- | --- |
| Native mobile accelerometer, gravity, gyroscope and magnetometer acquisition | Mobile sensor adapter, native capabilities/permissions and device delivery; Vector3 numeric values are already accepted under ADR 0033 | The owning mobile host executes sensor acquisition and cleanup | In that mobile sensor slice; controller delivery does not establish mobile device support |
| MIDI event type, device enumeration, and message delivery | Product approval for a MIDI domain plus a selected native host API | A user-approved MIDI ADR names scope, host API, ownership, and platform matrix | Only after that separate decision; MIDI is not automatically part of SDL input work |
| Complete GUI control consumption and nested viewport input routing | Root Control pointer/focus/hover/action navigation and descendant rectangle clipping exist; scroll clipping, exact navigation ranking, exact draw order and nested viewport ownership remain | The first complete GUI/nested viewport routing slice supplies those missing behaviors | Extend root GUI consumption between `OnInput` and unhandled stages and add independently owned nested viewport routing; root viewport coordinate conversion already runs |
| Synthetic mouse-motion refresh after changing the default cursor | Implemented through internal mouse motion and containing-window routing, with safe-point coalescing during active execution | Current GUI routing and nested viewport ownership | Changed defaults use the last parsed client position; explicit Viewport refresh queries native pointer. User Node input callbacks omit internal events, GUI hover/cursor and passive physics hover execute. |

Explicit Viewport cursor refresh and changed Input default-cursor policy emit internal mouse motion. GUI and passive physics hover execute; Node user input callbacks omit the internal device. Requests during frame/input/lifecycle delivery coalesce at the next safe point to preserve SceneTree non-reentrancy, and synthetic callbacks cannot reenter refresh. The containing Window evaluates parent overlap before nested viewport forwarding. Default changes retain immediate Control cursor precedence, use the last parsed client position and preserve real button polling.

### Consequences

Gameplay uses deterministic typed input and scene callbacks with a native SDL event source and pointer emulation. No method reports fictitious hardware success. A later agent can start a deferred row only by demonstrating its named trigger or by first obtaining the separate decision required by the row.

### Virtual game controls

TouchScreenButton and VirtualJoystick publish independent owner/slot contributions into the retained Input action aggregate. Releasing or rebinding one control cannot release another control or a physical/manual source; duplicate joystick action names aggregate separate axis slots. Unknown/empty actions do not publish a contribution and remain inspectable configuration warnings. Touch-button action notifications use a bounded owner-thread FIFO after the current input traversal, avoiding unsafe traversal reentry; scene callbacks observe committed state. Discrete generated InputEventAction notifications allocate and are disposed after delivery. Joystick motion reuses prepared contribution storage. Hide, pause, disable, focus loss, exit and disposal retire held contributions. Canceled touch contacts do not produce tap/flick outcomes.

Active virtual contacts use the existing internal processing lane to retire a lease at the next frame when inherited input/pointer/viewport policy prevents further contact delivery. Selected authoring subtrees suppress gameplay input and retain preview decoration; runtime hardware availability still controls TouchscreenOnly outside authoring.

Native popup input extends the existing Window host with retained opening order, owner safe areas and native root-client positional routing. Exclusive children with a distinct native host suppress parent WindowInput reception. Embedded exclusive children share their native ancestor and continue through embedded routing. Nonexclusive retargeting preserves the original native window ID, localizes only the popup delivery and releases transformed events. The native popup profile exercises exclusive, mouse/touch, consumer and force-retirement paths; prepared render intervals exclude the existing allocation-capable SDL event producer.
