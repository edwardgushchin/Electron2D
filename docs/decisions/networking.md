## ADR 0094: Typed native streams and packet transports

**Status:** Accepted

### Context

Games and tools need real byte streams, TCP listeners, UDP endpoint routing and local IPC before HTTP, TLS, WebSocket or multiplayer layers can execute. Existing typed C# and ownership rules remain authoritative under [ADR 0001](product.md#adr-0001), [ADR 0003](core-object-runtime.md#adr-0003), [ADR 0014](resources.md#adr-0014), [ADR 0021](product.md#adr-0021) and [ADR 0051](product.md#adr-0051).

### Decision

- Native sockets use the .NET socket backend internally. Raw socket handles and native option identities remain private. Linux listener setup applies SO_REUSEADDR without SO_REUSEPORT through one private pinned-handle call, allowing restart while accepted connections remain open and rejecting simultaneous listener sharing. Other native hosts use explicit exclusive listener binding pending their own verification gate. Browser raw sockets fail explicitly; an in-memory StreamPeerBuffer remains platform independent.
- Preserve the StreamPeer → StreamPeerSocket → TCP/UDS inheritance and SocketServer → TCP/UDS listener inheritance. PacketPeer owns packet reads; UDP and framed-stream consumers preserve packet boundaries. Runtime types inherit ElectronObject directly where the source uses its reference-counted object role. Managed references own object memory; IDisposable owns socket cleanup. Calls and disposal require the constructing thread, validated before disposal starts.
- Full stream reads/writes may wait until requested progress or failure; partial operations return a byte count without waiting. Use caller spans for repeated work and caller-owned arrays for snapshots. Primitive APIs use exact signed/unsigned C# widths and IEEE half/single/double encodings. BigEndian also governs string length prefixes. ASCII output replaces unrepresentable scalars with spaces. UTF-8 input skips a leading BOM, stops at NUL and replaces each malformed byte. GetString preserves Latin-1 byte decoding with NUL termination. Native connection, DNS and I/O failures use typed exceptions; socket phases use one shared StreamSocketStatus. GetStatus is cached; Poll advances nonblocking connection and detects FIN only after queued bytes drain.
- String reads have an explicit writable MaxStringBytes allocation budget, initially 16 MiB. Datagram and framed-packet buffer configuration rejects allocation above 64 MiB. UDP receive budget rounds up to a power of two and charges 24 metadata bytes per packet; records additionally retain IPv6 scope. Overflow drops whole datagrams. Framed stream packets use a fixed little-endian uint32 length independent of StreamPeer.BigEndian, ignore empty outgoing packets and accept zero-length incoming frames. Buffer resize rejects queued input; headers above the payload budget fail instead of permanently stalling a full buffer.
- PacketPeer.GetPacketError projects last-read success/unavailable/error through PacketReadStatus; LastReadException retains the original failure. Too-small caller storage leaves a packet queued. Variant serialization and its encode-buffer budget are excluded as dynamic wire representation under ADR 0001; raw packet/stream bytes are fully implemented and callers choose their typed message protocol.
- Accepted TCP/UDS connections transfer socket ownership and survive listener Stop. UDPServer owns pending peers, weakly tracks accepted peers and routes packets by endpoint. Accepted UDP peers borrow its shared socket; peer Close removes its endpoint without closing the listener. Server Stop disposes pending peers and detaches accepted peers. Lowering MaxPendingConnections trims newest pending peers; zero rejects new endpoints while accepted endpoints keep receiving. This corrects the pinned reversed limit-trimming loop. StreamPeerBuffer shrink clamps its cursor instead of allowing a negative readable count; Duplicate copies bytes and resets endian/cursor.
- Consumer-defined transports inherit StreamPeer or PacketPeer and override typed span/progress, availability and packet-capacity hooks. Extension-only facade identities map to these managed bases; native pointer/error-out ABI is adapted to spans and exceptions. GetMaxPacketSize reports outgoing raw payload capacity (UDP conservatively 65507; framed streams use their configured payload limit).
- Scope the first delivery to low-level native transports and framing. TLS/DTLS, certificate/trust resources, HTTP/WebSocket parsing, resolver services, ENet/WebRTC, multiplayer scene replication and router discovery retain their own concrete dependencies. The later integrations below add TLS stream ownership and HTTP/HTTPS with incremental compression; other protocol families retain their concrete dependencies.

### Verification boundary

NetworkingTests exercises native Linux x64 IPv4/IPv6 TCP/UDP, Unix-domain sockets and filesystem cleanup, loopback DNS configuration, independent binary/framing bytes, UTF-8 edges, partial transfers, FIN, port conflict/restart, packet budgets/zero datagrams/connected filtering, UDP peer routing and lifetime, multicast join/leave on loopback, ownership rejection and a public Node/SceneTree request/reply workflow. Headless scene scheduling does not establish rendered output. 64 warmed buffer-number, TCP number/poll and UDP caller-span packet/metadata cycles measure managed allocation after preparation; constructor/connection/DNS/snapshot/string/native allocator costs and broader network throughput remain outside that measurement. Other platforms, routed multicast/broadcast delivery, real network conditions and owner acceptance remain unverified.

### Rejected alternatives

- Publish native handles or socket option codes: ties consumers to a platform backend.
- Use Task/async operations for every small polling step: adds heap/state-machine work where immediate span/socket operations suffice. DNS resolution and full I/O remain explicitly blocking cold/caller-selected operations.
- Recreate heterogeneous error/data arrays or dynamic value serialization: conflicts with typed C# contracts.
- Model UDP peers as separately connected listener sockets: loses the shared listener's endpoint routing and stop ownership.
- Silently accept impossible frame headers, negative readable counts or reversed pending-limit trimming: preserves defects instead of useful transport semantics.

### TLS stream and security resource integration

The next connected delivery adds X509Certificate and CryptoKey resources, immutable TLSOptions and StreamPeerTLS over any borrowed StreamPeer. Resources use BCL PEM/DER parsing, typed filesystem paths, copied duplication and explicit Changed delivery. Certificate loads append an ordered chain; key loads replace transactionally. Key material buffers are cleared on replacement/disposal/finalization, while caller-exported strings remain caller-owned. TLS retains keys/certificates during use and rejects payload replacement, copying/reset and resource disposal until disconnect. The generic ResourceLoader recognizes `.key` private keys and `.crt` certificate chains with existing weak-cache modes and atomic decode-before-replace while preserving cached metadata.

64-bit Linux TLS uses system OpenSSL 3 (`libssl.so.3`, `libcrypto.so.3`) behind private source-generated imports and deterministic SafeHandles; that Linux dependency is not redistributed. Windows/macOS use private pinned OpenSSL 3.6.5 from their native packages, retaining notices and private loader identities. Cdecl imports preserve x86/LLP64/LP64 C-long widths. System-trust clients first validate peer chains with .NET OS trust on the polling owner, then OpenSSL verifies TLS certificate policy and expected name/IP; custom CA/unsafe semantics remain unchanged. Certificate downloads and automatic revocation fetching are disabled. The callback bounds supplied chains to 64 certificates and individual DER encodings to 1 MiB, catches exceptions before native return, and never writes OS trust stores. Producer/package and complete runtime execution are separate gates; full Windows/macOS acceptance remains pending. TLS 1.2 is the minimum, with TLS 1.3 negotiation. Fixed BIO/prepared transport buffers retain owner polling without Task/worker access to user streams. Setup/handshake is cold allocating work; warmed record I/O reuses spans/storage. Mobile/browser still require integration and executable fidelity gates, failing explicitly when unavailable.

Validating clients use system trust or a custom chain and the caller's expected DNS/IP name (or the option override); an empty expected name checks the chain only. ClientUnsafe disables name checks; a supplied custom chain still requires valid chain verification, while null disables certificate verification. Server options require a matching private key and leaf certificate, with remaining certificates sent as intermediates. Errors use AuthenticationException, with a distinct hostname/IP mismatch TLSStatus; failures release native state/retention and preserve the borrowed transport. This corrects the pinned initial-client-handshake classification that labelled every immediate failure as hostname mismatch. Poll peeks application records without consuming plaintext and drains encrypted output. Full I/O can wait; partial I/O is bounded and may accept plaintext into pending encrypted output. Disconnect sends a best-effort close notification when the underlying transport permits it, frees TLS state and never closes the borrowed stream. Abandoned sessions finalize native state and resource retention without transport access.

The built-in SslStream is retained as an independent interoperability oracle. Its async read/handshake contract does not directly supply this API's synchronous nonblocking polling and constructing-thread callbacks, so it is not used as a worker-thread adapter. The cryptographic operations below add generation/signing/encryption; the DTLS integration below supplies datagram encryption; integrations below add HTTP/HTTPS and WebSocket; raw TLS does not claim those protocols or general resource saving/serialization.

### HTTP and stream compression integration

HTTPClient implements HTTP/1.1 over the existing TCP/TLS layer or a borrowed StreamPeer. DNS lookup is asynchronous cold work; polled address candidates preserve fallback. The TCP local port is captured at binding before nonblocking connect, avoiding an endpoint query that consumed pending connection failure in the backend. Native owned connections and options close deterministically; a supplied connection remains caller-owned. The HTTP owner is its constructing thread. Shared HTTPMethod/HTTPResponseCode/HTTPStatus and separate HTTPRequestResult preserve enum domains under ADR 0051; unknown valid numeric response codes remain representable. Typed ordered scalar/repeated query entries replace dynamic dictionary value formatting; callers format other C# values before query construction.

Requests use validated origin/absolute/CONNECT/OPTIONS targets, copied UTF-8/raw bytes and headers, engine identity, Host, optional matching Content-Length and default Accept. Forward proxies use absolute targets; HTTPS proxies complete CONNECT before target TLS verification. Outbound request transfer coding is unsupported and rejects explicitly; the reference raw request API supplies a complete body with known length, not a streaming upload contract. Response parsing handles informational messages, headerless/bodyless/HEAD/CONNECT/upgrade responses, fixed-length, chunked and close-delimited bodies. Chunk extensions/trailers are consumed without contaminating the next exchange. Fixed prepared header/chunk-line budgets reject oversized data; caller-span body reads reuse storage. Reject conflicting/negative lengths, ambiguous TE/CL, malformed fields/status/chunk delimiters and truncated framed bodies. This corrects source headerless-response rejection, informational/headerless-body ambiguity, chunk-extension rejection and missing-length persistent-response data loss. Header snapshots consume their availability; body metadata remains separate.

HTTPRequest is a Node with internal scene processing, typed completion, progress, cancellation, redirects, timeouts, memory/file sinks and gzip/deflate decoding. Dedicated-worker mode creates and operates its own HTTPClient on that worker; only the scene owner delivers completion. Cancellation/tree exit joins worker cleanup, suppresses stale results and does not deliver a completion signal. State/resources release before event delivery so reentry and callback failure remain safe. Typed settings store in PackedScene without active operations. Timeout samples a finite nonnegative scene-process duration when started; live gzip/redirect/TLS/proxy configuration follows the documented response/new-connection boundaries. Unsafe-method 301/302/303/305 redirects become GET with cleared body/content headers; only safe methods auto-follow 307/308. Cross-origin redirects strip credential/cookie/Host fields. File transfers stage a sibling temporary file and commit only after a successful complete/decoded body, preserving an existing destination on cancellation/failure. This intentionally corrects destructive partial-file handling and redirected GET retaining the previous request body.

StreamPeerGZIP supplies the actual bounded incremental gzip/zlib prerequisite rather than a convenience facade. It uses the .NET 10 runtime's existing System.IO.Compression.Native PAL ABI through private source-generated imports and SafeHandle state; no new native package or vendored source is introduced. Codecs prepare native state/output capacity at Start, borrow pinned spans per call, support output backpressure and concatenated gzip members, and expose IsFinished for strict end-of-stream validation. HTTP decompression consumes wire data progressively and checks decoded limits before output; malformed/checksum/truncated compressed bodies fail instead of reporting success. Finish is compression-only and retains partial finishing state for drain/retry. The public BCL GZipStream was rejected as this incremental validator after an executable probe showed it accepting a gzip with a missing trailer. The private ABI is tied to the selected .NET 10 runtime and needs executable packaging verification on every claimed host. Native codec allocator totals remain external/unmeasured; engine PAL-state and buffers allocate only during preparation.

Prepared HTTP body-span/poll and gzip member/decode/read/reset intervals have zero-managed-allocation checks. Request construction, header snapshots/parsing transitions, DNS, native handshakes, convenience arrays, aggregate response buffers and file I/O remain explicit cold/loading work. HTTP/HTTPS/worker/proxy checks run natively on current Linux; browser HTTP host permissions and foreign runtime/backend packaging remain separate. Unified project/editor tools, general worker/job APIs, WebSocket/multiplayer protocols and real routed throughput are not established by this delivery.

### WebSocket message integration

WebSocketPeer extends PacketPeer with polled WS/WSS client and server upgrades, complete binary/text messages, close/control frames, heartbeat, subprotocol/header configuration and native TCP metadata/options. Client establishment reuses HTTPClient with an internal parsed HTTP-version check; server establishment borrows any live ordered StreamPeer, including pending TLS and consumer transports. Native client connections own their HTTP/TCP/TLS state; accepted/custom streams stay caller-owned on close/dispose. Closed/Connecting/Open/Closing and Binary/Text use distinct top-level WebSocketState/WebSocketWriteMode domains. Source calls adapt Error to typed exceptions and byte snapshots to spans/typed arrays; URL acronyms stay uppercase under ADR 0045.

Both roles require HTTP/1.1, valid upgrade tokens and nonce/subprotocol contracts. Server request parsing checks exactly three request-line parts before accessing the version, correcting the pinned unchecked index. Client validation accepts a Connection token list instead of requiring an exact single string. Required handshake fields reject caller overrides; malformed authority, header injection, nonce length, unsolicited subprotocol/extension and oversized handshakes fail explicitly. Handshake capacity is 4096 bytes. Extensions are not negotiated. Server extension offers can be ignored, but client extension responses and subsequent RSV bits fail. Configured subprotocols require a match; server selection preserves offered client order.

Prepared bounded byte rings and value metadata replace per-message native queue allocation. Configuration changes for buffer/queue capacity require Closed state; byte budgets are at most 64 MiB and packet counts at most 65536. Zero output configuration selects a prepared 64 MiB ceiling rather than unbounded growth. Four additional outgoing control records and fixed framing/control byte reserve preserve progress under application pressure. Inbound completion retains one accumulator and pauses receive until queued capacity frees; control pressure pauses receive until flush. Span/text sends copy into owned storage before return and overflow fails before enqueue. Text requires strict UTF-8 and fragmented text validates only after full assembly. Frame parsing enforces mask direction, canonical lengths, continuation order, control limits and reserved bits/opcodes. Native client masks use the BCL cryptographic RNG; unmeasured OS/crypto/TLS native internals remain external.

Ping echoes exact pong payload; monotonic heartbeat aborts an unanswered previous ping at the next interval. Close waits for a peer confirmation or can abort explicitly with a negative code; ordinary close has no implicit timeout. Closed metadata preserves peer reason/status, empty-close 1005 or a local protocol error; transport/forced closure reports minus one. TLS-buffered plaintext drains before treating native TCP EOF as WebSocket EOF, correcting premature final-close loss observed in the independent WSS check. No arbitrary background I/O adapter touches caller streams: BCL WebSocket is the independent asynchronous interoperability oracle, while runtime polling stays on its constructing thread.

WebSocketTests verifies real native Linux WS/WSS in both roles against independent .NET peers and scene-owned public polling, plus fragmented wire/control/security/backpressure/lifetime edges. Prepared server active/idle and native WS/WSS client mask/text/poll/span intervals each run 64-cycle zero-managed-allocation checks. Handshakes, snapshots, setup, diagnostics and external native allocation are separate; browser/foreign-host/routed/owner acceptance remains unverified. The multiplayer integration below adds the typed MultiplayerPeer owner and WebSocket consumer. Other protocols and unified project/editor tooling remain separate slices.

### Typed multiplayer and WebSocket cohort integration

MultiplayerPeer extends PacketPeer with shared MultiplayerConnectionStatus/TransferMode domains, typed identity/routing/next-packet metadata, virtual channel/mode/admission settings, lifecycle and Action<int> peer events. Managed users inherit this base directly; MultiplayerPeerExtension native pointer/Error/script-array hooks map to the same managed virtual properties/methods and PacketPeer span hooks. No duplicate extension wrapper or dynamic values are introduced. Events commit state before owner-thread dispatch, enumerate all subscribers without allocating on success and aggregate callback failures. GenerateUniqueID uses BCL cryptographic randomness in the positive nonreserved ID domain, with host collision checking. OfflineMultiplayerPeer models the reference local authority: permanently Connected/server/ID=1, no remote packets, discarded sends, successful empty reads and stable identity across Close. The higher typed scene integration below now supplies default SceneTree/Node multiplayer assignment.

WebSocketMultiplayerPeer supplies a native WS/WSS server/client cohort and owns the complete listener/accepted TCP/TLS/WebSocket lifetime. Clients become Connected only after receiving the first binary four-byte little-endian ID greater than one; the server sends this before its connection event. Outgoing client bytes go to the server, while server routing supports broadcast, positive target and negative exclusion. Actual transport metadata is Reliable/channel zero; requested settings retain their values without pretending WS supplies independent channels or unreliable delivery. Relay capability advertises the higher MultiplayerAPI contract, not automatic byte relay. Preserve the nine-byte advertised protocol reserve while clamping small/zero configurations to a valid nonnegative effective limit; do not invent an application envelope. Empty application messages are ignored/consumed.

Per-peer WebSocket budgets and a separate prepared host inbox/scratch replace per-packet native allocations. Capacity setters require Disconnected; buffers are bounded to 64 MiB and packet count to 65536. At least four bytes and one slot are required for ID establishment; reject impossible setup rather than connecting forever. Aggregate receive overflow applies backpressure to per-peer queues. Peer membership and connection/handshake work remain cold lifecycle transitions; repeated ready routing/reads/Poll/events do not allocate. Protocol/header templates apply to future transports and timeout/admission remains live. Whole monotonic handshake timeout includes Open waiting for identity, correcting the pinned early-return timeout bypass. Native errors drop only their connection. Broadcast attempts all recipients and reports aggregate failures instead of silently losing send errors.

Normal disconnection polls a clean close before detach/event; forced local disconnect and Close suppress their local events. Maps/state detach before callbacks. Recursive Poll rejects; callback Close/recreation invalidates old iterations through generation tracking. Cleanup releases remaining chains despite disposal subscriber failure, prevents recreation during cleanup and makes nested Close idempotent. Borrowed GetPeer references never transfer transport ownership. Existing copied server inbox packets retain source metadata after peer departure; host Close clears the inbox. These rules correct mutable-map callback invalidation and nondeterministic accepted-chain lifetime.

MultiplayerTests verifies native Linux WS/WSS cohorts with two clients and public scene polling, independent ID/raw-message wire acceptance, managed extension/offline contracts, routing/metadata/pressure/refusal/deadline/error/callback/lifetime boundaries and 64 warmed custom event/packet plus WS/WSS active/idle zero-managed-allocation intervals. Native TLS/OS/RNG allocation, foreign/browser/routed/human acceptance are separate. The typed scene integration below supplies MultiplayerAPI/SceneMultiplayer RPC/path/authority dispatch; the executable replication integration below supplies synchronization/spawning; the ENet integration below supplies native channels; WebRTC retains its backend dependency; transport readiness does not claim scene replication or unified editor/agent tooling.

### Cryptographic operations and prepared contexts

Crypto, HashingContext, HMACContext and AESContext use the platform BCL provider internally with no new native package or public backend handle. Shared flat HashType and separate AESMode preserve domain identity. Owner-thread operations/disposal and spans/typed exceptions adapt the native packed-array/Error ABI. Asymmetric calls borrow a locked independent key snapshot; resources retain their existing transactional load/copy and TLS replacement/disposal guards. Generated RSA/private keys and RSA/EC self-signed SHA256 X509 v3 CA identities use existing save/loader/TLS paths.

Preserve MD5/SHA1/SHA256 digest widths, SHA1/SHA256 HMAC, RSA PKCS1 encryption/signatures, EC DER signatures and raw AES128/256 ECB/CBC semantics. Hash/HMAC Update and HMAC keys require nonempty input; no-update Finish remains valid. Crypto.HMACDigest requires a nonempty message. AES uses exact blocks without padding/authentication, permits empty update and exact in-place buffers, and exposes live CBC chaining IV. Validate capacities/partial overlap before mutation; Finish closes digest computations, while AES Finish is idle-safe. Key sizes depend on provider support. Certificate generation requires CN/O/two-letter C, strict ordered fourteen-digit UTC dates, defaults matching the maintained contract, positive random serial, CA/path zero and no implicit SAN. Typed validation avoids failed or partially authored identity state.

Prepared digest/HMAC/AES span operations and random/comparison reuse storage; setup/import/asymmetric/snapshot calls allocate explicitly. CryptoTests verifies known/RFC/NIST vectors, RSA/EC wires with an independent BCL oracle, generated typed resource save/load, native TLS trust/interoperability and key use during TLS retention. Sixty-four warmed prepared intervals measure zero managed bytes. Provider-native allocation, foreign policies/platforms, routed traffic and human/editor/rendered acceptance remain separate. Existing authenticated file encryption is not changed by this raw AES API.

### Typed scene dispatch, authentication and relay

MultiplayerAPI is an owner-thread managed extensible base with a typed default factory. SceneMultiplayer supplies offline authority or borrowed MultiplayerPeer transport, bilateral captured-callback authentication/monotonic deadlines, custom span bytes and server admission notifications/relay. Preserve exact raw/system command identities, original sender scopes, call-local targeting, transport metadata, authority policy and callback failure/reset semantics. Prepared storage and capacity validation replace repeated packed-array construction; oversize input drains through the bounded transport snapshot error path before reporting failure. General dynamic object decoding is excluded under ADR 0001.

RPCMethod of TNode/T pairs immutable nonzero per-node wire ID, direct receiver callback and explicit concrete argument codecs. RPCOptions/RPCRegistration preserve typed configuration, policies and snapshots. No reflection/string method or pervasive object serialization is introduced. The internal RPC schema carries method ID, UTF8 relative node path and caller codec payload; it is not a foreign engine wire ABI. All participants agree on codecs/IDs. Authority defaults one and updates current descendants locally; no automatic authority/config replication is implied. Custom providers receive usable public codec/invocation hooks. Scene reconstruction authors method configuration in its existing typed factory/constructor.

SceneTree creates/owns its default interface before entry, borrows caller-assigned interfaces, and polls assigned branch snapshots after idle-frame-start delivery before node processing, including pause. Nearest ancestor branch selects Node.Multiplayer. Tree rollback/finalization detaches every API, disposing only tree-created defaults. API/transport replacement commits state before cleanup; owner/encoding/disposal guards prevent invalid transitions. Internal hierarchy invalidation runs before external observers. Ready message processing allocates no engine storage after preparation; paths/membership/setup and application codecs remain explicit boundaries.

The executable slice includes all typed RPC/admission/relay and Node/SceneTree consumer behavior. The executable replication integration below supplies typed spawner/synchronizer/property-schema consumers and concrete object-configuration overloads/packet batching; only file-backed scene authoring retains its resource-format prerequisite. SceneMultiplayerTests verifies native two-client WS/WSS scene flows, auth/authority/relay/codec/schema/lifetime/failure boundaries and 64 prepared active/idle zero-managed-allocation intervals. Foreign/routed/native allocator and human/rendered/editor/agent acceptance remain separate.

### Typed scene spawning and property replication

MultiplayerSpawner/MultiplayerSynchronizer consume the existing Node/SceneTree/SceneMultiplayer lifetime and explicit typed object-configuration overloads. SceneReplicationConfig owns ordered copied policies over immutable ReplicationProperty of TNode/T descriptors. SpawnFactory of T explicitly encodes copied custom arguments and constructs detached nodes. Stable nonzero numeric identities and direct C# getter/setter/factory/codecs replace dynamic property paths/Variant/Callable. Relative node paths still locate concrete targets. Processes/RIDs cannot be portable property values; codecs author portable concrete data. Shared ReplicationMode and separate VisibilityUpdateMode preserve semantic enum domains.

Preserve spawn/Always defaults, Never/OnChange/legacy sync/watch behavior, monotonic seconds, authority, target/sequence/schema validation, pre-Ready initial state, late replay and actual parent ownership. In-memory PackedScene roots carry internal template provenance; ordered borrowed templates can auto-spawn direct children without inventing a file scene format. Custom factories validate before user construction and reject reentry/invalid lifetimes. Remote-only spawn/despawn events and peer-loss/reset cleanup attempt every release despite callbacks. Interface replacement rebinds producer configuration even after previous cleanup errors; caller-owned APIs/transports remain borrowed.

Visibility uses explicit/public membership and conjunctive predicates, selectable internal frame updates and OR-composed root synchronization visibility. It controls tracked spawning and outgoing RPC delivery. Periodic/change-only groups batch with actual 128-minimum/1350-default sync and 65535-default delta budgets, respecting prepared/native/relay capacity. Always requests Unreliable; delta requests Reliable, with real transport semantics unchanged. High-resolution monotonic scheduling, encoded-byte changes, per-peer successful-send receipts and staged complete-group decode avoid silent omissions or malformed partial state. Setup/membership/first paths/templates/snapshots/errors allocate explicitly; prepared steady operations reuse storage and caller codecs remain their own boundary.

SceneReplicationTests verifies native public WS/WSS authoring/replication, pre-Ready state, automatic/custom/late/visibility lifetime, independent typed schema/malformed/old/authority/batching fixtures and 64 prepared active/idle zero-managed-allocation intervals. File-backed add/get scene paths remain Partial pending the approved typed PackedScene disk-format/loader/saver producer; editor/file/native allocator/foreign/routed/human/rendered/agent acceptance stays separate. Dynamic object decoding remains excluded under ADR 0001.

### Authoritative physics replication boundary

[ADR 0054](physics.md#adr-0054) requires CPU and independent GPU physics for
authoritative-server games. Reuse the existing transports, typed codecs, peer
authority and scene lifetime. Add a shared public physics contract for fixed-tick
input/acknowledgement, portable world-object identity, authoritative state and
client reconciliation. Local RID, object instance and vendor IDs are not network
identity. Existing property replication sequences measure transport publication;
they are not physics ticks or complete restore checkpoints.

The server validates commands for the controlling peer and confirms world state.
Clients retain bounded unacknowledged inputs/history, restore authoritative state,
replay inputs and interpolate remote objects. Visual smoothing must not corrupt
the solved pose. Restore state must cover contacts, sleep and joints as well as
body transforms/velocities; predicted and confirmed event identities prevent
duplicate gameplay effects. Creation/destruction, authority changes and late join
must remain coherent across correction. The wire contract is backend-neutral;
local replay storage can remain backend-private and must not require identical
CPU/GPU internal state or cross-platform bitwise determinism.

These are required capabilities, not current replication behavior. Acceptance
requires separate server/client processes, a CPU server with no GPU/window,
GPU clients, controlled latency/jitter/loss/reordering, joint/contact and sleep
scenarios, divergence recovery and an executable example. Measure wire bytes,
retained history and replay/readback costs separately from rendering and full
physics-step latency. The [physics audit](../components/physics-contract-audit.md)
keeps the missing integration explicit; transport/property replication tests do
not satisfy these physics gates.

### UPNP gateway discovery and control

UPNP and UPNPDevice use native SSDP sockets plus the existing HTTPClient internally, with shared UPNPResult and separate IGDStatus. Owner-thread collections borrow ordered device identities; clearing/disposing membership does not dispose retained devices or remove gateway mappings. Synchronous discovery/control is allocating cold work, with explicit native interface/IPV6/source-port/TTL configuration, bounded response census, filtered location/target dedup and per-device description/URLBase/WANIP/WANPPP assessment. Actual connected status and an assigned nonzero IP establish gateway usability; a private assigned address does not promise Internet reachability. Per-device metadata and semantic status classification correct the pinned backend cross-device/stale-code defects.

SOAP query/add/delete uses exact escaped portable fields, concrete service/action namespaces and typed fault outcomes. One-MiB bodies, depth-64 DTD-free XML and five-second monotonic HTTP deadlines bound untrusted input and stalled peers. No backend library/handle, automatic lease renewal or hidden thread is added. UPNPTests verifies independent native multicast, IPv4/IPv6 SOAP and public scene use; metadata cycles allocate zero managed bytes. A real IPv4 gateway read-only discovery/status/address workflow passed. Real gateway mapping changes, external reachability, routed IPv6 multicast, other-platform/native allocator/human/editor/rendered acceptance remain separate.

### Native DTLS packets and server cookies

PacketPeerDTLS borrows a connected PacketPeerUDP and DTLSServer prepares identity/cookie state without owning sockets. Reuse shared TLSStatus and TLSOptions/trust/resource retention, with Linux system OpenSSL 3.2+ fixed datagram BIO pairs and DTLS 1.2. Explicit owner polling drives complete records, cookie exchange and native retransmission timers. Address/scope/port-bound HMAC-SHA256 cookies use prepared native expected state and nonthrowing unmanaged callbacks; no managed GC-handle retention or hidden thread is required. Successful helper setup cannot repeat; failed setup rolls back. Accepted sessions independently retain identity and survive helper disposal. UDP generation changes invalidate old sessions.

Preserve the 488-byte advertised outgoing capacity, empty-send no-op and complete packet boundaries through prepared encrypted/plaintext storage and bounded receive queues. Native duplicate/MAC rejection, exact trust/name statuses, queue pressure, reentry and borrowed-transport cleanup execute. A cookie challenge continues on the same logical peer instead of exposing backend-dependent first-attempt failure; system OpenSSL retry policy is advanced by Poll, while callers choose their overall deadline. DTLSTests verifies native public scene packets, loss/retry/cookies/anti-replay/MAC/trust/lifetime, independent Bouncy Castle test-only peers in both roles (plus Unix OpenSSL processes) and 64 prepared active/idle zero-managed-allocation intervals. Foreign/browser/routed/native allocator and human/rendered/editor/agent acceptance remain separate; the ENet integration below supplies its executable host consumer.

### Native ENet channels and multiplayer

Use unchanged ENet1.3.18/FastLZ0.5.0 sources behind one private Linux64 library. The engine socket port maps private uint32 routing tokens to prepared real IPv4/IPV6/scope/port endpoints; no native address layout reaches the public API or protocol wire. Preserve original vendor licenses/hash manifests; platform TCP/address hooks unused by the UDP core fail explicitly. Linux zlib/Zstandard shared libraries supply the other block codecs. Native assets follow the existing RID packaging contract, with explicit foreign/toolchain gates.

ENetConnection owns native host/transport state, ENetPacketPeer borrows native peer slots, typed ENetEvent projects four event fields, and distinct ENet enum domains preserve exact native meanings/values. CreateHost binds an automatic port immediately. Channels/flags/reliable fragmentation, statistics, ping/throttle/timeout, raw socket sends, all five codecs, DTLS and whole-packet/span reads execute. Correct the channel-equality boundary and timeout multiplier/min/max units explicitly. Native packet queues have 16-MiB packet, 64-MiB outgoing payload and 65536-slot budgets; managed receive queues have 4096-slot/64-MiB budgets, endpoint preparation is bounded/reclaimed, and unread packet finalization supplements deterministic cleanup. Native packet/codec allocation remains a separate boundary.

ENetMultiplayerPeer provides actual server/client/mesh behavior for existing SceneMultiplayer/RPC/replication consumers. Preserve reserved zero-channel mode separation, positive negotiated channels, received metadata, uint32 connection identities, topology relay support and targeting.
