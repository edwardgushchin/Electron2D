## ADR 0047: Use FAudio over SDL3 with managed audio decoders

Last updated: 2026-10-02

### Status

Accepted. The first WAV/non-spatial stream/bus output slice executes through FAudio on Linux x64; remaining capabilities are recorded in coverage.

### Context

Electron2D needs audio playback, bus routing and effects through an engine-owned public API. The applicable `AudioServer` contract includes sends between buses and ordered effects. SDL_mixer 3 supports playback and flat mixing groups, but its group API does not directly provide that bus graph. FAudio provides source and submix voices, sends and effect chains over SDL3. The reference audio import surface accepts WAV, Ogg Vorbis and MP3 sources; imported WAV samples can use PCM, IMA ADPCM or QOA storage. Decoding those sources and storage formats is separate from mixing them.

### Decision

- Use FAudio on top of SDL3 as the native audio mixing and output backend. Model Electron2D audio buses, routing and effects using FAudio voices, submixes, sends and effect chains without exposing FAudio or SDL types to applications.
- Preserve the applicable reference audio API and behavior under [ADR 0004](product.md#adr-0004). FAudio's available operations do not by themselves prove `AudioServer`, audio stream, decoder or effect compatibility; audit their contracts and record any gaps in coverage when implementation begins.
- Compile the upstream FAudio# managed binding source into `Electron2D.dll` and ship pinned native FAudio and SDL dependencies through the engine project, under [ADR 0012](product.md#adr-0012).
- Accept WAV with PCM or IEEE-float samples, Ogg Vorbis, and MP3 as audio sources. Use the existing SDL3-CS audio bindings for WAV loading, with engine-owned validation and metadata/loop handling needed by the public contract. Use [NVorbis](https://github.com/NVorbis/NVorbis) for Ogg Vorbis and [NLayer](https://github.com/naudio/NLayer) for MP3 decoding. Do not require NAudio to use NLayer.
- Support PCM, IMA ADPCM and QOA as the WAV stream's internal sample formats. Use the [qoa-fu](https://github.com/pfusik/qoa-fu) C# translation for QOA encoding and decoding; implement the small IMA ADPCM codec in engine-owned C#. FAudio's MS ADPCM support is a different codec and does not implement IMA ADPCM. QOA and IMA ADPCM are import/storage choices, not additional accepted source-file formats.
- Compile the selected managed decoder sources into `Electron2D.dll` as internal types. Feed their decoded PCM to FAudio in bounded buffers; retain the source format, seek/loop behavior and resource ownership required by the applicable public audio API. No native decoder library or per-codec P/Invoke layer is selected. Pin source revisions, retain licenses and verify interoperability, corrupt-input handling, playback and target packaging when the executable audio/import slice is integrated. This decision does not select SDL_mixer as the mixer or decoder.
- Establish packaging and executable behavior for every claimed platform, especially Web, Android and iOS, under [ADR 0021](product.md#adr-0021). If FAudio cannot satisfy a target, resolve its backend integration through a new explicit decision before claiming audio support there; never silently substitute different semantics.

### Procedural PCM producer

AudioStreamGenerator : AudioStream creates independent AudioStreamGeneratorPlayback : AudioStreamPlaybackResampled queues. Custom, Output and Input execute through the existing native mixer. Input obtains AudioServer.GetInputMixRate from a separately owned paused SDL3 recording device; selecting the mode and creating/starting its playback prepare the actual input frequency without activating recording. Prepared frequency reads during mixing never open a device or use the output frequency as an input substitute. Existing queues retain their creation-time capacity while explicit device switches change the live source rate.

Each playback prepares power-of-two stereo storage strictly larger than truncated target-rate times BufferLength, with one reserved slot, up to 2^24 storage frames (128 MiB). Zero truncated frames produce zero usable slots, matching the ring boundary. Positive finite rate/duration configuration is validated; oversized creation rejects before allocation. Existing queues never resize after BufferLength edits; source frequency is live. PushBuffer copies a whole finite span or reports overflow without partial write; PushFrame and all successful queue/mix paths reuse prepared storage. One per-playback gate serializes producer/control/resampling history; it is shared with public BeginResample to avoid inversion or an unprotected history reset.

Generation is indefinite. A short source read supplies zero frames for the missing samples and increments skips once per underrun source block, saturated at Int32.MaxValue. It never reports an end-of-stream to the native voice. Playback time counts requested source block duration including silent demand/prefetch. Start ignores the finite position, resets skips/time, and resets the initial history only when generated time is zero. Stop preserves pending source frames/history; stopped-only ClearBuffer clears queue/time without resetting skips. Seek is a validated no-op. Initial inactive history preparation explicitly fills silence and reports a complete block to the shared resampler, avoiding a false end marker while retaining the pinned initial silence and producer queue. Resource copies contain configuration; transient playback queues do not enter Resource graphs.

### Recording input and microphone streams

AudioServer owns one SDL3 recording stream independently of its FAudio output context. SDL_OpenAudioDeviceStream opens it paused; the opened device format supplies the actual input rate and native quantum. The application side is finite stereo float PCM at that rate; SDL owns channel/sample conversion. A SafeHandle retains the managed delegate, destroys the stream/logical device after callbacks join, and balances the independent SDL audio-subsystem reference. Enumeration and device selection use exact native names plus Default; failed preparation/activation leaves the prior selected device and capture intact. A successful switch publishes prepared state before releasing the old device, clears reader history, and resets microphone resampling on its next mix. OS permissions or missing devices surface as typed exceptions; no other platform or physical-input acceptance is inferred.

ProjectSettings.AudioDriverEnableInput projects audio/driver/enable_input, false by default, and gates new manual or microphone starts. Prepared rate queries and Input generator configuration do not resume recording. Disabling the setting gates later requests rather than asynchronously stopping existing capture. SetInputDeviceActive(false) explicitly pauses the global recording stream even with active microphones; their independent playback state remains active and consumes remaining frames, then silence. A manual active request survives automatic microphone Stop and output-player detachment. Automatic capture pauses after the last microphone stops when no manual request remains. Multiple microphone cursors are independent: stopping one must not disable another's input. This corrects the pinned global-stop interference; explicit server pause retains its public semantics.

The bounded ring stores four actual native recording quanta. Callback draining uses one prepared quantum scratch buffer and a separate input-data gate; it never takes the FAudio/configuration gate. Owner operations that join native callbacks do not hold the input-data gate, preventing a stream-lock/ring-lock inversion. Monotonic frame cursors distinguish empty from exactly full and drop oldest overwritten frames; this corrects modulo-only full-buffer ambiguity and stale replay after wrap. GetInputFrames copies a whole requested nonnegative count or returns empty without consumption. The server reader never consumes microphone history. Nonfinite native frames become silence; finite values clamp to [-1,1]. Callback errors are contained at the native boundary and reported by owner queries or microphone mixing; stop/restart clears the failure.

AudioStreamMicrophone is a monophonic, unknown-length, parameterless Resource. It creates internal AudioStreamPlaybackMicrophone : AudioStreamPlaybackResampled state, borrowing the source. Start ignores a finite position and is idempotent while active; Stop/Dispose release its capture request on the audio owner. Seek is a validated no-op, time/loop queries return zero. Each cursor waits for min(50 ms, half the ring) of initial captured data, then reads only available frames and supplies silent shortages indefinitely through the shared cubic resampler. It never repeats overwritten or already consumed input and never ends on underrun. Engine closure stops standalone microphone requests as well as player voices and releases input; ordinary last-output-player detachment retains independent recording. Resource duplication copies inherited metadata only, never devices, queues or active requests.

If the final automatic native pause fails, its microphone request is still released and the failed input stream is destroyed before reporting the error. Disposed playbacks cannot retain dead capture requests; a later Start prepares a fresh device. Explicit manual pause failures retain the manual request for retry.

### Ordered effects and capture

AudioEffect : Resource creates independent AudioEffectInstance : ElectronObject state through typed OnInstantiate. Instances process finite stereo spans through OnProcess and select silent-input activity through OnProcessSilence. Buses borrow resources and own one instance per output stereo pair; public instance queries return borrowed state. Attached instances cannot be directly processed/disposed. Factories, processing and cleanup reject server configuration/Lock/Unlock reentrancy. Resource copies carry configuration; transient processing/capture state stays out of copied graphs.

The existing FAudio backend hosts ordered public effect FAPOs, an owned final gain FAPO, and the native peak meter. The native submix volume remains unity because FAudio applies that gain before its effects; the owned final stage preserves public pre-volume processing and post-volume metering without changing vendor source. SafeHandle wraps one native FAPOBase block with persistent properties and GCHandle-retained state. Voices hold native references until detached; managed instance cleanup follows native detachment and collects all errors. Structural effect edits recreate the edited bus chain, factory failure preserves the prior chain, native graph failure retains committed configuration while closing output, and routing rebuilds retain public processing identity/history.

Shared stereo-pair activity follows source usage, sends and post-gain peaks. Typed AudioBusesChannelDisableThresholdDB/Time default -60 dB/two seconds and are read at output preparation. Normal hooks continue through active silent tails; ProcessSilence opts into inactive blocks. The engine validates full finite PCM and uses actual pair data/activity rather than the pinned native partial silence hint. User callback/source-disposal errors remain inside the native boundary, silence the failed effect and report once at the owner scene frame; structural recreation resets processing failure. Nonfinite final gain output is likewise contained; gain edits reset its failure.

AudioEffectCapture owns one resource-shared power-of-two stereo ring, one reserved slot, sized strictly above the truncated output-rate × initial BufferLength. Preparation fixes capacity; repeated instantiation clears pending data and retains cumulative Int64 counters. Whole processing blocks fit or are discarded whole, preserving earlier queued samples. Nonnegative copied reads return exactly the requested frames or empty without consumption. Capture processes silence and preserves raw finite PCM, including amplitudes beyond unity. Positive finite duration is validated; the engine bounds storage to 2^27 frames/1 GiB before allocation. The initial request bound follows the capture contract; this does not claim encoded recording or public batch/file export. Linux x64 actual native PCM, logical pair projection and current Wayland host paths are verified; physical listening, actual multichannel devices and other platforms retain separate gates.

### Typed frequency-filter family

AudioEffectFilter and seven concrete low/high/band-pass, notch, band-limit and shelf resources execute through the existing effect-instance/FAPO chain. The directly constructed base uses low-pass mode. Typed CutoffHZ, Resonance, Gain and DB presets own coherent finite scalar configuration; resources and scene-local copies retain their exact type and configuration, while each instance prepares independent four-stage histories for both stereo channels. Coefficients are cached by primitive setting/rate values, updated at the next block without clearing history, and use the actual output mix rate. Bypass/disable and temporary reductions in stages retain history. Ordinary equations, stage quality/gain roots and float histories are verified against an independent byte-pinned C++ oracle; enum names/numeric presets are preserved, with actual one-through-four biquad transfer behavior documented.

The executable slice corrects two proven source defects rather than carrying them into a native callback: cutoff is effectively bounded below Nyquist (0.4999 × output rate), avoiding negative damping/unstable poles produced by the source's Nyquist-plus-512 bound; BandLimit uses its complementary band-rejection numerator, correcting an opposite band-pass response while retaining its bandwidth denominator. Nonpositive/reversed band edges and extreme quality/shelf damping receive effective positive/stable floors. Finite raw controls remain stored and ordinary settings retain their source PCM. Float overflow clears contaminated instance histories and reports an arithmetic error; native containment/recreation remains the existing effect-chain policy. These explicit numerical/response corrections are recorded in coverage and reproduced by analytical edge/response tests.

Copying uses the Resource graph/session contract; Gain authoring metadata is hidden only on concrete low/high/band-pass types, matching their unused control, while the inherited typed property remains. No editor, bus-layout loader, file export, native dependency or vendored source patch is introduced. The existing MIT runtime adaptation notice accompanies the equations. Current class/component documentation records Linux x64 PCM, actual native output-rate filtering, public Wayland host and warmed allocation checks; physical listening, multichannel hardware and other platforms retain separate gates.

### Peak limiting

AudioEffectHardLimiter executes through the current FAudio stereo-pair chain with a prepared two-millisecond lookahead line, one linked detector and a short minimum-gain sustain history per pair. Typed CeilingDB, PreGainDB and Release controls are live at the next block; silent blocks flush delayed PCM. Resource copies retain controls and never processing state. The pinned source processor can exceed its sample ceiling slightly and can retain attenuation when a positive release is shorter than one sample. The executable slice corrects both behaviors: a final finite sample cap enforces CeilingDB after all detector math, and exhausted release restores detector gain to unity while the prepared bucket history completes its sustain window. Tests compare ordinary PCM to a byte-pinned C++ processor and separately verify these safety/recovery edges, native output and allocation. This is a sample-domain guarantee; actual inter-sample peaks, physical devices and other platforms retain separate verification gates.

### Phase-vocoder pitch shifting

AudioEffectPitchShift uses the shared AudioFFTSize enum under ADR 0051 with a preparation-time frame size of 256, 512, 1024, 2048 or 4096. Each output stereo pair owns independent left/right FIFO, phase, FFT and overlap-add histories. Positive finite PitchScale and four-through-thirty-two Oversampling settings are typed and live at the next block; a unit scale bypasses without latency. The overlap upper bound keeps the frame step positive and CPU work bounded, correcting the pinned setter's unbounded upper side. A live overlap edit or bypass transition resets both channel histories so incompatible or stale frames cannot replay. The silent-input hook flushes delayed PCM after a finite source. Arithmetic overflow resets processing state and is reported through the ordinary native callback containment path.

The adaptation preserves the pinned phase-vocoder equations and float FFT operation order: a generic spectrum FFT produced a 0.0127-channel deviation on a short-window case, while the dedicated transform matches a byte-pinned C++ oracle within 3.3e-5 at the verified 44,100 Hz profile. The Wide Open License notice accompanies the adapted source. Native FAudio and public Linux Wayland hosts verify shifted stereo tones and warmed allocation boundaries; quality by listening, 48,000 Hz engine execution, actual multichannel devices and other platforms remain separate gates.

### Stereo width and interchannel delay

AudioEffectStereoEnhance executes on each FAudio stereo pair with one prepared float ring at the output rate. PanPullout scales the side component about the shared center; TimePulloutMS delays either the right channel or, when Surround is positive, a center contribution added to left and subtracted from right. The three authoring controls are finite and bounded to the pinned 0–4, 0–50 ms and 0–1 ranges. One coherent snapshot applies per block; live edits preserve the shared ring, matching the pinned mode history. Silent processing flushes delayed PCM after a source ends. Widened intermediate arithmetic prevents a legal finite center from overflowing, while out-of-range output clears history and reports an error. Resource and scene copies retain settings only. Analytic PCM, native tails, public hosts and warmed allocation verify the current Linux x64 slice; physical listening, actual multichannel hardware and other platforms retain separate gates.

### Consequences

- SDL3 remains the platform foundation and FAudio supplies the mix graph. Public audio types and lifecycle remain Electron2D-owned; audio decoding adds no further native deployment library.
- The managed decoder source and FAudio# binding join the single engine assembly only with an executable slice. FAudio 26.09 and qoa-fu are now pinned/internal in the first executable output slice; NVorbis 0.10.5 and NLayer 3.0.0 now compile internally and execute mono/stereo codec slices; multichannel Vorbis retains its independently verified decoder prerequisite. Current behavior and native/platform/physical verification limits are documented in the [audio component](../components/audio-playback.md).

### Rejected alternatives

- Use SDL_mixer 3 as the complete audio engine: rejected because its documented groups do not directly represent the required routed bus and effect-chain contract.
- Use SDL_mixer solely for decoding: rejected because the selected managed decoders cover the required source formats without a second native audio extension.
- Bind native libogg/libvorbis, dr_mp3 and qoa.h separately: rejected because managed implementations cover the selected formats without additional native packaging and per-codec interop.
- Build a custom mixer before validating the selected backend: rejected because FAudio already supplies a mix graph suited to the required bus roles.
