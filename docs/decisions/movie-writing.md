# Non-real-time movie writing

Last updated: 2026-10-16

<a id="adr-0109"></a>
## ADR 0109: Typed movie writers over the owned window lifecycle

- Status: Accepted
- Scope: MovieWriter hooks, Engine recording entry points, synchronous FAudio output and built-in recording encoders

### Decision

Keep MovieWriter as an abstract ElectronObject. Register borrowed custom instances with static AddWriter before runtime startup; most recent matching handler wins. Registering and disposing use the creating thread. Extension discovery executes during registration; selection and recording hooks execute serially on the runtime owner, which may differ on a platform application host. Registered writers cannot be disposed while a runtime is reserved, including selection before a recording lease exists. At most eight live custom registrations are retained; a later registration reclaims disposed entries. Built-in encoders are internally owned per recording and follow custom handlers in selection precedence.

Map the virtual callbacks to protected OnGetAudioMixRate, OnGetAudioSpeakerMode, OnGetSupportedExtensions, OnHandlesFile, OnWriteBegin, OnWriteFrame and OnWriteEnd. The first two retain 48000 Hz/stereo defaults. Replace unsafe audio pointers with a borrowed ReadOnlySpan<int> of interleaved full-range signed 32-bit PCM; replace Error-return callbacks with typed C# exceptions. Never expose backend pointers or a Variant payload. The frame Image is borrowed until its callback returns. Begin failure still attempts End for partial-output cleanup; later hook failures abort the run and collect cleanup failures.

Project command-line movie startup into Engine.Run/RunAsync overloads accepting a path and positive FPS. Keep the ordinary window reservation, event delivery, scene activation, fixed/process ordering, deferred work, pause/TimeScale and teardown. Prepare the movie/audio graph before constructing SceneTree, whose constructor already activates Autoplay. Set process and render delta to exactly 1/FPS before TimeScale; use the same fixed-step scheduler with explicit fixed-cadence accumulation, using a rational integer physics-tick remainder, without realtime jitter smoothing, catch-up dropping or MaxFPS waits. A low movie FPS must execute all due physics steps. RunAsync still yields through the existing application scheduler. GetWriteMoviePath returns the unchanged requested path through startup, hooks and teardown, and empty after release. Do not expose a second game loop or a simulated successful headless capture.

Expose configured recording through Engine.RunMovie(Window) and RunMovieAsync(Window), a typed library-host projection of the existing project movie-startup role. Sample MovieWriterFile (empty default) and MovieWriterFPS (60, positive) with feature overrides before runtime reservation. A blank configured path fails without consuming the window. Existing Run/RunAsync movie path and FPS arguments retain precedence, including their 60 FPS optional default; ordinary runs do not become recordings merely because a file setting is populated. MovieWriterDisableVSync (false) is sampled for every movie entry point before startup and passed with the reserved lifecycle, including Android's deferred host. When true, retain the Disabled presentation request after display creation and before renderer creation; preserve native supported-mode fallback. This per-run request neither changes the project setting nor persists to a later ordinary window. Scene callbacks may subsequently request another presentation mode through the existing DisplayServer API.

Use the existing FAudio graph, sources, sample voices, buses and effects. A private bridge, compiled against the pinned FAudio internals in the same target, creates a mastering voice with no SDL output stream and drives the existing engine procedure synchronously. Its state uses the same ordinary native voice destructor. No vendored source modification or second mixer is introduced. Recreate prior cold output/effect preparation at the movie rate, while rejecting independently attached playback instead of silently replacing it. Prepare maximum-quantum float storage once; retain unused samples between video frames. Return cumulative floor(frameCount * mixRate / FPS) audio frames, alternating block lengths when needed instead of the pinned truncated-rate drift. Output-device switching rejects during recording; output latency is zero. Input/microphone remains a separately timed external device and is not a deterministic recording source.

Every writer receives screen-encoded RGB8: linear half-float canvas input retains its precision through crop/resize and converts RGB before byte quantization. Alpha is not transferred. The public byte-only Image color-transform API is unchanged. The PNG sequence backend writes RGB8 frames and 32-bit PCM WAV, with the initial pixel dimensions fixed for the recording. Later viewport size changes use centered cover cropping and bilinear resize. Preserve explicit loss of alpha. Readback, resizing, encoding and filesystem operations are cold offline work and may allocate/block; the prepared mixer path retains ADR 0014's zero-allocation requirement. The WAV RIFF size limit rejects before appending an overflowing frame. MovieWriterMixRate and MovieWriterSpeakerMode project the existing editor/movie_writer configuration roles and are consumed by the built-in handler.

AVI/MJPEG uses the existing JPEG encoder and a classic RIFF AVI interleaver, with video stream 0 and PCM audio stream 1, word-aligned chunks and a final idx1 seek index. MovieWriterVideoQuality accepts finite 0..1 (default 0.75); AVI clamps values below 0.01 to the existing JPEG encoder's one-percent minimum. MovieWriterAudioBitDepth selects 16 (default) or 32 bits; Int32-to-Int16 conversion takes the signed high 16 bits. Sample these and the shared rate/channel settings at Begin. Preserve exact rational per-frame audio counts. RIFF lengths, stream lengths and index payload sizes describe actual committed data; reject an overflowing frame including future index space before writing it. A failed partial frame is truncated before finalizing complete frame pairs. The classic container's 32-bit RIFF extent and signed 16-bit stream rectangles bound output; reject unsupported dimensions before opening the destination. PNG remains lossless with 32-bit PCM regardless of AVI quality/depth settings.

OGV uses a private, source-built C ABI over pinned libtheora 1.2.0, libvorbis 1.3.7 and libogg 1.3.6. The archive hashes, source lists, original licenses and a narrowly adapted Vorbis encoder copy are retained in the native recipe; no global codec or external encoder process is required. The allocation adaptation reuses a shared residue setup object instead of losing its former allocation. The user waived upstream PR submission for this residue allocation fix on 2026-10-15; retain the guarded local adaptation and regression evidence. All producers/packages include the new private bridge, and static application profiles receive one archive containing the codec closure. This does not establish foreign execution or package publication.

The OGV handler samples shared video quality and MovieWriterOGVAudioQuality (-0.1..1, default 0.5), MovieWriterOGVEncodingSpeed (1..4, default 4) and MovieWriterOGVKeyframeInterval (1..1024, default 64). Speed uses the native supported level, capped at the queried encoder maximum. Video quality maps 0..1 to Theora 0..63. Preserve the encoder's positive-even-dimension requirement for 4:2:0 video; pad internal planes to macroblocks by extending edge pixels and retain exact visible dimensions. Convert RGB8 to limited-range YCbCr with explicit loss of alpha.

Vorbis channel mapping differs from the mixer. Reorder 5.1/7.1 into the standard Vorbis speaker order. Vorbis has no standard 3.1 layout: preserve its front/center/LFE roles in a six-channel 5.1 container with silent rear channels, while the mixer and writer input remain four-channel 3.1. Do not relabel center/LFE as the rear channels of four-channel quadraphonic Vorbis. Stereo remains two channels. Container conversion does not alter AudioServer speaker mode.

Preserve rational cumulative audio counts, including frames with no PCM samples; a zero-length per-frame block must not signal Vorbis EOS. Isolate the initial zero-duration Vorbis priming packet on its own page so very short recordings retain an unambiguous starting clock. Delay draining the newest Theora frame until its successor or End so the last packet receives EOS. Mux copied pending pages by granule time; End drains both logical streams, including header-only zero-frame output. Managed write callbacks contain exceptions, fail the recording and always release native/file ownership. A disk failure may leave incomplete output; scene failures finalize already submitted frames. Readback/conversion/encoding/muxing are cold allocating work, independent of the prepared mixer allocation contract.

### Verification boundary

Apply ADRs 0001/0003/0004/0014/0016/0021/0047/0045/0090/0095. Exercise actual pixels and native PCM, non-divisible clocks, stream/sample transport, channel profiles, lifecycle/failure cleanup and independent PNG/WAV decoding. Check cold registry errors without native initialization, prepared mixer allocations, fresh package/NativeAOT operation and ordinary Engine scheduling regressions. Local Linux execution does not establish foreign hosts, physical input/listening, full allocator totals or owner acceptance.
