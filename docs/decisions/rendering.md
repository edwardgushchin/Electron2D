## ADR 0028: GPU-first 2D rendering, shared SPIR-V shaders, browser WebGPU, and SDL_Renderer fallback

Last updated: 2026-10-21

### Status

Accepted.

### Context

Electron2D needs one portable 2D rendering contract for Windows, macOS, Linux (X11/Wayland), Android, iOS, Android TV, tvOS, and Web. That contract must support user-authored shaders without making simple 2D output depend on every target successfully creating a programmable graphics pipeline.

SDL exposes two relevant layers. The [SDL GPU API](https://wiki.libsdl.org/SDL3/CategoryGPU) provides cross-platform graphics devices, shaders, pipelines, command buffers, and render passes. The [SDL Render API](https://wiki.libsdl.org/SDL3/CategoryRender) accelerates a smaller set of simple 2D operations but does not expose arbitrary user shader pipelines. Treating both as equivalent would either remove shader support from the engine or make the fallback claim behavior it cannot provide.

[SDL_shadercross](https://github.com/libsdl-org/SDL_shadercross) accepts HLSL source and SPIR-V bytecode and translates them to formats used by SDL GPU backends. SDL3-CS already provides its managed ShaderCross binding. This supplies the common SPIR-V reflection and backend-translation layer. GLSL compilation needs its own import/build frontend; shadercross does not itself compile GLSL source.

SDL3-CS supplies managed bindings to the DisplayServer. The self-contained Linux x64 example packages native SDL and runs a window, input, and scene-frame host through the public Electron2D API. The rendering integration now contains executable GPU/fallback canvas paths and partial shader materials. Other target packages remain unverified; the current integration boundary is detailed below.

The pinned SDL GPU API has no browser backend. A standalone Chrome probe rendered a WGSL shader through WebGPU, but that probe did not use Electron2D's canvas or materials. Browser shader support therefore needs an engine-owned backend with the same public material contract.

### Decision

- Independent desktop Window hosts share one authoritative scene renderer under [ADR 0040](display.md#adr-0040). GPU surfaces use the same device and canvas targets with separate presentation claims. Compatibility surfaces use the main SDL renderer driver and replay frozen dependency-ordered submissions; cold activation/recovery imports retained canvas history once. Scene callbacks and simulation are never replayed and prepared frames add no CPU image bridge.

- Writable canvas textures use `DrawableTexture` and `BlitMaterial`, with `Shader.Mode.TextureBlit` for imported HLSL/GLSL fragments. The GPU rendering device owns sampled color attachments; ordered blit passes accept one through four equal-sized, equal-format targets, one mip level and up to four sources. Float4 MODULATE at location zero and float2 UV at one feed contiguous float4 outputs starting at zero, matching the target count. Reserved scalar float samplers `SOURCE_TEXTURE0` through `SOURCE_TEXTURE3` consume the supplied sources; absent sources use opaque white, matching the pinned executing implementation rather than the XML's black-texture prose. Other reflected material uniforms, default textures and registered globals retain the shared typed material contract. This domain has no authored vertex, scene instance, screen or lighting interface. It requires the GPU backend; compatibility rendering rejects sampling or executing writable textures explicitly. Setup is authorable without a renderer and lazily creates freshly cleared native storage in each session. Format/mipmap setters reset initialized storage to its authored clear color, keeping actual storage consistent with metadata; they never expose inert configuration. Resource archives and duplication preserve setup, not transient GPU results. Logical resource/server identities remain stable across setup; server replacement transfers matching owned drawable storage and aliases. Source/target aliasing, including proxies and native image aliases, rejects before drawing. GPU shutdown owns native retirement; resources may be reused in a later session.

- The first canvas-light consumer uses retained point/directional sources, multichannel CanvasTexture resources and copied contour geometry, shared by scene nodes, static server identities and tiles. Evaluate direct contour visibility in the fragment pass; None/PCF5/PCF13 retain their sample counts with screen-pixel spacing. This is an explicit backend adaptation of quantized shadow-atlas filtering. Generate a shader-requested signed nearest-contour field on GPU; overlapping contours retain internal distance features. Expose this through renderer-owned SDF_TEXTURE/SDF_COORDS in the existing HLSL/GLSL profile and executable viewport area/resolution presets. Do not expose editor-only light switches until editor scene/hint rendering exists. Programmable fragments receive automatic scene lighting through a cold, engine-owned SPIR-V function composition. Preserve the material module, its parameter/texture descriptors, discard and return flow; shade its computed color before ordinary blend. Built-in vertex variants deliver a per-item storage-record index, retaining all four material uniform slots. Generate lighting functions and exact ID relocation data with pinned tools, then compose without a source compiler in games. Preserve the original descriptor form for combined GLSL or paired HLSL textures. Additional normal/specular/point-mask samplers share the actual sixteen-sampler stage limit; reject capacity overflow before submission. Ordinary unlit canvas output must not require floating-point light targets.
- CanvasModulate : Entity selects one visible scene node per logical canvas to publish its finite authored Color through existing canvas modulation. It affects the whole canvas regardless of its transform, with independent CanvasLayer/World colors. Waiting nodes retain their own values; hiding, disposal, canvas exit, TopLevel rebinding and live World replacement reconcile membership and promote another visible node, or restore opaque white. Multiple visible nodes report a configuration warning; games must not depend on a particular winner. Registration uses weak identities and actual canvas membership; manually delivered entry/exit notifications cannot forge it. The node and Color restore through typed scene archives. Server CanvasSetModulate still commits immediately; the selected node can overwrite it on Color assignment or membership change, and session cleanup restores current authored modulation. Ordinary modulation executes on both current backends; light composition and unshaded material policy retain the existing GPU/compatibility gates.
- The primary native Electron2D rendering backend uses the SDL3 GPU API through the vendored SDL3-CS binding.
- Negative-width canvas strokes retain native line-list/line-strip topology for GPU submission, including derived arc/outline/dash commands. Keep independent strips separate and local single-line feathers in triangle batches. GPU vertex snapping rounds endpoints before the vertex program; the SDL_Renderer fallback expands each segment to the existing one-pixel triangle footprint and rounds its final corners. This preserves fallback precision limits rather than treating triangle coverage as exact native lines. Low-level point/two-vertex DrawPrimitive adaptation remains separate.
- On Web, use a separate engine-owned WebGPU canvas backend through browser interop. It submits the same retained canvas batches and applies the same typed ShaderMaterial parameters and textures. Keep browser WebGPU and JavaScript objects behind the existing backend-neutral public API. A persistent, nonblocking browser host owns WebGPU initialization, frame submission and disposal; it must not rely on SDL_GPU becoming available in the browser.
- Electron2D will support engine-provided and user-authored graphics shaders for 2D rendering on the GPU backend. Three-dimensional pipelines and shader functionality are outside the product boundary.
- Directly support exactly two shader source languages: HLSL and GLSL. Compile both to SPIR-V during project import or build. Source compilation is part of the project toolchain, not a required operation when a shipped game loads a material or draws a frame. RenderingDevice.ShaderCompileSPIRVFromSource is an explicit cold authoring/import/build bridge to the separately published ShaderImport executable, selected by ELECTRON2D_SHADER_IMPORT_TOOL or installed beside the host. RDShaderSource is a copied ElectronObject description for the executing vertex/fragment/compute stage family; ShaderLanguage owns GLSL/HLSL identities. No source compiler becomes a game dependency. The tool compiles independent stages, preserves stage diagnostics and validates device module structure/capabilities; pipeline factories retain interface/native validation. Successful anonymous modules may use a bounded content/compiler-footprint cache; preprocessing/include sources recompile so native dependency resolution remains authoritative. Explicit cache bypass performs a fresh compilation. Ray stages remain outside the product boundary; tessellation needs an accepted executing backend stage adapter. RDShaderFile : Resource stores named borrowed RDShaderSPIRV results and independent base diagnostics. Empty names select the default; missing names return null. Version lists copy and sort by Unicode scalar value, preserving the pinned alphabetic contract independently of culture and UTF-16 surrogate ordering. Nonzero valid scalar names preserve portable storage. Typed name/module records replace the internal heterogeneous dictionary; restored versions commit together after validation. Shallow/deep/local resource graphs preserve module aliases. Games load this saved graph and pass a selected result to the same device factories without invoking a source compiler.
- RenderingDevice shader binaries use an engine-owned, versioned SPIR-V container shared by the existing backend translation path. ShaderCompileBinaryFromSPIRV validates successful compute or paired graphics modules through the ordinary factory, then releases concrete native programs; symbolic specialization retains pipeline-time validation. Store the original modules and diagnostic name with bounded little-endian lengths, strict UTF-8, reserved flags and an integrity digest. Load validates the complete container before publishing a program and repeats runtime capability/interface/native checks. This adapts binary storage to the common SPIR-V architecture; it does not promise a driver pipeline-cache export, source-compiler invocation, external binary compatibility or reduced native creation cost. ShaderCreatePlaceholder reserves an owned uninitialized identity. Only successful ShaderCreateFromBytecode can initialize it, once; failed parsing or program creation leaves it retryable. Shader consumers reject an uninitialized identity, and FreeRID/disposal release it.
- ShaderInclude is a typed Resource owning bounded strict UTF-8 HLSL/GLSL include source. Its Code descriptor supports duplication and typed archives; ResourceLoader/ResourceSaver support `.hlslinc` and `.glslinc` source files. Each successful assignment emits Changed after commitment. Source/preprocessor dependency evaluation belongs to the selected build compiler, including guards, macros and conditional includes. Save source edits and rebuild dependents to publish new SPIR-V; runtime source mutation never compiles or changes an already loaded Shader. The importer evaluates dependencies on every build and preserves unchanged output bytes/timestamps; compiler errors leave the prior payload intact. This is the build-time projection of source/dependency invalidation under the existing compilation boundary.
- ShaderIncludeDB exposes the retained static built-in fragment discovery service under ADR 0095. The portable HLSL/GLSL library is embedded in the runtime assembly, uses stable literal case-sensitive forward-slash names and is readable before renderer startup for import/authoring. It returns immutable source, false/empty for missing names and an independent ordinal name array. Project import materializes that same library only in a private temporary search root for the native compilers; guards, nesting and conditional preprocessing remain compiler-owned. The initial `electron2d/color.hlslinc` and `electron2d/color.glslinc` fragments implement scalar/RGB/RGBA sRGB transfer functions, preserving alpha, negative and HDR values. Internal canvas color processing consumes the HLSL fragment. This adapts driver-dependent internal fragments to the common portable shader contract; it does not expose backend-private buffers, 3D fragments or a runtime source compiler. Compiled consuming modules retain their existing stage/backend capability requirements.

- Generate built-in rendering and physics shader bytecode during the runtime build from versioned sources and a pinned host compiler recipe. Store generated resources under the intermediate output directory and embed them in Electron2D.dll; do not version their generated `.spv` files. Keep fixed external-bytecode test fixtures as independent regression inputs. Package/game consumers receive compiled resources and require no source compiler. The bootstrap must not depend on the runtime assembly it is compiling.
- SPIR-V is the common intermediate representation and accepted precompiled input format. Every module, whether produced by the HLSL/GLSL importers or supplied externally, follows the same path: payload/capability validation, parameter and resource reflection, shader-interface validation, backend translation where needed, and GPU-program creation. No input origin bypasses this contract.
- The WebGPU backend translates validated SPIR-V to WGSL before browser shader-module and pipeline creation, preserving the reflected entry point, interface, bindings, material values and texture semantics. This applies to built-in shaders and to modules loaded or replaced at runtime through the public Shader API; an import-only conversion cannot be the sole path. Pin and package a Web-compatible translator when implementing this backend, and propagate translation, WGSL compilation, pipeline and device errors. WGSL remains an internal backend representation, not a third directly supported source language.
- Accept compatible SPIR-V produced by third-party compilers, including tools for Slang and WGSL. This is the extension boundary; Slang and WGSL are not additional directly supported source languages. Their output must meet the same stage, entry-point, SPIR-V version/capability, resource-binding and backend requirements as the built-in import paths.
- Use SDL_shadercross through the SDL3-CS ShaderCross binding for reflection and translation of SPIR-V to the active SDL GPU backend. HLSL import can use its HLSL-to-SPIR-V compiler; GLSL import uses a separately specified build-time compiler. The intended backend representations are SPIR-V for Vulkan, DXIL for Direct3D 12 and MSL for Metal. Translation or compilation of a backend representation does not add another public source language or guarantee support for every instruction on every target.
- The common runtime checks cover payload bounds/structure, the supported capabilities and stages, reflected resource layouts, bindings and shader interfaces; native translation/program-creation failures must propagate. This contract does not require adding SPIRV-Tools through a separate runtime C API. Additional instruction-level validation in import/build tools does not make that validator a runtime dependency. Document the checks actually performed; successful reflection alone is not proof of arbitrary SPIR-V validity.
- A directly supported language includes usable diagnostics, material parameters, textures, consistent resource bindings and backend verification. Successful source compilation alone is insufficient. Diagnostics must identify the source and stage, preserve compiler location information when available, and explain import, interface and backend failures. Reflected parameters and textures must connect to executable typed material APIs, with validation of types, layouts and bindings.
- Fixed one-dimensional sampled descriptor arrays use one typed logical material property and indexed shader defaults, independently of the image's ordinary/layered role. Preserve literal lengths, sampled scalar roles, original exported SPIR-V and resource aliases. Expand arrays into scalar native slots on the cold program path because the current GPU backend binds scalar descriptors; every element and additional engine sampler counts toward the existing sixteen-slot stage limit. Propagate selected slot handles through functions and control flow. Preserve implicit derivatives with candidate sampling and result selection; select explicit fetch/query branches to avoid unselected out-of-range fetches. This is an executable canvas adaptation, with explicit GPU-work cost rather than a native bindless performance guarantee. Keep renderer/global descriptors scalar, reject runtime/nested arrays and preserve atomic full-array validation/reload. Canvas HLSL import uses packaged DXC without descriptor-array flattening where needed; device/scalar compilation keeps its established route. See [the current contract and verification](../components/shader-materials.md#fixed-sampled-descriptor-arrays).
- HLSL and GLSL must share one documented material/resource interface contract. Equivalent shaders must receive the same parameter values and texture resources through the same engine API. Verify compilation errors, invalid bindings, material-parameter updates, texture sampling and rendered output for each language on every backend/platform that claims support. Missing material, texture or backend behavior keeps that language path incomplete. The canvas profile accepts independent secondary texture coordinates as fragment float2 location four, supplied by retained mesh UV2 storage through both ordinary and hardware-instanced vertex variants; location three remains internal to automatic lighting. This is an additional typed attribute consumer under ADR 0092, not a second texture sampler or an instance-data alias.
- Follow [ADR 0012](product.md#adr-0012) for the SDL3-CS/SDL_shadercross dependency path. This decision does not authorize restoring Silk.NET.Shaderc.Native or a separate runtime shaderc P/Invoke layer. Specify and pin the import/build compilers and account for their delivery separately from the native libraries actually required by the runtime's SPIR-V backend path. Compiler selection and native packaging require executable verification during integration.
- SDL_Renderer will be the fallback backend for the portable baseline of simple 2D drawing when the GPU backend is unavailable, cannot be initialized, or a host explicitly selects fallback mode.
- The SDL_Renderer fallback may select an OpenGL or OpenGL ES driver. This does not itself expose a window-associated GL/EGL/GLX context through the public API; the first executable fallback slice must audit those identities individually under [ADR 0042](display.md#adr-0042).
- SDL_Renderer fallback will not pretend to support arbitrary shaders. Shader-dependent resources or operations must be rejected explicitly before drawing when the active backend lacks the required capability; ignoring a shader, silently changing the effect, or reporting false success is prohibited.
- The public Electron2D rendering API will be backend-neutral and typed. It must expose the active backend and relevant capabilities without exposing SDL-owned handles or types. A project or host that requires shaders must be able to reject fallback during startup.
- Provide the applicable reference `RenderingDevice` compute API for user-owned simulations: local device lifetime, SPIR-V compute shaders, storage/uniform buffers, uniform sets, compute lists, dispatch/barriers, submission/synchronization and explicit readback. This user-requested compute slice supersedes the blanket exclusion of RenderingDevice and its compute resource family. Backend-neutral means no SDL handles/types are exposed; it does not prohibit explicit portable compute. Keep application-specific liquid models in consumers, with CPU and GPU implementations, rather than introducing an engine-only fluid API. Local compute also owns color images, sampled image arrays, samplers and writable images. RDTextureFormat/RDTextureView/RDSamplerState are copied ElectronObject descriptions, not canvas resources. TextureType.Texture and TextureArray name their two-dimensional storage roles; volume, one-dimensional and cube roles remain excluded. Use tightly packed byte mip chains per layer with hidden native alignment, copied initial/update data, explicit synchronous and queued readback, and copied allocation getters. Combined GLSL samplers and same-binding paired image/sampler declarations map to SamplerWithTexture with ordered sampler/texture RIDs. Independent Texture and Sampler descriptions borrow one RID each, may occupy different logical sets and may be reused by several image/filter pairs. Reuse the existing opaque-handle shader lowering through functions, returns and control flow; only consumed pairs occupy the sixteen native stage slots. Samplerless fetch/query reuses an image slot or a retained private point sampler. Preserve implicit derivatives with candidate sampling and result selection; explicit loads/queries select their native branch. Validate scalar/array roles, live current sets, comparison operations, integer filtering and active-output feedback at their consuming boundary. Resolve unknown depth metadata from actual comparison operations and reject a sampler that requires conflicting comparison modes. This is a scalar native binding adapter with shader-work cost, not a bindless throughput claim. Fixed device descriptor arrays follow the scalar-slot adapter below. Validate scalar signedness, explicit storage formats, array roles and integer filtering before recording; support queries report the executable local format/usage profile. Each dispatch closes its native pass; algorithms own race freedom within one dispatch. TextureCopy preserves raw texel/block bytes across validated mip/layer rectangles; preserve the three-component data-coordinate contract with zero Z origins and unit depth, integral backend projection, and explicit format capability limits. TextureClear selects complete mip/layer ranges on the GPU timeline with CanCopyTo usage, including transfer-only destinations through retained private color targets. These private targets also implement disjoint same-subresource copies and are released with the owning texture/device. Integer color-clear lanes retain their encoded 32-bit component bits on Vulkan; narrow signed lanes must be representable. Compressed color clears and unverified native conversion/reinterpretation profiles fail explicitly. Native view reinterpretation/swizzles, raw depth/stencil transfers, transient/frame last-use lifetimes, atomic images retain exact integration dependencies. Do not expose inert configuration switches for those absent lifetimes. Remaining depth-bounds/per-face state adapters retain their exact attachment/shader prerequisites; three-dimensional/ray-tracing operations remain outside the product boundary. Local compute resources are device-owned RID identities, owner-thread accessed and disposed before the device. Queued local readback captures request-time bytes and delivers typed callbacks at explicit local completion (Submit/Sync, synchronous GPU reads or resource freeing); automatic waits during new recording must not reenter user code. Provide a caller-owned Memory overload for prepared allocation-sensitive consumers. Preserve FIFO completion under nested operations, attempt other completed requests after callback failures and aggregate those failures. Device disposal cancels undelivered callbacks and releases retained transfer storage; caller-memory accessors must not reenter the device during destination acquisition. Unsupported compute capability must fail explicitly, and a consumer may offer a separately identified CPU algorithm. The first graphics slice owns paired vertex/fragment programs, readonly stage storage descriptors, vertex/index allocations and borrowed arrays, copied vertex/attachment/raster/blend descriptions, zero to eight color render targets plus optional depth and resolve attachments, direct/procedural/instanced/indexed and GPU-directed indirect draws, dynamic blend constants and framebuffer scissoring. Clear/load/store operations and copies remain ordered with compute; retained-device output feeds TextureRD and canvas without CPU transfer. Vertex-array instancing and descriptor-set remapping preserve logical bindings across stages. Depth/stencil images and pipelines now execute: query D16/D24/D32 and D24/S8 or D32/S8 support, initialize each layer/mip to depth/stencil zero through native clears, borrow at most one ordinary depth target beside zero to eight color targets, preserve attachment order while deriving color output slots, and store each available aspect across passes. RDPipelineDepthStencilState copies depth testing/writes and two-sided stencil operations; pinned stencil operation defaults are Zero (numeric 1), while Keep is numeric 0. CompareOperator and StencilOperation remain nested owner contracts. Eight-bit stencil masks use their low eight bits and visible references must fit 0–255. SDL_GPU provides shared masks/reference: both visible faces require equal effective values; culling permits different unused-face values and selects the surviving face. Independent per-face operations still execute. Different effective masks/references with both faces visible reject before native creation until a per-face backend adapter exists. Depth writes require an enabled depth test. Static constant/slope depth bias and bias clamp execute in the native rasterizer. Comparison samplers require a depth-comparison shader descriptor and a depth image; regular depth sampling remains available, including sampled arrays and mip levels. Active depth images participate in feedback rejection. Depth uploads/readback/copies require native aspect-transfer validation and are not advertised; depth images presently expose only depth-target and optional sampling roles. Multisample color/depth targets now retain exact queried sample counts (one, two, four or eight where available), with no native quality fallback. RDTextureFormat.Samples and IsResolveBuffer are copied allocation roles. Multisample resources are ordinary single-layer/single-mip render targets with empty initial data, initialized by native clears; ordinary sampled/storage multisample descriptors and raw sample transfers remain explicit adapters. Multisample input attachments execute through readonly fragment image fetches. RDFramebufferPass copies ordered color/depth/resolve/input/preserve descriptions, including unused resolve/input slots. FramebufferCreateMultipass and FramebufferFormatCreateMultipass execute ordered SDL_GPU passes; RenderPipelineCreate selects its pass and DrawListSwitchToNextPass retains list identity while resetting bindings, push data and scissor to the original region. Ending early executes remaining empty passes and resolves. InputAttachment requires an ordinary single-layer/single-mip color image; float/signed/unsigned GLSL/HLSL SubpassData reads lower privately to pixel-coordinate readonly fragment fetches, including explicit multisample loads. Original public bytecode remains intact. SDL_GPU forbids combining sampler and readonly graphics-storage flags, so an image with InputAttachment and Sampling retains a private readonly snapshot copied on the GPU timeline before each input pass. Input-only images bind directly. Descriptors must name the image selected by the active input index, with matching scalar/sample roles; active output/depth/resolve feedback rejects. Preserve lists control stores across inactive intermediate passes; duplicate preserves are idempotent and active preserves need no extra action. DrawListBegin clear colors index all ColorAttachment images in framebuffer order, including resolve images, independently of per-pass output locations. Sparse color output slots retain their logical indices and exact shader output masks while native target/blend arrays and pipeline-owned SPIR-V output locations compact active slots. Resolve/input/preserve indices remain logical; unused blend slots and extra trailing entries are ignored. Original modules remain unchanged. Attachmentless passes and non-color input aspects retain their exact native prerequisites; layered multiview follows the ordered-view contract below. Resolve destinations are marked ordinary matching single-sample color targets. Store-and-resolve preserves source samples for later passes; TextureResolveMultisample performs an ordered full-color resolve with CanCopyFrom/CanCopyTo roles. Resolved images feed sampling, readback and retained canvas normally. RDPipelineMultisampleState copies exact SampleCount and EnableAlphaToCoverage; the pipeline must match the framebuffer raster sample count. Sample masks are reserved in SDL_GPU, alpha-to-one and per-sample shading lack native states, so their configuration remains Blocked. IsDiscardable remains absent until frame/resource last-use analysis can avoid dropping contents still needed by another pass. Push constants now execute for compute/vertex/fragment through a private raw-word std140 uniform block per used stage, preserving the original 32-bit scalar/vector, compact array, row/column-major matrix and nested-struct byte layouts. Blocks retain the portable 128-byte limit and exact reflected extent; application data is copied at the setter and snapshotted at every recorded draw/dispatch. Pipeline changes and new lists require fresh push data. A push stage uses one of four native uniform slots, leaving three ordinary buffers; its private logical binding is chosen without reserving an application set. Additional scalar precision and pointer address/arithmetic semantics require their native shader capability/translation adapters. Pipeline specialization now executes for compute and paired graphics. RDPipelineSpecializationConstant is the ElectronObject identifier base; RDPipelineSpecializationConstant<T> owns a nullable Boolean/Int32/UInt32/Single value, preserving the unassigned default without a public Variant/object union. Factories copy descriptions, require distinct declared nonnegative identifiers and matching scalar types, and retain independently owned native variants with borrowed public shader identity. Modules freeze scalar defaults/overrides and dependent integer/logical/vector/composite constant operations before reflection, push translation and native creation. Compute local sizes and uniform/push array extents use the resolved values. Shader creation retains symbolic specialization templates so an unusable default can be repaired at pipeline creation; native layout/capability checks apply to the resolved variant. Wider scalar precision requires the native precision adapter. Depth bounds, raw depth resolve, attachmentless graphics and additional dynamic states retain exact prerequisites, with no inert switches or empty classes. Geometry/tessellation stages require an accepted backend stage adapter; no public native handles are added.
- Formatted texel buffers use an internal raw GPU storage-buffer representation with private element-count/layout metadata and build-time compiled pure format conversion functions. The public factory counts elements, following the pinned executing implementation; nonempty initial data covers the complete encoded capacity. Preserve those encoded bytes through ordinary buffer updates, copies, clears and synchronous/queued reads, excluding private metadata from every public offset. Derive native SPIR-V for indexed fetch/read/query, compute stores and signed/unsigned R32 atomics while retaining the original exported modules and logical TextureBuffer, SamplerWithTextureBuffer and ImageBuffer roles. Sampled declarations select the scalar class; storage declarations also select their concrete format. Combined sampled buffers retain sampler-first identities and lifetime validation, while texel fetches ignore filtering. Native buffer slots, rather than sampler slots, bound the executing stage capacity. Preserve coherent/volatile qualifiers and include storage-buffer memory in translated image barriers. Subword stores update disjoint packed fields atomically; integer narrowing clamps to the destination range. Graphics remains readonly. Uncompressed encodings up to 32-bit components include normalized/scaled/integer/float, packed unsigned/shared-exponent and sRGB lookup roles. Wider precision and unavailable writable graphics stages keep exact adapters. This adds no runtime source compiler, public backend handle, CPU frame bridge or three-dimensional image role.
- Fixed one-dimensional device descriptor arrays expand image, sampler, combined, texel-buffer and input-attachment roles into the existing scalar native slots. RDUniform lists identities in element order; combined roles repeat sampler/resource pairs. Ordinary uniform/storage buffers retain their pinned one-RID contract. Descriptor count remains separate from layered image type. Validate every element and the exact resolved count, preserve exported modules, propagate guarded selectors through helpers/control flow and defer specialized counts to the resolved pipeline. Sampled candidates share sixteen stage slots; images and texel buffers share their existing eight-slot category limits. Input array indices advance from the declared input index. Runtime/nested arrays and unavailable frontend syntax keep exact prerequisites. This adaptation adds shader work and makes no bindless performance claim. See [device descriptor arrays](../components/local-compute.md#fixed-device-descriptor-arrays).
- Ordinary signed/unsigned R32 storage images execute core integer atomics in compute, including fixed descriptor arrays. StorageAtomic validates the native simultaneous read-modify-write format capability; Image binding independently requires Storage, following the pinned executing contract. Existing R32 Storage allocations retain that native access too. Preserve operation/result signedness, prior values, coordinates, coherent/volatile declarations and original scope/memory semantics. Scalarize array image texel pointers only inside the selected operation branch; invalid selectors return zero or suppress stores. Keep the required constant-zero sample operand for ordinary images. Separate dispatches retain ordered native pass boundaries; kernels own synchronization and race freedom within one dispatch. Float/wider atomic capability, layered storage-image views and writable graphics keep their specific native adapters. See [integer image atomics](../components/local-compute.md#integer-image-atomics).
- Layered device framebuffers execute the complete viewCount parameter family through ordered native layer passes. Formats retain one through 256 views, following the depth-target layer address width rather than advertising a hardware multiview feature limit. Every attachment supplies at least that many layers, and an explicit format must agree. Draws, scissor/blend/push state, indexed/indirect commands and ordered color/depth/resolve/input passes execute independently for the first viewCount layers; extra layers remain untouched. Private per-view shader copies flatten built-in input blocks when needed and replace the vertex/fragment ViewIndex input with its exact scalar value before native compilation, retaining original exported bytecode. This is portable sequential execution, not simultaneous native hardware multiview or an XR scene domain. Resource identities, ownership, thread/callback guards, clears and prepared managed-allocation rules remain the ordinary device contracts. Attachmentless graphics and missing aspect/view operations retain their separate prerequisites.
- Readonly graphics storage-image declarations keep the public Image descriptor role and the native eight-image category. Private SPIR-V converts storage-image reads and size queries into unfiltered readonly image fetches at mip zero, preserving scalar values, coordinates and original exported modules. Native sampler and graphics-storage-read flags cannot share one allocation. A logical Sampling/Storage image therefore retains its sampling/compute allocation plus one private readonly GPU snapshot. Capture it before each authored draw, reuse it across that draw's views, and restore geometry/resources/push/scissor/blend state after restarting the native pass. Such devices conservatively store pass attachments across these copy boundaries; explicit input/preservation guarantees remain unchanged. The original image remains authoritative for writes and public readback. Freeing it or closing the device releases the private snapshot. Independent Texture/Sampler bindings execute through their separate sampled-resource adapter and are not relabeled Image.
- The active GPU canvas retains one renderer-owned RenderingDevice, exposed through static RenderingServer.GetRenderingDevice; an absent/compatibility renderer returns null. Its portable image RIDs bind through TextureRD and the array-only TextureLayeredRD/TextureArrayRD family, or server-owned TextureRDCreate wrappers. Canvas sampling uses the same native image allocation directly. Record on the scene owner thread; end lists before rendering. The renderer flushes after canvas authoring and before native drawing, and completes queued readbacks before FramePostDraw. Explicit Submit/Sync and caller disposal remain local-device operations. Resource/server wrapper identities borrow the global image and expire independently; freeing the image empties live metadata, and renderer shutdown invalidates the device. Resource archives omit process-local image bindings, while duplication borrows the same image. Readback keeps representable encoded Image formats, otherwise converts sampled color to floating-point RGBA on GPU; no frame CPU bridge is introduced. Integer canvas samplers preserve raw signed/unsigned scalar values and use nearest filtering with nearest mip selection; named descriptors validate scalar type and array role before binding and discard incompatible defaults/overrides on reload. HLSL integer Load supports combined descriptors and private matching samplers for separate images; GLSL exposes typed integer samplers. ### Consequences

- The GPU path is the normal rendering path and the only path that guarantees programmable shader behavior.
- The fallback keeps basic 2D games and editor recovery UI possible on systems where the GPU path cannot start, while its reduced capability remains visible to callers.
- Games that use custom shaders must declare or check that requirement instead of assuming fallback visual equivalence.
- Rendering code and vendored SDL3-CS managed bindings belong to `Electron2D.dll`; native SDL packaging remains a separate platform-specific integration boundary.
- Projects can supply HLSL, GLSL or externally compiled compatible SPIR-V without depending on SDL types. Shipped shader artifacts enter one validated SPIR-V path. The same validation and reflection requirements apply to imported and external modules.
- Browser WebGPU consumes that same contract through an internal SPIR-V-to-WGSL translation path; separate browser shader source or public WebGPU handles are not required.
- Every implemented rendering feature must be tested against each backend that claims it. Shader compilation and visual correctness additionally require backend- and platform-specific executable or image-based verification.

### Rejected alternatives

- **Use SDL_Renderer as the only or primary backend:** rejected because its simple 2D API cannot provide the required arbitrary shader pipeline.
- **Require the GPU backend with no fallback:** rejected because a reduced but explicit baseline renderer improves portability and startup recovery.
- **Emulate arbitrary shaders on SDL_Renderer:** rejected because it would create incompatible behavior, high maintenance cost, and misleading capability claims.
- **Silently drop shader effects on fallback:** rejected because output would be incorrect while appearing successful.
- **Expose SDL handles in the public API:** rejected because it would couple games and the editor to one backend and prevent controlled backend evolution.
- **Support HLSL only and leave GLSL entirely to external tools:** rejected because HLSL and GLSL are both directly supported project languages.
- **Add more directly supported languages for each available compiler:** rejected because each language entails diagnostics, material and texture integration, binding rules and backend verification. Compatible SPIR-V preserves extensibility without multiplying maintained source frontends.
- **Require source compilation when loading or drawing game materials:** rejected because source compilation belongs to import/build, while the runtime consumes the common shader artifact contract.
- **Treat compiler success as complete language support:** rejected because parameters, textures, resource interfaces, diagnostics and backend behavior must also work.
- **Add renderer interfaces and shader resources without executable behavior:** rejected because declarations alone do not satisfy the rendering contract.
- **Wait for SDL_GPU to gain a Web backend:** rejected as the browser implementation plan because the pinned SDL build exposes no such driver while WebGPU is available in the tested browser.

The published importer passes its HLSL, GLSL and external-SPIR-V suite with no compiler lookup through `PATH`. Its `Electron2D.Shaders.targets` integrates those inputs with SDK C# build/publish and Clean. The initial cache/import policy reuses artifact bytes and timestamps: normal builds compile and validate every input, replacing output only when bytes change; publish with `--no-build` reuses the last build artifacts. This supplies the first-slice cache/import contract without skipping source validation. A later compilation-skipping cache must account for compiler versions/options and actual include resolution, including new shadowing files and macro-only changes; it remains a toolchain optimization, not claimed behavior of this integration. Logical boolean types are recovered from the source compilers during import and stored as validated standard OpString records in the common SPIR-V artifact. External producers use the same metadata schema and physical-layout checks; runtime does not infer booleans from unsigned storage. Scalar bool maps to bool, boolean vectors to int component masks, and arrays use one such value per logical element under ADR 0005. [The component contract](../components/shader-materials.md#boolean-type-information) records the schema and verified limits. Additional build hosts remain unverified.

CanvasItem/Viewport sampling policies now cover texel filtering, ordinary/mirrored repeat, uploaded mipmaps and GPU anisotropy. [Canvas rendering](../components/canvas-rendering.md#texture-sampling) records native backend restrictions; unsupported fallback modes fail explicitly under this ADR. Named material samplers currently implement linear/base-level/clamp defaults independently of canvas policies; their configuration remains pending.

The tested Android arm64 phone now runs the GPU canvas and HLSL/SPIR-V material when four optional Vulkan features are disabled; the pipeline enables depth clipping because depth clamping is then unavailable. The tested Android TV exposes OpenGL ES 2 but no Vulkan hardware feature, so SDL_GPU remains unavailable and only the shaderless SDL_Renderer fallback works. The isolated Chrome probe has WebGL2 and WebGPU devices and a direct SDL_Renderer frame, but SDL 3.4.16/Emscripten exposes no SDL_GPU driver. [The platform matrix](../platform-verification.md) records the exact checks and limits. Standalone probes confirmed a GLES2 fragment shader and red readback on that TV and a WGSL/WebGPU shader frame in Chrome. The selected browser WebGPU backend and a shader-capable TV path remain unimplemented; both require shader translation, canvas/material integration, lifecycle and pixel verification before claiming the common shader contract there.

## ADR 0046: Render text with FreeType and HarfBuzz

Last updated: 2026-10-20

### Status

Accepted. The first font, canvas text and Label slice integrates this backend; platform and semantic claims require the executable gates below.

### Context

The existing canvas has GPU and SDL_Renderer paths. Public fonts and GUI text must preserve fractional shaping, Unicode layout and glyph raster behavior without exposing native handles or a second renderer. The initial SDL_ttf choice was tested against the applicable contract. SDL_ttf 3.2.2 integer text-operation rectangles lose fractional HarfBuzz positions; its shaping load flags follow raster hinting instead of the required unhinted metrics. Its public glyph API cannot select the required half/quarter-pixel raster phase, and its outline radius differs from the reference stroke policy. The published SDL3-CS.Linux.TTF 3.2.2.11 binary also fails to open the embedded Open Sans WOFF2, while the packaged direct FreeType face opens it successfully. Retaining SDL_ttf would require a second font raster path or a WOFF2-to-SFNT conversion layer in addition to direct FreeType and HarfBuzz.

### Decision

- Use public FreeType and HarfBuzz C APIs directly for font loading, SFNT-table access, fractional shaping and phase-aware glyph rasterization. Remove the redundant SDL_ttf dependency. Preserve unhinted 26.6 shaping advances and offsets independently of the chosen raster hinting; apply the specified rounding, residual carry, raster phase and outline stroke policy at their own stages.
- Font metadata queries use the primary realized face, including selected collection/variation/system sources. Project supported OpenType tags into `FontFeatureInfo` with an optional localized label, a boolean-versus-integer discriminator and a hidden-selection flag; return localized name strings as copied language/name maps. Preserve GSUB-before-GPOS duplicate precedence and native tool-locale capture. Name maps are materialized lazily on the serialized text owner, and each capture rejects expanded UTF-16 text beyond 64 MiB before publishing a partial result. These snapshots are cold introspection; configured feature values continue through the existing shaping path.
- Package native-only `MonoGame.Library.FreeType` 2.13.2.5 and `HarfBuzzSharp.NativeAssets` 14.2.1.301 assets under [ADR 0012](product.md#adr-0012). Their C ABI bindings remain internal engine source in the single `Electron2D.dll`. The FreeType package version is not its native library version: the tested Linux x64 payload reports 2.13.3. HarfBuzz obtains SFNT tables and unhinted metrics from FreeType through public callbacks, which also supports WOFF2 containers without interpreting private native storage.
- Accept scalable non-SFNT Type 1 outline sources through the same FreeType owner and HarfBuzz shaper. Set face glyph count/units explicitly and supply nominal/selector mapping and unhinted native kerning callbacks; retain normal metrics, raster, MSDF, feature, direction and cluster behavior. PFB/PFA file imports optionally attach same-name PFM then AFM metrics; explicit PFM/AFM imports resolve a matching PFB then PFA outline. Search lowercase then uppercase extensions. This resolves the reference PFM source role as an auxiliary source, since metric files contain no outlines. Preserve a private immutable stored metric snapshot with the outline source across copies, archives, variations, indexed cache rebuilds and Linux installed/automatic sources; a raw Data assignment clears that attachment. Enforce the combined 64 MiB source budget and validate attachment before publication. Do not synthesize SFNT metadata tables or add a public format-specific API. [Type 1 source evidence](../components/text.md#type-1-outline-and-auxiliary-metric-sources) records exact native/host verification limits.
- Confine mutable native font state to one serialized synchronous owner. Threaded native runtimes use a worker with a reusable request slot. The nonthreaded browser profile executes on its captured browser thread and rejects another owner instead of starting a worker or blocking the event loop. Browser hosts yield between frames; this does not introduce a multithreaded browser profile. Public resource state uses locks and emits public notifications outside those locks. Cached layouts and glyph textures reuse prepared storage; source replacement is validated before committing and releases old native ownership after invalidation. The built-in font defers native initialization until first text use.
- Keep text layout, explicit font fallbacks, measurement, line breaking, BiDi, justification, direction and drawing behind typed Electron2D APIs. Compile the bounded Avalonia 12.1.3 Unicode 17.0.0 algorithm/data closure internally, pinned to `8eeda4f6f546165b3f72e63c9f42247abb306905`, retaining its notices and reproducible import. Engine adapters correct integration behavior without modifying vendored algorithms. Unicode conformance does not by itself establish Label or font semantic parity.
- Use pinned ICU 78.3 / Unicode 17 word and locale-aware line break iterators for dictionary segmentation and line tailoring. Default UAX 14/29 algorithms alone do not split Thai words or reproduce CJK/Japanese dictionary word boundaries. Compile the bounded ICU common source closure behind the private `Electron2DTextBreak` C ABI and include only required break/property/dictionary data. Keep ICU symbols hidden under a private suffix and unique library identity; the engine must not replace or interpose on the .NET runtime's system ICU. Native build artifacts remain outside version control; the filtered, hash-pinned data is an intentional runtime input with a reproducible updater. Native host/toolchain and publish checks are required before claiming each target. The same private common closure supplies standalone lowercase/titlecase, normalization and identifier properties under ADR 0107. Its existing unchanged spoof/script-set/cleanup source closure is also linked into the private runtime for UTS 39 checks; confusables.cfu is already retained in the immutable package. Retain ulayout.icu alongside the existing data so Indic_Syllabic_Category is available; missing property data is an explicit error, not a permissive identifier result. The filtered payload now has 61 entries and remains reproducible from the unchanged release archive. Managed full uppercase remains shared with existing controls.
- Native antialiasing shares FontAntialiasing across FontFile/SystemFont and their realized/variation/automatic fallback data. Execute monochrome, grayscale and LCD FreeType modes. ProjectSettings.LCDSubpixelLayout captures None or horizontal/vertical RGB/BGR at first native text-owner startup; it is a restart-required preference. None selects ordinary grayscale for an LCD font. Component triples become logical RGBA coverage and feed the existing retained LCD shader/blend path, including strokes and clipping. Preserve independent intrinsic-color bitmap and bitmap-only authored image roles; scalable authored regions follow their explicit encoded coverage policy. Compatibility rejects actual component glyph submission. This does not implement MSDF image generation. See [font antialiasing](../components/text.md#native-font-antialiasing-and-lcd-layout).
- MSDF font generation uses the immutable msdfgen 1.13 core (`1874bcf7d9624ccc85b4bc9a85d78116f690f35b`) through the existing private text-native library. The serialized FreeType owner decomposes public outlines, including hinting and configured variations, into a bounded portable edge array; the native bridge generates multichannel distances with true distance in alpha and releases its cold result after copying. Preserve the source coordinate conversion, orientation, edge coloring, error correction and margin policy. One canonical MSDFSize/zero-outline cache feeds drawn sizes and shader outlines, without oversampling or subpixel phase changes; expose all three stored preferences on FontFile and SystemFont and propagate them through configured variants and owned fallbacks. Owned color or non-scalable fallbacks retain ordinary image generation; explicit authored canonical pages may carry caller-supplied encoded distances. Resource preferences preserve integer values; invalid source size/range or an image exceeding the 64 MiB byte budget fails at generation without publishing pixels. Existing source retirement and authored-cache ownership apply. The GPU canvas consumes the resulting regions through the retained MSDF path; Compatibility rejects actual distance-field submissions. Package the unmodified core and its license with the private text dependency; foreign native/visual acceptance requires its own gate.
- Copy rasterized glyph pixels into ordinary engine textures and draw through the existing canvas on both backends. No native glyph atlas, graphics context or second renderer is introduced. The shaped-buffer identity interface under ADR 0107 uses these same owners; it does not expose native font handles. Glyph pixels, font/layout caches and borrowed resource lifetimes are separate from renderer-owned GPU payloads. Font-owned glyph textures retain backend cache residency across unused frames until source retirement drops the residency request; backend entries hold no owner-font reference. Retirement waits for active reads before closing native faces. Already recorded immutable glyph snapshots retain their pixels, and an unused frame releases retired GPU payloads. Unleased ordinary texture eviction remains unchanged. Attached button controls also use balanced internal residency counts for their declared state textures; exit, replacement and disposal release those counts without texture-to-control references.
- Structured URI, file, email and list contexts and a typed custom Control hook are applicable text capabilities. Represent context ranges as scalar start/end/direction values, not spatial Vector3i. The GDScript-specific built-in parser is excluded from the C# product identity under [ADR 0001](product.md#adr-0001); it is not a prerequisite for drawing arbitrary text or supplying a custom typed parser. Keep this exclusion explicit on that enum value and do not expose an inert mode.
- Represent configurable font instances as typed FontVariation resources borrowing a base Font. Each realized instance owns an independent native face/shaping font/cache; source and native configuration changes retire it after active reads. Font.FindVariation returns a new caller-owned typed instance instead of an opaque native variation handle. Repeated factory calls create independent resources; stable identity belongs to each retained resource, and no native handle leaks through its public API. Copy design coordinates by numeric OpenType tags and support registered readable names through the typed setter; return axis minimum/maximum/default as FontVariationAxis scalar data rather than a spatial vector. Apply the same resource instance across font measurement/drawing, rich spans, factory/metadata queries, duplication and storage. This does not expose TextServer RID services; FontFile indexed authoring follows the separate record/ownership contract below.
- FontFile indexed cache authoring owns copied size/metric/glyph/kerning/image-page records and independent native instance configurations. Text/binary v3 BMFont imports execute through the same HarfBuzz callbacks and common text/canvas consumers; no separate Unicode shaper or renderer is introduced. Cache image rectangles remain pixels; scalar metrics and converted native 26.6 kerning use logical pixels. Authored edits validate copied replacements before publication, notify outside locks and retire after active readers. Matching typed FontVariation instances copy configured indexed records. Bounded typed archive snapshots store pixels and values without native identities. Fixed bitmap policies preserve Disable=0, IntegerOnly=1 and Enabled=2. This implements indexed authoring separately from the process-wide TextServer RID service.
- SystemFont owns selected native sources over an optional installed-font catalog on the retained OS service. Current Linux uses host Fontconfig without bundling or modifying system font state; other provider profiles use borrowed theme fallback until their CoreText/DirectWrite integrations execute. Preserve collection best-match logical indices and requested variable defaults through FontVariation; explicit coordinates take precedence. Missing text/graphemes may load at most 64 parent-owned fallback faces after explicit resources, with policy/source retirement deferred through active readers. FontFile.AllowSystemFallback defaults to true; explicit support queries remain distinct from automatic rendered coverage. Persist requested preferences and permission, never resolved machine paths/native identities. Platform/raster/MSDF gates remain per-row rather than inert properties.
- Verify text output on each claimed canvas backend and runtime platform under [ADR 0021](product.md#adr-0021). Desktop native assets enter this slice; mobile and browser text remain blocked until the corresponding FreeType/HarfBuzz artifacts, resolver integration and execution checks exist. Default theme construction without text must remain usable before native font initialization.

### Consequences

The direct bridge is the sole native font/shaping/raster foundation. It removes duplicate font ownership and conversion work required by SDL_ttf while preserving the existing canvas architecture. Public TextServer services, system-font discovery, project theme import and other font mechanisms retain their exact coverage dependencies; native library availability does not implement those APIs.

### Rejected alternatives

- Keep SDL_ttf plus a second precision/raster bridge: rejected after executable WOFF2 loading failure and the fractional metric, raster phase and outline mismatches above. SDL_ttf's own renderer is not used.
- Introduce SkiaSharp or another complete 2D renderer for text: rejected because Electron2D already owns its canvas and texture lifecycle.
- Rasterize glyphs without HarfBuzz shaping or implement Unicode paragraph rules heuristically: rejected because it cannot satisfy the multilingual text contract.

CanvasItem.OversamplingWithScale uses the namespace-level OversamplingWithScale enum (ParentNode=0, Disabled=1, Enabled=2, Max=3); this follows the existing TextureFilter property/type placement under ADR 0051 and avoids a C# member/type name collision. Max is nonselectable. ParentNode resolves through direct canvas parents, stopping at TopLevel and neutral boundaries; a root resolves disabled. Enabled automatic rasterization multiplies the viewport factor by the maximum signed component of the current logical global transform scale. Camera, canvas-layer, draw-command and interpolated presentation transforms do not contribute. Nonpositive item factors fall back to the viewport policy. Explicit font factors, authored bitmap glyphs and MSDF retain their owning raster rules.

Before visible retained recording, resolve the item factor and request rerecording on changes even when transform notifications are disabled. Active viewports and scale-enabled items share quantized raster-level references. SVG variants and native glyph atlas pages are retained by level; engine-generated pages do not mix native raster factors. Explicit authored packing pages keep their caller-owned layout and pixel lifetime; retiring a level removes its generated glyph records without retiring those authored pages. Explicitly requested font raster factors remain source-owned until source cache retirement. Releasing the last automatic owner retires the matching SVG identity and automatic font cache records/pages, while immutable pixels already retained by canvas commands remain usable until ordinary renderer eviction. Reparenting, TopLevel, visibility restoration, canvas/viewport changes and disposal must resolve or release ownership. First generation and changing scale are cold allocations; stable replay requires executable warmed-frame checks.

The TextServer font-cache producer shares FontFile realization through stable owned identities and borrowed runtime Font views under ADR 0107. Atlas storage includes fractional phases and explicit oversampling variants. Fixed-size policies apply coherently to scalable native shaping, metrics, raster geometry and copied outlines as well as authored bitmap data. Cache size/geometry queries use the selected source size and requested scale. Selected face changes refresh intrinsic metadata; ordinary same-face edits preserve descriptive overrides.

- ShowRect is editor-only magenta gizmo drawing in the pinned source. Keep that member Blocked until the first self-hosted editor canvas gizmo drawing slice and add/test its flag and fill there. Do not ship an inert bool. Public independent offscreen viewport rendering remains subject to its existing lifecycle gate; this slice integrates the current root-window renderer and CanvasLayer groups on both backends.

Raw retained canvas items also accept typed visibility callbacks through RenderingServer.CanvasItemSetVisibilityNotifier. The local area extends command/custom bounds; parent visibility, alpha, cull layers and clipping still apply. Samples are OR-combined across every submitted viewport, then committed once after successful backend frame completion. A global submitted frame with no participating viewport exits previously visible raw notifiers. This differs from the scene-node last-sample policy only at its explicitly retained hidden/stopped viewport boundary. Disable, free, scene-node disposal and renderer teardown clear callbacks silently. Replacing callback/area preserves current screen state but invalidates stale queued delivery. Commit every state before callbacks, attempt later transitions after failures and never replay committed transitions. Callback mutation/free is allowed after submission, while nested rendering remains rejected.

The GPU-owned white texture retains its renderer cache until backend disposal, avoiding recreation on empty frames. Other platforms require their platform gate.

ScreenVisibilityTests covers defaults, enums, target cache identity/path changes/errors, every process policy, weak disposal, silent departure/reentry, event failure with policy application, ownership, packing and 64 warmed nested ProcessMode transitions with zero managed bytes. ScreenVisibilityRenderingTests covers twelve native region/mask/layer/default-canvas/alpha/border/degenerate stages, black readback confirming no runtime gizmo, actual RigidBody participation, committed peer state, stale event suppression, failure continuation/native release and 64 warmed active enabler transitions with zero managed bytes per compatibility/GPU Linux Wayland path. Native allocator counts, other platforms, broad-scene cost and owner visual acceptance are unverified; no vendor source changes.

## ADR 0079: Retained nine-patch controls

- Status: Accepted
- Scope: NinePatchRect control, borrowed texture regions and all axis modes on both current canvas backends

## ADR 0080: Shared ranges, progress controls and sliders

- GridContainer fills direct eligible controls in row-major order with Columns >= 1 (default one). Local-visible children determine minimum size; visible-in-tree children participate in arrangement. Truncate bound minima and maxima to integer pixels, aggregate the largest minimum and effective maximum per occupied column/row, and refit selected expanding columns/rows uniformly on each axis without stretch ratios. Treat empty declared columns as expanding by count, without storage proportional to Columns; only occupied columns contribute separation. Assign integer remainder to the first expanding occupied columns/rows and reverse horizontal placement under RTL. Signed HSeparation/VSeparation resolve theme constants with built-in default four; changed assignments run immediate theme notification/cache/redraw/minimum/reflow work and then deferred child layout under ADR 0083. Cross Fill/Center/End use the line cross minimum, with final fitting inherited. Signed H/V theme gaps, allowed-size hooks, typed factories/storage, desired-size forwarding and existing maximum propagation execute. TextureRectTests verifies all four modes across both orientations and direction combinations.
- SplitContainer and fixed HSplit/VSplit arrange all eligible ordinary panels with real internal drag controls, [0] initial relative offsets, weighted capped defaults, multi-offset range/overlap clamping and structural desired-size preservation. Keep primary integer truncation, the two-expanded-panel ratio default, signed drag margins/offset, RTL and collapse behavior. Touch handles use internal TextureRect children, directional borrowed theme icons and idle/hover/press tints. Orthogonal adjacent descendant intersections use pass-through internal controls so both axes receive one gesture. Reuse prepared layout/resource/intersection storage and attached texture residency. Editor drag-area highlighting stays Blocked for the first editor context/overlay slice under ADR 0027; inherited accessibility remains on Control.
- FoldableContainer : Container arranges visible title controls at the trailing edge and ordinary non-top-level controls in one content rectangle. Folded hides ordinary children; expanded shows all eligible ordinary children, including previously hidden ones. Its title moves above/below the body through shared BarPosition, with source RTL/alignment, translated shaping, trimming, themed arrows/colors/styleboxes and flipped bottom styles. Mouse press in the title and exact ui_accept activate; tooltip/hit testing obey the folded title region and native focus remains visible. FoldableGroup : Resource keeps weak members and defaults ResourceLocalToScene=true, AllowFoldingAll=false. Properties change fold state silently; Fold/Expand/input emit FoldingChanged with actual state even for equal/refused requests. Expanding folds peers and emits group Expanded before committing the source state. Callback failures still finish required commitment/layout; nested same-target requests terminate and a later reentrant group selection wins. Grid propagation supplies the combined bounds for constraint collection, then independently subtracts each cell's column/row offset for final fitting. Raising a maximum therefore releases an obsolete smaller allocation without manual resize/sort. Enqueues made during capture wait for a later flush; cross-thread acceptance remains atomic with lifetime. The class stays Partial for that exact member; do not expose an inert property. Other container types retain their own coverage triggers. ## ADR 0083: Typed themes, owner lookup and panel consumers

- Depends on: [0081](#adr-0081), [0082](#adr-0082), [0023](scene.md#adr-0023), [0046](#adr-0046), [0001](product.md#adr-0001), [0008](scene.md#adr-0008), [0013](resources.md#adr-0013), [0014](resources.md#adr-0014), [0021](product.md#adr-0021)

- Scalable SVG icon resources use DPITexture and viewport oversampling under [ADR 0039](resources.md#adr-0039). Theme consumers borrow the source resource; per-viewport raster variants remain runtime-owned and are resolved during retained canvas replay.

- Theme : Resource stores six executable typed categories: Color, integer Constant, borrowed Font, integer FontSize, borrowed Texture Icon and borrowed StyleBox. Preserve DataType numeric identities Font=2 and Max=6. Generic category-presence/list/rename/clear operations cover all six categories; generic Variant get/set remains projected through concrete typed getter/setter families under ADR 0001.

A Theme query addresses one explicit theme type and applies that category's resource fallback policy; lists expose stored keys, including null resource entries and nonpositive font sizes where stored. Deep copies preserve aliases between default and named fonts.
- ThemeDB : ElectronObject is the process service for built-in defaults and universal fallbacks. The built-in Theme contains actual current Panel/PanelContainer and ProgressBar styles/text data, HSlider/VSlider styles/icons/constants, box/grid separation constants and the first Label styles/colors/constants/font slots. GetDefaultTheme remains Partial for default assets and type entries required by other GUI slices. GetProjectTheme is Blocked until the Theme file loader and startup project configuration actually load and own a project theme; do not expose a null-success stub. Fallback base scale starts one and font size sixteen; font/icon/style fallbacks are typed borrowed resources, with a real lazy 16-pixel SVG error icon and hollow four-margin/two-border style initially. The initial FallbackFont and built-in DefaultFont share an owned embedded Open Sans SemiBold resource whose native face loads on first text use. FallbackFont accepts null and live borrowed replacements without rewriting Theme.DefaultFont. FallbackChanged reports committed replacement changes. Built-in SVG icons retain DPITexture source and adapt to viewport oversampling. Nonunit default-theme base-scale construction and dependent refresh remain a separate Partial integration. Slider SVG sources are validated during service construction; native rasterization is lazy, and the service owns their resources. The error source remains lazy.
- Control and Window expose the same six typed query, Has, add/remove override and override-presence families, Theme and ThemeTypeVariation, bulk override batching and ThemeChanged. Preserve notification IDs 45 and 32 respectively. Use one internal ThemeOwner implementation for their shared behavior; no new public ownership abstraction is introduced. Owner/lifetime and scene-capture guards continue to apply. Bulk override state is a source-compatible boolean: Begin is idempotent, End without Begin throws, and a completed batch publishes one theme change.
- Theme file archives use the existing typed dynamic property names for all six categories and variation bases. Fresh schema restoration accepts only those validated names and exact value roles, preserving defaults, raw/null entries, resource aliases, empty category groups and variation child order. Reserved structural arrays carry that shape without a Variant facade or reflected invocation. Theme has an explicit archive factory, and scene-held Theme resources follow the ordinary graph/lease/cache ownership contract.
- ThemeDB.GetProjectTheme returns the real selected project Theme. Engine.Start and windowed startup load typed gui/theme/custom and gui/theme/custom_font resources before main-loop activation. File/schema preparation is atomic: failure releases prepared objects and retains the previous selection. Publication uses an owned snapshot, with borrowed resources valid until the next successful replacement; old project graphs/fonts are then retired. Callback errors after publication propagate after required notification and cleanup. Clearing a project font restores the prior built-in/default and universal font identities while preserving intervening manual assignments. Empty initial paths preserve programmatic ThemeDB configuration. Configuration changes take effect at the next startup; this slice does not invent a live reload API.
- Lookup resolves local override, nearest branch themes, project Theme, built-in Theme and universal fallback. Variation bases and default scale/font/font size include the project Theme at that same priority. Project resource edits use existing deferred owner invalidation. All project file operations remain ordinary typed authoring, and the selected project resource has no public Instance accessor.
- A node's own override is eligible only for an empty/default request or a request matching its own type/variation. For resource search, choose the variation dependency chain from the nearest theme that defines it, followed by native type ancestry, then search each nearest-to-outer Control/Window theme for those types. An intervening neutral Node ends owner inheritance. After branch resources, search the project theme, built-in theme and finally the category fallback. Existence queries do not turn a universal fallback into a stored match. Theme replacement, variations and relevant hierarchy changes invalidate query caches. A cyclic active variation dependency chain throws InvalidOperationException instead of entering the pinned infinite loop; resource descendant lists separately suppress repeats.
- Resource-content changes reach scene owners through deferred delivery; direct override edits use immediate notification unless bulk updates suppress it. ThemeChanged is delivered before mandatory cache-clear/redraw/minimum/reflow work; failures still attempt required post-work and continue live descendant propagation. Preserve callback ordering, subscription cleanup, tree membership and thread ownership. Resource callbacks may originate off-thread, so they queue invalidation rather than mutating scene state from that thread. Detached owner queries bypass resolved-value caches and observe current ancestor/global data immediately without attached notifications; this bounded constructed-node correction prevents stale values before tree entry. Restore redraw/minimum/layout consumers when a theme value changes; do not leave these as passive dictionaries.
- Panel draws its resolved `panel` StyleBox. PanelContainer draws the same key, reserves its resolved content margins/minimum, and fits each eligible direct control inside the resulting content rectangle. It retains Container scheduling/fitting and defaults MouseFilter.Stop. Use exact factories and typed stored defaults. Box/HBox/VBox and Grid separation projections resolve actual theme constants while retaining the built-in default of four. Equal resolved separation assignments stay silent. A changed value equal to the inherited gap removes the local override; other changes add one. Their legacy editable descriptors are not independently stored and use inherited revert defaults; typed nullable override descriptors preserve actual local override presence/value, so packing does not freeze an inherited gap. Editor skin authoring is separate.
- Preserve invalidation across reentrant virtual getters with a cache generation check; an in-flight getter cannot refill a cache invalidated by its own callback. Deferred override-resource delivery rechecks bulk state on the owner thread. Same-owner notification reentry settles iteratively with the same 64-pass ceiling as branch propagation. Container schedules theme-driven sorting in finally even when ThemeChanged fails, so box/grid/panel layout cannot retain stale geometry after a failed observer.
- PackedScene restores dynamic theme overrides on fresh Control/Window targets through only six reserved typed descriptor families: ThemeColorOverride/Color?, ThemeConstantOverride/int?, ThemeFontOverride/Font, ThemeFontSizeOverride/int?, ThemeIconOverride/Texture and ThemeStyleBoxOverride/StyleBox. A missing fresh descriptor is rebuilt from the exact target role, prefix and value type; all other unknown or mismatched schemas remain rejected under the revised ADR 0023. Never reuse source-owner delegates or introduce a Variant/get-set facade.
- Font objects, font theme storage/defaults/overrides and font lookup execute with the FreeType/HarfBuzz Font resource/loading/shaping slice under ADR 0046. Control/Window GetThemeDefaultFont searches nearest branch defaults, project defaults, the built-in default and the nullable universal fallback independently of item overrides. Remaining GUI types add and verify their corresponding built-in styles/icons/defaults with their first complete consumer slices. Project Theme archive and startup loading execute in the profile above; editor authoring and nonunit built-in asset scaling retain their own triggers.

### Virtual touch consumers under ADR 0083

TouchScreenButton : Entity borrows normal/pressed Texture, BitMap and Shape. Its hit region is the union of authored shape intersection with a unit pixel rectangle and set bitmap pixels; a normal-texture rectangle is the fallback when neither mask is supplied. Shape centering uses normal texture dimensions. PassbyPress supports entering/leaving the region with the same finger; canceled contacts and lifecycle retirement release state. ShapeVisible displays actual shape outlines only under the existing collision-debug hint. Visibility remains an executable device policy, separate from ordinary CanvasItem visibility.

VirtualJoystick : Control retains the fixed/dynamic/following base, clamp/deadzone scaling, initial position ratio, tip geometry and four themed styleboxes. Shared top-level VirtualJoystickMode and distinct JoystickVisibility/TouchButtonVisibility preserve numeric domains. Configuration uses finite authored values; nonpositive clamp radius yields zero output, avoiding division by zero. State and owner contributions commit before notifications, following ADR 0038; required cleanup continues after callback failures and later mutation supersedes older work. Geometry configuration resets silently; lifecycle cancellation releases the gesture without tap/flick. Runtime finger/vector state and action leases are not scene storage.

Bundled touch scenes require BitMap file registration and atomic packed-mask storage; dimensions and pixels restore as one validated typed payload. Runtime contact/vector state remains absent from scene storage.
