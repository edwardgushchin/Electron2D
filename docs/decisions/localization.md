## ADR 0007: Use a typed process-wide translation service

Last updated: 2026-10-18

- Status: Accepted
- Scope: Runtime message translation

### Context

Godot `Object` provides per-object translation enablement, a domain, and `tr`/`tr_n`. Electron2D needs the same caller-facing capability through typed messages and resource-backed catalog assets without a Variant-based API or another managed assembly.

### Decision

- `TranslationServer` is a process-wide in-memory catalog selected by one `CultureInfo`. It owns a registry of `TranslationDomain` objects, including the main domain named `""`. Domains register borrowed `Translation : Resource` catalogs without owning their disposal. Resource edits become visible immediately; removal, clearing, or disposal stops their lookup. A removed domain remains usable independently; a disposed registered domain leaves the registry.
- Registered domain lookups and server lookups share direct entries, resource priority, locale override, and enablement. Standalone domains resolve their own resource catalogs. A domain override replaces the selected culture for that domain.
- Keys are culture, domain, context, and source text. At startup the typed project test locale overrides the current managed UI culture when nonempty; the typed fallback locale defaults to `en` and can be disabled with an empty value. Both settings are sampled at Engine startup. Callers may change `TranslationServer.Culture` during a run.
- Resource lookup ranks every matching catalog against the requested locale with the fixed default-aware CompareLocales score, then tries the configured fallback only if no message resolves. It does not replace the request with its parent or invariant culture before ranking resources. Standalone and registered domains use this same path. Later resource registrations win equal scores. Electron2D direct-entry conveniences retain the selected/parent/invariant candidate route: selected and parent candidates compete by the same requested-locale score, direct entries win score ties, and an invariant direct entry is an explicit lowest-priority universal fallback. Thus a weaker parent entry cannot replace a better regional/script catalog, while equal-score direct overrides remain authoritative. Missing or empty resource results allow the next eligible catalog; direct empty results retain their explicit override meaning. Runtime culture/catalog assignment keeps the accepted managed CultureInfo boundary. Locale comparison prepares immutable parsed identities in an ephemeron cache keyed by the supplied string object, so repeated live identities allocate nothing without retaining retired caller strings. Message results and mutable catalog state are not cached. GetToolLocale uses the same default-aware score.
- `ElectronObject` stores a translation-enabled flag and domain and exposes typed `Tr`/`TrN` methods.
- `Node` inherits its translation domain from its parent until an explicit assignment; `SetTranslationDomainInherited` restores this behavior. Its `AutoTranslateMode` resolves through the nearest ancestor, and `Atr`/`AtrN` apply that policy before ordinary object translation. A scene root samples the typed `root_node_auto_translate` project setting when its tree starts. Tree entry, mode changes and active inherited-domain changes deliver translation-change notifications.
- The permanent typed project root layout selector uses 0 application locale, 1 LTR, 2 RTL and 3 system UI locale. A separate forced RTL setting affects inherited and application/system locale modes, while explicit LTR/RTL remain authoritative. Each SceneTree samples both policies with feature overrides before root entry; detached nodes use current project values. Window and Control share domain-aware ancestry and root resolution. Local translation/layout notifications reflow descendants; global Culture changes now notify the attached application MainLoop. Domain-local policy/catalog edits retain explicit notification, matching their separate source operations.
- Culture assignment publishes the supplied CultureInfo under the catalog lock, then synchronously notifies the current Engine.MainLoop only when its normalized culture name differs. Equal-name assignment retains the supplied managed identity without another notification. Server PseudolocalizationEnabled assignments notify even when equal; ReloadPseudolocalization applies all options before notification and preserves runtime enablement. A SceneTree propagates through its existing depth-first membership snapshot, including disabled/paused nodes; independent library trees are notified explicitly. Callbacks run after the setter lock is released and cannot roll back committed state. A foreign caller can commit Culture, but its SceneTree notification fails the ordinary owner-thread guard; callers use the existing scene scheduler for owner delivery. Reentrant system delivery retains separate prepared buffers per depth, clears captured references after success/failure, and allocates no managed storage after the exercised hierarchy/depth capacities warm. No observer registry, hidden dispatcher or background game thread is introduced.
- Missing messages return the source text. Deprecated single-catalog getters are omitted under ADR 0004; FindTranslations is the current resource query.
- Each domain offers configurable singular-message pseudolocalization: accents, doubled vowels, fake bidirectional controls, placeholder preservation, override, expansion, prefix, and suffix. The main domain is exposed through server convenience members. Plural results are not pseudolocalized, matching the pinned reference behavior. Locale matching and Unicode transformations are tracked as Partial where exact reference parity is not yet established.
- Eleven typed built-in `ProjectSettings` definitions configure locale selection and main-domain pseudolocalization; a twelfth configures initial root-node automatic translation and two more configure root/forced layout direction. `Engine.Start` and `Engine.Run` sample the catalog settings at startup, while `SceneTree` samples the root mode at construction. `TranslationServer.ReloadPseudolocalization()` reapplies the eight transformation options but preserves the current runtime enabled flag; enabling or disabling during a run is an explicit server operation. Already constructed scene trees may have completed ready callbacks before a manual `Engine.Start`. Project settings are prepared completely before one startup translation notification is sent to an already attached MainLoop. Asset remaps remain deferred.
- Direct plural registrations receive `Func<long, string>`. Resource catalogs use copied plural-form lists and an optional typed `Func<long, int>` selector. Known locales use fixed language/region gettext rules when no caller selector is assigned; unknown multi-form rules fail explicitly. Locale assignment prepares the rule, duplication preserves the optional caller override and recomputes automatic state, and warm selection allocates no managed storage. Caller delegates remain borrowed and copied by reference.
- PO/MO import uses strict UTF-8 with a 16 MiB input budget, at most 100,000 messages and 64 plural forms. Header Language/X-Language selects the locale; absent language keeps the English default. PO continuation strings, contexts, plural indexes, fuzzy and obsolete entries are handled. MO supports both byte orders and ordinary original/translated string tables; unsupported system-dependent extension tables and non-UTF-8 catalogs fail explicitly. Malformed input never publishes a partial resource. Import is read-only; ResourceSaver preserves imported messages and rules through `.e2dres`.
- Catalog state is lock-protected; resource lookup and its overridable callbacks run outside the server lock. Direct plural selectors retain their existing locked-lookup contract. The global enabled flag is internal and uses volatile access. Applications control translation per object through `ElectronObject`.

### Consequences

- The current runtime supports deterministic direct and resource-backed translation lookup without `Variant` or another package. Typed resource copying preserves independent message containers.
- The locale catalog supplies copied language/script/country code arrays, English names, aliases, supported-script/regional defaults and gettext definitions. StandardizeLocale preserves pinned parsing/casing/modifiers without requiring a .NET culture entry; CompareLocales uses its default script/country identity. Runtime catalog Locale still uses the accepted CultureInfo role. Fixed typed selectors serve the built-in table; explicit catalog definitions use the bounded expression evaluator. Four two-form predicates that incorrectly returned index one for singular are corrected against integer cardinal examples in CLDR48. This is a fixed gettext table, not arbitrary CLDR decimal-category support. UTF-8 PO and ordinary MO string-table catalogs now use ResourceLoader. The stored Translation.PluralRulesOverride definition, including an imported Plural-Forms header, is parsed once into a bounded immutable expression tree and takes priority over the fixed locale rule, while an explicit caller delegate takes priority over both. Empty or syntactically invalid public definitions retain automatic locale fallback; import rejects invalid declared definitions. The definition is stored in resource metadata and copied independently of caller overrides. Runtime lookup now uses these scores consistently; automatic operating-system culture acquisition after startup and asset remaps remain separate. The numeric-input consumer now implements FormatNumber/ParseNumber/GetPercentSign using the pinned numeral-system table; this current formatting capability does not imply broader locale negotiation.
- Direct plural selectors run during locked lookup and should be short; resource selectors run after snapshotting state. Recursive selector logic remains the caller's responsibility.
- Global catalog state must be restored or cleared by isolated tests and applications that replace languages.

### Rejected alternatives

- Return `object`/`Variant` translations: rejected by ADR 0001 and unnecessary for string messages.
- Hard-code English singular/plural rules for every locale: rejected because that would be incorrect for many languages.
- Add a catalog library: rejected because the selected UTF-8 PO and MO string-table formats require only bounded managed parsing; no additional assembly is needed.
