## ADR 0092: Typed 2D mesh surfaces on the retained canvas

### Status

Accepted. Refines the typed resource projection in [ADR 0001](product.md#adr-0001) and the backend contract in [ADR 0028](rendering.md#adr-0028).

### Decision

Mesh : Resource supplies the applicable surface-query/material callbacks. ArrayMesh stores copied two-dimensional vertices, vertex colors, primary/secondary UVs and optional indices through MeshSurfaceData; named fields replace the heterogeneous array-of-arrays without Variant/object dispatch. MeshInstance : Entity projects the MeshInstance2D scene role, preserving borrowed Mesh/Texture, texture_changed and inherited canvas behavior. CanvasItem.DrawMesh and logical RID drawing feed the same retained canvas submission; all five primitive topologies execute through native GPU and compatibility triangles. Points and lines keep one-framebuffer-pixel width after transforms, with no antialias fringe. Per-surface materials override the drawing item's material; unsupported shaders fail through the existing fallback gate.

The native/backend-neutral surface arrays preserve the exercised pinned channel packing: positions are little-endian float X/Y pairs; colors clamp/truncate to RGBA8 UNORM on import; primary UV remains two little-endian float components. Vertex stride is eight bytes. Attribute stride is four bytes for color plus eight bytes per present primary/secondary UV channel, in that order. Region updates use byte offsets, including partial records, validate affected finite values before publishing and preserve untouched bytes. UseDynamicUpdate remains a policy hint and does not make other surfaces inert. Resource queries return independent channel copies; successful repeated updates and replay reuse prepared storage. This is not a public SDL buffer or GPU-device pointer.

Resource Mesh.GetRID is a stable weak borrowed logical identity until disposal, independent of an active renderer. RenderingServer owns caller-created mesh identities until FreeRID/shutdown; owned and resource-owned identities are distinguished before mutation/free. Retained draws observe current ArrayMesh buffers without requiring a fresh command. Custom Mesh callbacks publish Changed after edits and provide copied typed channels; their prepared replay snapshots are refreshed on that revision. Custom callbacks must keep the resource revision stable while preparing a snapshot; changing it rejects the mixed result and permits retry. Repeated replay uses the captured surface count without calling user callbacks. Custom callback allocation is separate from the runtime preparation measurement. MeshInstance uses the ordinary scene owner/capture mutation guards and local Resource graph duplication.

This profile does not redefine unsupported source capabilities as irrelevant. Morph targets/weights execute through the typed authoring/extraction and independent 2D deformation contract below; Authored LOD storage/scale selection executes through the contract below; automatic simplification remains the ImporterMesh producer dependency. Mesh skin/bones/weights now use typed MeshSurfaceData/packed-region channels and actual owned/scene palettes, as specified below. Attribute compression executes through the packed UV/joint-frame contract below. Remaining missing capabilities reject or remain absent, with exact member-specific coverage triggers; no inert setter or nominal data-only support is reported as complete. GetFaces extracts copied local Vector2 triangle faces, expanding indexed and sequential triangles and alternating-winding strips; point and line surfaces contribute nothing. The returned TriangleMesh resource and lightmap-size hint remain excluded as 3D intersection/lightmap capabilities. Shadow mesh requires the first 2D light/shadow geometry consumer; placeholder meshes require the missing-asset placeholder producer. 3D-only triangle-mesh/collision/lightmap operations retain their accepted product exclusions, not an invented 3D runtime type.

ImmediateMesh : Mesh builds one invisible draft through SurfaceBegin, current Color/UV/UV2 and SurfaceAddVertex2D, then SurfaceEnd publishes sequential ArrayMesh-backed storage. First attribute activation backfills earlier vertices with the assigned value; later assignments affect only future vertices. Empty/incomplete topology rejects without losing the draft. ClearSurfaces cancels the draft and removes completed surfaces. End, clear and inherited material edits publish Changed after commit and outside the storage gate, keeping Electron2D resource/canvas invalidation consistent even where the pinned immediate builder does not notify on clear/material edits. Duplication copies completed geometry and material graphs, never transient draft state. Methods serialize individual operations; callers synchronize whole construction sequences shared across threads. Structural authoring is a cold allocation boundary; replay and repeated material/transform updates use prepared storage. Secondary UV now follows the same first-call backfill, future-vertex assignment, reset and commit/copy rules through SurfaceSetUV2. MeshSurfaceData.UV2s and ArrayFormat.TexUV2 carry independent finite coordinate pairs. Packed updates validate both UV channels before any write. ArrayMesh archives write AMS2 with the secondary channel and read legacy AMS1 without it; invalid data preserves prior storage. Retained mesh/custom/skin/instance drawing preserves secondary coordinates, with zero defaults on other geometry. The GPU vertex layout uses a separate float2 at location seven and forwards it to fragment float2 location four, preserving instance custom data at location two and the internal lighting index at three. Compatibility drawing retains ordinary primary-UV sampling and rejects programmable shaders as before. SurfaceTool uses this completed secondary storage/consumer in its typed mesh-authoring profile below.

### Ownership, errors and verification

Meshes own channel storage and borrow materials; nodes and drawing commands borrow meshes/textures. Owned server meshes close with the renderer. Invalid geometry, nonfinite inputs, out-of-range indices and regions fail before mutation. Resource Changed runs after committed edits; callback failure does not roll back valid geometry. Warmed successful paths are checked under [ADR 0014](resources.md#adr-0014). Exact managed/native pixel and platform limits are recorded in the [mesh component](../components/meshes.md); builds do not establish rendered or human acceptance.

This extends the applicable packed-data operations; it does not reinstate the excluded dynamic array container/selectors.

This ordinary stream remains available until device-buffer export selects retained writable storage described below. Both current native backends consume poses, colors, UVs, material overrides and inherited canvas policies. Custom data is preserved as raw float32 components on all backends and reaches an optional GPU fragment float4 at location two, independently of tint. Compatibility rejects custom shaders explicitly. Shader vertex programs remain their separately recorded dependency.

RenderingServer owns created MultiMesh storage and borrows its Mesh identity; resource-owned identities remain weak and cannot be mutated/freed through owned APIs. MeshCreate now records its canonical RID in the owned resource so linked mesh queries return that same identity. MultiMeshAllocateData executes typed allocation atomically, including indirect mode on the GPU backend. The writable-buffer decision below supplies actual global RenderingDevice storage and an executing canvas consumer. Compatibility rejects enabled indirect mode before mutation.

### Numerical normal and tangent channels

MeshSurfaceData.Normals contains optional finite Vector3 directions, and Tangents contains optional finite Vector4 XYZ directions with W handedness. These are mesh-local shader data and add no spatial scene domain. ArrayFormat.Normal=2/Tangent=4 share one enum family with RenderingServer. Ordinary surfaces retain two-float positions in the first contiguous block; interleaved normal/tangent records follow that block, four bytes per present channel. Each direction uses octahedral UNORM16 with float32 clamp/truncate. Tangent encoding preserves the sign bit with the pinned bias and reserved-code sanitation. Exact words are retained internally, so partial updates, archives and tangent regeneration do not drift untouched bits. Zero directions have deterministic positive-Z storage instead of undefined NaN conversion; finite extreme encoding uses widened normalization. Normal-only input produces the actual arbitrary fallback tangent and tangent flag. Attribute color/UV strides and skin records remain separate.

ImmediateMesh captures/backfills both channels through SurfaceSetNormal/SurfaceSetTangent. SurfaceTool enables them before the first vertex, imports/appends/indexes every captured field, accepts optional fan values, and generates clockwise-front planar normals with flat minus-one or shared position/group smoothing. Indexed normal generation expands and reindexes seams; opposite unit face contributions cancel, and degenerate faces contribute zero. MeshDataTool.GetFaceNormal follows that same clockwise-front convention, correcting its previously reversed sign. Append applies inverse-transpose XY normal data, basis-transformed tangent data and reflected handedness; normal-bearing singular transforms reject before replacement. MeshDataTool readers/writers use the shared channels. Tangent generation uses the internal vendored MikkTSpaceSharp under ADR 0012, validates before publication, calibrates extreme position/UV spans and releases all temporary unmanaged blocks on errors. Indexed shared vertices retain the last face-corner output, matching the producer contract. ArrayMesh.RegenNormalMaps prepares every surface before one atomic publication, retains exact normal words, names/materials/policy flags, and preserves old storage after any generation error.

The retained CanvasVertex adds float3 normal at byte 56 and float4 tangent at 68 (84-byte stride). GPU inputs use locations eight/nine and forward to optional fragment float3 location five and float4 location six. Ordinary, custom, points/lines/strips, hardware instances, palettes and canvas groups preserve these mesh-local values. Canvas transforms and skin deform positions; they do not reinterpret this numerical payload as world-space shading. Missing channels on other geometry forward zero. Compatibility retains ordinary texture/color output and its existing shader rejection. Structural generation/import/copies may allocate; warmed packed edits and completed replay reuse storage. ### Four numerical custom channels

MeshCustomFormat is one namespace-level value contract shared by Mesh, SurfaceTool and RenderingServer under ADR 0051. MeshCustomData supplies a typed format and copied little-endian byte records; MeshSurfaceData.Custom0 through Custom3 name the four independent payloads. Exact indexing compares canonical selected-format records independently of capture origin while retaining distinct raw signed-zero words. Current Linux GLSL/HLSL retained pixels exercise all eight formats, ordinary/authoring/custom meshes, hardware instances, eight-slot skin, strips, points, lines and groups; 64 active and 64 idle frames allocate zero managed bytes. Wider platforms and complete native allocation totals remain unverified.
