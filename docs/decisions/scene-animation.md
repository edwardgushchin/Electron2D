## ADR 0093: Typed reusable scene animation

- Status: Accepted
- Date: 2026-10-04
- Depends on: [0001: C# typed API](product.md#adr-0001), [0002: typed events](product.md#adr-0002), [0005: property descriptors](core-object-runtime.md#adr-0005), [0008: node roles](scene.md#adr-0008), [0014: resource lifetime and copying](resources.md#adr-0014), [0037: typed interpolation](scene.md#adr-0037), [0051: enum identity](product.md#adr-0051)

### Context

Runtime tweens execute one-off instructions. Games also need reusable named clips, authored keys, relative scene targets, repeatable seeking and playback sections. Arbitrary property strings or a general value container would conflict with the typed property decision. A clip must work on multiple node instances without storing a target instance in the asset.

### Decision

- `Animation : Resource` stores heterogeneous track metadata, with every key container and evaluator implemented as a concrete generic value type. `AddTrack<TOwner,TValue>` requires a writable `PropertyDescriptor<TOwner,TValue>`. Its optional typed interpolator uses the same role as the tween interpolator; no reflection property setter, dynamic dictionary or universal value accessor is introduced.
- A track's relative path resolves its node from the mixer's root. An optional property suffix must equal the descriptor name. Descriptors are immutable and shared by copies. Values are read and written through generic APIs; mismatched key types fail explicitly. Node-role substitution applies to the descriptor owner, not merely to names.
- `AnimationLibrary : Resource` borrows named animations and detaches observers on replace/remove/dispose. Names use ordinal comparison. Resource duplication copies containers; deep copying passes nested resource keys and library members through the resource graph session. Managed resources and nodes retain their existing owner-thread authoring rules.
- `AnimationMixer : Node` owns library namespaces, root-path binding caches and automatic idle/physics/manual selection. `AnimationPlayer : AnimationMixer` owns clip selection, time, queue, speed, sections and completion. Node's internal callbacks provide automatic advancement and inherited pause/lifetime policy. No second clock or SceneTree registry is added.
- Track/resource changes, tree mutation, root changes, selection and explicit cache clearing invalidate the typed target bindings. Evaluation snapshots the current binding array and abandons that pass when a callback changes its resource or selection. Disposed/queued targets do not receive values. A setter failure pauses the unchanged playback and propagates through existing Node/SceneTree error handling.
- Endpoint loops share `SpriteFrames.LoopMode`, whose meanings and valid values already match this domain. The existing two-value `ProcessPhase` stays unchanged: animation's three-value callback domain is distinct because it admits Manual.
- Failure-return methods use exceptions consistently with existing typed resources. Mutation commits before observer notification. Library replacement emits removed then added, with observers seeing committed replacement state; reentrant removal cannot leak a subscription.
- The first executable profile is value-property keys and single-clip playback: continuous/nearest/discrete interpolation, float/double angular curves, time-aware typed cubic curves, named markers, queues, reverse, sections and automatic phases. Discrete evaluation writes every crossed key in direction order, including repeated loop seams; bindings initialize their sampled value after construction or seek. Typed multi-source property accumulation and capture now execute. Numeric values accumulate relative to zero or the first enabled RESET key; non-deterministic mode normalizes per-property weights. Bool/integer values promote during accumulation and round only at output, Int64 uses decimal precision, angle values unwrap around their rest value, and Transform uses existing affine group operations. Strings blend Unicode scalar codes and lengths; typed numeric/vector/color/string/jagged-int arrays have independent output containers. Uninterpolatable references use discrete holding; custom typed interpolation remains available for other values. Value-key optimization and persistence remain applicable follow-up slices. Three-dimensional transform/blend-shape tracks, their compression and root-motion extraction follow the 2D exclusion policy.
- Animation nodes have no empty packed-scene factory: packing them fails explicitly until library/track persistence and constructor state restoration exist. In-memory authoring and execution are independent of disk format, editor tooling or agent file-load acceptance.

- `AnimationMixer.Capture` creates an owned typed snapshot resource from current Capture-track target values. It replaces its previous snapshot only after preparation succeeds. Fade expiry, cache clearing, Pause/Stop and disposal release snapshots without disposing borrowed targets or authored resources. Typed `OnPostProcessKeyValue<TValue>` runs after sampling for ordinary and captured keys, using the actual target instance ID; it exposes no universal value container. Snapshot cleanup failures still allow Node cleanup.
- `AnimationPlayer` retains outgoing clip state for named/default/custom crossfades and supports explicit/automatic capture, curve/ease settings and first/last-key-derived duration. Capture's clock uses absolute SpeedScale independently of custom clip speed. Playback pause/stop clears queued names and capture caches. Weighted evaluation snapshots its prepared property list and abandons commits after reentrant controller, source, target topology or capture-snapshot changes. Nested Advance fails explicitly.
- Preserve the pinned order of transition weights: the main clip weight uses the prior outgoing weights, then outgoing weights decay for this update. Interrupted transitions keep existing outgoing clips and add the prior main clip with its current remaining contribution. This means the first timed update can still show the outgoing pose, and large delta/interrupted transitions can look abrupt. Internal semantic documentation records numeric samples instead of changing this order silently.

- `AnimationTree : AnimationMixer` evaluates borrowed `AnimationRootNode` definitions on the existing weighted property path. `AnimationNode` is a Resource, separate from scene Node. Typed `AnimationParameter<TValue>` definitions project animation-domain parameter schemas; generic cells belong to each tree/path, with exact key identity and no universal value accessor. Read-only timing diagnostics are internally writable. Test-only evaluation suppresses persistent state/output; sequential graph sharing is supported, concurrent evaluation of a shared definition is not.
- BlendTree owns its reserved output and connection containers, borrows child definitions, rejects self-containment/connection cycles and shifts connections when inputs are removed. Rename preserves per-path cells, removal detaches obsolete observers on preparation. Sync controls silent branch clocks; track-path filters affect per-track weights. Blend2/3, Add2/3, Sub2, TimeScale/TimeSeek and clip custom timelines execute. AnimationTree defaults to deterministic ForceContinuous mixing, internal startup seek and optional provider reconciliation; provider membership/root changes use existing libraries/bindings and never dispose borrowed resources.
- Graph topology/cache edits invalidate stale property commits; graph notifications reach attached trees even if another handler fails. Resource copy/disposal retains the established alias/ownership policy. No graph persistence factory, expression evaluator, empty transition state or generic property parameter dictionary is introduced. State-machine slices consume this executable graph foundation separately. OneShot/Transition now execute typed action/name requests, per-tree timer/selection cells, before-decay unit-curve fades, filtering, reset/restart/loop-break and automatic policies on that mixer. Input mutation dispatch is virtual so policy/connection storage stays aligned before observer delivery. External seek deltas project previous minus requested position and predictive cycle-end timing propagates through selected nodes. Graph lifecycle notices use prepared reusable records/delegates on existing SceneTree deferred batches, preserving order/failure cleanup without steady closure allocation. BlendSpace1D/2D now use it for named borrowed points, typed blend positions, linear/triangle interpolation, discrete/carry and independent/cyclic clocks. Shared mode enums retain one semantic identity; selected-point identity and current tree libraries preserve clocks/lengths through edits and graph sharing. Automatic triangulation is a cold on-demand authoring operation; warm graph evaluation keeps stack scratch and the existing mixer.

- Method tracks now carry one exact Node receiver type and immutable `AnimationMethodKey<TOwner, TArguments>` keys; different payload signatures coexist without object arrays, reflection invocation or an untyped payload accessor. Names are diagnostic; the delegate is executable identity. Value tuples/immutable records express multiple arguments. Relative method paths identify only the receiver node. Continuous scalar Bézier tracks use float/double descriptors and `AnimationBezierKey` geometry. Their two finite handle offsets clamp incoming x ≤ 0 and outgoing x ≥ 0. Ten bisection steps invert cubic time and then interpolate adjacent samples; loop seam wrapping, easing and interpolation metadata do not change this geometry. The runtime balance-ratio parameter remains finite metadata; editor-only mirrored/balanced handle modes require the separate editor capability.
- Method callbacks use the existing graph/property evaluation and track filters. Startup/internal seek selects an exact key; external seek selects the preceding nearest key within clip bounds. Update-only seek/Stop and effectively zero track weights suppress callbacks. Normal execution visits crossed keys in direction order, including section boundaries and repeated linear/ping-pong crossings. Immediate callback reentry/resource edits abandon the stale pass. Deferred calls retain their queued typed key, use SceneTree's captured safe-point batches and skip disposed/deleting or moved receiver nodes. Clearing source caches does not revoke accepted queued calls; target lifetime determines delivery. Callback failures propagate through the existing player/deferred error contract.
- Deferred bindings prepare max(16, key count) reusable records and cached delegates when bound. `AnimationMixer.PrepareMethodCallbacks` grows their minimum pending capacity explicitly between frames; successful dispatch never grows that pool. Capacity exhaustion throws, preserving already accepted queued calls, and ordinary player failure pauses unchanged playback. SceneTree's shared action queues still warm their largest batch separately. User callback allocations are outside engine control. Bézier/property and prepared callback execution share the zero warmed managed-allocation requirement; native/driver allocation is a separate measurement.

- Nested animation tracks now carry string clip keys and resolve only AnimationPlayer targets from node-only relative paths. Ordinary crossings choose the final crossed key in traversal order, including reverse/section/repeated-loop paths; internal startup and external seeks select the nearest preceding in-clip key. [stop]/missing names stop previously controlled playback on ordinary crossings and are ignored on seeks. Child clips retain their own clock and ordinary node phase; no separate timeline scheduler is introduced.
- Seek initialization selects the child clip before positioning it, and uses that child's length/loop policy, correcting stale-assignment clamping and parent-period folding. Finite children whose elapsed key offset is expired do not start on internal startup; external seeks clamp/sample their endpoint. A paused child's external seek samples without starting it; running/internal seeks retain playback. Update-only seek samples the selected pose while preserving the child's prior playing/stopped policy and suppressing method effects. Stop's reset pass therefore does not restart children.
- Controlled children are tracked by exact successful control revision. Ownership is established before startup callbacks, so failure or owner stop can clean them immediately; observer control takeover abandons stale follow-up seek and future cleanup. Pause/Stop, selected-clip change, cache clearing/rebuild and owner disposal stop still-controlled children with values retained. Targets/resources remain borrowed. Self/currently-evaluating player control rejects before mutation, preventing synchronous nested seek recursion. Earlier property writes/clock changes are not rolled back after a later failure.
- Prepared direct-evaluation and weighted caches remain separate because their property/discrete responsibilities differ. Playback/seek/stop reset evaluation state and discrete initial cursors while retaining reusable bindings; root/tree/resource invalidation rebuilds them cold. Nested starts/stops and ordinary child property passes then allocate no managed storage after warmup. A resource edit that removes the final event track is recognized when execution moves back to the direct path, so prior controlled children cannot remain orphaned.

- Audio tracks now store AnimationAudioKey with a borrowed nullable AudioStream and finite start/end trim. Negative trims clamp to zero. Node-only paths resolve AudioStreamPlayer or AudioStreamEmitter without reflection; a receiver shares one prepared polyphonic transport across clip bindings. AudioMaxPolyphony defaults to 32 and accepts 0..128. Keys/copies/track metadata and deep Resource aliases use the existing typed container contract.
- Ordinary crossings choose the last key; startup/seek choose the preceding in-range key and add elapsed key time to start trim. Update-only suppresses starts while existing cues still update/retire. End trim expires cues against traversed clip time, including loops; finite timeline rewinds retire obsolete cues. Every active cue stays in bounded per-binding records rather than losing earlier repeated-key voices. Clip weights set child gain, normalize per receiver in non-deterministic mode, and UseBlend=false keeps unit cue gain. Initial gain is applied before transport start.
- Preparation creates independent child states, sample requests/native sample voices and parent native storage before repeated dispatch. Repeated starts lease prepared states, reset through ordinary Start/Stop and retain independent generations. Randomizer selection/variation occurs at each actual trigger; randomizers nested in prepared composite factories use an internal prepared wrapper and select at actual start. The normal public factory path remains fresh. Custom callbacks and cold graph edits keep their existing ownership/allocation boundary. Direct source revisions and top-level randomizer structure changes invalidate preparation; rebuilding/capacity changes are cold.
- Pause/Stop, selected-clip changes, structural cache invalidation and disposal stop owned cue output. Cleared owned transport detaches its disposed source from the receiver, while borrowed authored streams remain alive. Stream/sample selection, node pause/process/gain/pitch/mix target and emitter spatial/Area routing use existing FAudio paths. No new backend, vendor patch or independent scene clock is introduced. Native PCM/capture and actual window/pixel hosts are separate from physical listening/platform acceptance.

### Consequences

A game can author a clip against a typed property, attach it by library name and execute it in a real rendered scene. Warmed steady playback avoids per-frame generic value boxing or path parsing. Editing/rebinding, transition preparation and capture may allocate. Immutable strings and independent array results allocate when published; warmed scalar/vector/transform accumulation uses prepared typed storage. Existing rendering consumes the ordinary setters and needs no animation-specific backend path. Linux host/readback checks establish rendered execution; other platforms, editor/disk round trips and human visual acceptance remain separate gates.
